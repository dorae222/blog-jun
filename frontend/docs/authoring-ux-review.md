# 글 작성 흐름 UX 점검 (워크스트림 H2)

대상: `fix/about-logos`(운영 반영본) 프론트엔드. 로그인 → 대시보드 → 새 글 → 작성(이미지·템플릿) → 저장/발행 → 수정 흐름을 코드로 따라가며
"내가 매일 쓴다"는 가정으로 걸리는 곳을 모았다. 우선순위: **P0** 글이 날아가거나 저장이 안 됨 / **P1** 매번 불편 / **P2** 가끔 불편.
상태: ✅ 이번 브랜치(`feat/workspace`)에서 고침, ⏳ 남김.

## 흐름 요약(변경 전)

1. `/login` → 성공하면 무조건 `/dashboard`로 이동.
2. 대시보드 "새 포스트" 또는 사용자 메뉴 "새 글 작성" → `/editor`.
3. `Editor.jsx`: 제목 입력 시 slug를 제목에서 매번 다시 만듦 → 본문은 NotionEditor(WYSIWYG)/Split/Source 중 하나.
4. 30초 `setInterval` 자동 저장(제목·본문이 있을 때) → 새 글이면 `createPost` 후 `/editor/:slug`로 이동.
5. "Publish"는 `status: 'published'`만 덧붙여 저장.
6. 수정은 대시보드 목록의 연필 아이콘 → `/editor/:slug`.

## 새로 생긴 작성 흐름(변경 후)

- 어디서든 `n` → 새 글. 제목을 쓰고 본문을 쓰면 **4초 뒤 서버에 초안 자동 생성**, 주소가 `/editor/<slug>`로 바뀌어도 편집기는 그대로.
- 입력은 0.6초마다 로컬 임시저장. 브라우저가 죽어도 다시 열면 "임시저장본 복구" 안내.
- Cmd/Ctrl+S는 언제든 즉시 저장(발행 글이면 "업데이트"). Alt+P 미리보기.
- "발행" → 점검 모달 → 빠진 것(카테고리·요약·slug)을 그 자리에서 채우고 발행. `published_at` 자동.
- 발행한 글 수정은 로컬 임시저장만 되고, Cmd/Ctrl+S 또는 "점검 후 반영"으로만 공개 글이 바뀐다.
- 어디서든 `m` → 빠른 메모(Enter 저장, `#태그` 인식). `/notes`에서 정리하고 "글로 변환"하면 초안 글 편집기로 이동.
