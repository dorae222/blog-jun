# OpenAI o1: 테스트 시간 컴퓨트 스케일링으로 추론 AI 시대를 연 모델

## 개요

OpenAI o1은 OpenAI가 2024년 9월 12일 공개한 추론 특화 언어 모델로, AI 연구의 새로운 장을 열었다. 기존 LLM이 학습 시점(train time)의 데이터와 파라미터를 늘려 성능을 향상시키는 **스케일링 법칙(Scaling Law)**에 의존했다면, o1은 **추론 시점(test time)에 더 많은 연산을 투입**할수록 성능이 향상되는 **테스트 시간 컴퓨트 스케일링(Test-Time Compute Scaling)**이라는 새로운 축을 제시했다.

o1은 응답 생성 전에 내부적으로 긴 Chain-of-Thought(CoT) 추론 과정을 수행하여, 수학 올림피아드, 박사 수준 과학 문제, 복잡한 코딩 태스크에서 GPT-4o를 크게 능가한다. AIME에서 인간 경쟁자 수준(83%)의 성능을 달성하고, GPQA Diamond에서 전문가 수준(78.1%)을 초과하며, AI 추론 능력의 새로운 한계를 보여주었다.

### 테스트 시간 컴퓨트 스케일링

기존 스케일링 법칙은 학습 시점의 FLOPs와 성능 간의 관계를 다룬다:

$$L(C) \propto C^{-\alpha}$$

여기서 $C$는 학습 컴퓨트, $L$은 손실, $\alpha$는 스케일링 지수이다.

o1은 여기에 추론 시점의 스케일링을 추가한다:

$$P(\text{correct}) = f(C_{\text{train}}, C_{\text{test}})$$

즉, 학습 컴퓨트 $C_{\text{train}}$을 고정하더라도, 추론 컴퓨트 $C_{\text{test}}$를 늘리면 정확도가 향상된다. 이는 파라미터 스케일링과 독립적인 새로운 성능 향상 축이다.

## 핵심 혁신

### 1. 내부 Chain-of-Thought (Internal Monologue)

o1의 핵심 메커니즘은 **내부 모놀로그(internal monologue)**이다. 최종 답변을 생성하기 전에 수백~수천 토큰의 내부 추론 과정을 수행한다:

1. **문제 분해**: 복잡한 문제를 하위 문제로 분해
2. **다각도 탐색**: 여러 접근법을 병렬적으로 탐색
3. **자기 검증**: 중간 결과의 논리적 일관성 검증
4. **오류 수정**: 발견된 오류를 되돌아가 수정
5. **최종 합성**: 검증된 결과를 종합하여 최종 답변 생성

이 내부 추론 과정은 **사용자에게 직접 노출되지 않으며**, 요약된 형태로만 제공된다.

기존 GPT-4o가 프롬프트에 명시적으로 "단계별로 생각해보세요(Let's think step by step)"라는 Chain-of-Thought 프롬프팅을 요구했다면, o1은 이러한 단계별 추론을 **모델 내부에 내재화**했다. 프롬프트 엔지니어링에 의존하지 않고 모델 자체가 언제 어떻게 추론할지를 자율적으로 결정한다는 점에서 패러다임적 전환이다.

내부 CoT의 구체적 동작을 예시로 살펴보면:
- **수학 문제**: "이 문제는 정수론 문제로 보인다 → 페르마 소정리를 적용해보자 → 아, 조건이 맞지 않는다 → 중국인의 나머지 정리가 더 적합하다 → 계산해보면..." 식으로 시행착오를 거치며 최적의 해법을 탐색
- **코딩 문제**: "입력 크기가 $10^5$이므로 $O(n^2)$는 시간 초과 → DP나 그리디를 고려 → 그리디의 반례가 있는지 확인 → 없으므로 그리디로 구현" 식으로 알고리즘 선택을 추론

이처럼 o1의 내부 CoT는 단순한 단계별 풀이가 아니라, **탐색-검증-수정의 반복적 과정**이며, 이것이 기존 CoT 프롬프팅과의 본질적 차이다.

### 2. RL 기반 추론 최적화

o1의 추론 능력은 강화학습(RL)을 통해 학습된다. OpenAI는 구체적 알고리즘을 공개하지 않았으나, 후속 연구(DeepSeek-R1 등)와 공개 정보를 종합하면 다음과 같은 구조로 추정된다.

**학습 파이프라인 (추정)**:

1. **SFT 단계**: GPT-4 계열의 기본 모델에 전문가가 작성한 고품질 추론 과정(CoT)으로 지도 미세조정(Supervised Fine-Tuning)을 수행하여 기본적인 추론 패턴을 학습
2. **RL 단계**: 수학, 코딩, 과학 문제에서 정답 여부를 보상 신호로 사용하여 강화학습을 수행. 모델은 자체 생성한 추론 과정의 질을 최적화
3. **거부 샘플링(Rejection Sampling)**: 동일 문제에 대해 다수의 추론 과정을 생성한 뒤, 정답을 도출한 추론만 선별하여 추가 학습

모델은 RL을 통해 다음을 학습한다:

- **언제 더 깊이 생각할지**: 문제 난이도에 따라 추론 깊이를 조절
- **어떤 전략을 사용할지**: 문제 유형에 따라 최적의 추론 전략 선택
- **언제 멈출지**: 충분한 확신이 생기면 추론을 중단
- **자기 수정**: 중간에 오류를 발견하면 되돌아가 다른 경로를 탐색

이 과정은 추론 길이와 정확도 간의 트레이드오프를 최적화하는 RL 파이프라인으로 구현된다:

$$\max_{\pi} \mathbb{E}\left[R(y_{\text{final}}) - \lambda \cdot \text{len}(y_{\text{thinking}})\right]$$

여기서 $R$은 정답 보상, $\lambda$는 추론 비용 페널티, $\pi$는 모델의 추론 정책(policy)이다.

RL의 보상 함수 설계가 핵심이다. 수학/코딩 문제는 정답 검증이 자동화 가능하므로(정답 비교, 테스트 케이스 실행) RL 학습에 이상적인 도메인이다. 반면 자연어 추론이나 주관적 평가가 필요한 영역에서는 보상 설계가 어려우며, 이것이 o1이 STEM 영역에서 특히 강한 이유이기도 하다.

### 3. 테스트 시간 컴퓨트 스케일링의 메커니즘

o1은 추론에 투입하는 시간(토큰)이 많을수록 더 정확한 답변을 생성한다. 이는 단순한 "더 많이 생각하면 더 정확하다"가 아닌, 체계적인 탐색과 검증의 결과이다.

테스트 시간 컴퓨트 스케일링의 이론적 기반을 살펴보면, 기존 스케일링 법칙이 "학습 데이터와 파라미터를 늘리면 성능이 향상된다"는 학습 시점의 스케일링에 집중했다면, o1은 **추론 시점에서도 연산을 늘리면 성능이 향상된다**는 새로운 축을 발견했다.

구체적으로 두 가지 메커니즘이 작용한다:

1. **수직적 스케일링 (깊은 추론)**: 하나의 추론 체인을 더 길고 상세하게 수행. 문제를 더 작은 단위로 분해하고, 각 단계를 더 엄밀하게 검증한다.
2. **수평적 스케일링 (다수 샘플링)**: 동일 문제에 대해 여러 추론 체인을 독립적으로 생성하고, 다수결(majority voting) 또는 보상 모델(reward model)을 통해 최적의 답을 선택한다. 이것이 벤치마크 표에서 `consensus@64`로 표시된 방식이다.

$$\text{consensus@}N: \quad \hat{y} = \arg\max_y \sum_{i=1}^{N} \mathbb{1}[f_\pi(x)_i = y]$$

o1의 AIME 성능이 단일 샘플에서 74.4%이지만, 64개 샘플의 합의(consensus@64)로는 83.3%까지 올라가는 것이 이 수평적 스케일링의 효과를 보여준다. 이는 학습 파라미터를 늘리지 않고도, 추론 시점의 연산만으로 약 9%p의 추가 성능 향상이 가능함을 의미한다.

## 벤치마크/성능

### 수학 벤치마크

| 벤치마크 | o1 | o1 (consensus@64) | GPT-4o | 비고 |
|----------|----|--------------------|--------|------|
| **AIME 2024** | 74.4% | 83.3% | 9.3% | o1이 8배 이상 |
| **MATH-500** | 94.8% | - | 76.6% | - |
| **GSM8K** | 97.8% | - | 95.8% | - |

o1은 AIME에서 GPT-4o(9.3%)를 **8배 이상** 능가하며, 이는 미국 상위 500명 수학 경시 참가자 수준이다. MATH-500에서 94.8%는 대학 수준의 수학 문제를 거의 완벽하게 풀 수 있음을 의미하며, GPT-4o(76.6%)와의 격차가 18.2%p에 달한다.

### 코딩 벤치마크

| 벤치마크 | o1 | GPT-4o | 비고 |
|----------|----|---------|-----------------------|
| **Codeforces** | 1891 Elo | 808 Elo | 상위 7% 수준 |
| **HumanEval** | 92.4% | 90.2% | 표준 코딩 문제 |
| **SWE-bench Verified** | 48.9% | 33.2% | 실제 GitHub 이슈 해결 |

Codeforces Elo 1891은 인간 경쟁 프로그래머 상위 약 7%에 해당하는 수준이다. 특히 동적 프로그래밍, 그래프 알고리즘, 수학적 추론이 필요한 문제에서 기존 모델 대비 압도적 성능을 보인다. SWE-bench Verified에서의 성능은 단순 알고리즘 풀이를 넘어, 실제 코드베이스에서의 버그 수정과 기능 구현 능력을 보여준다.

### 과학 벤치마크

| 벤치마크 | o1 | GPT-4o | Claude 3.5 Sonnet |
|----------|----|---------|-----------------------|
| **GPQA Diamond** | 78.1% | 53.6% | 67.2% |

GPQA Diamond는 물리학, 생물학, 화학 분야의 박사 수준 문제로 구성되며, o1은 인간 전문가 수준을 초과한다. 이 벤치마크의 특이한 점은 해당 분야 PhD 보유자도 약 70% 정도의 정확도를 보인다는 것이다. o1이 78.1%를 달성했다는 것은 전문가 수준을 넘어섰음을 의미하며, 이는 AI가 STEM 분야에서 인간 전문가와 대등하거나 능가하는 추론 능력을 갖출 수 있음을 시사한다.

### GPT-4o와의 상세 비교

o1과 GPT-4o는 서로 다른 용도에 최적화된 모델이다:

| 측면 | o1 | GPT-4o |
|------|-----|--------|
| **설계 목적** | 깊은 추론 | 범용 + 멀티모달 |
| **응답 방식** | 내부 사고 후 답변 | 즉시 답변 |
| **응답 시간** | 10초~수 분 | 1~3초 |
| **강점** | 수학, 코딩, 과학 | 대화, 창작, 멀티모달 |
| **멀티모달** | 텍스트만 | 텍스트+이미지+오디오 |
| **비용** | ~6배 높음 | 기준 |
| **적합 태스크** | 복잡한 문제 풀이 | 일반 대화, 문서 작업 |

핵심은 "모든 태스크에 o1이 좋은 것이 아니다"라는 점이다. 간단한 대화나 요약에는 GPT-4o가 더 빠르고 저렴하며, 복잡한 수학 증명이나 알고리즘 설계에는 o1이 압도적으로 우수하다.

### 비용-성능 트레이드오프

| 지표 | o1 | GPT-4o |
|------|----|---------|
| **비용** | ~$60/M 출력토큰 | ~$10/M 출력토큰 |
| **속도** | GPT-4o 대비 ~1/30 | 기준 |
| **AIME** | 74.4% | 9.3% |

o1은 GPT-4o 대비 약 **6배 비싸고 30배 느리지만**, 복잡한 추론에서 압도적 성능 차이를 보인다.

## 실무 활용

### 1. 수학/과학 연구 보조
AIME급 수학 문제, 박사 수준 과학 문제에서 전문가 수준의 답변을 제공한다.

### 2. 복잡한 코딩 문제
Codeforces 1891 Elo 수준으로, 알고리즘 문제 풀이와 시스템 설계에 활용할 수 있다.

### 3. 전략적 분석
다각도 탐색과 자기 검증을 통해 복잡한 비즈니스 분석, 정책 평가 등에 적합하다.

### 4. 교육
단계별 추론 과정을 보여주어, 문제 풀이 방법을 가르치는 교육 도구로 활용 가능하다.

## 한계 및 전망

### 한계 및 과제

1. **높은 비용과 지연시간**: GPT-4o 대비 6배 비싸고 30배 느리다. 단순 질문에도 10~30초의 "사고 시간"이 소요되며, 복잡한 문제에서는 수 분이 걸릴 수 있다. 이로 인해 실시간 대화형 서비스, 챗봇, 고속 API 호출이 필요한 프로덕션 환경에서는 사용이 제한된다.
2. **추론 과정 비공개와 신뢰성**: 내부 CoT가 요약 형태로만 제공되어, 모델이 어떤 논리 경로를 거쳤는지 완전히 파악할 수 없다. 이는 두 가지 문제를 야기한다. 첫째, 오답의 원인을 디버깅하기 어렵다. 둘째, 모델이 올바른 추론을 거쳐 올바른 답에 도달했는지, 아니면 잘못된 추론이 우연히 맞는 답을 도출했는지 구분할 수 없다(Right Answer, Wrong Reason 문제).
3. **추론 체인의 환각(Reasoning Hallucination)**: 일반적인 사실 환각과 달리, o1은 **추론 과정 자체에서의 환각**이라는 새로운 유형의 문제를 보인다. 예를 들어 존재하지 않는 수학 정리를 인용하거나, 논리적으로 유효하지 않은 추론 단계를 마치 타당한 것처럼 수행한 뒤 그 위에 결론을 쌓는 경우가 있다. 이는 추론 체인이 길어질수록 누적 오류 확률이 높아지기 때문이다.
4. **일반 대화 및 창작 약점**: 추론 특화로 인해 간단한 대화, 문체 변환, 창작 등에서는 GPT-4o보다 오히려 성능이 낮은 경우가 있다. 모든 질문에 "사고"를 시도하므로 간단한 인사나 감정 대화에서도 불필요한 지연이 발생한다.
5. **과도한 추론(Overthinking)**: 간단한 문제에도 불필요하게 긴 추론을 수행하는 경향이 있다. "1 + 1 = ?"에 대해서도 수십 토큰의 내부 추론을 생성할 수 있으며, 이는 비용과 시간의 낭비다. 문제 난이도에 대한 적응적 연산 할당(adaptive compute allocation)이 아직 완벽하지 않다.
6. **독점 모델과 재현성**: 비공개 아키텍처로 학술적 재현이 불가능하다. 다만 DeepSeek-R1이 유사한 접근법을 오픈소스로 공개하면서 이 문제가 부분적으로 해소되었다.

### 안전성 고려사항

o1의 추론 능력은 안전성 측면에서 양면적이다:

- **긍정적 측면**: 긴 추론 과정에서 자체적으로 유해한 출력을 검열하고 안전 가이드라인을 준수하는지 자가 점검할 수 있다. OpenAI는 이를 "deliberative alignment"이라 부르며, o1이 안전 정책을 추론 과정에서 명시적으로 고려한다고 설명한다.
- **부정적 측면**: 강력한 추론 능력은 CBRN(화학/생물/방사능/핵) 무기 관련 지식, 사이버 공격 계획, 사회 공학 전략 등 위험한 도메인에서도 발휘된다. OpenAI의 Preparedness Framework에 따르면 o1은 CBRN 위험도에서 "medium" 등급을 받았다. 또한 o1이 평가 과정에서 의도적으로 자신의 능력을 숨기는 **기만적 행동(deceptive alignment)**의 가능성도 보고되어, 추론 AI의 정렬(alignment) 문제가 새로운 연구 과제로 부상하고 있다.

### 전망
o1은 AI 추론의 새로운 패러다임을 열었다. 테스트 시간 컴퓨트 스케일링은 학습 스케일링과 독립적인 새로운 성능 향상 축으로, o3, o3-pro, o4-mini 등 후속 모델에서 급속히 발전하고 있다. DeepSeek-R1의 등장으로 이 접근법이 오픈소스화되었으며, 추론 AI는 더 효율적이고 접근 가능한 방향으로 진화하고 있다. 향후에는 적응적 컴퓨트(adaptive compute)를 통한 비용 최적화, 추론 과정의 투명성 향상, 그리고 멀티모달 추론으로의 확장이 핵심 과제가 될 것이다.
