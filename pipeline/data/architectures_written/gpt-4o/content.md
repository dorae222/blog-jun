# GPT-4o: 네이티브 멀티모달의 새로운 기준

## 개요

GPT-4o("o"는 "omni"를 의미)는 2024년 5월 OpenAI가 발표한 네이티브 멀티모달 모델이다. 기존 GPT-4V가 텍스트 LLM에 별도의 비전 모듈을 연결하여 이미지를 처리한 **파이프라인 방식**이었다면, GPT-4o는 **텍스트, 이미지, 오디오를 처음부터 통합하여 단일 엔드-투-엔드 모델**로 학습한 진정한 네이티브 멀티모달 모델이다.

가장 주목할 만한 능력은 **실시간 음성 대화**이다. 평균 320ms의 응답 지연시간으로 사람과 대화하는 것과 유사한 속도를 달성하며, 음성의 감정, 톤, 웃음, 노래 등 비언어적 특성을 이해하고 생성할 수 있다. 기존 ChatGPT의 음성 모드가 음성→텍스트→LLM→텍스트→음성의 3단계 파이프라인이었던 것과 달리, GPT-4o는 오디오를 직접 처리하여 중간 변환에서 손실되던 감정과 뉘앙스 정보를 보존한다.

128K 컨텍스트 윈도우와 함께 시각적 이해, 코드 생성, 복잡한 추론에서 GPT-4 Turbo와 동등한 성능을 유지하면서, 속도는 2배 빠르고 비용은 50% 절감된다.

## 아키텍처 상세

*Figure 1: GPT-4o의 네이티브 멀티모달 통합 Transformer 아키텍처 (텍스트+이미지+오디오). (OpenAI, 2024)*

### 추정 아키텍처 (비공개)

OpenAI는 GPT-4o의 상세 아키텍처를 공개하지 않았으나, 공개된 정보와 연구 커뮤니티의 분석을 종합하면:

1. **통합 토큰 공간**: 텍스트, 이미지 패치, 오디오 프레임이 모두 동일한 토큰 공간에 매핑
2. **단일 트랜스포머**: 모든 모달리티가 하나의 트랜스포머 모델에서 처리
3. **엔드-투-엔드 학습**: 별도의 ASR(음성인식) → LLM → TTS(음성합성) 파이프라인이 아닌, 직접 오디오-오디오 처리

이는 Chameleon, Emu3 등이 추구하는 조기 융합(early fusion) 방식의 상용화 버전으로 볼 수 있다.

### 네이티브 멀티모달 vs 파이프라인 멀티모달

GPT-4o의 아키텍처를 이해하려면 기존 멀티모달 접근법과의 차이를 명확히 파악해야 한다. 기존 GPT-4V는 **후기 융합(late fusion)** 방식으로, 텍스트 LLM과 비전 인코더(CLIP 계열)를 별도로 학습한 뒤 어댑터 레이어로 연결했다. 음성 처리의 경우 Whisper(ASR) → GPT-4 → TTS라는 3단계 파이프라인을 거쳤다.

반면 GPT-4o는 **조기 융합(early fusion)** 방식으로, 모든 모달리티의 토큰이 처음부터 동일한 Transformer의 동일한 어텐션 레이어에서 상호작용한다. 이 구조의 장점은 다음과 같다:

- **교차 모달 어텐션(Cross-Modal Attention)**: 텍스트 토큰이 이미지 패치와 오디오 프레임에 직접 어텐션을 수행하여, 모달리티 간 정보가 모든 레이어에서 자유롭게 흐른다.
- **정보 손실 최소화**: 파이프라인 방식에서 ASR 단계의 텍스트 변환 시 손실되던 운율, 감정, 억양 정보가 원본 오디오 토큰에 보존된다.
- **지연시간 단축**: 3단계 순차 처리를 1단계 병렬 처리로 압축하여, 엔드-투-엔드 지연시간이 크게 감소한다.

각 모달리티의 토큰화 방식은 다음과 같이 추정된다:
- **텍스트**: 개선된 BPE 토크나이저 (`o200k_base`, 200K 어휘)
- **이미지**: ViT 스타일의 패치 임베딩 (이미지를 고정 크기 패치로 분할 후 선형 투영)
- **오디오**: 오디오 스펙트로그램을 프레임 단위로 분할 후 토큰화

### 네이티브 멀티모달의 의미

기존 파이프라인 방식 (GPT-4V 음성 모드):
$$\text{Audio} \xrightarrow{\text{ASR}} \text{Text} \xrightarrow{\text{LLM}} \text{Text} \xrightarrow{\text{TTS}} \text{Audio}$$

네이티브 멀티모달 방식 (GPT-4o):
$$\text{Audio + Image + Text} \xrightarrow{\text{GPT-4o}} \text{Audio + Text}$$

파이프라인 방식에서는 ASR 단계에서 감정, 톤, 억양 정보가 손실되고, TTS 단계에서 단조로운 음성만 생성되었다. GPT-4o는 이 중간 단계를 제거하여 풍부한 비언어적 정보를 보존한다.

### 모델 사양 (공개 정보)

| 항목 | 값 |
|------|---|
| 컨텍스트 길이 | 128,000 토큰 |
| 출력 토큰 | 최대 16,384 |
| 지원 모달리티 (입력) | 텍스트, 이미지, 오디오, 비디오 |
| 지원 모달리티 (출력) | 텍스트, 오디오 |
| 음성 응답 지연 | 평균 320ms |
| 지원 언어 | 50+ 언어 |
| 이미지 입력 | 최대 20장 |

## 핵심 혁신

### 1. 실시간 음성-음성 대화

평균 320ms 지연으로 사람 수준의 대화 속도를 달성했다. 기존 GPT-4V 음성 모드의 평균 2.8초(최소 5.4초)와 비교하면 약 10배 빠르다. 음성의 감정을 인식하고 적절한 감정으로 응답하며, 웃음, 노래, 속삭임 등 다양한 음성 스타일을 생성할 수 있다.

### 2. 토크나이저 개선

GPT-4o는 `o200k_base`라는 새로운 토크나이저를 도입했다. 기존 GPT-4의 `cl100k_base`(100K 어휘)에서 200K 어휘로 확장되었으며, 특히 비영어권 언어에서 토큰 효율이 크게 향상되었다.

| 언어 | GPT-4 (cl100k) | GPT-4o (o200k) | 개선율 |
|------|----------------|----------------|--------|
| 한국어 | 기준 | ~1.7배 효율적 | 약 40% 토큰 절감 |
| 일본어 | 기준 | ~1.4배 효율적 | 약 30% 토큰 절감 |
| 중국어 | 기준 | ~1.4배 효율적 | 약 30% 토큰 절감 |
| 힌디어 | 기준 | ~4.0배 효율적 | 약 75% 토큰 절감 |
| 아랍어 | 기준 | ~2.0배 효율적 | 약 50% 토큰 절감 |

토큰 효율 향상은 비용 절감과 직결된다. 같은 양의 한국어 텍스트를 처리할 때 약 40% 적은 토큰을 사용하므로, API 비용이 그만큼 절감되고 컨텍스트 윈도우도 실질적으로 더 넓게 사용할 수 있다.

### 3. 비용 효율성과 GPT-4 Turbo 비교

GPT-4 Turbo 대비 동등한 텍스트 성능을 유지하면서:
- 추론 속도: 2배 빠름
- API 비용: 50% 절감
- 비영어권 토크나이제이션: 크게 개선 (한국어 등에서 토큰 효율 향상)

GPT-4 Turbo와의 상세 비교:

| 항목 | GPT-4 Turbo | GPT-4o | 비교 |
|------|------------|--------|------|
| 입력 비용 (/1M 토큰) | $10.00 | $2.50 | **75% 절감** |
| 출력 비용 (/1M 토큰) | $30.00 | $10.00 | **67% 절감** |
| TTFT (첫 토큰 지연) | 약 2초 | 약 1초 | 2배 빠름 |
| 처리량 (tokens/s) | 기준 | ~2배 | 2배 빠름 |
| 128K 컨텍스트 | 지원 | 지원 | 동일 |
| 비전 | 외부 모듈 | 네이티브 | 통합 |
| 오디오 | 미지원 | 네이티브 | 신규 |

이러한 비용 절감은 모델 아키텍처 최적화, 양자화, 추론 인프라 개선, 그리고 네이티브 멀티모달 설계로 인한 파이프라인 단순화에서 비롯된 것으로 추정된다.

### 4. 통합 멀티모달 추론

이미지를 보면서 음성으로 설명을 듣고, 텍스트로 응답하는 등 세 가지 모달리티 간 자유로운 교차 추론이 가능하다. 예를 들어 화이트보드 사진을 찍어 보여주면서 음성으로 질문하면, 시각 정보와 음성 정보를 동시에 이해하여 응답한다.

### 5. 실시간 추론 인프라

GPT-4o의 실시간 음성 대화를 가능케 하는 것은 Realtime API라는 새로운 추론 인프라다. 기존 REST API가 요청-응답 패턴이었다면, Realtime API는 **WebSocket 기반의 양방향 스트리밍**을 지원한다.

이 인프라의 핵심 특성:
- **양방향 오디오 스트리밍**: 사용자 음성 입력과 모델 음성 출력이 동시에 스트리밍
- **중단 감지(Interruption Detection)**: 사용자가 말하기 시작하면 모델의 응답을 즉시 중단
- **VAD(Voice Activity Detection)**: 서버 측 음성 활동 감지로 자동 발화 구간 분리
- **다중 동시 세션**: 하나의 연결에서 텍스트, 오디오, 함수 호출을 동시에 처리

이는 단순한 API 업데이트가 아니라, AI 모델과 사용자 간 상호작용의 패러다임을 변화시키는 인프라 혁신이다. 기존의 "입력 → 처리 → 출력" 순차 모델에서, 사람과의 대화처럼 입출력이 겹칠 수 있는 **풀 듀플렉스(full-duplex) 통신**으로의 전환이다.

## 학습 상세

상세한 학습 방법은 공개되지 않았으나, 알려진 정보를 종합하면:

- **사전학습 데이터**: 텍스트, 이미지, 오디오를 포함한 대규모 멀티모달 데이터
- **정렬**: RLHF(Reinforcement Learning from Human Feedback) 기반
- **안전성**: 레드팀 테스트 + 외부 안전성 평가
- **스트리밍 최적화**: 실시간 오디오 입출력을 위한 추론 최적화

GPT-4 수준의 텍스트 추론 능력을 유지하면서 멀티모달 통합을 달성하기 위해, 대규모 합성 데이터와 실제 데이터의 혼합 학습이 수행된 것으로 추정된다.

import base64

client = OpenAI()

# 이미지 이해
with open("photo.jpg", "rb") as f:

response = client.chat.completions.create(

### 주요 활용 분야

1. **실시간 음성 어시스턴트**: 고객 서비스, 교육, 접근성 도구
2. **멀티모달 문서 분석**: 이미지+텍스트가 혼합된 보고서, 프레젠테이션 분석

## 한계 및 전망

### 한계 및 과제

1. **비공개 아키텍처**: 학술 재현 및 분석 불가. 네이티브 멀티모달의 정확한 구현 방식, 학습 데이터 구성, 모델 크기 등이 모두 비공개이므로 학술 연구에서의 재현이나 비교가 근본적으로 불가능하다.
2. **API 의존성과 서비스 종속**: 셀프호스팅 불가하며 OpenAI의 서비스 가용성, 가격 정책, 이용 약관에 완전히 종속된다. 서비스 장애 시 대안이 없으며, 가격 인상이나 정책 변경에 대응하기 어렵다.
3. **멀티모달 환각(Hallucination)**: 텍스트 환각 문제에 더해, 이미지의 세부 내용을 잘못 해석하거나 존재하지 않는 시각 정보를 생성하는 멀티모달 특유의 환각이 발생한다. 예를 들어 이미지 내 텍스트를 잘못 읽거나, 객체 간 공간 관계를 오인하는 경우가 보고되고 있다.
4. **음성 안전성**: 사실적인 음성 생성 능력은 음성 딥페이크, 감정 조작, 사기 통화 등 새로운 안전 위험을 수반한다. OpenAI는 사전 학습된 음성만 허용하고 임의 음성 복제를 금지하는 등의 제한을 두고 있지만, 기술적으로는 악용 가능성이 열려 있다.
5. **비디오 이해의 제한**: 이미지 입력은 지원하지만, 비디오 스트림의 실시간 이해는 여전히 제한적이다. 비디오는 개별 프레임 샘플링 방식으로 처리되어, 동작이나 시간적 맥락을 완전히 파악하기 어렵다.
6. **오디오 출력 제어의 어려움**: 음성 생성에서 특정 감정, 억양, 속도를 정밀하게 제어하기 어렵다. 간혹 부적절한 톤으로 응답하거나, 사용자의 감정 상태에 맞지 않는 음성을 생성하는 경우가 있다.
7. **Realtime API 비용**: 실시간 음성 API의 비용은 텍스트 API 대비 상당히 높다. 오디오 입력 $100/M 토큰, 오디오 출력 $200/M 토큰으로, 대규모 음성 서비스 운영 시 비용 부담이 크다.

### 전망

GPT-4o는 네이티브 멀티모달 모델의 상용화 기준을 정립하였다. 2025년에는 이미지 생성(DALL-E 통합), 비디오 입력 처리, 향상된 추론 능력(o1 계열 통합) 등이 추가되며 진화를 계속하고 있다. 오픈소스 진영에서는 Qwen3-Omni가 유사한 옴니모달 능력을 공개 모델로 구현하며 경쟁하고 있으며, 향후 네이티브 멀티모달이 AI 모델의 기본 요건이 될 것으로 전망된다.
