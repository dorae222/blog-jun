# LLaMA 3: 오픈소스 LLM의 GPT-4 도전

## 개요

**LLaMA 3**는 Meta가 2024년 4월 18일 공개한 오픈소스 대규모 언어 모델 시리즈로, **8B, 70B, 405B** 세 가지 규모로 제공된다. LLaMA 2 대비 훈련 데이터를 **7.5배(2T→15T 토큰)** 확대하고, 128K 토큰 컨텍스트와 GQA를 전 모델에 도입하여 성능과 효율 모두를 대폭 향상시켰다.

특히 **405B 모델은 오픈소스 모델 중 최초로 GPT-4 수준에 근접**하는 성능을 달성하여 오픈소스 LLM 생태계의 이정표가 되었다. 8B 모델조차 LLaMA 2-70B에 필적하는 성능을 보이며, 데이터 스케일링의 위력을 극적으로 보여주었다.

**참고 논문**: [The Llama 3 Herd of Models](https://arxiv.org/abs/2407.21783)

### LLaMA 2 대비 핵심 변화

#### 1. GQA 전면 도입

LLaMA 2에서 34B/70B에만 적용했던 GQA를 **전 모델(8B 포함)에 적용**했다:

$$\text{GQA}: Q \in \mathbb{R}^{n_h \times d_h}, \quad K, V \in \mathbb{R}^{n_g \times d_h}$$

8B 모델: Q 32헤드, KV 8헤드. 70B: Q 64헤드, KV 8헤드. 405B: Q 128헤드, KV 8헤드. GQA를 통해 KV 캐시 메모리가 대폭 감소하면서도 MHA 수준의 표현력을 유지한다.

#### 2. 어휘 크기 4배 확장 (32K → 128K)

토크나이저를 **128,256 어휘**로 확장했다. 이는 LLaMA 2의 32K 대비 4배 증가로, 다국어 텍스트의 토큰화 효율이 크게 향상된다. 동일한 텍스트를 더 적은 토큰으로 표현할 수 있어, 실질적인 컨텍스트 길이가 확대되는 효과가 있다.

LLaMA 3의 토크나이저는 OpenAI의 tiktoken 라이브러리를 기반으로 한 BPE(Byte Pair Encoding) 토크나이저이다. LLaMA 2에서 사용한 SentencePiece BPE 대비 학습 속도가 빠르고, 128K 규모의 대용량 어휘에 적합하다. 어휘 확장의 구체적 효과를 살펴보면:

- **영어 토큰화 효율**: 동일 텍스트 기준 약 15% 적은 토큰으로 표현 가능
- **한국어/일본어/중국어**: 토큰화 효율이 약 2~3배 향상 (기존 32K에서는 비라틴 문자의 토큰화 효율이 매우 낮았음)
- **코드**: 프로그래밍 언어별 키워드, 연산자, 일반적 코드 패턴이 단일 토큰으로 인코딩되는 비율 증가

어휘 크기의 확장은 임베딩 레이어와 출력 레이어의 파라미터 수를 증가시키지만, Transformer 블록의 파라미터 수에는 영향을 주지 않는다. 8B 모델 기준으로 임베딩 파라미터가 약 0.5B 증가하지만, 토큰 수 감소로 인한 학습 및 추론 효율 개선이 이를 상쇄한다.

#### 3. 128K 컨텍스트

LLaMA 2의 4K에서 **32배 확장**했다. RoPE의 기본 주파수를 500,000으로 조정하여 장거리 위치 인코딩 성능을 확보했다.

### 모델 사양

| 모델 | 파라미터 | 레이어 | 히든 | Q 헤드 | KV 헤드 |
|------|---------|--------|------|--------|--------|
| 8B | 8B | 32 | 4,096 | 32 | 8 |
| 70B | 70B | 80 | 8,192 | 64 | 8 |
| 405B | 405B | 126 | 16,384 | 128 | 8 |

### GQA 아키텍처 상세

GQA(Grouped Query Attention)는 MHA(Multi-Head Attention)와 MQA(Multi-Query Attention)의 중간 지점에 위치하는 어텐션 메커니즘이다. 표준 MHA에서는 모든 Query 헤드가 독립적인 Key-Value 헤드를 가지지만, GQA에서는 여러 Query 헤드가 하나의 Key-Value 헤드를 공유한다.

$$\text{GQA}(Q, K, V) = \text{Concat}(\text{head}_1, ..., \text{head}_{n_h}) W^O$$
$$\text{head}_i = \text{Attention}(Q W_i^Q, K W_{g(i)}^K, V_{g(i)}^V)$$

여기서 $g(i) = \lfloor i \cdot n_g / n_h \rfloor$는 Query 헤드 $i$가 사용할 KV 그룹 인덱스이다. LLaMA 3의 모든 모델은 8개의 KV 헤드를 사용하므로, 8B(Q 32헤드)에서는 4:1 비율, 405B(Q 128헤드)에서는 16:1 비율의 KV 공유가 이루어진다.

GQA의 실질적 이점은 추론 시 KV 캐시 메모리 절감에 있다. 128K 컨텍스트에서 MHA를 사용할 경우, 70B 모델의 KV 캐시만으로도 수십 GB의 메모리가 필요하지만, GQA(8 KV 헤드)를 사용하면 이를 1/8로 줄일 수 있다. 이는 긴 컨텍스트 추론의 실용성을 결정하는 핵심 설계 결정이다.

### 데이터 스케일링의 위력

LLaMA 3의 가장 중요한 혁신은 아키텍처가 아니라 **데이터 규모**에 있다. 15T 토큰은 Chinchilla 최적 비율($D \approx 20N$)을 크게 초과하는 의도적 과학습(overtraining)이다:

| 모델 | 파라미터 | Chinchilla 최적 | 실제 학습 | 과학습 비율 |
|------|---------|----------------|----------|----------|
| 8B | 8B | 160B | **15T** | **94x** |
| 70B | 70B | 1.4T | **15T** | **11x** |
| 405B | 405B | 8.1T | **15T** | **1.9x** |

이 전략은 추론 시 더 작은 모델을 사용할 수 있게 해, 추론 비용 최적화에 유리하다.

### 스케일링 법칙 분석

Meta는 LLaMA 3 개발 과정에서 Chinchilla 스케일링 법칙을 재검증하고, 독자적인 스케일링 법칙을 도출하였다. 핵심 발견은 다음과 같다:

**1. 플래그십 모델의 최적 학습 토큰은 Chinchilla 예측보다 적을 수 있다.** Chinchilla 법칙은 학습 컴퓨트와 추론 컴퓨트의 비용을 동등하게 취급하지만, 실제 배포 환경에서는 추론 비용이 압도적이다. 따라서 학습에 더 많은 컴퓨트를 투자하여 소형 모델의 성능을 극대화하는 것이 총 비용 관점에서 최적이다.

**2. 로그-선형 스케일링이 넓은 범위에서 유효하다.** 학습 FLOPs와 검증 손실 간의 관계는 다음과 같은 로그-선형 형태를 따른다:

$$\mathcal{L}(C) = A \cdot C^{-\alpha} + \mathcal{L}_{\infty}$$

여기서 $C$는 학습 컴퓨트(FLOPs), $A$와 $\alpha$는 피팅 파라미터, $\mathcal{L}_{\infty}$는 환원 불가능한 손실이다. 이 관계를 활용하여 소규모 실험에서 대규모 모델의 성능을 예측할 수 있었다.

다음 그래프는 LLaMA 3 학습에 활용된 IsoFLOPs 스케일링 법칙 곡선이다. 각 컴퓨트 예산에서 최적의 학습 토큰 수를 결정하는 데 사용되었다.

![IsoFLOPs 스케일링 법칙 곡선 - 컴퓨트 예산별 학습 토큰 수와 검증 손실의 관계](figures/fig_3.png)
*Figure 3: IsoFLOPs 스케일링 법칙 - 각 곡선은 고정된 컴퓨트 예산(6e18~1e22 FLOPs)에서 학습 토큰 수에 따른 검증 손실을 보여준다. 곡선의 최소점(분홍 다이아몬드)이 해당 컴퓨트에서의 최적 토큰 수이다. (Source: LLaMA 3 논문)*

## 핵심 혁신

### 1. 405B: 오픈소스 최초의 Frontier급 모델

405B는 MMLU 88.6%, HumanEval 61.0%를 달성하며 GPT-4(초기)에 근접했다. 오픈소스 모델이 독점 모델의 성능 영역에 진입한 최초의 사례이다.

### 2. 데이터 품질 파이프라인

Meta는 15T 토큰 수집을 위해 정교한 데이터 품질 필터링 파이프라인을 구축했다. Heuristic 필터링, 중복 제거(deduplication), 분류 모델 기반 품질 점수 부여, PII 제거 등 다단계 파이프라인이 적용되었다.

### 3. 의도적 과학습 전략

Chinchilla 법칙을 의도적으로 초과하여 학습함으로써, 8B 같은 소형 모델에서도 이전 세대 대형 모델에 필적하는 성능을 달성했다. 이는 배포 시 추론 비용을 절감하는 실용적 전략이다.

## 학습 상세

- **데이터**: 15T 토큰 (영어 비중 감소, 코드·수학·다국어 비중 대폭 증가)

### 멀티모달 확장: LLaMA 3.2 Vision

LLaMA 3.2(2024년 9월)에서 텍스트 전용이었던 LLaMA 3 아키텍처가 멀티모달로 확장되었다. 11B와 90B 두 가지 비전 모델이 제공되며, 이미지 이해, 차트/표 분석, 시각적 질의응답 등을 지원한다.

비전 확장의 아키텍처 구조는 다음과 같다:

- **비전 인코더**: 사전 학습된 ViT(Vision Transformer)를 비전 인코더로 사용
- **어댑터(Cross-Attention Adapter)**: 이미지 토큰과 텍스트 토큰을 연결하는 Cross-Attention 레이어를 삽입
- **학습 전략**: 비전 인코더와 어댑터만 학습하고, 언어 모델 가중치는 동결(freeze)

이 접근법은 LLaVA 패밀리의 아키텍처와 유사하지만, 기반 언어 모델의 규모(90B)와 학습 데이터의 규모에서 차별화된다. 특히 문서 이해(DocVQA), 차트 분석(ChartQA) 등 실무 관련 벤치마크에서 강력한 성능을 보인다.

또한 LLaMA 3.2에서는 경량 모델(1B, 3B)도 함께 발표되어, 모바일 및 엣지 디바이스에서의 온디바이스 추론이 가능해졌다. 1B 모델은 Qualcomm, MediaTek 등의 모바일 칩셋에서 실행할 수 있도록 최적화되었다.

## 커뮤니티 채택과 생태계 영향

LLaMA 3는 오픈소스 LLM 생태계에서 가장 광범위하게 채택된 모델 중 하나이다. Hugging Face에서 LLaMA 3 기반 파인튜닝 모델은 수천 개에 달하며, 다음과 같은 영역에서 활발한 활용이 이루어지고 있다.

**파인튜닝 생태계**: Unsloth, Axolotl, TRL 등의 파인튜닝 프레임워크에서 LLaMA 3를 최우선으로 지원한다. 특히 8B 모델은 소비자 GPU(RTX 4090, 24GB)에서 QLoRA 파인튜닝이 가능하여, 개인 개발자와 소규모 팀의 접근성이 높다.

**양자화 배포**: GGUF(llama.cpp), AWQ, GPTQ 등 다양한 양자화 포맷이 지원되며, 4-bit 양자화된 8B 모델은 약 5GB 메모리로 실행 가능하다. Ollama, LM Studio 등의 로컬 추론 도구에서도 즉시 사용할 수 있다.

**벤치마크 기준선 역할**: LLaMA 3-8B는 소형 모델의 성능 기준선으로 자리 잡았으며, 이후 등장한 Qwen 2.5, Mistral, Gemma 2 등의 경쟁 모델들이 LLaMA 3를 기준으로 성능을 비교한다.


### 2. 128K 컨텍스트 활용

장문 문서 분석, 다중 문서 RAG, 대규모 코드베이스 분석 등에 활용할 수 있다.

### 3. 8B 모델의 실용성

8B 모델은 4-bit 양자화 시 약 5GB 메모리로 소비자 GPU에서 실행 가능하며, 이전 세대 70B 수준의 성능을 제공한다.

## 한계 및 전망

### 한계

1. **Dense 구조의 비효율**: 405B 전체 파라미터가 활성화되어 추론 비용이 높다. 동일 성능을 MoE(Mixture of Experts)로 달성하면 활성 파라미터 수를 1/4~1/8로 줄일 수 있다. DeepSeek-V2(236B 총 파라미터, 21B 활성)가 이를 입증하였으며, Meta도 LLaMA 4에서 MoE로 전환하였다.
2. **커스텀 라이선스**: Apache 2.0이 아닌 Meta 커스텀 라이선스로, 7억 MAU 이상 서비스에 제한이 있다. 이는 대규모 상업 서비스에서의 자유로운 활용을 제한하며, "진정한 오픈소스"인가에 대한 논쟁의 원인이 되었다.
3. **멀티모달 한계**: 기본 모델은 텍스트 전용이며, LLaMA 3.2에서야 멀티모달 확장이 이루어졌다. 멀티모달 모델도 이미지 이해에 한정되며, 이미지 생성이나 비디오 처리는 지원하지 않는다.
4. **한국어 성능의 상대적 약점**: 15T 학습 토큰의 다국어 비중이 확대되었으나, 여전히 영어 중심이다. 한국어 벤치마크에서 동급 한국어 특화 모델(SOLAR, HyperCLOVA X) 대비 낮은 성능을 보이며, 한국어 미세 조정 없이 직접 사용하기에는 한계가 있다.
5. **추론 능력의 한계**: GSM8K(96.8%)와 MATH(73.8%)에서 높은 점수를 기록하지만, 더 복잡한 수학 문제나 다단계 논리 추론에서는 GPT-4 및 Claude 3.5 대비 뒤처진다. 이는 학습 데이터의 추론 관련 비율보다는 RLHF 정렬 과정의 차이에서 기인하는 것으로 분석된다.

### 전망

LLaMA 3는 오픈소스 LLM이 독점 모델의 성능 영역에 진입한 이정표이다. 405B의 Dense 구조 비효율은 LLaMA 4에서 MoE로 전환하여 해결되었으며, 15T 토큰 데이터 스케일링 전략은 이후 Qwen, DeepSeek 등 경쟁 모델들의 데이터 투자를 촉진했다.
