# Gemma 4: 1B-27B 사이즈와 네이티브 멀티모달의 오픈 가중치 라인업

## 개요

Gemma 4는 2026년 Google이 공개한 4세대 오픈 가중치(open-weight) 모델 계열이다. Gemma 시리즈는 Gemini와 동일한 연구 인프라에서 출발하면서도 **Apache 2.0 호환 라이선스**로 공개되어, 로컬 추론과 온디바이스 배포에 최적화된 라인업이다.

Gemma 4 세대에서는 **1B, 4B, 12B, 27B의 4가지 변형 사이즈**가 제공되며(추정), 모든 변형이 텍스트, 이미지, 오디오를 처리할 수 있는 멀티모달 능력을 갖췄다. 특히 27B 변형은 **단일 H100 GPU에서 양자화 없이 추론이 가능**하면서도 동급 클래스의 폐쇄형 모델에 근접한 성능을 보인다.

Gemma 시리즈의 핵심 가치는 실용적 사이즈와 자유로운 라이선스의 결합으로, 학술 연구, 스타트업의 자체 호스팅, 엣지 디바이스 배포 등에서 폭넓게 활용된다.

## 아키텍처 상세

### 기본 구조

| 변형 | 파라미터 | 추론 환경 | 주요 용도 |
|------|----------|-----------|-----------|
| **Gemma 4 1B** | 약 10억 | 모바일/엣지 디바이스 | 온디바이스 챗봇, 로컬 자동완성 |
| **Gemma 4 4B** | 약 40억 | 노트북 CPU, 저사양 GPU | 개인 PC 챗봇, 교육용 |
| **Gemma 4 12B** | 약 120억 | RTX 4090/5090 단일 GPU | 스타트업 자체 호스팅 |
| **Gemma 4 27B** | 약 270억 | 단일 H100 GPU | 엔터프라이즈, 연구 기관 |

### 공통 아키텍처

| 구성 요소 | 사양 |
|-----------|------|
| **아키텍처** | Dense Decoder-only Transformer |
| **어텐션** | Grouped-Query Attention (GQA) |
| **정규화** | RMSNorm |
| **활성화 함수** | SwiGLU (또는 GeGLU 변형) |
| **위치 인코딩** | RoPE |
| **컨텍스트 길이** | 128K 토큰 |
| **어휘 크기** | 256K (멀티링구얼 강화) |
| **모달리티** | 텍스트, 이미지, 오디오 |
| **라이선스** | Apache 2.0 호환 |

### 멀티모달 인코더 통합

Gemma 4는 모달리티별 별도 인코더의 출력을 트랜스포머 입력 공간에 투영하는 방식으로 멀티모달을 구현한다.

- **이미지**: SigLIP 2 계열 인코더 → 패치 임베딩
- **오디오**: Universal Speech Model(USM) 계열 인코더 → 오디오 토큰
- **텍스트**: SentencePiece (256K vocab)

이렇게 변환된 토큰들은 단일 트랜스포머에서 통합 처리된다.

## 핵심 혁신

### 1. 모든 사이즈 멀티모달화

Gemma 3까지는 텍스트 중심이었으며 일부 변형(예: PaliGemma)에서만 이미지 처리가 가능했다. Gemma 4에서는 1B 모델조차 멀티모달을 지원한다. 이는 모바일 디바이스에서 카메라 입력을 분석하거나, 오디오 메모를 즉시 요약하는 등의 시나리오를 가능하게 한다.

작은 모델에서 멀티모달을 구현하기 위해 다음 기법이 활용되었을 것으로 추정된다.

- 큰 변형(27B)에서 작은 변형(1B/4B)으로의 멀티모달 distillation
- 가벼운 비전 인코더(SigLIP 2 small) 활용
- 모달리티별 LoRA 또는 어댑터 활용

### 2. 단일 GPU 추론 최적화

Gemma 4 27B는 단일 H100 GPU(80GB HBM)에서 양자화 없이 추론 가능한 사이즈로 설계되었다. 이는 다음 시나리오에서 강점을 갖는다.

- 엔터프라이즈 자체 호스팅 (데이터 외부 유출 방지)
- 학술 연구의 재현성 확보
- 정부/공공기관의 보안 환경

이러한 사이즈 정책은 Llama, Mistral 등 다른 오픈 가중치 라인업과 차별화되는 Gemma의 일관된 가치이다.

### 3. Apache 2.0 호환 라이선스

Gemma 시리즈는 Llama 라인업의 LLaMA 라이선스(상업 이용에 일부 조건 부여)와 달리, Apache 2.0과 호환되는 자유로운 라이선스로 공개된다. 이는 다음과 같은 차이를 만든다.

- 1억 명 이상 사용자를 가진 기업도 별도 협의 없이 사용 가능
- 모델 가중치를 직접 재배포 가능
- 파생 모델의 라이선스 제약 최소화

### 4. Knowledge Distillation 활용

작은 변형(1B/4B)은 큰 변형(27B)의 행동을 모방하도록 distillation 손실로 학습되었을 가능성이 높다. distillation 손실은 다음과 같이 구성된다.

$$L_{\text{distill}} = \alpha L_{\text{CE}}(y, p_{\text{student}}) + \beta L_{\text{KL}}(p_{\text{teacher}} || p_{\text{student}})$$

여기서 $L_{\text{CE}}$는 정답 토큰에 대한 교차 엔트로피, $L_{\text{KL}}$은 교사 모델의 분포에 대한 KL 발산이다.

## 한계 및 의의

### 한계

1. **폐쇄형 최상위 모델과의 격차**: 27B 변형이 동급 오픈 가중치 모델과는 경쟁하지만, Claude Opus 4.7이나 Gemini 3.1 Pro 같은 폐쇄형 플래그십에는 미치지 못한다.
2. **컨텍스트 길이 한계**: 128K 컨텍스트는 GPT-5.5나 Gemini 3.1 Pro의 1M 대비 작다.
3. **에이전트 능력 부족**: 도구 호출, Computer Use 등 에이전트 시나리오에서 폐쇄형 모델 대비 신뢰성이 낮다.
4. **소형 변형의 멀티모달 정확도**: 1B/4B 변형의 멀티모달 능력은 27B 대비 상당한 격차가 있다.

### 의의

Gemma 4는 **오픈 가중치 멀티모달의 대중화**, **자유로운 라이선스의 가치 확립**, **사이즈 라인업의 표준화**라는 세 가지 의미를 지닌다. 첫째, 1B 모델부터 멀티모달을 지원하면서 온디바이스 AI 시나리오의 가능성을 크게 확장하였다. 둘째, Apache 2.0 호환 라이선스는 산업계가 부담 없이 채택할 수 있는 기준선을 제시한다. 셋째, 1B/4B/12B/27B의 라인업은 사용자가 자신의 인프라에 맞는 사이즈를 선택할 수 있게 하여, "한 사이즈가 모두에게 맞지 않음"을 인정하는 실용주의적 접근의 표준이 되었다.

향후 Gemma 5 세대에서는 더 작은 모델(0.5B 이하)의 모바일 최적화, 추론 특화 변형, 그리고 비디오 입력 지원이 핵심 방향이 될 것으로 전망된다.
