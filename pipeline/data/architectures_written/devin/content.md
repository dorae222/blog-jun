# Devin: 자율 AI 소프트웨어 엔지니어의 등장

**Cognition** · **2024-03-12** · **AI Developer** · **상용**

## 개요

Devin은 Cognition이 2024년 3월 발표한 세계 최초의 "자율 AI 소프트웨어 엔지니어"로, 자연어 명세만으로 엔드투엔드 소프트웨어 개발 작업을 수행한다고 주장했다. 코드 에디터, 터미널, 웹 브라우저를 통합한 개발 환경에서 장기 계획 수립, 코드 작성, 버그 수정, 테스트 실행, 배포까지 전체 개발 라이프사이클을 처리할 수 있다고 소개되었다.

Devin의 발표는 AI 업계에 폭발적 반향을 불러일으켰다. SWE-bench 벤치마크에서 13.86%의 이슈 해결률을 기록하여 당시 기존 접근법(1.96%)을 크게 상회했으며, "AI가 소프트웨어 엔지니어를 대체할 것인가"라는 담론을 촉발시켰다. 동시에 이는 SWE-agent, OpenHands 등 오픈소스 대안의 개발을 자극하여, 소프트웨어 엔지니어링 에이전트 분야 전체의 발전을 이끈 촉매 역할을 했다.

Devin의 등장이 가져온 가장 큰 변화는 **"AI 코딩 도구의 패러다임 전환"**이다. Copilot으로 대표되는 자동완성(autocomplete) 패러다임에서, 에이전트가 자율적으로 개발 전체를 수행하는 에이전틱(agentic) 패러다임으로의 전환을 대중화시켰다. 이후 Anthropic의 Claude Code, OpenAI의 Codex Agent 등이 이 방향을 따라갔다.

## 아키텍처 상세

Devin의 내부 아키텍처는 공개되지 않았으나, 공개된 데모와 사용자 경험을 통해 다음과 같은 구조가 추정된다.

### 통합 개발 환경

Devin은 세 가지 핵심 인터페이스를 단일 시스템으로 통합한다.

| 인터페이스 | 기능 | 용도 |
|-----------|------|------|
| 코드 에디터 | 파일 생성, 수정, 삭제 | 구현 |
| 터미널 | 빌드, 테스트, Git, 패키지 관리 | 실행/검증 |
| 웹 브라우저 | 문서 검색, API 레퍼런스 | 정보 수집 |

각 인터페이스는 **샌드박스(sandbox) 환경** 내에서 격리되어 실행된다. 구체적으로, Devin은 클라우드 기반 가상 머신에서 동작하며, 사용자의 로컬 환경과 분리된 독립적인 컴퓨팅 환경을 제공한다. 셸(shell)은 완전한 리눅스 터미널로, `pip`, `npm`, `git`, `docker` 등 일반적인 CLI 도구를 자유롭게 실행할 수 있다. 코드 에디터는 VS Code 스타일의 파일 탐색과 편집을 지원하며, 에이전트가 직접 파일을 열고 특정 라인을 수정하는 방식으로 동작한다. 브라우저는 Chromium 기반으로, 단순한 텍스트 크롤링이 아닌 렌더링된 웹페이지를 시각적으로 탐색할 수 있어 Stack Overflow 답변, 공식 문서, API 레퍼런스 등을 실시간으로 참조한다.

이 세 도구 간의 전환은 에이전트가 자율적으로 결정한다. 예를 들어, 코드를 작성하다가 알 수 없는 에러가 발생하면 터미널에서 로그를 확인하고, 해결 방법을 찾기 위해 브라우저를 열어 검색한 뒤, 다시 에디터로 돌아와 코드를 수정하는 일련의 흐름이 자동으로 이루어진다. 이러한 도구 전환의 자연스러움이 Devin의 핵심 경쟁력 중 하나다.

### 장기 계획 수립

Devin의 핵심 차별점은 복잡한 엔지니어링 작업을 여러 단계로 분해하는 플래닝 능력이다.

$$\text{Request} \xrightarrow{\text{decompose}} \{T_1, T_2, ..., T_n\} \xrightarrow{\text{order}} G(T, E) \xrightarrow{\text{execute}} \text{Result}$$

여기서 $T_i$는 하위 태스크, $G(T, E)$는 태스크와 의존 관계의 그래프다.

```
사용자 요청: "FastAPI로 TODO 앱 만들어서 배포해줘"

Devin 실행 계획:
+-- 1. 프로젝트 구조 설계
|   +-- FastAPI 프로젝트 초기화
|   +-- 데이터베이스 스키마 설계 (SQLite)
|   +-- API 엔드포인트 설계
+-- 2. 코드 구현
|   +-- 모델 정의 (SQLAlchemy)
|   +-- CRUD 엔드포인트 구현
|   +-- Pydantic 스키마 작성
+-- 3. 테스트
|   +-- pytest 단위 테스트 작성
|   +-- 통합 테스트 실행
+-- 4. 배포 설정
|   +-- Dockerfile 작성
|   +-- 환경 변수 설정
|   +-- 클라우드 배포
+-- 5. 문서화
    +-- README.md 작성
    +-- API 문서 생성
```

플래닝 알고리즘은 **계층적 분해(hierarchical decomposition)** 방식을 따르는 것으로 추정된다. 최상위 목표를 중간 수준의 마일스톤으로 분해하고, 각 마일스톤을 다시 구체적인 실행 가능한 액션으로 세분화한다. 이 과정에서 태스크 간 의존 관계를 파악하여 실행 순서를 결정한다. 예를 들어 "테스트 실행"은 "코드 구현"이 완료된 후에만 수행할 수 있다.

특히 중요한 것은 **실패 시 재계획(replanning)** 능력이다. 실행 중 테스트가 실패하거나, 빌드 에러가 발생하거나, 예상치 못한 의존성 충돌이 발생하면, Devin은 현재 계획을 수정하여 새로운 경로를 탐색한다. 이는 단순한 재시도가 아니라, 에러 메시지를 분석하고 원인을 추론한 뒤 대안적인 접근법을 시도하는 적응적 전략이다. 예를 들어 특정 라이브러리 버전이 호환되지 않으면, 호환 가능한 버전을 검색하거나 대체 라이브러리를 사용하는 방향으로 계획을 변경한다.

### 실시간 협업

작업 중 사용자와 실시간으로 소통할 수 있으며, 방향 수정이나 추가 정보 제공이 가능하다. 작업 과정은 타임라인 형태로 시각화되어 사용자가 각 단계를 추적할 수 있다.

Devin의 협업 인터페이스는 **Slack 유사 채팅 UI**를 통해 구현된다. 사용자는 Devin이 작업 중인 동안 언제든 메시지를 보내 추가 요구사항을 전달하거나, "이 부분은 React 대신 Vue로 해줘"와 같은 방향 수정을 요청할 수 있다. Devin은 이러한 피드백을 현재 컨텍스트에 통합하여 진행 중인 계획을 동적으로 수정한다.

타임라인 뷰는 Devin이 어떤 파일을 편집했는지, 어떤 명령을 실행했는지, 어떤 웹페이지를 참조했는지를 시간순으로 보여준다. 사용자는 특정 시점의 스냅샷을 확인하여 에이전트의 의사결정 과정을 추적하고, 필요한 경우 이전 단계로 롤백을 요청할 수 있다. 이러한 투명성은 "블랙박스" 에이전트에 대한 신뢰 구축에 핵심적인 역할을 한다.

### 학습 기반 적응

작업 중 새로운 API나 라이브러리를 만나면, 공식 문서를 검색하고 학습하여 사용법을 파악한다. 이는 단순 패턴 매칭을 넘어선 적응적 문제 해결 능력이다.

Devin의 학습은 주로 **인컨텍스트 학습(in-context learning)**에 기반한다. 작업 세션 내에서 브라우저를 통해 수집한 문서, 에러 메시지, 그리고 이전 시도의 결과를 컨텍스트 윈도우에 축적하여 점진적으로 문제 해결 전략을 정교화한다. 이는 모델 파라미터를 수정하는 파인튜닝(fine-tuning)이 아니라, 프롬프트 내에서 이루어지는 학습이다.

Cognition은 Devin 2에서 **지식 기반(knowledge base)** 기능을 도입했다. 사용자가 프로젝트별 코딩 스타일, 아키텍처 결정, 배포 절차 등을 미리 등록해두면, Devin이 이를 참조하여 프로젝트 맥락에 맞는 코드를 생성한다. 또한, 이전 작업 세션에서 학습한 패턴을 후속 세션에 적용하는 세션 간 학습도 제한적으로 지원되는 것으로 알려져 있다.

## 핵심 혁신

1. **엔드투엔드 자율성**: 요구사항 분석부터 배포까지 전체 개발 프로세스를 인간 개입 최소화 상태로 수행하는 첫 번째 상용 시스템이다. 이는 코드 완성(code completion)에서 코드 생성(code generation)으로의 패러다임 전환을 대중화시켰다.

2. **장기 작업 상태 관리**: 수십 분에서 수시간에 걸치는 개발 작업에서도 컨텍스트를 유지하고 일관된 전략을 실행하는 장기 메모리 시스템을 갖추었다.

3. **학습 기반 적응**: 작업 중 새로운 API나 라이브러리를 만나면, 공식 문서를 브라우저로 검색하고 학습하여 사용법을 파악한다.

4. **시장 촉매 효과**: Devin의 등장은 SWE-agent, OpenHands, Goose, Claude Code 등 수많은 후속 도구의 개발을 촉발시켰다.

## 벤치마크/성능

| 시스템 | SWE-bench (2024.03) | SWE-bench Verified (2025) | 비고 |
|--------|---------------------|--------------------------|------|
| **Devin** | 13.86% | 비공개 | 초기 발표 수치 |
| SWE-agent (GPT-4) | 12.47% | 23.0% | 오픈소스 |
| OpenHands (Claude 3.5) | - | 53.0% | 오픈소스 |
| Claude Code (Opus 4) | - | 72.0%+ | 최고 성능 |

초기 발표 당시 Devin은 압도적 성능을 보였으나, 이후 오픈소스 에이전트들이 급격히 성능을 개선하면서 격차가 좁혀졌다. 일부 독립적 검증에서 발표 수치와 차이가 있었다는 비판적 분석도 제기되었다.

### SWE-bench 상세 분석

SWE-bench는 실제 GitHub 이슈와 그에 대응하는 pull request를 기반으로 한 벤치마크로, 에이전트가 이슈 설명만을 보고 올바른 코드 패치를 생성해야 한다. Devin이 발표한 13.86%는 전체 SWE-bench(2294개 인스턴스) 기준이었으며, 이후 등장한 SWE-bench Verified는 인간이 검증한 500개 하위 집합으로 더 신뢰할 수 있는 평가 기준을 제공한다.

주목할 점은 2024년 3월 이후 에이전트 성능의 급격한 향상이다. SWE-bench Verified 기준 2024년 중반 20%대에 머물던 최고 성능이, 2025년에는 70%를 초과하기에 이르렀다. 이는 기반 모델(foundation model)의 성능 향상과 에이전틱 아키텍처의 발전이 결합된 결과다.

### 경쟁 에이전트 비교

| 에이전트 | 접근 방식 | 강점 | 약점 |
|----------|-----------|------|------|
| **Devin** | 클라우드 샌드박스 + 독자 모델 | 완전한 격리 환경, UI 제공 | 비용 높음, 폐쇄적 |
| **Claude Code** | CLI 기반 + Claude 모델 | 최고 수준 코드 이해력, 유연성 | 로컬 환경 의존 |
| **Cursor** | IDE 통합 + 다중 모델 | 에디터 수준 통합, 빠른 반응 | 대규모 자율 작업에 제한적 |
| **GitHub Copilot Workspace** | GitHub 통합 | 이슈-PR 파이프라인 자동화 | 초기 단계, 제한적 자율성 |
| **OpenHands** | 오픈소스, 다중 모델 지원 | 커스터마이징 가능, 투명성 | 설정 복잡도 |

실제 사용 환경에서 Devin의 태스크 완료율은 작업 복잡도에 따라 크게 달라진다. 단일 파일 수정이나 간단한 기능 추가에서는 70~80% 수준의 성공률을 보이지만, 다중 서비스 연동이나 복잡한 리팩토링 작업에서는 30~40%대로 떨어지는 것으로 보고되고 있다.

## 한계 및 과제

### 높은 추론 비용

Devin은 하나의 태스크를 수행하기 위해 수백에서 수천 번의 LLM 호출을 수행한다. 각 단계에서 계획 수립, 코드 생성, 에러 분석, 재계획 등이 반복되기 때문이다. 이로 인한 태스크당 비용은 단순한 작업에서도 수 달러, 복잡한 작업에서는 수십 달러에 달할 수 있다. 이는 Copilot의 월 $10 구독과 비교하면 상당한 차이이며, 비용 효율성 측면에서 인간 개발자 대비 경쟁력을 확보하기 위한 과제가 남아있다.

### 복잡한 멀티스텝 태스크의 신뢰성

에이전트가 작업 체인의 초기 단계에서 잘못된 방향을 선택하면, 이후 모든 단계가 연쇄적으로 영향을 받는 **에러 누적(error cascading)** 문제가 있다. 예를 들어 데이터베이스 스키마 설계를 잘못하면 이후의 모델 정의, API 구현, 테스트 모두가 잘못된 기반 위에 구축된다. 재계획 능력이 있음에도 근본적인 설계 오류를 감지하고 처음부터 다시 시작하는 판단은 여전히 어렵다.

### 컨텍스트 윈도우 한계

LLM의 컨텍스트 윈도우에는 물리적 한계가 있으며, 장시간 작업일수록 이전 맥락이 유실되거나 우선순위가 변경되는 문제가 발생한다. 대규모 코드베이스에서 수십 개의 파일을 동시에 다루어야 하는 상황에서, 전체 프로젝트의 구조와 각 파일 간의 관계를 한 번에 파악하기 어렵다. 이는 모든 LLM 기반 에이전트에 공통되는 구조적 한계이기도 하다.

### 보안 우려

자율적 코드 실행은 본질적으로 보안 리스크를 수반한다. Devin이 실행하는 셸 명령이 의도치 않게 민감한 데이터를 노출하거나, 잘못된 배포 명령이 프로덕션 환경에 영향을 줄 수 있다. 샌드박스 환경이 이를 어느 정도 완화하지만, 사용자가 데이터베이스 크레덴셜이나 API 키를 제공해야 하는 배포 시나리오에서는 여전히 주의가 필요하다. 또한 에이전트가 생성한 코드 자체에 보안 취약점이 포함될 가능성도 지속적으로 제기되는 문제다.

## 구현

**프로토타입 개발**: MVP(Minimum Viable Product) 수준의 애플리케이션을 자연어 명세만으로 빠르게 구축할 수 있다. 스타트업의 아이디어 검증이나 해커톤에서 유용하다. 실제로 CRUD 기반 웹 앱, REST API 서버, 간단한 대시보드 등은 30분~1시간 내에 동작 가능한 수준으로 생성할 수 있다. 다만 프로덕션 수준의 에러 처리, 인증/인가, 성능 최적화 등은 별도의 인간 검토가 필요하다.

**코드베이스 마이그레이션**: 레거시 코드의 프레임워크 마이그레이션(예: Flask $\rightarrow$ FastAPI, JavaScript $\rightarrow$ TypeScript)을 자동화할 수 있다. 특히 패턴이 일정한 반복적 변환 작업에서 효과적이며, Devin은 기존 테스트 스위트를 실행하여 마이그레이션의 정확성을 자체 검증하는 방식으로 품질을 보장한다.

**반복적 유지보수 작업**: 의존성 업데이트, 보안 패치, 코드 스타일 통일 등 반복적이지만 시간이 많이 드는 유지보수 작업을 위임할 수 있다. Dependabot 알림에 대응하여 패키지 버전을 업데이트하고, 테스트를 실행하여 호환성을 확인한 뒤 PR을 생성하는 전체 워크플로우를 자동화할 수 있다.

**버그 수정 및 디버깅**: GitHub 이슈에 보고된 버그를 분석하고, 코드베이스에서 관련 파일을 찾아 원인을 파악한 뒤 패치를 생성하는 작업에 활용할 수 있다. SWE-bench 벤치마크 자체가 이 시나리오를 평가하는 것이며, Devin이 초기에 주목받은 핵심 사용 사례이기도 하다.

## 관련 모델

Devin은 SWE-agent에서 영감을 받은 것으로 추정된다. 이후 오픈소스 대안인 OpenHands(구 OpenDevin)가 Devin의 비전을 오픈소스로 구현하려는 시도로 등장했으며, Claude Code와 Goose 등이 다른 접근 방식으로 에이전틱 코딩 시장에 진입했다. Cognition은 Devin 2를 출시하여 복잡한 코드베이스 탐색과 병렬 작업 처리 능력을 개선했다.
