## 개요

대규모 언어 모델(LLM)은 사전학습 과정에서 방대한 텍스트 코퍼스를 학습하여 뛰어난 언어 생성 능력을 보여주지만, 학습 데이터에 포함되지 않은 최신 정보에 접근할 수 없고, 사실에 기반하지 않은 내용을 생성하는 환각(hallucination) 문제를 본질적으로 안고 있습니다. 검색 증강(Retrieval-Augmented) 접근법은 외부 지식 저장소에서 관련 문서를 동적으로 검색하여 모델에 제공함으로써 이러한 한계를 극복하려는 시도입니다.

Ram et al. (2023)이 TACL에 발표한 **"In-Context Retrieval-Augmented Language Models"** 은 검색 증강의 가장 단순하면서도 효과적인 형태를 제시합니다. 핵심 아이디어는 검색된 문서를 언어 모델의 입력 시퀀스 앞에 단순히 이어붙이는(prepend) 것만으로도, 별도의 파인튜닝이나 아키텍처 수정 없이 언어 모델링 성능을 크게 향상시킬 수 있다는 것입니다. 이 논문은 RALM(Retrieval-Augmented Language Modeling)과 RAG(Retrieval-Augmented Generation)의 개념적 차이를 처음으로 명확히 구분하고, 다양한 검색 전략과 재순위화 기법의 효과를 체계적으로 비교 분석합니다.

다음 그래프는 In-Context RALM의 핵심 결과를 요약합니다. BM25 검색만으로도 baseline 대비 큰 perplexity 감소를 달성하며, Predictive Reranking을 추가하면 성능이 더욱 향상됩니다.

![In-Context RALM의 핵심 실험 결과 — 검색 방법별 Perplexity 비교](figures/fig_1.png)
*Figure 1: GPT-2 345M과 GPT-2 XL 1.5B에서 검색 없음, BM25, Predictive Reranking 적용 시 WikiText-103 테스트 세트의 Perplexity 비교. 모든 모델 규모에서 In-Context RALM이 LM 수정 없이 일관된 성능 향상을 달성한다 (Ram et al., 2023).*

본 논문의 주요 기여는 다음 네 가지로 요약됩니다.

1. **파인튜닝 불필요(Training-Free) 검색 증강**: 기존의 RETRO, REALM 등이 검색 모듈과 언어 모델을 공동 학습해야 했던 것과 달리, 어떤 사전학습된 언어 모델이든 수정 없이 즉시 검색 증강의 혜택을 받을 수 있음을 실증합니다.
2. **Stride 기반 주기적 검색 전략**: 긴 시퀀스를 처리할 때 일정 간격(stride)마다 검색을 수행하는 체계적인 프레임워크를 제안하고, stride 크기와 성능 간의 관계를 정량적으로 분석합니다.
3. **다단계 재순위화 파이프라인**: BM25 초기 검색 후 언어 모델 자체를 재순위화에 활용하는 2단계 파이프라인이 최적의 성능을 달성함을 보여줍니다.
4. **RALM vs RAG 개념 정립**: 두 패러다임의 차이를 명확히 정의하고, 각각의 적용 맥락과 장단점을 분석합니다.

## 배경 및 문제

### 언어 모델의 근본적 한계

자기회귀(autoregressive) 언어 모델은 주어진 토큰 시퀀스 $x_1, x_2, \ldots, x_{t-1}$을 조건으로 다음 토큰 $x_t$의 확률을 예측합니다.

$$P(x_1, x_2, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_1, x_2, \ldots, x_{t-1})$$

이 확률 분포는 전적으로 모델 파라미터 $\theta$에 인코딩된 지식에 의존합니다. 따라서 학습하지 못한 사실이나 학습 이후에 생성된 정보, 또는 학습 데이터에서 드물게 등장한 지식에 대해서는 정확한 예측이 어렵습니다. 파라미터 수를 늘려 더 많은 지식을 저장하는 scaling 전략도 가능하지만, 학습 및 추론 비용의 급격한 증가를 수반합니다.

### 기존 검색 증강 접근법의 문제점

검색 증강은 모델이 알지 못하는 정보를 외부에서 가져와 보완하는 자연스러운 해결책이지만, 기존 접근법들은 상당한 제약을 가지고 있었습니다.

| 접근법 | 방식 | 한계 |
|--------|------|------|
| REALM (Guu et al., 2020) | 검색기와 LM을 공동 사전학습 | 대규모 사전학습 비용, 기존 LLM에 적용 불가 |
| kNN-LM (Khandelwal et al., 2020) | 토큰 수준에서 최근접 이웃 보간 | 별도의 datastore 구축 필요, 추론 속도 저하 |
| RETRO (Borgeaud et al., 2022) | Chunked cross-attention으로 검색 통합 | 전용 아키텍처 변경 필요, 기존 LLM 호환 불가 |
| Atlas (Izacard et al., 2022) | 검색기-생성기 공동 파인튜닝 | 태스크별 파인튜닝 필요 |

이러한 접근법들은 공통적으로 (1) 모델 아키텍처의 변경, (2) 추가 학습, 또는 (3) 전용 인프라 구축을 요구합니다. 이미 배포된 대규모 언어 모델에 즉시 적용하기가 어려웠으며, 새로운 모델이 출시될 때마다 검색 증강 과정을 처음부터 다시 수행해야 하는 비효율이 존재했습니다.

### RALM과 RAG의 개념적 구분

본 논문이 특히 중요하게 기여하는 부분 중 하나는 RALM(Retrieval-Augmented Language Modeling)과 RAG(Retrieval-Augmented Generation)를 명확히 구분한 것입니다.

- **RALM**은 언어 모델링 자체의 성능, 즉 perplexity를 개선하는 데 초점을 맞춥니다. 외부 문서를 통해 다음 토큰 예측의 정확도를 높이는 것이 목표이며, 평가 지표는 perplexity입니다.
- **RAG**는 질의응답, 요약, 대화 등 특정 다운스트림 태스크에서 외부 지식을 활용하여 생성 품질을 높이는 데 초점을 맞춥니다. 평가 지표는 태스크에 따라 BLEU, ROUGE, EM(Exact Match), F1 등 다양합니다.

이 구분은 검색 증강 연구의 범위와 목표를 명확히 하는 데 기여하며, 이후 연구들이 자신의 위치를 정립하는 데 중요한 참조점이 되었습니다.

## 핵심 아이디어

### In-Context RALM의 기본 원리

In-Context RALM의 핵심은 놀랍도록 단순합니다. 기존 언어 모델의 조건부 확률 계산에 검색 문서를 추가적인 컨텍스트로 제공하는 것입니다.

기본 언어 모델의 확률:

$$P_{\text{LM}}(x_t \mid x_{<t}; \theta)$$

In-Context RALM의 확률:

$$P_{\text{RALM}}(x_t \mid [d_1; d_2; \ldots; d_k; x_{<t}]; \theta)$$

여기서 $[\cdot; \cdot]$는 시퀀스의 연결(concatenation)을 의미하며, $d_1, d_2, \ldots, d_k$는 쿼리 $q$를 기반으로 외부 코퍼스 $\mathcal{C}$에서 검색된 상위 $k$개의 관련 문서입니다. 중요한 점은 모델 파라미터 $\theta$가 전혀 변경되지 않는다는 것입니다.

아래 그림은 이 메커니즘의 동작 방식을 직관적으로 보여줍니다. 검색된 문서가 입력 프리픽스 앞에 단순히 연결되며, 모델은 자신의 기존 in-context learning 능력을 활용하여 이 추가 정보를 자연스럽게 처리합니다.

![In-Context RALM 입력 구성 예시 -- 검색 문서를 입력 앞에 prepend](figures/fig_2.png)
*Figure 2: In-Context RALM의 기본 메커니즘. 검색된 문서(좌측)를 입력 프리픽스 앞에 단순히 이어붙이는 것만으로 언어 모델의 다음 토큰 예측 성능을 향상시킨다. 모델 아키텍처나 파라미터의 수정이 전혀 필요하지 않다 (Ram et al., 2023).*

### 왜 단순한 Prepend가 작동하는가

직관적으로, 관련 문서를 컨텍스트에 추가하는 것은 모델에게 "오픈 북 시험"을 보게 하는 것과 유사합니다. 모델이 파라미터에 저장하지 못한 지식이라도, 입력에 명시적으로 제공되면 attention 메커니즘을 통해 해당 정보를 참조하여 더 정확한 예측을 수행할 수 있습니다.

Transformer의 self-attention 메커니즘에서 각 토큰은 입력 시퀀스 내 모든 이전 토큰에 대한 attention weight를 계산합니다.

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

검색된 문서가 입력 앞에 prepend되면, 생성 대상 토큰들은 자연스럽게 이 문서 토큰들에 대해서도 attention을 수행하게 됩니다. 관련성 높은 문서일수록 더 높은 attention weight를 받게 되며, 이는 곧 더 정확한 다음 토큰 예측으로 이어집니다.

이 접근법이 효과적인 근본적 이유는 현대 대규모 언어 모델이 가진 강력한 in-context learning 능력에 있습니다. GPT-3 이후의 모델들은 프롬프트에 포함된 정보를 효과적으로 활용하여 예측을 수행할 수 있으며, 검색된 문서가 프롬프트의 일부로 제공되면 모델은 이를 마치 few-shot 예시처럼 자연스럽게 활용합니다.

## 방법론

### Stride 기반 검색 전략

긴 텍스트 시퀀스를 처리할 때, 전체 시퀀스에 대해 단 한 번만 검색을 수행하면 시퀀스의 후반부에서는 검색 문서의 관련성이 떨어질 수 있습니다. 이 문제를 해결하기 위해 논문은 stride 기반의 주기적 검색 전략을 제안합니다.

전체 토큰 시퀀스 $x_1, x_2, \ldots, x_T$가 주어졌을 때, stride $s$마다 검색을 수행합니다. 위치 $t$ (단, $t \mod s = 0$)에서의 검색 쿼리 $q_t$는 직전 $w$개의 토큰으로 구성됩니다.

$$q_t = (x_{t-w}, x_{t-w+1}, \ldots, x_{t-1})$$

이 쿼리로 검색된 문서 집합은 다음과 같습니다.

$$\mathcal{D}_t = \text{Retrieve}(q_t, \mathcal{C}, k) = \{d_1^{(t)}, d_2^{(t)}, \ldots, d_k^{(t)}\}$$

해당 stride 구간 $[t, t+s)$의 토큰들에 대해서는 $\mathcal{D}_t$가 컨텍스트로 사용됩니다. 따라서 구간 내 위치 $t' \in [t, t+s)$에서의 예측은 다음과 같이 조건화됩니다.

$$P(x_{t'} \mid \mathcal{D}_t, x_{<t'})$$

아래 그래프에서 stride 크기에 따른 perplexity 변화를 확인할 수 있습니다. Stride가 작아질수록 perplexity가 감소하지만, 한계 효용은 점차 줄어듭니다.

![검색 stride 크기에 따른 Perplexity 변화 분석](figures/fig_7.png)
*Figure 5: WikiText-103 개발 세트에서 검색 stride s(연속 검색 사이의 토큰 수)에 따른 Perplexity. s=4에서 성능과 런타임의 최적 균형점이 형성되며, 이 값을 논문 전체에서 기본 설정으로 사용한다 (Ram et al., 2023).*

쿼리 길이 $\ell$ 또한 성능에 큰 영향을 미치는 하이퍼파라미터입니다. 아래 그래프는 BM25에서 쿼리 토큰 수에 따른 perplexity 변화를 보여줍니다.

![BM25 쿼리 길이에 따른 Perplexity 변화 분석](figures/fig_8.png)
*Figure 6: WikiText-103 개발 세트에서 BM25를 사용할 때 쿼리 토큰 수 l에 따른 Perplexity. 모델 규모에 관계없이 l=32 부근에서 최적 성능이 형성되며, 이 값을 논문 전체에서 기본 쿼리 길이로 사용한다 (Ram et al., 2023).*

Stride 크기 $s$는 검색 빈도와 계산 비용 사이의 트레이드오프를 결정하는 핵심 하이퍼파라미터입니다.

| Stride $s$ | 검색 빈도 | 문서 신선도 | 계산 비용 | 적합한 시나리오 |
|:-----------:|:---------:|:----------:|:---------:|:--------------:|
| 1 | 매 토큰 | 최고 | 매우 높음 | 이론적 상한 |
| 4 | 높음 | 높음 | 높음 | 정밀도 우선 |
| 16 | 중간 | 중간 | 중간 | 균형점 |
| 64 | 낮음 | 낮음 | 낮음 | 효율 우선 |

논문의 실험 결과에 따르면, stride $s = 4$에서 성능 대비 비용의 최적점이 형성됩니다. $s$가 이보다 더 줄어들어도 성능 개선 폭이 크지 않은 반면, $s$가 16을 넘어가면 성능 저하가 뚜렷해집니다.

### 문서 Prepending 메커니즘

검색된 문서를 입력에 prepend하는 구체적인 방식도 성능에 영향을 미칩니다. 논문에서 사용하는 prepending은 다음과 같은 형태입니다.

$$\text{input}_t = [d_1^{(t)}; \texttt{[SEP]}; d_2^{(t)}; \texttt{[SEP]}; \ldots; d_k^{(t)}; \texttt{[SEP]}; x_{t-w:t+s}]$$

여기서 $\texttt{[SEP]}$는 문서 간 경계를 나타내는 구분자이며, $x_{t-w:t+s}$는 쿼리 윈도우와 현재 stride 구간을 포함한 원본 텍스트입니다. 문서의 수 $k$가 증가하면 더 많은 외부 정보를 참조할 수 있지만, 모델의 최대 컨텍스트 윈도우 크기 $L$에 의해 제약됩니다.

$$\sum_{i=1}^{k} |d_i| + w + s \leq L$$

### 검색 및 재순위화 전략

논문은 세 가지 검색 방법과 재순위화 전략을 체계적으로 비교합니다.

**1. BM25 (Sparse Retrieval)**

BM25는 어휘 기반의 희소 검색 방법으로, 쿼리와 문서 간의 어휘적 매칭을 기반으로 관련성을 점수화합니다.

$$\text{BM25}(q, d) = \sum_{t \in q} \text{IDF}(t) \cdot \frac{f(t, d) \cdot (k_1 + 1)}{f(t, d) + k_1 \cdot \left(1 - b + b \cdot \frac{|d|}{\text{avgdl}}\right)}$$

여기서 $f(t, d)$는 문서 $d$에서 용어 $t$의 빈도, $\text{IDF}(t)$는 역문서 빈도, $k_1$과 $b$는 하이퍼파라미터, $\text{avgdl}$은 평균 문서 길이입니다. BM25는 구현이 간단하고 빠르지만, 의미적 유사도를 포착하지 못하는 한계가 있습니다.

**2. Dense Retrieval**

Dense retrieval은 쿼리와 문서를 밀집 벡터 공간에 임베딩하고, 벡터 간 유사도를 계산하여 관련 문서를 검색합니다.

$$\text{score}(q, d) = \text{sim}(E_q(q), E_d(d))$$

여기서 $E_q$와 $E_d$는 각각 쿼리와 문서 인코더이며, $\text{sim}$은 코사인 유사도 또는 내적입니다. 논문에서는 Contriever (Izacard et al., 2022) 등의 사전학습된 dense retriever를 활용합니다. Dense retrieval은 의미적 유사도를 포착할 수 있지만, BM25보다 계산 비용이 높고 도메인 외 일반화(out-of-domain generalization)에서 취약할 수 있습니다.

아래 그래프는 BM25를 포함한 네 가지 기성(off-the-shelf) 검색기의 성능을 비교합니다. 흥미롭게도 BM25가 dense retriever들과 대등하거나 오히려 우수한 성능을 보이며, 이는 단순한 어휘 기반 검색만으로도 충분히 효과적인 검색 증강이 가능함을 시사합니다.

![네 가지 기성 검색기의 In-Context RALM 성능 비교](figures/fig_3.png)
*Figure 3: WikiText-103 개발 세트에서 BERT, Contriever, Spider, BM25 네 가지 검색기를 사용한 In-Context RALM의 Perplexity. 모든 RALM은 stride s=4에서 최적 쿼리 길이로 평가된다. BM25가 dense retriever들과 대등한 성능을 보이는 점이 주목할 만하다 (Ram et al., 2023).*

**3. LM 기반 재순위화 (LM Reranking)**

가장 효과적인 전략으로, BM25로 초기 후보 문서를 검색한 후 언어 모델 자체를 활용하여 재순위화합니다. 각 후보 문서 $d$에 대해, 해당 문서가 컨텍스트로 주어졌을 때 쿼리 토큰들의 로그 우도를 재순위화 점수로 사용합니다.

$$\text{score}_{\text{LM}}(d, q) = \frac{1}{|q|} \sum_{t=1}^{|q|} \log P_{\text{LM}}(q_t \mid d, q_{<t})$$

이 점수는 직관적으로 "이 문서가 현재 텍스트의 연속을 예측하는 데 얼마나 도움이 되는가"를 측정합니다. 문서 $d$가 쿼리 $q$의 내용과 관련이 깊을수록, 해당 문서를 컨텍스트로 제공받은 모델은 쿼리 토큰들을 더 높은 확률로 예측하게 됩니다.

2단계 파이프라인의 전체 흐름은 다음과 같습니다.

1. **1단계 (BM25 검색)**: 쿼리 $q_t$에 대해 BM25로 상위 $N$개의 후보 문서를 빠르게 검색합니다 (예: $N = 50$).
2. **2단계 (LM 재순위화)**: 각 후보 문서에 대해 $\text{score}_{\text{LM}}$을 계산하고, 최종 상위 $k$개를 선택합니다 (예: $k = 1$ 또는 $k = 5$).

이 파이프라인은 BM25의 속도와 LM 재순위화의 정밀도를 결합하여 최적의 성능을 달성합니다.

## 실험 결과

### 실험 설정

논문은 다음과 같은 실험 환경에서 In-Context RALM의 효과를 검증합니다.

- **평가 데이터셋**: WikiText-103, RealNews, CC-News 등 언어 모델링 벤치마크
- **검색 코퍼스**: Wikipedia 덤프, 뉴스 코퍼스 등 각 데이터셋에 대응하는 외부 코퍼스
- **평가 대상 모델**: GPT-2 (117M, 345M, 774M, 1.5B), GPT-Neo (1.3B, 2.7B), GPT-J (6B)
- **평가 지표**: Perplexity (PPL)

Perplexity는 언어 모델의 예측 불확실성을 측정하는 표준 지표로, 값이 낮을수록 좋은 성능을 의미합니다.

$$\text{PPL}(X) = \exp\left(-\frac{1}{T}\sum_{t=1}^{T} \log P(x_t \mid x_{<t})\right)$$

### WikiText-103 결과

아래 그래프는 다양한 규모의 GPT-2 모델에서 검색 증강(BM25) 적용 전후의 perplexity를 비교합니다. 모든 모델 규모에서 일관된 성능 향상이 관찰됩니다.

![다양한 규모의 GPT-2 모델에서 In-Context RALM 성능 비교](figures/fig_4_1.png)
*Figure 4: WikiText-103 테스트 세트에서 GPT-2 계열 모델의 검색 증강 전후 Perplexity 비교. 117M부터 1.5B까지 모든 규모에서 BM25 기반 In-Context RALM이 baseline 대비 일관된 성능 향상을 달성한다 (Ram et al., 2023).*

WikiText-103에서의 perplexity 비교 결과는 다음과 같습니다.

몇 가지 핵심 관찰점이 있습니다.

첫째, **모든 규모의 모델에서 일관되게 perplexity가 감소**합니다. 117M부터 6B까지 모델 규모에 무관하게 약 30-33%의 상대적 감소율을 보이며, 이는 In-Context RALM의 범용적 적용 가능성을 입증합니다.

둘째, **BM25 단독으로도 상당한 성능 향상**을 보이며, LM 재순위화를 추가하면 성능이 추가로 개선됩니다. 2단계 파이프라인의 각 단계가 독립적으로 기여함이 확인됩니다.

셋째, PPL 감소의 절대값은 모델이 클수록 작아지는 경향이 있습니다(GPT-2 Small에서 약 12포인트, GPT-J에서 약 3.7포인트). 이는 대규모 모델의 baseline PPL 자체가 이미 낮기 때문이며, 상대적 감소율은 모든 모델에서 일관됩니다.

### 재순위화의 잠재력

재순위화가 왜 효과적인지, 그리고 얼마나 큰 개선 잠재력이 있는지를 분석한 결과도 주목할 만합니다. 아래 그래프는 BM25로 검색된 상위 16개 문서 중 oracle(최적의 문서를 항상 선택하는 이상적 재순위기)이 달성할 수 있는 perplexity를 보여줍니다.

![BM25 상위 16개 문서에서 오라클 재순위화의 성능 향상 가능성](figures/fig_9.png)
*Figure 7: 재순위화의 잠재력 분석. BM25로 검색된 상위 16개 문서 중 최선을 선택하는 오라클이 WikiText-103 개발 세트에서 달성하는 Perplexity 개선량. 오라클과 실제 재순위기 간의 격차는 더 나은 재순위화 전략의 개발 여지를 시사한다 (Ram et al., 2023).*

오라클 성능과 BM25 1순위 문서 간의 큰 격차는, BM25가 반환하는 후보 문서들 중에 실제로 더 적합한 문서가 존재하지만 BM25의 순위 함수가 이를 최상위에 배치하지 못하고 있음을 보여줍니다. 이 격차가 바로 LM 재순위화가 메울 수 있는 영역이며, 동시에 더 나은 재순위화 알고리즘의 개발 여지를 시사합니다.

### 검색 전략 비교

다양한 검색 전략의 성능을 비교한 결과입니다.

| 검색 전략 | WikiText-103 PPL (GPT-2 Large) | 검색 지연(ms/query) |
|-----------|:-----------------------------:|:------------------:|
| Baseline (검색 없음) | 18.3 | - |
| BM25 | 14.1 | ~5 |
| Contriever (Dense) | 14.8 | ~15 |
| BM25 + Dense Rerank | 13.4 | ~20 |
| BM25 + LM Rerank | 12.6 | ~80 |

BM25가 dense retrieval보다 우수한 성능을 보이는 점이 주목할 만합니다. 이는 WikiText-103이 Wikipedia 기반 데이터셋이라 어휘적 매칭이 특히 효과적이기 때문으로 분석됩니다. 도메인이 다른 경우(과학 논문, 코드 등)에서는 dense retrieval이 더 유리할 수 있습니다.

### Stride 크기에 따른 성능 변화

Stride 크기가 성능에 미치는 영향을 정량적으로 분석한 결과입니다.

| Stride $s$ | PPL (GPT-2 Large) | 상대적 개선률 | 검색 횟수 (1000 토큰 기준) |
|:----------:|:-----------------:|:------------:|:------------------------:|
| Baseline | 18.3 | - | 0 |
| 64 | 16.2 | -11.5% | 15.6 |
| 32 | 15.3 | -16.4% | 31.3 |
| 16 | 14.5 | -20.8% | 62.5 |
| 8 | 14.1 | -22.9% | 125 |
| 4 | 13.8 | -24.6% | 250 |

Stride가 작아질수록 perplexity가 감소하지만, 한계 효용(marginal utility)은 점차 줄어듭니다. $s = 4$에서 $s = 8$로의 개선(0.3 PPL)은 $s = 32$에서 $s = 16$으로의 개선(0.8 PPL)보다 훨씬 작습니다. 실용적 관점에서 $s = 4 \sim 16$이 성능과 비용의 적절한 균형점입니다.

### 모델 규모와 검색 증강 효과의 관계

논문의 중요한 발견 중 하나는 모델의 in-context learning 능력이 강할수록 검색 증강의 효과가 더 크다는 것입니다.

소규모 모델(GPT-2 Small, 117M)은 제한된 attention capacity로 인해 검색 문서의 정보를 완전히 활용하기 어렵습니다. 문서가 컨텍스트에 추가되어도 관련 정보를 효과적으로 추출하는 능력이 부족합니다.

반면 대규모 모델(GPT-J, 6B)은 풍부한 attention head와 깊은 레이어를 통해 검색 문서에서 태스크 관련 정보를 정교하게 추출하고 통합할 수 있습니다. 이는 few-shot in-context learning에서도 관찰되는 패턴으로, 모델 규모가 클수록 프롬프트에 포함된 정보를 더 잘 활용합니다.

이 관찰은 중요한 실용적 함의를 가집니다. GPT-4, Claude, LLaMA-3 등 수십~수백 B 규모의 현대 모델에서는 In-Context RALM의 효과가 논문에서 보고된 것보다 훨씬 더 클 수 있음을 시사합니다.

### 다운스트림 태스크에서의 효과

In-Context RALM은 언어 모델링(perplexity) 개선뿐 아니라, open-domain QA 등 다운스트림 태스크에서도 효과를 검증합니다. 아래 그래프는 Natural Questions와 TriviaQA에서 컨텍스트 내 문서 수를 변화시키며 제로샷 성능을 측정한 결과입니다.

![Natural Questions와 TriviaQA에서 In-Context RALM 제로샷 성능](figures/fig_10.png)
*Figure 8: Natural Questions 및 TriviaQA 개발 세트에서 In-Context RALM의 제로샷 성능. DPR로 검색된 문서 수를 변화시키며 LLaMA 7B/13B 모델에서 EM(Exact Match) 성능을 측정한다. 문서 수가 증가할수록 성능이 향상되며, 모델 규모가 클수록 검색 문서를 더 효과적으로 활용한다 (Ram et al., 2023).*

이 결과는 In-Context RALM이 perplexity 감소를 넘어 실제 태스크에서도 유의미한 성능 향상을 가져옴을 보여주며, 특히 파인튜닝 없이도 제로샷 설정에서 효과적이라는 점이 주목할 만합니다.

## 의의 및 한계

### 이론적 의의

In-Context RALM은 검색 증강 언어 모델 연구에서 패러다임 전환적 의미를 가집니다.

첫째, **검색 증강의 민주화**를 실현했습니다. 기존에는 검색 증강을 적용하려면 전문적인 ML 인프라와 학습 파이프라인이 필요했습니다. In-Context RALM은 어떤 API 기반 LLM이든 단순한 프롬프트 엔지니어링만으로 검색 증강의 혜택을 받을 수 있게 했습니다.

둘째, **검색과 생성의 모듈성(modularity)** 을 확립했습니다. 검색 모듈과 언어 모델이 독립적으로 개선될 수 있으며, 더 나은 검색 엔진이 개발되면 언어 모델의 변경 없이 즉시 성능이 향상됩니다. 반대로 더 강력한 언어 모델이 출시되면 동일한 검색 파이프라인과 즉시 결합할 수 있습니다.

셋째, **scaling law에 대한 새로운 관점**을 제시합니다. 모델 파라미터를 늘리는 parametric scaling과 검색을 통해 외부 지식을 확장하는 non-parametric scaling이 상호 보완적임을 보여줍니다. 이는 "모델을 더 크게 만드는 것만이 능사가 아니다"라는 메시지를 전달합니다.

### 실용적 의의

실용적 측면에서 In-Context RALM은 현재 널리 사용되는 [[RAG]] 시스템의 이론적 기반을 제공합니다.

- **LangChain**, **LlamaIndex** 등 RAG 프레임워크의 기본 메커니즘이 바로 In-Context RALM의 원리(검색 후 prepend)에 기반합니다.
- 기업 환경에서 사내 문서를 기반으로 LLM의 응답을 개선하는 패턴(enterprise RAG)이 이 연구의 직접적 응용입니다.
- OpenAI의 ChatGPT에 통합된 retrieval plugin, Bing Chat의 웹 검색 통합 등 상용 서비스에서도 이 원리가 핵심적으로 활용되고 있습니다.

### 한계점

**1. 컨텍스트 윈도우 제약**

검색 문서를 입력에 prepend하므로, 모델의 최대 컨텍스트 길이 $L$이 근본적 제약이 됩니다. 여러 문서를 삽입할수록 원본 입력을 위한 공간이 줄어듭니다. 이 문제는 최근의 long-context 모델(128K+ 토큰)에 의해 부분적으로 완화되고 있지만, 근본적 한계는 여전히 존재합니다.

**2. 검색 품질 의존성과 Noise 문제**

검색된 문서의 품질이 낮으면 오히려 성능이 저하될 수 있습니다. 잘못된 정보를 포함한 문서가 컨텍스트에 추가되면 모델이 오도될 수 있으며, 이는 환각을 증폭시킬 위험이 있습니다. 이 문제는 이후 연구에서 adaptive retrieval(필요할 때만 검색), self-reflection(검색 결과의 품질을 모델이 스스로 평가) 등의 기법으로 개선되고 있습니다.

**3. 평가 범위의 한계**

논문의 실험은 주로 언어 모델링(perplexity) 평가에 집중되어 있으며, 질의응답, 사실 검증, 요약 등 다운스트림 태스크에서의 효과는 체계적으로 검증되지 않았습니다. 이후 연구에서는 open-domain QA(Natural Questions, TriviaQA), 사실 검증(FEVER) 등에서도 In-Context RALM의 효과가 확인되었습니다.

**4. 추론 지연(Latency) 증가**

매 stride마다 외부 검색 엔진을 호출해야 하므로, 기본 언어 모델 대비 추론 시간이 증가합니다. 특히 LM 재순위화를 사용하면 각 후보 문서에 대해 forward pass를 수행해야 하므로 지연이 더 커집니다. 실시간 응답이 중요한 대화형 시스템에서는 검색 빈도와 재순위화 비용 간의 트레이드오프를 신중히 고려해야 합니다.

**5. 문서 위치에 따른 Attention 편향**

Lost in the Middle (Liu et al., 2023) 연구에서 밝혀진 바와 같이, 긴 컨텍스트에서 모델은 입력의 시작과 끝 부분에 더 많은 attention을 할당하는 경향이 있습니다. 여러 문서를 prepend할 때 문서의 배치 순서가 성능에 영향을 미칠 수 있으며, 이는 In-Context RALM에서도 고려해야 할 요소입니다.

### 후속 연구와의 관계

In-Context RALM 이후 검색 증강 분야에서 다양한 발전이 이루어졌습니다.

- **Self-RAG (Asai et al., 2023)**: 모델이 검색의 필요성을 스스로 판단하고, 검색 결과의 관련성을 평가하는 자기 반성적(self-reflective) RAG
- **CRAG (Yan et al., 2024)**: 검색 결과의 품질을 평가하고 보정하는 교정 메커니즘(corrective mechanism) 도입
- **Adaptive Retrieval**: 모든 토큰에 대해 검색하는 것이 아니라, 모델의 불확실성이 높을 때만 선택적으로 검색하는 방식
- **[[RAG]] + Fine-tuning 하이브리드**: In-Context RALM의 단순성과 파인튜닝의 효과를 결합하는 접근법

In-Context RALM은 이러한 후속 연구들의 기반이 되는 baseline 역할을 하며, "가장 단순한 형태의 검색 증강이 얼마나 효과적인가"에 대한 중요한 참조점을 제공합니다. 검색 증강 언어 모델 분야를 연구하거나 실무에 RAG를 적용하려는 분에게, 이 논문은 반드시 숙지해야 할 핵심 문헌입니다.
