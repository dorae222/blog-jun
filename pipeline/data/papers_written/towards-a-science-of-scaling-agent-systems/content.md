## 개요

"Towards a Science of Scaling Agent Systems" (Yubin Kim et al., 2025)는 LLM 기반 멀티 에이전트 시스템(Multi-Agent System, MAS)의 **스케일링 법칙**을 체계적으로 탐구한 연구이다. 단일 에이전트 시스템(Single Agent System, SAS)과 다양한 MAS 아키텍처(Centralized, Decentralized, Independent, Hybrid)를 3개 LLM 제품군(OpenAI, Google, Anthropic)과 4개 에이전트 벤치마크에 걸쳐 비교 실험하여, **에이전트 수를 늘리는 것이 항상 성능을 향상시키지는 않으며, 태스크 구조와 모델 역량에 따라 스케일링 패턴이 극적으로 달라진다**는 핵심 발견을 보고한다.

주요 결과를 요약하면 다음과 같다:

- **Finance Agent** 벤치마크에서는 MAS가 SAS 대비 **+57~81%** 성능 향상을 달성한 반면, **PlanCraft**에서는 **-39~-70%** 성능 저하가 발생
- Centralized 및 Hybrid 아키텍처가 전반적으로 우수한 스케일링 효율성을 보임
- 에이전트 이질성(heterogeneity)이 특정 조건에서 동질적 고성능 구성보다 우수한 성과를 냄
- 최적 에이전트 수는 모델 역량과 조율 전략에 의존하며, 무한히 늘린다고 성능이 향상되지 않음

이 연구는 "더 많은 에이전트 = 더 좋은 성능"이라는 직관을 실증적으로 반박하고, 멀티 에이전트 시스템 설계를 위한 **과학적 프레임워크**의 토대를 마련하고자 한다. 에이전트 시스템이 산업 전반에 빠르게 도입되고 있는 2025년 현재, 이 논문의 실증적 근거는 실무자와 연구자 모두에게 중요한 참고 자료가 된다.

## 배경 및 문제

### LLM 에이전트 시대의 도래

2023년 이후 LLM 기반 에이전트 시스템은 급속히 발전했다. ReAct (Yao et al., 2023), AutoGPT, CrewAI, LangGraph 등의 프레임워크가 등장하면서, 단일 LLM의 능력을 넘어서는 복잡한 태스크를 여러 에이전트의 협업으로 해결하려는 시도가 폭발적으로 증가했다. 특히 소프트웨어 개발(SWE-Agent), 과학 연구(AI Scientist), 금융 분석, 웹 브라우징 등 다양한 도메인에서 에이전트 시스템의 실용적 가치가 입증되고 있다.

에이전트 시스템의 핵심 전제는 단순하다: **하나의 LLM이 해결하기 어려운 복잡한 문제를 여러 LLM의 협업으로 해결할 수 있다**는 것이다. 이는 인간 세계에서 복잡한 프로젝트를 팀으로 수행하는 것과 유사한 논리이다. 그러나 인간 팀에서도 "사람을 더 투입하면 항상 빨라지는가?"라는 질문에 대한 답은 자명하지 않다. 소프트웨어 공학의 고전인 Brooks의 "The Mythical Man-Month"(1975)는 이미 50년 전에 이 문제를 지적한 바 있다.

그러나 **스케일링**이라는 관점에서는 아직 체계적인 이해가 부족하다. LLM 자체의 스케일링 법칙은 Kaplan et al. (2020)의 연구 이후 잘 정립되었다. 모델 파라미터 수 $N$, 학습 데이터 양 $D$, 연산량 $C$와 성능 $L$ 사이에 다음과 같은 멱법칙(power law) 관계가 성립한다:

$$L(N) \propto N^{-\alpha_N}, \quad L(D) \propto D^{-\alpha_D}, \quad L(C) \propto C^{-\alpha_C}$$

여기서 $\alpha_N \approx 0.076$, $\alpha_D \approx 0.095$, $\alpha_C \approx 0.050$이다. 이 관계는 놀라울 정도로 깨끗하며, 수십 배의 스케일 범위에서도 일관되게 성립한다.

그러나 LLM 기반 에이전트 **시스템**의 스케일링 ( 즉 에이전트 수, 조율 구조, 모델 이질성 등을 변화시킬 때 성능이 어떻게 변하는지 ) 에 대한 체계적 연구는 거의 존재하지 않았다. 모델 수준의 스케일링과 시스템 수준의 스케일링은 본질적으로 다른 문제이다. 모델 스케일링은 연속적이고 단조로운 반면, 에이전트 시스템 스케일링은 이산적이고 다차원적이며 태스크에 의존적이다.

### 해결하려는 핵심 질문

이 논문은 다음의 근본적 질문들에 답하고자 한다:

1. **아키텍처 효과**: SAS와 MAS의 성능 차이는 어떠한가? 어떤 MAS 아키텍처가 우월한가?
2. **모델 지능 스케일링**: 모델의 지능(Intelligence Index)이 높아질수록 에이전트 시스템의 성능은 어떻게 변하는가?
3. **태스크 의존성**: 멀티 에이전트의 효과는 태스크 유형에 따라 어떻게 달라지는가?
4. **비용-성능 트레이드오프**: MAS의 추가 비용은 성능 향상으로 정당화되는가?
5. **에이전트 이질성**: 서로 다른 역량의 모델을 혼합하면 어떤 효과가 있는가?
6. **최적 에이전트 수**: 에이전트를 늘리면 언제까지 성능이 향상되며, 한계점은 어디인가?

이 질문들은 단순한 학술적 호기심을 넘어, 실무적으로도 매우 중요하다. 에이전트 시스템의 API 비용이 에이전트 수에 비례하여 증가하기 때문에, "어떤 구성이 비용 대비 가장 효율적인가?"는 프로덕션 배포 시 핵심 의사결정이 된다.

### 기존 연구의 한계

기존 멀티 에이전트 연구들은 대부분 **특정 태스크에 특화된** 시스템을 제안하고 평가하는 데 집중했다. 예를 들어 MetaGPT (Hong et al., 2024)는 소프트웨어 개발에, CAMEL (Li et al., 2023)은 역할 기반 대화에 초점을 맞추었다. 그러나 이들은 **범용적 스케일링 원리**를 도출하지 못했으며, 다음과 같은 한계를 가진다:

- **단일 모델/벤치마크에 국한**: 대부분의 연구가 하나의 LLM(주로 GPT-4)과 하나의 태스크만을 사용하여, 결과의 일반화 가능성이 불확실
- **아키텍처 간 공정 비교 부재**: 서로 다른 MAS 아키텍처를 동일 조건에서 비교한 연구가 거의 없음. 각 연구가 자체 벤치마크와 평가 기준을 사용하여 교차 비교가 불가능
- **스케일링 역학 미분석**: 모델 역량이나 에이전트 수의 변화에 따른 체계적 분석이 없음. 대부분 고정된 구성에서의 일회성 평가에 그침
- **비용 고려 부재**: 성능만 보고하고, 실제 운영 비용과의 트레이드오프를 무시. 학술적으로 최고 성능이 실무적으로 최선이 아닐 수 있음

이 논문은 이러한 한계를 극복하기 위해, **3개 LLM 제품군 x 4개 벤치마크 x 5개 아키텍처**에 걸친 대규모 실험을 수행한다. 이러한 규모의 교차 분석은 기존 연구에서 시도된 적이 없다.

## 핵심 아이디어

### 에이전트 시스템의 분류 체계

이 논문의 첫 번째 기여는 에이전트 시스템 아키텍처에 대한 **명확한 분류 체계**를 제시한 것이다. 저자들은 에이전트 시스템을 크게 5가지로 분류한다. 각 아키텍처는 **정보 흐름(information flow)**과 **의사결정 구조(decision structure)**에서 근본적으로 다르며, 이 차이가 스케일링 행동을 결정짓는다.

#### 1. Single Agent System (SAS)

단일 LLM이 모든 도구(tool)에 접근하여 태스크를 독립적으로 해결한다. 기준선(baseline)으로 사용된다. 구조적 오버헤드가 없으며, 단일 모델의 역량에 전적으로 의존한다.

SAS의 성능 $P_{\text{SAS}}$는 순수하게 모델 역량 $I$(Intelligence Index)에 의해 결정된다:

$$P_{\text{SAS}} = f(I, T)$$

여기서 $T$는 태스크이다. SAS는 조율 오버헤드가 0이므로, 모든 연산 자원이 태스크 해결에 직접 투입된다.

#### 2. MAS-Centralized (중앙 집중형)

하나의 **오케스트레이터(Orchestrator)** 에이전트가 전체 태스크를 하위 태스크로 분해하고, 여러 **서브 에이전트(Sub-agent)**에게 할당한 뒤, 결과를 종합하여 최종 답을 생성한다. 오케스트레이터만이 전체 맥락을 파악하며, 서브 에이전트들은 독립적으로 작업한다.

이 구조의 정보 흐름은 **star topology**를 따른다. 오케스트레이터 $O$가 중심에 위치하고, 서브 에이전트 $\{A_1, A_2, \ldots, A_{n-1}\}$이 주변에 배치된다. 통신은 항상 $O \leftrightarrow A_i$ 경로를 통해 이루어지며, 서브 에이전트 간 직접 통신($A_i \leftrightarrow A_j$)은 없다.

이 구조는 관리자-직원 관계에 비유할 수 있으며, 다음과 같은 장점이 있다:
- 태스크 분해와 결과 통합이 체계적
- 각 서브 에이전트의 작업 범위가 명확
- 오케스트레이터가 전체 진행 상황을 추적 가능
- 통신 복잡도가 $O(n)$으로 효율적 (에이전트 수에 선형)

단점으로는 오케스트레이터가 병목(bottleneck)이 될 수 있으며, 오케스트레이터의 역량에 의해 전체 시스템의 상한이 결정된다.

#### 3. MAS-Decentralized (분산형)

모든 에이전트가 **동등한 지위**를 가지며, **토론(debate)과 투표(voting)** 메커니즘을 통해 합의에 도달한다. 각 에이전트가 독립적으로 태스크를 분석하고 답안을 제시한 후, 다른 에이전트들의 의견을 참조하여 자신의 답을 수정하는 과정을 반복한다. 최종 답은 다수결 투표로 결정된다.

이 구조의 정보 흐름은 **fully connected topology**를 따른다. 모든 에이전트 쌍 간에 통신이 가능하며, 통신 복잡도는 $O(n^2)$이다. 이는 에이전트 수가 많아질수록 조율 오버헤드가 급격히 증가함을 의미한다.

이 구조는 학술 세미나나 동료 검토(peer review) 과정에 비유할 수 있다. 각 참여자가 독립적으로 의견을 제시하고, 토론을 통해 합의에 도달하는 과정이다.

장점으로는 단일 실패점(single point of failure)이 없고, 다양한 관점이 반영되며, 자기 교정(self-correction) 기능이 내재되어 있다. 단점으로는 합의에 도달하는 데 시간이 걸리고, 에이전트 수 증가에 따른 조율 비용이 이차적으로 증가한다.

#### 4. MAS-Independent (독립형)

각 에이전트가 **완전히 독립적으로** 태스크를 해결하며, 에이전트 간 소통이 전혀 없다. 최종 답은 다수결 투표(majority voting)로 결정된다. 이것은 앙상블(ensemble) 기법의 에이전트 시스템 버전이라고 볼 수 있다.

정보 흐름이 없으므로 통신 복잡도는 $O(0)$이다. 그러나 투표를 위한 최소한의 집계 과정이 필요하다. 이 구조의 핵심 가정은 **"다양한 에러 패턴을 가진 독립 판단들의 다수결이 개별 판단보다 정확하다"**는 Condorcet의 배심원 정리(Jury Theorem)에 기반한다.

수학적으로, 각 에이전트의 정답 확률이 $p > 0.5$이고 에이전트들의 에러가 독립적이면, $n$명의 다수결 정답 확률은:

$$P(\text{majority correct}) = \sum_{k=\lceil n/2 \rceil}^{n} \binom{n}{k} p^k (1-p)^{n-k}$$

이 값은 $n \to \infty$일 때 1에 수렴한다. 그러나 실제로는 LLM 에이전트들이 **동일한 모델**에서 파생되므로 에러 패턴이 상관되어 있어, 순수한 Condorcet 정리의 가정이 충족되지 않는다.

#### 5. MAS-Hybrid (하이브리드)

중앙 집중형과 분산형을 결합한 구조이다. 오케스트레이터가 태스크를 분배하되, 서브 에이전트들이 결과를 제출한 후 **토론 단계**를 거쳐 합의에 도달한다. 이를 통해 중앙 집중형의 체계적 분업과 분산형의 자기 교정(self-correction) 장점을 모두 취한다.

실행 흐름을 정리하면 다음과 같다:

1. 오케스트레이터가 태스크를 분석하고 하위 태스크를 생성 (Centralized 단계)
2. 서브 에이전트들이 독립적으로 하위 태스크를 수행
3. 서브 에이전트들이 서로의 결과를 검토하고 토론 (Decentralized 단계)
4. 토론 결과를 바탕으로 합의된 답을 오케스트레이터에게 전달
5. 오케스트레이터가 최종 답변을 생성

이 구조는 통신 복잡도가 $O(n^2)$에 가까우며, 가장 높은 조율 오버헤드를 가진다. 그러나 분업의 효율성과 토론의 품질 향상 효과를 동시에 얻을 수 있다.

### 아키텍처 비교 요약

| 아키텍처 | 의사결정 구조 | 통신 복잡도 | 조율 오버헤드 | 핵심 장점 |
|---------|-------------|-----------|-------------|---------|
| SAS | 단일 | $O(0)$ | 없음 | 단순성, 비용 효율 |
| Centralized | 위계적 | $O(n)$ | 중간 | 체계적 분업 |
| Decentralized | 수평적 | $O(n^2)$ | 높음 | 자기 교정, 다양성 |
| Independent | 없음 | $O(0)$ | 낮음 | 앙상블 효과 |
| Hybrid | 혼합 | $O(n^2)$ | 최고 | 분업 + 교정 |

### Intelligence Index: 모델 역량의 정량화

에이전트 시스템의 스케일링을 분석하기 위해서는 서로 다른 LLM의 역량을 **통일된 척도**로 비교할 수 있어야 한다. 그러나 현실에서 LLM들은 서로 다른 기업에서, 서로 다른 학습 데이터와 방법론으로 만들어진다. GPT-5와 Gemini 2.5 Pro의 "역량"을 어떻게 비교할 수 있는가?

저자들은 기존 벤치마크 점수를 종합한 **Intelligence Index**를 도입한다. 이 지표는 다음과 같은 방식으로 산출된다:

1. 다수의 공개 벤치마크(MMLU, HumanEval, MATH, GPQA 등)에서의 모델 점수를 수집
2. 각 벤치마크 점수를 0-100 범위로 정규화
3. 벤치마크들의 가중 평균으로 단일 스칼라 값을 계산

수학적으로:

$$I_{\text{model}} = \sum_{b \in \mathcal{B}} w_b \cdot \frac{s_b - s_b^{\min}}{s_b^{\max} - s_b^{\min}} \times 100$$

여기서 $\mathcal{B}$는 벤치마크 집합, $w_b$는 벤치마크 $b$의 가중치, $s_b$는 해당 모델의 원점수, $s_b^{\min}$과 $s_b^{\max}$는 전체 모델 중 최소/최대 점수이다.

이를 통해 OpenAI의 GPT-5 nano부터 GPT-5, Google의 Gemini 2.0 Flash부터 Gemini 2.5 Pro, Anthropic의 Claude Sonnet 3.7부터 Sonnet 4.5까지를 하나의 축(Intelligence Index) 위에 배치하여 **모델 간, 제품군 간 비교**가 가능해진다.

물론 이 지표는 완벽하지 않다. 단일 스칼라로 LLM의 모든 역량을 표현하는 것은 불가피한 정보 손실을 수반한다. 예를 들어, 수학 추론에 강하지만 코딩에 약한 모델과 그 반대의 모델이 비슷한 Intelligence Index를 가질 수 있다. 그러나 스케일링 분석을 위한 **실용적 도구**로서는 충분한 변별력을 제공한다.

### 스케일링의 두 축: Intelligence vs. Agents

이 논문이 분석하는 스케일링은 두 가지 차원을 가진다:

1. **Intelligence Scaling** (수직적 스케일링): 동일 아키텍처에서 모델의 지능을 높이는 것 (예: GPT-5 nano → GPT-5 mini → GPT-5)
2. **Agent Scaling** (수평적 스케일링): 동일 모델에서 에이전트 수를 늘리는 것 (예: 1개 → 3개 → 5개 → 7개 → 9개)

이 두 축의 조합과 아키텍처 선택이 성능에 미치는 영향을 체계적으로 분석하는 것이 이 논문의 핵심이다.

기존의 LLM 스케일링 법칙이 "더 큰 모델 = 더 나은 성능"이라는 단순하고 일관된 관계를 보여주었던 것과 달리, 에이전트 시스템에서는 이러한 단순한 관계가 성립하지 않을 수 있다. 이것이 이 논문의 가장 중요한 가설이자, 실험을 통해 검증하고자 하는 명제이다.

## 방법론

### 실험 설계

저자들은 **3 (LLM 제품군) x 4 (벤치마크) x 5 (아키텍처)** 조합의 대규모 실험을 수행했다. 각 조합에서 다수의 실험을 반복하여 통계적 유의성을 확보했다. 총 실험 수는 수백 건에 달하며, 이는 기존 연구 대비 압도적인 규모이다.

#### 사용된 LLM 모델

| 제품군 | 모델 | Intelligence Index (근사) | 특성 |
|--------|------|--------------------------|------|
| OpenAI | GPT-5 nano | ~60 | 경량, 저비용 |
| OpenAI | GPT-5 mini | ~62 | 중간 역량 |
| OpenAI | GPT-5 | ~64 | 고성능, 고비용 |
| Google | Gemini 2.0 Flash | ~48 | 경량, 초저비용 |
| Google | Gemini 2.5 Flash | ~56 | 중간 역량, 저비용 |
| Google | Gemini 2.5 Pro | ~60 | 고성능 |
| Anthropic | Sonnet 3.7 | ~44 | 경량 |
| Anthropic | Sonnet 4.0 | ~47 | 중간 역량 |
| Anthropic | Sonnet 4.5 | ~54 | 고성능 |

각 제품군 내에서 3개의 모델을 선택하여 Intelligence Index에 따른 스케일링 경향을 관찰한다. 주목할 점은 세 제품군의 Intelligence Index 범위가 서로 다르다는 것이다: OpenAI(60-64), Google(48-60), Anthropic(44-54). 이 차이 자체가 에이전트 시스템의 스케일링 분석에 중요한 변수가 된다.

#### 벤치마크

4개의 에이전트 벤치마크는 서로 다른 유형의 태스크를 대표하며, 특히 **태스크 분해 가능성(decomposability)**의 스펙트럼을 커버하도록 선택되었다:

**1. BrowseComp-Plus**

웹 브라우징 기반 정보 검색 및 종합 태스크이다. 복잡한 질문에 대해 실제 웹을 탐색하여 답을 찾아야 한다. 이 태스크는 부분적으로 분해 가능하다 ( 여러 웹사이트를 동시에 탐색할 수 있지만, 최종 답변을 위해서는 수집된 정보의 종합이 필요하다.

태스크 특성:
- 정보 검색: 병렬화 가능
- 정보 종합: 순차적 추론 필요
- 전반적 분해 가능성: 중간

**2. Finance Agent**

금융 데이터 분석 및 의사결정 태스크이다. 재무제표 분석, 매출 추이 예측, 비용 구조 분석, 시장 비교 등 구조화된 경제 도메인의 문제를 해결한다.

태스크 특성:
- 데이터 분석: 높은 병렬화 가능성 (매출, 비용, 시장 비교를 각각 독립적으로 수행 가능)
- 결론 도출: 분석 결과 종합 필요하지만, 각 분석이 자체 완결적
- 전반적 분해 가능성: **높음**

**3. PlanCraft**

Minecraft 환경에서의 순차적 계획 수립 태스크이다. 주어진 인벤토리에서 아이템을 제작(crafting)하는 계획을 세워야 한다. 각 제작 행동이 인벤토리 상태를 변경하고, 다음 행동은 변경된 상태에 의존한다.

태스크 특성:
- 행동 시퀀스: 엄격하게 순차적 (행동 $a_t$는 상태 $s_t$에 의존, $s_{t+1} = \text{transition}(s_t, a_t)$)
- 상태 의존성: 각 단계가 이전 상태에 완전히 의존
- 전반적 분해 가능성: **매우 낮음**

**4. Workbench**

다양한 도구를 사용하는 일반적 에이전트 태스크 모음이다. 코딩, 파일 조작, 검색 등 여러 유형의 소규모 태스크를 포함한다.

태스크 특성:
- 태스크 다양성: 매우 높음
- 일부 태스크는 분해 가능, 일부는 순차적
- 전반적 분해 가능성: **혼합**

이 벤치마크들의 태스크 분해 가능성 스펙트럼을 정리하면:

$$\text{PlanCraft} \ll \text{BrowseComp} < \text{Workbench} \ll \text{Finance Agent}$$

이 스펙트럼이 MAS의 효과를 결정짓는 핵심 요인임이 실험을 통해 밝혀진다.

#### 아키텍처 구현 세부 사항

각 MAS 아키텍처는 다음과 같이 구현되었다:

**MAS-Centralized**: 오케스트레이터가 태스크를 분석하고 서브 에이전트 $n_a - 1$개에게 하위 태스크를 할당한다. 각 서브 에이전트는 할당된 하위 태스크를 독립적으로 수행하고 결과를 오케스트레이터에게 반환한다. 오케스트레이터가 모든 결과를 종합하여 최종 답변을 생성한다. 전체 에이전트 수는 $n_a$이다.

오케스트레이터의 프롬프트는 태스크 분석, 하위 태스크 생성, 서브 에이전트 지시, 결과 종합의 4단계로 구성된다. 서브 에이전트는 할당된 하위 태스크와 관련 도구만 접근 가능하며, 전체 태스크의 맥락은 제공되지 않는다.

**MAS-Decentralized**: $n_a$개의 동등한 에이전트가 각각 독립적으로 태스크를 분석한 후, 여러 라운드의 토론을 진행한다. 각 라운드에서 에이전트는 다른 에이전트들의 답변을 참조하여 자신의 답을 수정할 수 있다. 최종적으로 다수결 투표를 통해 답을 결정한다.

토론 라운드 수 $R$은 일반적으로 2-3으로 설정된다. 각 라운드 $r$에서 에이전트 $i$의 답변 $a_i^{(r)}$은 이전 라운드의 모든 에이전트 답변 $\{a_j^{(r-1)}\}_{j=1}^{n_a}$을 참조한다.

**MAS-Independent**: $n_a$개의 에이전트가 서로 소통 없이 독립적으로 태스크를 해결한다. 최종 답은 다수결 투표로 결정한다. 각 에이전트에 대한 프롬프트와 도구 설정은 SAS와 동일하다.

**MAS-Hybrid**: 오케스트레이터가 태스크를 분배하고 서브 에이전트들이 독립적으로 작업한 후, 결과를 바탕으로 토론 단계를 거친다. 토론 후 합의된 결과를 오케스트레이터가 최종 정리한다.

### 분석 지표

저자들은 단순한 정확도 비교를 넘어 다음의 정량적 지표들을 활용한다:

**상대적 성능 변화율**: SAS 대비 MAS의 성능 변화를 백분율로 측정한다.

$$\Delta_{\text{rel}} = \frac{\text{mean}_{\text{MAS}} - \text{mean}_{\text{SAS}}}{\text{mean}_{\text{SAS}}} \times 100\%$$

이 지표는 직관적이지만, SAS의 성능이 매우 낮은 경우(분모가 작은 경우) 과도하게 부풀려질 수 있는 단점이 있다.

**Cohen's d (효과 크기)**: 두 조건 간 차이의 실질적 크기를 표준편차 단위로 측정한다.

$$d = \frac{\bar{x}_{\text{MAS}} - \bar{x}_{\text{SAS}}}{s_{\text{pooled}}}$$

여기서 합동 표준편차는:

$$s_{\text{pooled}} = \sqrt{\frac{(n_1 - 1)s_1^2 + (n_2 - 1)s_2^2}{n_1 + n_2 - 2}}$$

일반적인 해석 기준은 다음과 같다:
- $|d| < 0.2$: 무시할 수 있는 효과
- $0.2 \leq |d| < 0.5$: 작은 효과
- $0.5 \leq |d| < 0.8$: 중간 효과
- $0.8 \leq |d| < 1.2$: 큰 효과
- $|d| \geq 1.2$: 매우 큰 효과

이 지표는 $\Delta_{\text{rel}}$보다 더 보수적이며 통계적으로 견고하다. 샘플 크기와 변동성을 모두 고려하기 때문이다.

**비용-성능 효율성**: 정규화된 API 비용 대비 성능으로 측정한다. 이를 통해 단순히 "더 좋은가?"가 아니라 "비용 대비 효율적인가?"를 판단할 수 있다. 실무에서는 절대 성능보다 이 지표가 더 중요할 수 있다.

$$\text{Efficiency} = \frac{P_{\text{MAS}}}{C_{\text{MAS}}} \bigg/ \frac{P_{\text{SAS}}}{C_{\text{SAS}}}$$

이 비율이 1보다 크면 MAS가 비용 효율적이고, 1보다 작으면 SAS가 더 효율적이다.

## 실험 결과

### 1. Intelligence Scaling: 모델이 똑똑해지면 에이전트 시스템도 좋아지는가?

![모델 지능과 시스템 아키텍처에 따른 에이전트 스케일링](figures/fig_1.png)
*Figure 1: 세 LLM 제품군(OpenAI, Google, Anthropic)에서 Intelligence Index에 따른 평균 성능(%) 추이. SAS를 기준선으로, 4가지 MAS 아키텍처의 스케일링 행동을 비교한다. 퍼센트 수치는 동일 Intelligence Index에서 최고 MAS 대비 SAS의 상대적 성능 변화를 나타낸다.*

Figure 1은 이 논문의 핵심 결과 중 하나이다. 4개 벤치마크의 평균 성능을 Intelligence Index에 따라 플롯한 것으로, 세 가지 주요 발견이 있다.

**첫째, 모든 제품군에서 Intelligence Index가 높아질수록 성능이 향상된다.** 이는 예상대로이며, 모델 자체의 역량이 에이전트 시스템 성능의 기반이 됨을 확인한다. OpenAI에서는 GPT-5 nano(약 50%) → GPT-5(약 58%)로 약 8%p 향상이 관찰되며, Google에서는 Gemini 2.0 Flash(약 35%) → Gemini 2.5 Pro(약 55%)로 약 20%p의 더 큰 향상이 나타난다. Anthropic에서도 Sonnet 3.7(약 38%) → Sonnet 4.5(약 55%)로 일관된 상승이 관찰된다.

이 결과는 "에이전트 시스템의 성능은 궁극적으로 기반 모델의 역량에 의해 제한된다"는 직관을 뒷받침한다. 아무리 정교한 조율 구조를 적용하더라도, 개별 에이전트의 역량이 부족하면 시스템 전체의 성능에 한계가 있다.

**둘째, MAS의 효과는 제품군마다 다르다.** OpenAI 모델에서는 최고 MAS가 SAS 대비 **+8.7%**의 성능 향상을 보이며, Google 모델에서도 **+8.1%**의 개선이 관찰된다. 그러나 Anthropic 모델에서는 오히려 **-4.6%**의 성능 저하가 발생한다.

이 결과의 의미는 심오하다. **동일한 MAS 아키텍처**를 적용했음에도 불구하고, 어떤 모델에서는 도움이 되고 어떤 모델에서는 해가 된다는 것이다. 저자들은 이를 모델의 **내재적 통신 대역폭(intrinsic communication bandwidth)**과 **추론 정합성(reasoning alignment)**의 차이로 해석한다. 즉, 어떤 모델은 다른 에이전트의 출력을 효과적으로 활용하는 반면, 어떤 모델은 타 에이전트의 출력으로 인해 오히려 혼란을 겪는다는 것이다.

이 현상을 더 깊이 이해하기 위해서는 각 모델의 학습 과정에서의 차이를 고려해야 한다. 특히 instruction tuning과 RLHF/RLAIF 과정에서 멀티 턴 대화나 협업 시나리오가 얼마나 반영되었는지가 MAS에서의 성능에 영향을 미칠 수 있다.

**셋째, Centralized와 Hybrid 아키텍처가 전반적으로 우수한 스케일링 효율을 보인다.** 특히 OpenAI 모델에서 이 경향이 두드러진다. Figure 1에서 Centralized(다이아몬드)와 Hybrid(사각형) 마커가 대부분의 경우 SAS(원) 위에 위치하는 것을 확인할 수 있다. 이는 체계적 조율이 에이전트 수 증가의 이점을 더 효과적으로 활용함을 보여준다.

반면 Independent(별표)와 Decentralized(세모)는 SAS와 유사하거나 약간 아래에 위치하는 경우가 많다. 조율 없는 단순 앙상블(Independent)이나 과도한 조율(Decentralized)이 항상 최선은 아님을 보여준다.

### 2. SAS vs. MAS: 태스크에 따른 극적인 차이

![SAS와 MAS의 벤치마크별 비교 성능](figures/fig_2.png)
*Figure 2: 4개 벤치마크에서 SAS와 MAS 아키텍처의 성능 분포 비교. 박스 플롯은 성공률 분포(0~1 범위)를 보여주며, 퍼센트 주석은 SAS 기준 상대적 개선/저하를 나타낸다. 흰색 다이아몬드는 각 아키텍처의 평균 성능을 표시한다.*

Figure 2는 이 논문에서 가장 극적이고 시사하는 바가 큰 결과를 보여준다. **동일한 에이전트 아키텍처가 태스크에 따라 극적으로 다른 효과를 나타낸다.** 모든 모델과 구성을 합산한 박스 플롯으로, 각 벤치마크에서의 분포를 명확하게 비교할 수 있다.

#### Finance Agent: MAS의 압도적 우위 (+57~81%)

Finance Agent 벤치마크에서는 **모든** MAS 아키텍처가 SAS를 크게 앞선다. 수치를 정리하면:

| 아키텍처 | SAS 대비 변화 |
|---------|-------------|
| MAS-Independent | +57% |
| MAS-Decentralized | +75% |
| MAS-Centralized | +81% |
| MAS-Hybrid | +73% |

가장 높은 개선율은 Centralized에서의 +81%이며, 가장 낮은 Independent에서도 +57%의 향상을 보인다. 이는 금융 분석 태스크가 **자연스럽게 병렬화 가능한 하위 태스크로 분해**되기 때문이다.

구체적으로, 금융 분석 태스크를 다음과 같이 분해할 수 있다:

1. **매출 추이 분석**: 과거 매출 데이터를 분석하고 추세를 파악
2. **비용 구조 검토**: 고정비/변동비 비율, 비용 변화 추이 분석
3. **시장 비교**: 동종 업계 비교, 시장 점유율 분석
4. **리스크 평가**: 재무 건전성, 신용 위험 평가
5. **종합 판단**: 위 분석 결과를 종합하여 투자 의사결정

1-4의 각 하위 태스크는 **독립적으로 수행 가능**하며, 5에서만 결과의 통합이 필요하다. 이러한 구조는 Centralized 아키텍처의 "오케스트레이터가 분배하고, 서브 에이전트가 독립 수행하고, 결과를 종합"하는 패턴과 완벽하게 일치한다.

MAS-SAS 박스 플롯에서 주목할 점은 MAS의 **중앙값(median)**뿐 아니라 **분포 전체**가 SAS보다 높다는 것이다. 이는 MAS의 이점이 특정 사례에만 국한되지 않고 **일관적**임을 보여준다.

#### PlanCraft: MAS의 일관된 실패 (-39~-70%)

반면 PlanCraft에서는 모든 MAS 아키텍처가 SAS보다 **크게 뒤처진다**:

| 아키텍처 | SAS 대비 변화 |
|---------|-------------|
| MAS-Independent | -70% |
| MAS-Decentralized | -41% |
| MAS-Centralized | -50% |
| MAS-Hybrid | -39% |

가장 심한 경우 Independent에서 -70%의 성능 저하가 관찰된다. 이는 PlanCraft의 태스크 구조적 특성 때문이다.

PlanCraft는 Minecraft 환경에서 아이템 제작(crafting) 계획을 수립하는 태스크이다. 핵심적으로, **각 제작 행동이 인벤토리 상태를 변경**하며, **다음 행동은 변경된 상태에 의존**한다. 형식적으로:

$$s_{t+1} = \text{transition}(s_t, a_t), \quad a_{t+1} = \pi(s_{t+1})$$

여기서 $s_t$는 시간 $t$에서의 인벤토리 상태, $a_t$는 수행할 제작 행동, $\pi$는 정책(policy)이다. 정책 $\pi$는 **현재 상태에 완전히 의존**하므로, 태스크가 **엄격하게 순차적(strictly sequential)**이며 **상태 의존적(state-dependent)**이다.

이런 상황에서 여러 에이전트가 관여하면:

1. **상태 동기화 문제**: 에이전트 A가 나무를 사용하여 판자를 만든 후, 에이전트 B는 나무가 이미 소진되었다는 것을 알아야 한다. 그러나 병렬 실행에서는 이 정보가 즉시 전달되지 않을 수 있다.
2. **조율 오버헤드**: 순차적 태스크에서 조율은 순수한 비용이다. 분업의 이점 없이 통신 비용만 발생한다.
3. **충돌하는 계획**: 에이전트 A는 "나무 → 판자 → 작업대" 경로를, 에이전트 B는 "나무 → 막대" 경로를 동시에 제안할 수 있다. 이는 동일한 자원(나무)에 대한 충돌이다.

이것은 **"더 많은 요리사가 국을 망친다(Too many cooks spoil the broth)"**는 직관과 정확히 일치하며, Brooks의 법칙 "Adding manpower to a late software project makes it later"의 AI 에이전트 버전이라고 할 수 있다.

주목할 점은 가장 적은 저하를 보이는 것이 Hybrid(-39%)라는 것이다. Hybrid 아키텍처의 토론 단계가 일종의 "오류 교정" 역할을 하여 피해를 줄이는 것으로 보인다. 반면 Independent(-70%)가 최악인 것은 당연하다 ) 독립적 에이전트들이 상태를 공유하지 않고 각자 계획을 세우면, 다수결로는 좋은 순차적 계획을 선택할 수 없다.

#### BrowseComp-Plus와 Workbench: 중간 영역

BrowseComp-Plus에서는 아키텍처에 따라 결과가 갈린다. Independent는 -35%로 크게 실패하지만, Hybrid(+9%)와 Centralized(+6%)는 소폭 개선을 보이며, Decentralized는 0%(동일)이다.

이는 웹 탐색 태스크의 이중적 성격을 반영한다. **검색 단계**는 병렬화 가능하므로 MAS가 유리하지만, **정보 종합 단계**는 조율이 필요하다. Independent는 종합 과정이 없으므로 실패하고, Centralized와 Hybrid는 오케스트레이터가 종합 역할을 수행하므로 소폭 이점을 얻는다.

Workbench는 -11%에서 +6% 사이의 미미한 변화를 보여, MAS의 효과가 태스크 유형에 따라 상쇄됨을 보여준다. Workbench가 다양한 유형의 소규모 태스크를 포함하고 있기 때문에, 분해 가능한 태스크에서의 이점과 순차적 태스크에서의 손실이 평균적으로 상쇄되는 것이다.

#### 핵심 통찰: 태스크 분해 가능성(Task Decomposability)

이 결과에서 도출되는 핵심 원리는 **태스크의 분해 가능성**이 MAS 효과의 결정적 요인이라는 것이다:

- **높은 분해 가능성** (Finance Agent): 하위 태스크가 독립적이고 병렬 처리 가능 → MAS 우수
- **낮은 분해 가능성** (PlanCraft): 순차적, 상태 의존적 → MAS 불리
- **중간 분해 가능성** (BrowseComp, Workbench): 아키텍처에 따라 결과가 다름

이를 수학적으로 표현하면, 태스크 $T$의 분해 가능성 $\mathcal{D}(T)$가 높을수록 MAS의 기대 성능 향상 $\mathbb{E}[\Delta_{\text{rel}}]$이 커진다고 볼 수 있다:

$$\mathbb{E}[\Delta_{\text{rel}}] \propto \mathcal{D}(T) - \mathcal{C}(\text{arch})$$

여기서 $\mathcal{C}(\text{arch})$는 해당 MAS 아키텍처의 조율 오버헤드를 나타낸다. MAS가 유리하려면 $\mathcal{D}(T) > \mathcal{C}(\text{arch})$이어야 한다. 즉, 태스크의 분해 이점이 조율 비용을 초과해야 한다.

이 관계를 더 구체화하면, 아키텍처별 조율 오버헤드 순서는 다음과 같다:

$$\mathcal{C}(\text{Independent}) < \mathcal{C}(\text{Centralized}) < \mathcal{C}(\text{Decentralized}) \leq \mathcal{C}(\text{Hybrid})$$

이는 Finance Agent(높은 $\mathcal{D}$)에서 모든 아키텍처가 성공하고, PlanCraft(낮은 $\mathcal{D}$)에서 모든 아키텍처가 실패하며, BrowseComp(중간 $\mathcal{D}$)에서 낮은 오버헤드의 Centralized/Hybrid만 성공하는 이유를 설명한다.

### 3. 에이전트 이질성의 효과

![에이전트 이질성이 멀티 에이전트 성능에 미치는 영향](figures/fig_4.png)
*Figure 4: Centralized(좌)와 Decentralized(우) 아키텍처에서의 에이전트 이질성 효과. 고역량/저역량 모델의 다양한 조합을 BrowseComp-Plus 벤치마크에서 비교한다. 고역량 모델은 GPT-5, Claude Sonnet 4.5, Gemini 2.5 Pro이며, 저역량 모델은 GPT-5 nano, Claude Sonnet 3.7, Gemini 2.0 Flash이다.*

에이전트 이질성(heterogeneity) 실험은 실무적으로 매우 중요한 시사점을 제공한다. 실제 시스템에서는 비용 절감을 위해 모든 에이전트에 최고 성능 모델을 사용하기 어렵기 때문이다. 만약 고성능 모델과 저성능 모델을 적절히 혼합하여 동등하거나 더 나은 성능을 달성할 수 있다면, 비용 효율성이 크게 개선될 것이다.

저자들은 BrowseComp-Plus 벤치마크에서 다음의 구성을 비교한다:

#### Centralized 아키텍처에서의 구성

| 구성 | 오케스트레이터 | 서브 에이전트 |
|------|-------------|-------------|
| All High-Intelligence | 고역량 모델 | 고역량 모델 |
| All Low-Intelligence | 저역량 모델 | 저역량 모델 |
| High Orch. + Low Sub-agents | 고역량 모델 | 저역량 모델 |
| Low Orch. + High Sub-agents | 저역량 모델 | 고역량 모델 |

#### Centralized 아키텍처에서의 발견

Centralized 아키텍처에서는 **오케스트레이터와 서브 에이전트의 역량 배분**이 성능에 큰 영향을 미친다. 주목할 만한 결과는 다음과 같다:

**Anthropic 모델에서의 역전 현상**: 저역량 오케스트레이터(Sonnet 3.7) + 고역량 서브 에이전트(Sonnet 4.5) 조합의 정확도가 0.42로, 동질적 고역량 구성(All Sonnet 4.5)의 0.32를 **31% 앞서는** 놀라운 결과를 보인다.

이 결과는 상당히 반직관적이다. 왜 더 강한 모델이 오케스트레이터가 되면 오히려 성능이 떨어지는가? 저자들은 이를 다음과 같이 해석한다:

1. **과도한 분해(over-decomposition)**: 고역량 오케스트레이터가 태스크를 지나치게 세분화하여 서브 에이전트에게 비효율적인 하위 태스크를 할당할 수 있다
2. **과도한 수정(over-editing)**: 고역량 오케스트레이터가 서브 에이전트의 결과를 지나치게 수정하면서 원래의 유용한 정보를 손상시킬 수 있다
3. **역할 적합성(role suitability)**: 저역량 모델이 "단순하지만 명확한" 지시를 내리는 데 더 적합할 수 있으며, 고역량 모델은 실제 작업 수행에 더 적합할 수 있다

**서브 에이전트 역량의 중요성**: 세 제품군 모두에서 일관되게, **고역량 오케스트레이터 + 저역량 서브 에이전트** 조합보다 **저역량 오케스트레이터 + 고역량 서브 에이전트** 조합이 더 우수한 성능을 보인다.

수치로 비교하면:

| 제품군 | High Orch. + Low Sub | Low Orch. + High Sub |
|--------|---------------------|---------------------|
| OpenAI | 0.19 | 0.21 |
| Anthropic | 0.34 | 0.42 |
| Google | 0.22 | 0.23 |

이 결과가 모든 제품군에서 일관되게 나타난다는 점은 주목할 만하다. **실제 작업을 수행하는 서브 에이전트의 역량이 작업을 지시하는 오케스트레이터의 역량보다 더 중요하다**는 것이다.

이는 실무적으로 다음을 의미한다:

> 비용 효율적 MAS 설계에서, 오케스트레이터에는 가벼운(저비용) 모델을 사용하고, 실제 작업을 수행하는 서브 에이전트에 고성능 모델을 배치하는 것이 합리적이다.

예를 들어, GPT-5 nano를 오케스트레이터로, GPT-5를 서브 에이전트로 사용하면, 전체 에이전트에 GPT-5를 사용하는 것보다 비용을 절감하면서도 유사하거나 더 나은 성능을 얻을 수 있다.

#### Decentralized 아키텍처에서의 발견

Decentralized 아키텍처에서는 더욱 흥미로운 결과가 나타난다. 오케스트레이터가 없으므로 "High/Low Orch." 구분 대신 **혼합 역량(Mixed Intelligence)** 구성과 동질적 구성을 비교한다.

**혼합 역량 구성이 동질적 고역량 구성과 비슷하거나 심지어 더 나은 성능을 달성한다**:

| 제품군 | All High | All Low | Mixed |
|--------|----------|---------|-------|
| OpenAI | 0.50 | 0.32 | **0.53** |
| Anthropic | 0.37 | 0.29 | **0.47** |
| Google | **0.43** | 0.19 | 0.42 |

OpenAI에서는 Mixed(0.53)가 All High(0.50)보다 6% 높고, Anthropic에서는 Mixed(0.47)가 All High(0.37)보다 **27% 높다**. Google에서만 All High(0.43)가 Mixed(0.42)와 거의 동등하다.

이 현상은 **인지적 다양성(cognitive diversity)**의 효과로 해석할 수 있다. 서로 다른 역량 수준의 에이전트가 토론할 때:

1. **저역량 에이전트**가 "단순하지만 핵심적인" 관점을 제시한다. 복잡한 추론보다는 기본적인 사실 관계에 집중하므로, 고역량 에이전트가 놓칠 수 있는 기초적 오류를 지적할 수 있다.
2. **고역량 에이전트**가 이를 정교화한다. 저역량 에이전트의 단순한 관찰을 바탕으로 더 깊은 분석을 수행한다.
3. **상호 보완적 시너지**가 발생한다. 동질적 고역량 에이전트들은 비슷한 사고 패턴(similar reasoning patterns)을 가지므로, 동일한 유형의 오류를 반복할 수 있다. 반면 이질적 구성은 다양한 에러 패턴을 가져 상호 교정 효과가 더 크다.

이는 인간 팀에서도 관찰되는 현상으로, 전문가만으로 구성된 팀보다 다양한 배경의 구성원을 가진 팀이 특정 문제에서 더 나은 해결책을 찾는 "집단 지성(collective intelligence)" 효과와 유사하다. Surowiecki의 "The Wisdom of Crowds"(2004)가 강조한 바와 같이, 군중의 지혜는 개인의 역량보다 **다양성**에 더 크게 의존한다.

### 4. 최적 에이전트 수: 무한히 늘려도 될까?

![에이전트 수 스케일링에 따른 모델 의존적 조율 한계](figures/fig_5.png)
*Figure 5: Gemini 2.0 Flash(좌)와 Gemini 2.5 Pro(우)에서 에이전트 수($n_a \in \{1, 3, 5, 7, 9\}$)에 따른 MAS 성능 변화. 점선은 단일 에이전트 기준선 성능을 나타낸다.*

에이전트 수($n_a$)를 1에서 9까지 변화시킨 실험은 **조율 오버헤드의 한계**를 명확히 보여준다. 이 실험은 Google의 두 모델 ( 저역량(Gemini 2.0 Flash)과 고역량(Gemini 2.5 Pro) ) 을 대상으로 수행되었다.

#### Gemini 2.0 Flash (저역량 모델)

Figure 5 좌측 패널에서 관찰되는 주요 패턴:

- **SAS 기준선**이 상대적으로 낮으므로, MAS로의 전환 시 **개선 여지가 크다**
- Centralized 아키텍처에서 비교적 안정적인 스케일링을 보이며, **7개 에이전트**에서 최적 성능을 달성한다
- 7개 이후에는 성능이 하락하기 시작하여, 조율 오버헤드가 병렬화 이점을 초과함을 보여준다
- Decentralized 아키텍처에서도 유사한 패턴이 관찰되지만, 최적점이 더 일찍 나타난다. 이는 Decentralized의 $O(n^2)$ 통신 복잡도가 더 빠르게 부담이 되기 때문이다

저역량 모델에서 MAS의 이점이 더 오래 유지되는 이유는 직관적이다. 개별 에이전트의 역량이 낮으므로, 여러 에이전트의 다양한 시도(diverse attempts)가 서로를 보완하는 효과가 크다. 이는 약한 학습기(weak learner)를 결합하는 앙상블의 원리와 일맥상통한다.

#### Gemini 2.5 Pro (고역량 모델)

Figure 5 우측 패널에서 관찰되는 주요 패턴:

- **SAS 기준선이 이미 높기 때문에**, MAS로의 전환 시 개선 여지가 상대적으로 작다
- Decentralized 아키텍처가 더 일찍 최적점에 도달하며, **5개 에이전트** 이상에서는 수확 체감(diminishing returns)이 뚜렷하다
- Centralized 아키텍처는 더 안정적이지만, 역시 5개 이상에서는 유의미한 개선이 없다
- 9개 에이전트에서는 일부 아키텍처에서 SAS 기준선 아래로 떨어지는 경우도 관찰된다

고역량 모델에서 MAS의 이점이 빠르게 소진되는 이유도 직관적이다. 개별 에이전트가 이미 충분히 강하므로, 추가 에이전트가 제공하는 **한계 기여(marginal contribution)**가 작다. 반면 조율 오버헤드는 에이전트 수에 비례하여 증가하므로, 순이익(net benefit)이 빠르게 감소한다.

#### 핵심 교훈

이 결과에서 도출되는 실무적 교훈은 명확하다:

1. **최적 에이전트 수는 모델 역량에 의존한다**: 저역량 모델은 더 많은 에이전트(5-7개)로부터 이익을 얻지만, 고역량 모델은 적은 수의 에이전트(3-5개)로 충분하다
2. **조율 전략에 따라 최적점이 달라진다**: Centralized가 일반적으로 더 많은 에이전트를 안정적으로 관리할 수 있다. 이는 $O(n)$ 통신 복잡도 덕분이다
3. **무한 스케일링은 불가능하다**: 어느 시점 이후에는 조율 오버헤드가 병렬화 이점을 초과하여 성능이 오히려 하락한다

이를 일반화하면, 에이전트 수 $n_a$에 따른 성능 $P(n_a)$는 대략 다음과 같은 형태를 따른다:

$$P(n_a) = P_{\text{base}} + \alpha \cdot \log(n_a) - \beta \cdot n_a^{\gamma}$$

여기서:
- $P_{\text{base}}$: 단일 에이전트의 기본 성능
- $\alpha$: 병렬화 이점의 계수 (태스크 분해 가능성에 비례)
- $\beta$: 조율 오버헤드의 계수 (아키텍처에 의존)
- $\gamma$: 오버헤드 성장률 (Centralized: $\gamma \approx 1$, Decentralized: $\gamma \approx 2$)

병렬화 이점은 로그 함수적으로 증가하는 반면(수확 체감), 조율 오버헤드는 에이전트 수에 따라 다항식적으로 증가하므로, 반드시 **교차점**이 존재한다. 이 교차점이 바로 최적 에이전트 수 $n_a^*$이다.

$$n_a^* = \arg\max_{n_a} P(n_a)$$

$n_a^*$은 $\alpha$ (태스크에 의존), $\beta$ (아키텍처에 의존), $P_{\text{base}}$ (모델에 의존)에 따라 달라지므로, 최적 에이전트 수가 태스크, 아키텍처, 모델의 3원 함수임을 확인할 수 있다.

### 5. 벤치마크별 상세 스케일링 역학

![LLM 제품군별 벤치마크 스케일링 역학](figures/fig_6.png)
*Figure 6: 4개 벤치마크에서 Intelligence Index에 따른 최고 MAS 변형 vs. SAS 기준선의 성능 곡선. 색상은 LLM 제품군(분홍: OpenAI, 파랑: Google, 주황: Anthropic)을, 마커 형태는 아키텍처 유형(회색 마커: SAS, 기타: 다양한 MAS 변형)을 구분한다.*

Figure 6은 벤치마크별로 세분화된 스케일링 역학을 보여주며, Figure 1의 평균화된 결과 이면의 풍부한 패턴을 드러낸다. 각 패널을 상세히 분석한다.

#### BrowseComp-Plus (좌상단)

Intelligence Index가 높아질수록 전반적으로 성능이 향상되지만, 제품군 간 차이가 크고 복잡한 교차 패턴이 나타난다:

- **Anthropic 모델(주황)**이 저지능 구간(Intelligence Index ~42-47)에서 가장 높은 성능(~40%)을 보인다. 이는 Sonnet 3.7이 단일 에이전트로서 웹 브라우징에 상대적으로 강함을 시사한다
- 그러나 고지능 구간(~54)에서는 Google(파랑)과 OpenAI(분홍)가 비슷하거나 더 높은 성능을 달성한다
- SAS(회색 마커)와 MAS 최고 변형(색상 마커) 사이의 간격이 벤치마크 중 가장 좁다. 이는 BrowseComp의 분해 가능성이 중간 수준임을 반영한다

#### Finance Agent (우상단)

가장 뚜렷하고 극적인 스케일링 패턴을 보인다:

- 세 제품군 모두에서 Intelligence Index 증가에 따른 성능 향상이 강하게 나타난다
- **SAS(회색)와 MAS(색상) 사이의 간격이 모든 Intelligence Index에서 크다**. 이는 Finance Agent에서 MAS의 이점이 모델 역량과 무관하게 일관적임을 보여준다
- 고지능 구간에서 OpenAI와 Google의 MAS가 70-80%의 높은 성능을 달성하며, SAS 대비 20-30%p의 큰 차이를 보인다

특히 구조화된 태스크에서의 협력적 스케일링이 매우 강하다:
- OpenAI: +23.1%, Cohen's $d > 1.2$ (매우 큰 효과)
- Google: +20.8%, Cohen's $d > 1.2$ (매우 큰 효과)

$d > 1.2$는 통계학에서 "매우 큰 효과"로 분류되며, 이는 MAS의 이점이 단순한 노이즈가 아니라 **실질적이고 의미 있는 차이**임을 확인해준다.

#### PlanCraft (좌하단)

가장 복잡한 스케일링 패턴을 보이며, 다른 벤치마크와는 질적으로 다르다:

- **Anthropic 모델(주황)**이 SAS에서는 가장 높은 성능(~60-78%)을 달성한다. 이는 Anthropic 모델이 순차적 추론에 특히 강함을 시사한다
- 그러나 MAS로 전환 시 가장 큰 성능 저하를 겪는다. **MAS 성능이 SAS보다 일관되게 낮다**
- 비조율 변형(Independent)에서는 -35.0%의 저하가 발생하며, 효과 크기는 $d \approx 0.35$로 비교적 작다. 이는 분산이 크기 때문이다
- 흥미롭게도, OpenAI(분홍)는 SAS에서의 성능이 상대적으로 낮지만, MAS로의 전환 시 성능 저하도 적다. 이는 OpenAI 모델의 조율 내성(coordination tolerance)이 높음을 시사한다

이 패턴은 "순차적 태스크에서는 가장 역량 있는 단일 에이전트가 최선"이라는 교훈을 명확히 전달한다.

#### Workbench (우하단)

비교적 안정적인 스케일링을 보이며, MAS의 효과가 미미하다:

- 세 제품군 모두에서 성능이 60-80% 범위에 수렴한다
- SAS와 MAS의 차이가 크지 않으며, Intelligence Index 증가에 따른 향상도 완만하다
- 이는 Workbench가 다양한 태스크 유형을 포함하고 있어, MAS의 장단점이 상쇄되기 때문으로 해석된다

Workbench의 이 "중립적" 결과는 실무적으로도 중요한 시사점을 가진다. 실제 에이전트 시스템이 처리하는 태스크가 **혼합적(mixed)**인 경우 ( 즉 분해 가능한 태스크와 순차적 태스크가 섞여 있는 경우 ) MAS의 기대 이점은 크지 않을 수 있다.

### 6. 비용-성능 트레이드오프

비용-성능 분석은 학술적 성능 비교를 넘어 **실무적 의사결정**에 직접적인 근거를 제공한다. MAS는 본질적으로 SAS보다 더 많은 API 호출을 필요로 하므로, 비용이 증가한다. 핵심 질문은 "이 추가 비용이 성능 향상으로 정당화되는가?"이다.

#### OpenAI: 일관된 MAS 우위

OpenAI 모델에서는 MAS(특히 Centralized, Hybrid)가 비용 증가에도 불구하고 일관된 성능 향상을 달성한다. 비용-성능 평면에서 MAS 포인트가 SAS 포인트의 **우상단**에 위치한다 ( 비용은 더 들지만 성능도 비례적으로 또는 그 이상으로 향상된다.

이는 OpenAI 모델이 **더 강한 통신 시너지(communication synergy)**를 가지고 있음을 시사한다. 에이전트 간 정보 교환이 효율적으로 이루어져, 추가 비용 대비 성능 이점이 유의미하다.

실무적 함의: OpenAI 모델 기반 에이전트 시스템에서는 MAS가 **비용 효율적**일 가능성이 높다. 특히 Centralized 아키텍처를 사용하면 비용 대비 최대의 성능 향상을 얻을 수 있다.

#### Google: 효율성 고원(Plateau)

Google 모델에서는 MAS가 소폭의 성능 향상을 보이지만, 비용 증가 대비 개선이 빠르게 포화(plateau)된다. 비용-성능 평면에서 MAS와 SAS 포인트가 거의 수평선 위에 위치한다 ) 비용은 더 들지만 성능은 비슷하다.

이는 **경량 조율(lightweight coordination)** 하에서 수확 체감이 발생함을 의미한다. Google 모델의 MAS는 "있으면 좋지만 없어도 크게 문제없는" 수준의 개선만 제공한다.

실무적 함의: Google 모델 기반 시스템에서는 비용 효율성 관점에서 **SAS가 더 합리적인 선택**일 수 있다. MAS를 도입하더라도 에이전트 수를 최소한(3개 이하)으로 유지하는 것이 바람직하다.

#### Anthropic: 높은 분산과 불안정성

Anthropic 모델에서는 MAS의 성능 분산이 높고, 때로는 SAS보다 저조한 성능을 보인다. 비용-성능 평면에서 MAS 포인트의 **오차 막대(error bar)**가 매우 크며, 일부는 SAS보다 좌하단에 위치한다 ( 비용은 더 들면서 성능은 더 낮다.

이는 조율 오버헤드(coordination overhead)에 대한 민감도가 높음을 반영한다. Anthropic 모델은 멀티 에이전트 환경에서 성능의 **예측 가능성(predictability)**이 낮다.

실무적 함의: Anthropic 모델 기반 시스템에서는 MAS 적용에 **신중해야** 한다. 특히 프로덕션 환경에서 성능의 안정성이 중요한 경우, SAS를 기본으로 하고 특정 태스크(높은 분해 가능성)에만 선별적으로 MAS를 적용하는 것이 합리적이다.

#### 제품군 의존적 스케일링 법칙

이 결과를 종합하면, 비용-성능 관계는 **제품군 의존적(family-dependent) 스케일링 법칙**을 따른다. 이는 기존의 모델 수준 스케일링 법칙에는 없는 새로운 차원이다.

동일한 MAS 아키텍처라도 사용하는 LLM에 따라 비용 효율성이 극적으로 달라지므로, 실무에서는 **모델 선택 → 아키텍처 선택** 순서의 최적화가 필요하다.

저자들은 이를 다음과 같이 요약한다:

> "The efficacy of multi-agent coordination is contingent on each model family's intrinsic communication bandwidth and reasoning alignment."

즉, 멀티 에이전트 조율의 효과는 각 모델 제품군의 **내재적 통신 대역폭**과 **추론 정합성**에 좌우된다.

## 주요 발견의 통합적 해석

### "스케일링 법칙"이란 무엇인가?

Kaplan et al. (2020)이 LLM의 파라미터 수, 데이터 양, 연산량과 성능 사이의 멱법칙(power law)을 발견한 이후, "스케일링 법칙"은 AI 연구의 핵심 개념이 되었다. 이 법칙은 놀라울 정도로 단순하고 보편적이다: $L(X) \propto X^{-\alpha}$ 형태의 관계가 수십 배의 스케일 범위에서도 일관되게 성립한다.

이 논문은 이 개념을 **에이전트 시스템**으로 확장하여, 에이전트 수, 모델 역량, 아키텍처 구조, 태스크 특성 사이의 스케일링 관계를 탐구한다.

그러나 LLM 자체의 스케일링 법칙과 달리, 에이전트 시스템의 스케일링은 **단순한 멱법칙을 따르지 않는다**. 대신 다음과 같은 **다차원적, 조건적 스케일링 관계**가 발견된다:

1. **태스크 의존성**: 동일 시스템이 태스크에 따라 +81%에서 -70%까지의 범위를 보임. 이 151%p의 범위는 어떤 단일 변수(모델 크기, 데이터 양 등)의 변화로는 관찰할 수 없는 극적인 차이이다
2. **모델 의존성**: 동일 아키텍처가 모델 제품군에 따라 정반대의 효과를 보일 수 있음. OpenAI에서 +8.7%인 것이 Anthropic에서 -4.6%
3. **비단조성(Non-monotonicity)**: 에이전트 수를 늘려도 성능이 단조 증가하지 않고 최적점을 가짐. 모델 수준 스케일링이 (현재까지) 단조 증가인 것과 대조적
4. **상호작용 효과**: 모델 역량 x 아키텍처 x 태스크의 3원 상호작용이 존재. 단순한 주효과(main effect) 분석으로는 포착할 수 없는 복잡한 패턴

이러한 복잡성은 에이전트 시스템 스케일링이 모델 수준 스케일링과 본질적으로 다른 문제임을 보여준다. 모델 수준에서는 "더 크면 더 좋다"가 (대략적으로) 성립하지만, 에이전트 시스템에서는 "상황에 따라 다르다"가 정답이다.

### 실무적 의사결정 프레임워크

이 논문의 결과를 실무에 적용하기 위한 의사결정 프레임워크를 정리하면 다음과 같다:

**Step 1: 태스크 구조 분석**

가장 먼저 해야 할 것은 대상 태스크의 분해 가능성을 평가하는 것이다:

- 태스크가 독립적 하위 태스크로 분해 가능한가? → MAS 적극 고려
- 태스크가 순차적이고 상태 의존적인가? → SAS 유지, MAS 비추천
- 부분적으로 분해 가능한가? → Centralized/Hybrid를 조심스럽게 시도

실용적인 판단 기준: "이 태스크를 인간 팀에게 맡긴다면, 팀원들이 독립적으로 작업할 수 있는가?" 답이 "예"이면 MAS가 유리할 가능성이 높고, "아니오"이면 SAS가 더 나을 가능성이 높다.

**Step 2: 모델 선택**

다음으로 사용할 LLM을 선택한다:

- OpenAI 모델: MAS로부터 가장 일관된 이점을 얻을 수 있음. MAS 도입을 적극 고려
- Google 모델: MAS 이점이 빠르게 포화되므로, 비용 대비 효과 분석이 필수. 소규모 MAS만 고려
- Anthropic 모델: MAS 적용에 신중해야 함. 특히 고역량 모델의 오케스트레이터 역할에 주의. SAS에서의 성능이 이미 높을 수 있음

**Step 3: 아키텍처 선택**

태스크와 모델이 결정되면 적절한 아키텍처를 선택한다:

- 분업이 명확한 태스크: **Centralized** (가장 안정적, 비용 효율적)
- 다양한 관점이 필요한 태스크: **Decentralized** 또는 **Hybrid**
- 독립적 검증이 중요한 태스크: **Independent** (앙상블 효과, 가장 단순)
- 분업 + 토론이 모두 필요한 태스크: **Hybrid** (최고 성능이지만 최고 비용)

**Step 4: 에이전트 수 최적화**

에이전트 수는 모델 역량과 태스크에 맞추어 결정한다:

- 고역량 모델 (GPT-5, Gemini 2.5 Pro, Sonnet 4.5): **3-5개**로 충분
- 저역량 모델 (GPT-5 nano, Gemini 2.0 Flash, Sonnet 3.7): **5-7개**까지 이점이 있을 수 있음
- 9개 이상: 대부분의 경우 수확 체감, 비용 대비 비효율. 특수한 경우에만 고려

**Step 5: 이질성 활용**

비용 최적화를 위해 에이전트 이질성을 활용한다:

- Centralized: **저비용 모델을 오케스트레이터로, 고비용 모델을 서브 에이전트로** 배치
- Decentralized: 혼합 역량 구성이 동질적 고성능보다 효율적일 수 있으므로 적극 활용
- 전체 에이전트에 최고 성능 모델을 사용하는 것이 최적이 아닐 수 있음을 기억

## 의의 및 한계

### 학술적 의의

1. **첫 번째 체계적 스케일링 연구**: 다수의 LLM 제품군, 벤치마크, 아키텍처를 동시에 고려한 최초의 대규모 비교 연구이다. 기존의 단편적 관찰들을 통합적 프레임워크 안에서 재해석할 수 있게 한다. 특히 3개 제품군 x 4개 벤치마크 x 5개 아키텍처의 60가지 조합을 체계적으로 분석한 것은 기존 연구에서 시도된 적이 없는 규모이다.

2. **태스크 의존성의 실증**: "멀티 에이전트가 항상 좋다" 또는 "항상 나쁘다"라는 극단적 주장이 모두 틀렸음을 보여주고, **태스크 분해 가능성**이 핵심 결정 요인임을 실증했다. Finance Agent(+81%)와 PlanCraft(-70%)의 극단적 대비는 이 점을 강력하게 뒷받침한다. 이 발견은 향후 에이전트 시스템 연구에서 "태스크 특성 분석"을 필수적 선행 단계로 정립하는 데 기여할 것이다.

3. **이질성의 가치 발견**: 동질적 고성능 구성이 최적이 아닐 수 있다는 반직관적 발견은, 향후 에이전트 시스템 설계의 패러다임을 바꿀 수 있는 중요한 결과이다. 특히 Decentralized에서 Mixed > All High인 결과는 "집단 지성"과 "인지적 다양성"에 대한 AI 시스템 수준의 실증적 근거를 제공한다.

4. **비용-성능 트레이드오프 정량화**: 학술 연구에서 흔히 간과되는 비용 측면을 명시적으로 분석하여, 실무적 의사결정에 직접 활용 가능한 결과를 제시했다. 이는 학술 연구와 산업 실무 사이의 간극을 좁히는 데 기여한다.

5. **제품군 의존적 스케일링 법칙**: 동일 아키텍처라도 모델 제품군에 따라 효과가 달라진다는 발견은, "보편적 에이전트 아키텍처"를 추구하는 대신 **모델-아키텍처 공동 최적화**가 필요함을 시사한다.

### 실무적 시사점

1. **만능 해결책은 없다**: 멀티 에이전트 시스템을 도입할 때, 대상 태스크의 구조를 먼저 분석해야 한다. 순차적이고 상태 의존적인 태스크에 MAS를 적용하면 오히려 성능이 저하될 수 있다. "MAS를 적용하면 무조건 좋아진다"는 마케팅적 주장에 현혹되지 말아야 한다.

2. **비용 효율적 설계**: 오케스트레이터에 가벼운 모델을, 서브 에이전트에 고성능 모델을 사용하는 이질적 구성이 비용 효율적일 수 있다. 모든 에이전트에 최고 성능 모델을 사용하는 것이 최선이 아닐 수 있다. 이는 특히 API 비용이 중요한 실무 환경에서 의미가 크다.

3. **에이전트 수의 sweet spot**: 무조건 많은 에이전트를 사용하는 것이 아니라, 모델 역량과 태스크에 맞는 최적 에이전트 수를 찾아야 한다. 대부분의 경우 3-7개 범위가 최적이며, 9개 이상은 거의 항상 비효율적이다.

4. **모델 선택이 아키텍처 선택에 선행**: 동일 아키텍처라도 모델 제품군에 따라 효과가 크게 달라지므로, 모델 선택 → 아키텍처 선택의 순서가 중요하다. 아키텍처를 먼저 고정하고 모델을 선택하는 것은 차선(suboptimal)일 수 있다.

### 한계

1. **벤치마크의 제한성**: 4개의 벤치마크만을 사용하여 일반적 결론을 도출하기에는 한계가 있다. 특히 코딩(SWE-bench), 과학 연구, 창의적 작문, 고객 서비스 등의 도메인은 포함되지 않았다. 코딩 태스크는 분해 가능성이 중간 수준이므로 흥미로운 결과가 나올 수 있었을 것이다.

2. **모델 세대의 제한**: 실험 당시의 모델(GPT-5, Gemini 2.5, Sonnet 4.5 등)만을 사용했으며, 향후 더 강력한 모델이 등장하면 스케일링 패턴이 달라질 수 있다. 특히 모델 자체가 에이전트 시스템에 최적화되면(agentic training), 현재의 결론이 수정될 가능성이 있다. OpenAI의 o3나 Anthropic의 extended thinking 모델처럼 추론 능력이 강화된 모델에서는 MAS의 효과가 달라질 수 있다.

3. **아키텍처 구현의 단순성**: 실험에 사용된 MAS 아키텍처는 비교적 표준적인 구현이다. 실제 프로덕션 시스템에서는 더 정교한 조율 메커니즘을 사용할 수 있다:
   - 동적 태스크 할당(dynamic task allocation): 진행 상황에 따라 하위 태스크를 재조정
   - 적응적 에이전트 수 조절(adaptive agent scaling): 필요에 따라 에이전트를 추가/제거
   - 실시간 피드백 루프(real-time feedback loop): 중간 결과를 바탕으로 전략을 수정
   - 메모리 공유(shared memory): 에이전트 간 상태 동기화

   이러한 고급 기법의 효과는 분석되지 않았으며, 이들이 PlanCraft 같은 순차적 태스크에서 MAS의 단점을 완화할 수 있는지는 미지수이다.

4. **정적 분석의 한계**: 에이전트 수와 구성을 사전에 고정하고 실험했으나, 실제 시스템에서는 런타임에 동적으로 에이전트를 추가/제거하는 것이 더 효과적일 수 있다. 예를 들어, 태스크의 복잡도를 먼저 평가한 후 적절한 에이전트 수를 결정하는 "메타 에이전트" 접근이 가능하다.

5. **다중 턴(multi-turn) 상호작용**: 실험이 주로 단일 태스크 완료에 초점을 맞추었으며, 장기간에 걸친 다중 턴 대화나 프로젝트 수준의 협업은 다루지 않았다. 실무에서는 에이전트 시스템이 수시간 또는 수일에 걸쳐 작업하는 경우가 있으며, 이런 장기 작업에서의 스케일링 패턴은 단기 태스크와 다를 수 있다.

6. **공정성과 편향**: 각 LLM 제품군의 API 호출 방식, 프롬프트 최적화 정도, 토큰 비용 구조가 다르므로, 완전히 공정한 비교가 어려울 수 있다. 특히 시스템 프롬프트의 구성이 MAS에서의 성능에 영향을 미칠 수 있으며, 이에 대한 민감도 분석은 수행되지 않았다.

## 관련 연구

### 멀티 에이전트 LLM 시스템

멀티 에이전트 LLM 시스템에 대한 연구는 빠르게 확장되고 있다. 주요 연구들을 살펴본다:

**CAMEL** (Li et al., 2023)은 역할 기반(role-playing) 프레임워크를 제안하여 두 에이전트 간의 자율적 협업을 탐구했다. "AI 사회(AI Society)" 시나리오에서 서로 다른 역할(예: 프로그래머와 디자이너)을 부여받은 두 에이전트가 태스크를 협력적으로 해결하는 방식이다. 이 연구는 멀티 에이전트 협업의 가능성을 최초로 입증했지만, 2-에이전트 시나리오에 국한되었다.

**MetaGPT** (Hong et al., 2024)는 소프트웨어 개발 프로세스를 다수의 전문화된 에이전트로 모델링했다. PM(Project Manager), 아키텍트, 개발자, QA 등의 역할을 가진 에이전트들이 실제 개발 워크플로우를 모방하여 협업한다. 이 연구는 **표준화된 출력 형식(Standardized Operating Procedures, SOPs)**을 도입하여 에이전트 간 통신의 효율을 높였다.

**AutoGen** (Wu et al., 2023)은 여러 에이전트 간의 대화를 프로그래밍 가능한 방식으로 조율하는 프레임워크를 제공한다. 특히 "대화형 에이전트(conversational agents)" 패러다임을 제시하여, 에이전트 간 상호작용을 코드로 정의할 수 있게 했다.

**CrewAI**는 역할, 목표, 도구를 가진 에이전트 팀의 협업을 간소화한 프레임워크이다. 실무 지향적 설계로 빠르게 인기를 얻었지만, 학술적 평가는 제한적이다.

**AgentBench** (Liu et al., 2023)는 LLM을 에이전트로 평가하기 위한 다차원 벤치마크를 제시했다. 8개의 환경(운영 체제, 데이터베이스, 웹 등)에서 LLM의 에이전트 역량을 체계적으로 평가했다.

그러나 이러한 프레임워크 연구들은 주로 **시스템 설계**에 초점을 맞추었으며, 스케일링 역학에 대한 체계적 분석은 수행하지 않았다. 본 논문은 이 공백을 메운다.

### LLM 스케일링 법칙

LLM의 스케일링 법칙은 **Kaplan et al. (2020)**에 의해 처음 체계적으로 연구되었다. 이들은 모델 파라미터 수, 학습 데이터 양, 연산량과 성능(크로스 엔트로피 손실) 사이의 멱법칙 관계를 발견했으며, 이 관계가 7자릿수의 스케일 범위에서도 일관되게 성립함을 보였다.

**Hoffmann et al. (2022, Chinchilla)**는 이를 정교화하여, 주어진 연산 예산에서 최적의 파라미터-데이터 비율을 제시했다. Chinchilla의 핵심 통찰은 "기존 모델들은 학습 데이터 대비 과도하게 크다"는 것이며, 동일 연산 예산으로 더 작지만 더 많은 데이터를 학습한 모델이 더 나은 성능을 보인다는 것이다.

**Clark et al. (2022)** 등은 스케일링 법칙을 다운스트림 태스크로 확장하여, 사전학습 손실과 벤치마크 성능 사이의 관계를 분석했다.

이 논문은 이러한 "모델 수준"의 스케일링 법칙을 "시스템 수준"으로 확장하려는 첫 번째 체계적 시도이며, 에이전트 수, 조율 구조, 태스크 특성이라는 새로운 스케일링 차원을 도입한다. 그러나 모델 수준의 스케일링처럼 깨끗한 멱법칙이 아니라, **조건적이고 다차원적인** 스케일링 관계가 발견된다는 점에서 질적으로 다른 종류의 "법칙"이다.

### 앙상블 및 자기 일관성(Self-Consistency)

멀티 에이전트의 Independent 아키텍처는 사실상 **앙상블** 기법의 에이전트 시스템 버전이다. 기계학습에서 앙상블은 다수의 약한 학습기(weak learner)를 결합하여 강한 학습기(strong learner)를 만드는 검증된 기법이다.

**Wang et al. (2023)**의 Self-Consistency는 동일 모델에서 여러 추론 경로를 샘플링하고 다수결로 최종 답을 선택하는 방법으로, 수학 추론(GSM8K, MATH) 등에서 일관된 성능 향상을 보였다. 이는 Independent MAS와 매우 유사한 원리이다.

그러나 중요한 차이점이 있다. Self-Consistency는 **동일 모델에서 온도(temperature)를 높여** 다양한 샘플을 생성하는 반면, Independent MAS는 **별도의 에이전트 인스턴스**를 사용한다. 전자는 확률적 다양성(stochastic diversity)에 의존하고, 후자는 에이전트별 맥락과 프롬프트의 차이에서 다양성을 얻을 수 있다.

이 논문은 Independent 아키텍처가 Self-Consistency와 유사한 원리로 작동하지만, 에이전트 시스템의 맥락에서는 **조율된 아키텍처(Centralized, Hybrid)**가 더 효율적일 수 있음을 보여준다. 이는 단순한 다수결보다 체계적 분업과 토론이 더 큰 가치를 제공함을 의미한다.

### 인간 조직 이론과의 연결

이 논문의 에이전트 아키텍처 분류는 인간 조직 이론과 흥미로운 유사성을 가진다:

| 에이전트 아키텍처 | 인간 조직 모델 | 특성 |
|----------------|--------------|------|
| Centralized | 위계적 조직(Hierarchical) | 관리자가 업무 분배, 부하 직원이 수행 |
| Decentralized | 자율 팀(Autonomous Team) | 동등한 구성원들의 토론과 합의 |
| Independent | 독립 컨설턴트 그룹 | 각자 독립 작업 후 결과 종합 |
| Hybrid | 매트릭스 조직(Matrix) | 위계적 분업 + 수평적 협의 |

조직 이론에서도 인력 스케일링의 한계는 잘 알려져 있다:

- **Brooks의 법칙**: "Adding manpower to a late software project makes it later." 통신 오버헤드가 $O(n^2)$로 증가하기 때문이다
- **Ringelmann 효과(사회적 태만)**: 팀 크기가 커질수록 개인의 기여가 줄어드는 현상
- **그룹씽크(Groupthink)**: 동질적 그룹에서 비판적 사고가 억제되는 현상

이 논문의 결과는 이러한 조직 이론적 직관이 LLM 에이전트 시스템에서도 유효함을 실증한다. 특히 에이전트 수 증가에 따른 수확 체감(Figure 5)은 Brooks의 법칙의 직접적 증거이며, 혼합 역량 구성의 우위(Figure 4)는 인지적 다양성의 가치와 그룹씽크 회피를 연상시킨다.

## 결론

"Towards a Science of Scaling Agent Systems"는 LLM 기반 멀티 에이전트 시스템의 스케일링을 과학적으로 분석한 선구적 연구이다. 3개 LLM 제품군, 4개 벤치마크, 5개 아키텍처에 걸친 대규모 실험을 통해 도출된 핵심 메시지는 명확하다:

> **멀티 에이전트 시스템의 효과는 보편적이지 않다.** 태스크의 분해 가능성, 모델의 내재적 특성, 조율 아키텍처, 에이전트 수의 복합적 상호작용에 의해 결정되며, 이를 이해하지 않고 단순히 "더 많은 에이전트"를 투입하는 것은 비용 낭비일 뿐 아니라 성능 저하를 초래할 수 있다.

이 연구의 5대 핵심 발견을 다시 정리하면:

1. **태스크 분해 가능성이 MAS 효과의 결정적 요인**이다. 병렬 분해 가능한 태스크(Finance Agent)에서는 +81%까지 향상되지만, 순차적 태스크(PlanCraft)에서는 -70%까지 저하된다.

2. **Centralized와 Hybrid 아키텍처가 가장 안정적인 스케일링**을 보인다. 체계적 분업이 비구조적 협업보다 효율적이다.

3. **에이전트 이질성이 동질적 고성능 구성보다 우수할 수 있다.** 특히 Decentralized 아키텍처에서 혼합 역량 구성이 모든 고역량 구성을 27%까지 앞선다.

4. **최적 에이전트 수는 유한하다.** 저역량 모델은 5-7개, 고역량 모델은 3-5개가 대체적 최적이며, 9개 이상은 거의 항상 비효율적이다.

5. **비용-성능 트레이드오프는 모델 제품군에 의존한다.** OpenAI에서는 MAS가 비용 효율적이지만, Anthropic에서는 불안정하다.

이 연구가 제시하는 프레임워크 ) Intelligence Scaling, Agent Scaling, 태스크 분해 가능성, 비용-성능 트레이드오프, 이질성 효과, 는 향후 에이전트 시스템 연구와 실무 설계의 기초가 될 것이다.

향후 연구 방향으로는 (1) 더 많은 벤치마크와 도메인으로의 확장, (2) 동적 에이전트 수 조절 메커니즘의 개발, (3) 에이전트 시스템에 최적화된 모델 학습(agentic training), (4) 장기 프로젝트에서의 스케일링 분석 등이 중요할 것이다.

특히 실무자의 관점에서, 이 논문은 "어떤 태스크에 멀티 에이전트를 적용할 것인가?", "몇 개의 에이전트를 사용할 것인가?", "어떤 아키텍처를 선택할 것인가?", "비용은 정당화되는가?"라는 질문에 대해 **데이터 기반의 답**을 제공한다.

에이전트 시스템이 빠르게 실무에 도입되는 2025년 현재, 이러한 과학적 근거에 기반한 설계 원칙의 중요성은 더욱 커질 것이다. "더 많은 에이전트가 항상 더 나은가?"라는 질문에 대한 이 논문의 대답은 단호하다: **"아니다. 상황에 따라 다르며, 그 '상황'을 이해하는 것이 바로 에이전트 시스템 스케일링의 과학이다."**
