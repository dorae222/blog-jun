# Scaling LLM Test-Time Compute: 테스트 시점 연산 스케일링

## 논문 개요

:::info
**Paper:** Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters (arXiv:2408.03314, 2024)
**저자:** Charlie Snell, Jaehoon Lee, Kelvin Xu, Aviral Kumar
**소속:** UC Berkeley, Google DeepMind
**키워드:** Test-Time Compute, Compute-Optimal Scaling, Search vs Revision, Process Reward Model
:::

LLM의 성능을 향상시키는 전통적인 방법은 **모델 크기를 키우는 것**이다. 더 많은 파라미터, 더 많은 학습 데이터, 더 많은 학습 연산 ( 이른바 **학습 시점 스케일링(train-time scaling)**이다. 그러나 이 논문은 근본적으로 다른 질문을 던진다: **테스트 시점에 더 많은 연산을 투입하면, 모델 크기를 키우는 것과 동등하거나 더 나은 결과를 얻을 수 있는가?**

답은 놀랍게도 **"그렇다"**이다. 적절한 전략으로 테스트 시점 연산을 스케일링하면, 모델 파라미터를 **14배 이상** 늘리는 것과 동등한 성능 향상을 달성할 수 있다. 이 발견은 "더 큰 모델을 학습시키는 것"에서 "같은 모델로 더 많이 생각하게 하는 것"으로의 패러다임 전환을 시사한다.

---

## 배경: 학습 시점 vs 테스트 시점 스케일링

### 기존 스케일링 법칙

LLM 스케일링 법칙 연구들은 학습 시점 연산에 초점을 맞춰왔다:

- **Kaplan et al. (2020)**: 모델 크기, 데이터 크기, 연산량의 관계를 멱법칙으로 정리
- **Chinchilla (Hoffmann et al., 2022)**: 주어진 연산 예산에서 모델 크기와 데이터 크기의 최적 비율

이 연구들의 공통 가정은 **추론은 비용이 무시할 수 있는 수준**이라는 것이다. 그러나 LLM이 점점 더 어려운 문제를 풀어야 하는 상황에서, 추론 시점에 더 많은 연산을 투입하는 것은 충분히 합리적인 전략이다.

### 인간의 사고 과정과의 유추

인간도 쉬운 문제에는 즉각적으로 답하지만, 어려운 문제에는 더 오래 생각한다. 시험 문제를 풀 때:

- **쉬운 문제**: 즉시 답 작성 (System 1 사고)
- **어려운 문제**: 여러 접근법 시도, 풀이 검토, 수정 반복 (System 2 사고)

테스트 시점 연산 스케일링은 LLM에게 이러한 **"더 오래 생각하는" 능력**을 부여하는 것이다.

### 테스트 시점 연산의 두 가지 축

본 논문은 테스트 시점 연산을 활용하는 두 가지 근본적으로 다른 전략을 분석한다:

1. **검색 기반 (Search-based)**: 여러 풀이를 병렬로 생성하고, 검증기로 최선을 선택
2. **수정 기반 (Revision-based)**: 하나의 풀이를 반복적으로 수정하여 개선

:::info
이 구분은 이전의 [[lets-verify]] 논문에서 제시된 PRM(Process Reward Model)의 활용 방식과 직접적으로 연결된다. PRM은 검색 기반 전략에서 검증기로 사용되며, 수정 기반 전략에서는 수정 방향을 안내하는 역할을 한다.
:::

## 핵심 아이디어: Compute-Optimal 테스트 시점 스케일링

### 연산 예산의 최적 분배

핵심 질문: 테스트 시점에 $C$ FLOPs의 연산 예산이 있을 때, 이를 어떻게 분배해야 최적인가?

이 논문의 핵심 기여는 이 질문에 대한 **분석적 프레임워크**를 제공하는 것이다.

연산 예산 $C$를 다음과 같이 분해할 수 있다:

$$C = N \times c_{\text{gen}} + c_{\text{verify}}$$

여기서:
- $N$: 생성하는 풀이의 수
- $c_{\text{gen}}$: 풀이 하나를 생성하는 연산량
- $c_{\text{verify}}$: 검증에 사용되는 연산량

최적의 $N$은 문제의 난이도, 모델의 능력, 검증기의 정확도에 따라 달라진다.

### 검색 기반 전략

검색 기반 전략의 변형들:

#### Best-of-N 샘플링

가장 단순한 형태:
1. $N$개의 독립적인 풀이 생성
2. PRM으로 각 풀이 점수 부여
3. 최고 점수 풀이 선택

연산량: $C = N \times c_{\text{gen}} + N \times c_{\text{PRM}}$

#### 빔 탐색 (Beam Search)

PRM 가이드 하에 단계별 탐색:
1. 각 단계에서 여러 연속(continuation)을 생성
2. PRM으로 각 연속의 점수 부여
3. 상위 $k$개만 유지하고 다음 단계로 진행

연산량이 같아도 best-of-N보다 더 세밀한 탐색이 가능하다.

#### 트리 탐색 (Tree Search)

더 체계적인 탐색:
1. 풀이를 트리 구조로 전개
2. 각 노드(단계)에서 PRM 점수를 기반으로 탐색 방향 결정
3. 유망하지 않은 경로를 조기에 중단(pruning)

```
문제
├── 단계1-a (PRM: 0.9) ← 탐색 계속
│   ├── 단계2-a (PRM: 0.8) ← 탐색 계속
│   └── 단계2-b (PRM: 0.3) ← 중단
├── 단계1-b (PRM: 0.7) ← 탐색 계속
│   └── 단계2-c (PRM: 0.6) ← 탐색 계속
└── 단계1-c (PRM: 0.2) ← 중단
```

### 수정 기반 전략

수정 기반 전략은 순차적 개선을 수행한다:

1. 초기 풀이 생성
2. 풀이를 모델에게 다시 보여주고 수정 요청
3. 수정된 풀이를 다시 수정 (반복)

이 전략의 핵심 장점: **이전 시도의 정보를 활용**할 수 있다. 검색 기반이 독립적인 풀이를 생성하는 반면, 수정 기반은 이전 풀이의 실패 원인을 학습하여 점진적으로 개선한다.

그러나 한계도 명확하다:
- 초기 풀이가 근본적으로 잘못된 방향이면 수정으로 벗어나기 어려움
- 수정 횟수가 많아져도 성능 향상이 포화되는 경향

## 실험 설계

### 벤치마크

MATH 벤치마크를 사용하여 실험을 수행했다. 각 문제에 대해:

- 다양한 연산 예산 ($C$)에서의 정확도 측정
- 같은 연산 예산으로 더 큰 모델을 실행하는 것과 비교
- 문제 난이도별 분석

### 모델 구성

- **생성기**: PaLM 2 계열 모델 (Small, Medium, Large)
- **검증기(PRM)**: 별도 학습된 프로세스 보상 모델
- **비교 기준**: 같은 연산 예산으로 한 번만 추론하는 더 큰 모델

### 연산 예산 정규화

공정한 비교를 위해, 모든 전략의 연산량을 **기본 모델의 단일 추론 FLOPs**로 정규화:

$$\text{Compute Multiplier} = \frac{C}{c_{\text{base}}}$$

예를 들어, Compute Multiplier = 10이면 기본 모델의 10배 연산을 테스트 시점에 사용하는 것이다.

## 실험 결과

### 핵심 결과: 테스트 시점 연산의 효과

#### Compute Multiplier에 따른 정확도 향상

| Compute Multiplier | Best-of-N | Beam Search | 수정 기반 | Compute-Optimal |
|-------------------|-----------|-------------|----------|----------------|
| 1x | 33.0% | 33.0% | 33.0% | 33.0% |
| 4x | 39.2% | 41.5% | 36.8% | 42.3% |
| 16x | 48.1% | 52.7% | 42.4% | 54.1% |
| 64x | 55.3% | 61.4% | 47.2% | 63.8% |
| 256x | 60.7% | 67.3% | 50.1% | 70.2% |

핵심 관찰:

1. **빔 탐색이 best-of-N을 일관되게 능가**: 단계별 PRM 가이드가 효과적
2. **수정 기반은 빠르게 포화**: 일정 수준 이후 추가 수정이 큰 개선을 가져오지 않음
3. **Compute-Optimal 전략이 가장 효과적**: 문제 난이도에 따라 전략을 동적으로 선택

#### 모델 크기 스케일링과의 비교

가장 충격적인 결과:

| 설정 | MATH 정확도 |
|------|------------|
| PaLM 2-S (1x) | 33.0% |
| PaLM 2-S (64x compute-optimal) | 63.8% |
| PaLM 2-L (1x, ~14x 파라미터) | 62.5% |

:::tip
Small 모델에 64배의 테스트 시점 연산을 투입하면, 14배 큰 Large 모델의 단일 추론 성능을 능가한다. 이는 "더 작은 모델을 더 오래 생각하게 하는 것"이 "더 큰 모델을 한 번 실행하는 것"보다 효율적일 수 있음을 보여주는 획기적인 결과이다.
:::

### 난이도별 최적 전략

문제 난이도에 따라 최적의 연산 분배 전략이 달라진다:

| 난이도 | 최적 전략 | 이유 |
|--------|----------|------|
| 쉬움 (Level 1-2) | 적은 N, 수정 불필요 | 대부분 첫 시도에 정답 |
| 중간 (Level 3) | 적당한 N, 빔 탐색 | 다양한 접근법 탐색이 도움 |
| 어려움 (Level 4-5) | 큰 N, 빔 탐색 + 수정 | 모든 전략을 결합해야 효과적 |

이 결과는 **적응적 연산 분배(adaptive compute allocation)**의 필요성을 시사한다:

1. 문제의 난이도를 먼저 추정
2. 난이도에 따라 최적의 전략과 연산 예산 결정
3. 쉬운 문제에는 적은 연산, 어려운 문제에는 많은 연산 투입

### PRM 품질의 영향

PRM의 품질이 테스트 시점 스케일링의 효과에 결정적이다:

| PRM 정확도 | Best-of-100 정확도 | Beam Search 정확도 |
|-----------|-------------------|-------------------|
| 60% | 42.1% | 44.5% |
| 70% | 48.3% | 53.2% |
| 80% | 54.8% | 61.4% |
| 90% | 59.2% | 67.8% |
| Oracle | 72.4% | 78.3% |

PRM이 정확할수록 테스트 시점 연산의 효과가 극대화된다. 이는 **PRM의 개선이 테스트 시점 스케일링 효과의 핵심 병목**임을 보여준다.

:::warning
PRM의 정확도가 낮으면, 더 많은 연산을 투입해도 성능 향상이 제한적이다. 극단적으로 PRM이 무작위 수준이면, best-of-N은 majority voting과 동등해진다. [[lets-verify]]에서 제시한 PRM의 품질이 여기서 직접적으로 중요해진다.
:::

## 검색 vs 수정의 트레이드오프

### 검색 기반의 장단점

**장점:**
- 독립적 풀이 생성으로 **다양성 확보**
- 병렬화 가능 (여러 GPU에서 동시 생성)
- PRM 품질이 좋으면 매우 효과적

**단점:**
- 이전 시도의 정보를 활용하지 않음 (각 풀이가 독립)
- 풀이 수에 비례하는 연산 비용
- PRM에 대한 의존도가 높음

### 수정 기반의 장단점

**장점:**
- 이전 시도에서 학습하여 **점진적 개선**
- 초기 풀이가 부분적으로 맞으면 효율적
- PRM 없이도 가능 (모델 자체의 자기 수정)

**단점:**
- **포화(saturation)**: 수정 횟수가 많아져도 개선이 제한적
- 순차적 실행으로 **병렬화 불가**
- 초기 방향이 잘못되면 빠져나오기 어려움

### Compute-Optimal 전략

논문이 제시하는 최적 전략은 두 접근법을 **적응적으로 결합**하는 것이다:

1. **난이도 추정**: 문제에 대한 모델의 불확실성을 초기 샘플링으로 추정
2. **전략 선택**:
   - 쉬운 문제: 적은 수의 독립 풀이 + 수정 없음
   - 중간 문제: 빔 탐색으로 효율적 탐색
   - 어려운 문제: 넓은 빔 탐색 + 유망한 풀이 수정
3. **조기 종료**: 충분히 높은 PRM 점수의 풀이가 나오면 즉시 종료

## 이론적 분석

### 왜 검색이 수정보다 스케일링에 유리한가

검색 기반 전략이 수정 기반보다 스케일링에 유리한 이유를 분석적으로 설명할 수 있다.

$N$개의 독립적인 풀이 중 적어도 하나가 정답일 확률:

$$P(\text{correct} | N) = 1 - (1 - p)^N$$

여기서 $p$는 단일 풀이의 정답 확률이다. $N$이 증가하면 이 확률은 1에 수렴한다.

반면, 수정 기반에서 $T$번 수정 후의 정답 확률은:

$$P(\text{correct} | T) = p + (1-p) \cdot r + (1-p)(1-r) \cdot r + ... \approx p + r \cdot (1-p) \cdot \frac{1 - (1-r)^{T-1}}{r}$$

여기서 $r$은 한 번의 수정으로 틀린 풀이를 맞게 바꿀 확률이다. $T$가 커져도 이 확률은 $p + r(1-p)/(1-(1-r))$으로 수렴하며, 1에 도달하지 않는다.

### Verifier의 역할에 대한 분석

검증기의 정확도를 $v$라 하면, best-of-N에서 올바른 풀이를 선택할 확률:

$$P(\text{select correct}) = \frac{v \cdot k}{v \cdot k + (1-v) \cdot (N-k)}$$

여기서 $k$는 $N$개 풀이 중 정답인 것의 수이다. $v$가 높을수록 정답 풀이가 선택될 확률이 높아지며, $v = 1$ (완벽한 검증기)이면 하나라도 정답 풀이가 있으면 반드시 그것을 선택한다.

이 분석은 **PRM의 품질이 검색 기반 스케일링의 효율성을 결정**한다는 실험 결과를 이론적으로 뒷받침한다.

## 실용적 시사점

### 추론 비용 최적화

테스트 시점 연산 스케일링의 실용적 가치는 **비용 효율성**에 있다:

| 전략 | 학습 비용 | 추론 비용/질문 | 총 비용 (100만 질문) |
|------|----------|-------------|-------------------|
| 대형 모델 학습 | $10M | $0.10 | $10.1M |
| 소형 모델 + TTC 스케일링 | $1M | $0.50 | $1.5M |

소형 모델 + 테스트 시점 연산 스케일링이 총 비용 면에서 훨씬 효율적일 수 있다. 특히 학습 비용은 일회성이지만 매우 높고, 추론 비용은 반복적이지만 상대적으로 낮다.

### 적응적 연산 분배의 실용성

모든 질문에 동일한 연산을 투입하는 것은 비효율적이다. 적응적 분배를 통해:

- **쉬운 질문 (70%)**: 1x 연산 → 빠른 응답
- **중간 질문 (20%)**: 10x 연산 → 약간 느리지만 정확한 응답
- **어려운 질문 (10%)**: 100x 연산 → 충분한 시간을 들여 정확한 응답

평균 연산은 ~13x로, 모든 질문에 100x를 투입하는 것보다 7배 이상 효율적이다.

### 실시간 vs 비실시간 사용 사례

| 사용 사례 | 지연 허용 | 권장 전략 |
|----------|---------|----------|

## OpenAI o1/o3 모델과의 관계

### 테스트 시점 연산의 상용화

OpenAI의 o1 (2024.09), o3 (2024.12) 모델은 본 논문의 아이디어를 실제 상용 제품에 적용한 것으로 추정된다:

- **긴 체인 오브 소트**: 모델이 답을 내기 전에 내부적으로 긴 추론 체인을 생성
- **적응적 연산**: 어려운 문제에 더 많은 "생각" 시간 투입
- **내부 검증**: 추론 과정에서 자체적인 검증과 수정 수행

o3의 ARC-AGI 벤치마크 결과는 이 접근법의 잠재력을 극적으로 보여준다 ) 낮은 연산 설정에서도 인간 수준의 성능을, 높은 연산 설정에서는 인간을 능가하는 성능을 달성했다.

### 학습 시점 + 테스트 시점의 결합

미래의 LLM 스케일링은 학습 시점과 테스트 시점을 **결합하여 최적화**하는 방향으로 발전할 것이다:

$$\text{Total Compute} = C_{\text{train}} + \mathbb{E}[C_{\text{test}}]$$

주어진 총 연산 예산에서, 학습에 더 투자할지 테스트 시점에 더 투자할지의 최적 비율을 결정하는 것이 핵심 과제가 된다.

## 한계와 후속 연구 방향

### 연구의 한계

1. **MATH 벤치마크 한정**: 수학 추론에 특화된 결과이며, 다른 도메인에서의 일반화는 검증 필요
2. **PRM 의존성**: 검색 기반 전략의 효과가 PRM 품질에 크게 의존
3. **지연 시간**: 더 많은 연산 = 더 긴 응답 시간, 실시간 애플리케이션에서의 제약
4. **단일 모델 크기 실험**: 다양한 모델 크기에서의 체계적 비교 부족
5. **비용 분석의 단순화**: GPU 유형, 배치 처리, 메모리 제약 등 실제 환경의 복잡성 미반영

### 후속 연구 방향

1. **자동 난이도 추정**: 질문의 난이도를 효율적으로 예측하여 연산 분배 최적화
2. **학습-추론 결합 최적화**: 학습 시점과 테스트 시점 연산의 최적 비율 결정
3. **효율적 PRM 학습**: PRM800K 규모의 데이터 없이도 효과적인 PRM 학습
4. **다중 도메인 확장**: 수학 외 코딩, 과학적 추론, 상식 추론 등으로 확장
5. **하드웨어 최적화**: 테스트 시점 탐색을 위한 전용 하드웨어/소프트웨어 설계

## 결론

"Scaling LLM Test-Time Compute"는 LLM 연구에서 **패러다임 전환**을 제시한 중요한 논문이다. "더 큰 모델을 학습시키는 것"에서 "같은 모델로 더 많이 생각하게 하는 것"으로의 전환은, 연산 자원의 활용 방식에 대한 근본적인 재고를 요구한다.

핵심 발견 ( 적절한 전략으로 테스트 시점 연산을 스케일링하면 모델 파라미터를 14배 이상 늘리는 것과 동등한 효과를 얻을 수 있다 ) 은 이론적으로도, 실용적으로도 깊은 시사점을 가진다.

이 연구는 [[lets-verify]]에서 제시된 PRM의 실용적 가치를 더욱 확고히 했으며, OpenAI의 o1/o3 모델로 이어지는 "추론 시점 스케일링" 트렌드의 이론적 기반을 제공했다. [[test-time-compute-scaling]]은 앞으로 LLM 연구의 핵심 키워드가 될 것이며, 학습 시점 스케일링과의 최적 결합은 다음 세대 AI 시스템의 핵심 설계 원칙이 될 것이다.
