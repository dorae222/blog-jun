## 개요

"ReAct: Synergizing Reasoning and Acting in Language Models" (Yao et al., 2023)는 Princeton 대학교의 Shunyu Yao와 Google Research의 공동 연구로 ICLR 2023에서 발표된 논문입니다. 이 연구는 현대 LLM 에이전트의 가장 핵심적인 패러다임인 **ReAct(Reasoning + Acting)**를 제안합니다.

핵심 아이디어는 언어 모델이 **추론 트레이스(Thought)와 태스크별 행동(Action)을 교대로 생성**하도록 하는 것입니다. 기존에는 추론(Chain-of-Thought)과 행동(tool use/API call)이 분리된 별개의 접근법이었지만, ReAct는 이 둘을 유기적으로 결합합니다. 추론은 행동 계획을 수립하고 결과를 해석하는 데 활용되며, 행동의 결과(관찰)는 다음 추론의 근거가 됩니다.

![4가지 프롬프팅 방법의 비교 — Standard, CoT(Reason Only), Act-only, ReAct(Reason+Act)로 HotPotQA와 AlfWorld 태스크를 해결하는 과정](figures/fig_1.png)

*Figure 1: 4가지 프롬프팅 방법의 비교. (1) HotPotQA: (a) Standard는 바로 답을 출력, (b) CoT는 추론만 수행, (c) Act-only는 검색 행동만 수행, (d) ReAct는 추론과 행동을 교대로 수행하여 정확한 답에 도달. (2) AlfWorld: (a) Act-only는 환각으로 실패, (b) ReAct는 추론으로 행동을 안내하여 성공. (Yao et al., 2023)*

이 논문은 현대 LLM 에이전트 연구의 기초를 놓은 가장 영향력 있는 논문 중 하나입니다. LangChain, LlamaIndex, AutoGPT 등 실무에서 널리 사용되는 에이전트 프레임워크들이 모두 ReAct 패턴을 핵심으로 채택하고 있으며, 이후 [[reflexion]], Toolformer, LATS 등 수백 편의 후속 연구를 촉발했습니다.

## 배경 및 동기

### 추론과 행동의 분리 문제

2022년 시점에서, LLM의 추론(reasoning)과 행동(acting)은 별개의 연구 흐름으로 발전해 왔습니다.

**추론 연구 계열**: [[chain-of-thought]] (Wei et al., 2022), [[self-consistency]] (Wang et al., 2023), Zero-shot CoT (Kojima et al., 2022) 등은 LLM이 중간 추론 과정을 생성하여 최종 답의 정확도를 높이는 데 집중했습니다. 하지만 이 접근법은 **모델의 내부 지식에만 의존**하므로, 지식이 부정확하거나 최신이 아닌 경우에 취약합니다.

**행동 연구 계열**: WebGPT (Nakano et al., 2021), SayCan (Ahn et al., 2022), Inner Monologue (Huang et al., 2022) 등은 LLM이 외부 도구(검색 엔진, API, 물리적 액추에이터)를 사용하여 환경과 상호작용하는 데 집중했습니다. 하지만 이 접근법은 행동의 **계획과 해석에 대한 명시적 추론이 부족**하여, 복잡한 태스크에서 비효율적이거나 환각에 빠지기 쉽습니다.

### 왜 추론과 행동을 결합해야 하는가?

인간의 인지 과정을 관찰하면, 추론과 행동은 밀접하게 연결되어 있습니다. 요리 레시피를 따라할 때, 우리는 다음과 같이 사고합니다.

> "지금 양파를 볶아야 하는데(추론), 프라이팬에 기름을 두르고(행동), 기름이 달궈진 것을 확인한 뒤(관찰), 양파를 넣어야겠다(추론)"

이처럼 추론은 행동을 **계획하고 안내**하며, 행동의 결과는 추론의 **근거와 수정 기회**를 제공합니다. ReAct는 이 자연스러운 인지 패턴을 LLM에 구현합니다.

### 구체적 문제 사례

ReAct의 필요성을 보여주는 구체적 사례를 살펴보겠습니다.

**질문**: "Apple Remote는 원래 어떤 프로그램과 상호작용하도록 설계되었으며, 그 프로그램을 제어할 수 있는 다른 장치는 무엇인가?"

- **CoT (Reason Only)**: 모델의 내부 지식에만 의존하여 "iPod"이라고 답하지만, 이는 부정확합니다. 외부 검색 없이는 "Front Row" 소프트웨어와 그 후속 정보를 정확히 알기 어렵습니다.
- **Act Only**: Search[Apple Remote] → 결과를 받아 → Search[Front Row] → 하지만 결과 해석 없이 답을 찾지 못하거나 잘못된 정보를 선택합니다.
- **ReAct**: Thought 1: "Apple Remote와 Front Row media center를 검색해야 한다" → Act 1: Search[Apple Remote] → Obs 1: 정보 수신 → Thought 2: "Front Row는 단종된 미디어 센터 소프트웨어다. 키보드 기능키로도 제어할 수 있다" → Act 2: Finish[keyboard function keys] → 정답

## 핵심 아이디어

### ReAct의 Thought-Action-Observation 루프

ReAct의 핵심은 **Thought-Action-Observation (TAO)** 루프입니다. 매 스텝에서 모델은 다음을 교대로 생성합니다.

**Thought (추론 트레이스)**: 현재 상황을 분석하고, 다음 행동을 계획하며, 이전 관찰을 해석합니다. Thought는 모델의 내부 추론 과정을 자연어로 외부화한 것입니다.

**Action (행동)**: 외부 환경과 상호작용하는 구체적 행동입니다. 태스크에 따라 다른 행동 공간을 갖습니다.
- 지식 탐색 태스크: `Search[query]`, `Lookup[keyword]`, `Finish[answer]`
- 인터랙티브 환경: `go to shelf 1`, `take lamp from shelf 1`, `put lamp in/on desk 1`

**Observation (관찰)**: 환경이 행동에 대해 반환하는 피드백입니다. 검색 결과, 환경 상태 변화 등이 해당합니다. 관찰은 모델이 생성하는 것이 아니라 **환경이 제공**합니다.

형식적으로, ReAct는 다음과 같은 교대 시퀀스를 생성합니다.

$$t_1, a_1, o_1, t_2, a_2, o_2, \ldots, t_n, a_n, o_n$$

여기서 $t_i$는 Thought, $a_i$는 Action, $o_i$는 Observation입니다.

### Thought의 역할

논문에서는 Thought가 수행하는 역할을 세 가지로 분류합니다.

**1. 태스크 분해(Task Decomposition)**: 복잡한 질문을 하위 질문으로 분해합니다.
> "이 질문에 답하려면 먼저 X를 알아야 하고, 그 다음 Y를 찾아야 한다"

**2. 정보 추출(Information Extraction)**: 관찰에서 태스크 관련 정보를 추출합니다.
> "검색 결과에 따르면, Front Row는 2005년에 출시된 미디어 센터 소프트웨어이다"

**3. 행동 계획 및 수정(Action Planning & Revision)**: 다음 행동을 계획하거나, 이전 행동의 결과에 따라 전략을 수정합니다.
> "Front Row를 검색했지만 찾을 수 없었다. 'Front Row software'로 다시 검색해보자"

:::info
ReAct의 핵심 강점은 Thought가 모델의 추론 과정을 **투명하게 드러내어** 인간이 모델의 행동 이유를 이해하고 개입할 수 있게 한다는 점입니다. 이는 블랙박스 에이전트와의 결정적 차이점입니다.
:::

### 프롬프트 구조

ReAct는 Few-shot 프롬프팅을 사용합니다. 프롬프트에 1~6개의 예시를 포함하며, 각 예시는 완전한 TAO 시퀀스를 보여줍니다.

```
Question: ...
Thought 1: ...
Action 1: Search[...]
Observation 1: ...
Thought 2: ...
Action 2: Lookup[...]
Observation 2: ...
Thought 3: ...
Action 3: Finish[answer]
```

이 예시를 통해 모델은 Thought와 Action을 교대로 생성하는 패턴을 학습합니다.

## 실험 결과

### 지식 집약적 추론 태스크

#### HotPotQA

HotPotQA는 두 개의 위키피디아 문서에 걸친 다단계 추론이 필요한 질의응답 벤치마크입니다.

| 방법 | EM (Exact Match) | F1 |
|------|-----------------|-----|
| Standard (PaLM-540B) | 25.7 | 33.0 |
| CoT (PaLM-540B) | 29.4 | 37.1 |
| Act Only (PaLM-540B) | 25.7 | 34.2 |
| **ReAct (PaLM-540B)** | **27.4** | **38.3** |
| CoT-SC (PaLM-540B, k=21) | 29.4 | 38.7 |
| **ReAct + CoT-SC** | **35.1** | **42.1** |

ReAct 단독으로도 Act-only를 크게 능가하며, CoT-SC와 결합하면 최고 성능을 달성합니다. 특히 중요한 점은 ReAct가 **환각(hallucination)을 크게 줄인다**는 것입니다. CoT는 내부 지식에만 의존하므로 사실과 다른 추론 체인을 생성할 위험이 높지만, ReAct는 외부 검색을 통해 사실을 확인하므로 이 위험이 완화됩니다.

#### FEVER (Fact Verification)

| 방법 | 정확도 |
|------|--------|
| Standard | 57.1 |
| CoT | 56.3 |
| Act Only | 58.9 |
| **ReAct** | **60.9** |

FEVER는 주장의 사실 여부를 검증하는 태스크로, 외부 지식 접근이 특히 중요합니다. ReAct는 추론으로 검증 전략을 수립하고 행동으로 증거를 수집하여, 다른 방법들을 일관적으로 능가합니다.

#### 오류 유형 분석

논문에서는 ReAct와 CoT의 오류 유형을 상세히 분석합니다.

**CoT의 주요 오류**: 환각(hallucination)이 전체 오류의 약 **56%**를 차지합니다. 모델이 존재하지 않는 사실을 만들어내거나, 부정확한 내부 지식에 기반한 추론을 합니다.

**ReAct의 주요 오류**: 검색 실패(search failure)가 약 **23%**, 추론 오류가 약 **47%**를 차지합니다. 환각은 크게 줄지만, 검색 결과에서 관련 정보를 찾지 못하는 경우가 새로운 오류 원인이 됩니다.

### 인터랙티브 의사결정 태스크

#### AlfWorld

AlfWorld는 TextWorld 기반의 인터랙티브 가상 환경으로, 6종류의 가정용 태스크(물건 찾기, 물건 옮기기, 청소하기 등)를 수행합니다.

| 방법 | 평균 성공률 |
|------|------------|
| BUTLER (모방학습 + 10만 스텝 학습) | 22% |
| Act Only (1-shot) | 45% |
| **ReAct (1-shot)** | **71%** |
| Act Only (6-shot) | 45% |
| **ReAct (6-shot)** | **71%** |

ReAct는 단 1~2개의 예시만으로도, 10만 스텝 이상 학습한 모방학습 모델을 크게 능가합니다. Act-only 대비 26%p의 향상은 Thought가 행동 계획에 제공하는 가치를 명확히 보여줍니다.

Act-only의 주요 실패 원인은 **환각과 반복 행동**입니다. 예를 들어 존재하지 않는 물건을 집으려 하거나, 같은 행동을 반복합니다. ReAct에서는 Thought가 현재 상황을 분석하고 다음 행동을 계획하므로, 이러한 오류가 크게 줄어듭니다.

#### WebShop

WebShop은 웹 쇼핑 환경에서 사용자의 요구사항에 맞는 상품을 검색하고 구매하는 태스크입니다.

| 방법 | 성공률 | 보상 점수 |
|------|--------|----------|
| 모방학습 (IL) | 29.1 | 59.9 |
| IL + RL | 28.7 | 62.4 |
| Act Only | 30.1 | 62.3 |
| **ReAct** | **40.0** | **66.6** |

ReAct는 1,800개의 인간 시연(demonstration)으로 학습된 모방학습+강화학습 모델을 능가합니다.

### Human-in-the-Loop

![인간 개입을 통한 행동 수정 예시 — ReAct의 환각 사고를 인간이 수정하여 태스크를 성공시키는 과정](figures/fig_9.png)

*Figure 3: Human-in-the-loop 행동 수정 예시. (a) ReAct 에이전트가 환각으로 인해 실패하는 트래젝토리. (b) 인간이 두 개의 Thought만 수정하여(Act 17, 23) 에이전트가 올바른 추론과 행동을 생성하도록 유도, 태스크를 성공시킨다. (Yao et al., 2023)*

ReAct의 중요한 실용적 이점은 **인간 개입이 용이하다**는 것입니다. Thought가 자연어로 드러나므로, 인간이 모델의 추론 과정을 읽고 잘못된 Thought만 수정하면 에이전트의 행동을 교정할 수 있습니다. 논문에서는 AlfWorld에서 인간이 평균 2개의 Thought만 수정하여 실패했던 태스크를 성공시키는 사례를 보여줍니다.

## 방법론 상세 분석

### 4가지 프롬프팅 방법의 구조적 차이

| 방법 | 추론 | 행동 | 외부 지식 | 환각 위험 |
|------|------|------|----------|----------|
| Standard | X | X | X | 높음 |
| CoT (Reason Only) | O | X | X | 중간 |
| Act Only | X | O | O | 높음 (행동 환각) |
| **ReAct** | **O** | **O** | **O** | **낮음** |

### ReAct + CoT-SC 결합 전략

논문에서는 ReAct와 CoT-SC를 결합하는 두 가지 전략을 제안합니다.

**전략 1 (ReAct → CoT-SC)**: ReAct로 먼저 시도하고, ReAct가 $n$ 스텝 내에 답을 찾지 못하거나 반복적 행동에 빠지면 CoT-SC로 폴백합니다.

**전략 2 (CoT-SC → ReAct)**: CoT-SC로 먼저 시도하고, 다수결 투표에서 과반수 답이 없으면(낮은 일관성) ReAct로 전환합니다.

실험 결과, 전략 1이 더 효과적이며, ReAct + CoT-SC 결합은 각각의 단독 사용보다 일관적으로 우수합니다.

### 파인튜닝 vs 프롬프팅

논문에서는 소형 모델(PaLM-8B, PaLM-62B)에서의 파인튜닝도 실험합니다. 3,000개의 ReAct 스타일 트래젝토리로 파인튜닝한 결과, 프롬프팅만으로는 어려웠던 소형 모델에서도 ReAct 패턴이 효과적으로 학습됩니다.

:::tip
실무에서 ReAct 패턴을 적용할 때는, LangChain의 `create_react_agent`나 직접 구현한 TAO 루프를 사용할 수 있습니다. 핵심은 Thought/Action/Observation의 구분을 명확히 하고, Thought에서 충분한 추론이 이루어지도록 프롬프트를 설계하는 것입니다.
:::

## 한계 및 의의

### 한계

1. **프롬프트 설계 의존성**: ReAct의 성능은 Few-shot 예시의 품질에 크게 의존합니다. 잘 설계된 예시가 없으면 모델이 Thought와 Action의 적절한 교대를 학습하지 못할 수 있습니다.

2. **행동 공간의 제한**: 논문에서 실험한 행동 공간(Search, Lookup, Finish)은 비교적 단순합니다. 복잡한 실세계 환경(다양한 API, 멀티스텝 도구 사용)에서의 확장성은 추가 검증이 필요합니다.

3. **검색 실패 취약성**: ReAct는 외부 검색에 의존하므로, 검색이 관련 정보를 반환하지 못하면 성능이 크게 저하됩니다. 이는 검색 시스템의 품질에 대한 의존성을 의미합니다.

4. **지연 시간**: 매 스텝마다 외부 환경과 상호작용하므로, 총 지연 시간이 CoT 대비 크게 증가합니다.

### 학술적 의의

1. **LLM 에이전트 패러다임의 확립**: ReAct는 "LLM이 추론하면서 행동한다"는 에이전트 패러다임을 확립한 기념비적 논문입니다. 이후 [[reflexion]], AutoGPT, BabyAGI, LATS 등 거의 모든 LLM 에이전트 연구가 ReAct를 기반으로 합니다.

2. **추론과 행동의 시너지 실증**: 추론만 하는 것(CoT)보다도, 행동만 하는 것(Act)보다도, 둘을 결합하는 것이 우월함을 체계적으로 실증했습니다.

3. **해석 가능한 에이전트**: Thought를 통해 에이전트의 추론 과정이 투명하게 드러나므로, 인간이 이해하고 개입할 수 있는 에이전트의 가능성을 열었습니다.

### 실무적 영향

ReAct는 2023년 이후 가장 널리 사용되는 LLM 에이전트 패턴입니다. LangChain, LlamaIndex, Microsoft AutoGen, CrewAI 등 주요 에이전트 프레임워크들이 모두 ReAct 패턴을 기본으로 채택하고 있으며, 이를 기반으로 다양한 실세계 응용(코드 생성, 데이터 분석, 고객 지원 등)이 구축되고 있습니다.

## 추가 분석

### 오류 유형 상세 분석

논문에서 제시하는 ReAct와 CoT의 오류 유형 비교는 두 방법의 근본적 차이를 이해하는 데 중요합니다.

**CoT의 오류 분포** (HotPotQA 기준):

| 오류 유형 | 비율 | 설명 |
|---------|------|------|
| 환각 (Hallucination) | 56% | 존재하지 않는 사실 생성 |
| 추론 오류 | 28% | 올바른 사실에서 잘못된 결론 도출 |
| 기타 | 16% | 형식 오류, 불완전 답변 등 |

**ReAct의 오류 분포** (HotPotQA 기준):

| 오류 유형 | 비율 | 설명 |
|---------|------|------|
| 검색 실패 | 23% | 관련 정보를 찾지 못함 |
| 추론 오류 | 47% | 올바른 정보에서 잘못된 결론 |
| 조기 종료 | 15% | 충분한 정보 수집 전에 답변 |
| 환각 | 15% | 정보를 잘못 해석하거나 왜곡 |

핵심 관찰은 **ReAct가 환각을 56%에서 15%로 크게 줄였다**는 것입니다. 이는 외부 검색을 통한 사실 확인(grounding)이 환각 방지에 매우 효과적임을 보여줍니다. 하지만 대신 검색 실패라는 새로운 오류 유형이 등장합니다.

이 예시는 ReAct의 중요한 실무적 이점을 보여줍니다. 정적인 학습 데이터에 의존하는 CoT와 달리, ReAct는 실시간으로 외부 정보를 검색하여 최신 상태를 반영할 수 있습니다. 이는 지식이 빠르게 변하는 도메인(뉴스, 스포츠, 기술 등)에서 특히 유용합니다.

### ReAct의 행동 공간 설계

ReAct의 성능은 **행동 공간(action space)**의 설계에 크게 의존합니다. 논문에서 사용한 행동 공간을 태스크별로 정리하면 다음과 같습니다.

**HotPotQA/FEVER (지식 탐색)**:
- `Search[entity]`: 위키피디아에서 엔티티 검색
- `Lookup[keyword]`: 현재 페이지에서 키워드 찾기
- `Finish[answer]`: 최종 답변 제출

**AlfWorld (인터랙티브 환경)**:
- `go to [location]`: 특정 장소로 이동
- `take [object] from [location]`: 물건 집기
- `put [object] in/on [location]`: 물건 놓기
- `open/close [object]`: 열기/닫기
- `toggle [object]`: 켜기/끄기
- `clean/heat/cool [object]`: 처리하기

**WebShop (웹 쇼핑)**:
- `search[query]`: 상품 검색
- `click[element]`: 웹 요소 클릭
- `buy`: 상품 구매

행동 공간이 잘 설계되어야 에이전트가 효율적으로 태스크를 수행할 수 있습니다. 너무 세밀하면 의사결정의 부담이 커지고, 너무 추상적이면 세밀한 제어가 어렵습니다.

### ReAct 패턴의 실무 구현

ReAct를 실무에서 구현할 때의 핵심 고려사항을 정리합니다.

**1. 프롬프트 설계**: Few-shot 예시에서 Thought의 구체성과 Action의 정확성이 중요합니다. 모호한 Thought("이걸 검색해보자")보다 구체적인 Thought("저자의 출생연도를 찾기 위해 위키피디아를 검색하자")가 더 효과적입니다.

**2. 도구(Tool) 통합**: 실무에서는 Search/Lookup 외에도 다양한 도구(계산기, 코드 실행기, 데이터베이스 쿼리, API 호출 등)를 통합할 수 있습니다. 각 도구의 입출력 형식을 명확히 정의하는 것이 중요합니다.

**3. 최대 스텝 수 제한**: 무한 루프를 방지하기 위해 최대 스텝 수를 설정해야 합니다. 논문에서는 태스크에 따라 6~15 스텝을 사용합니다.

**4. 오류 복구**: Action이 실패하거나 예상치 못한 Observation이 반환될 때, 에이전트가 graceful하게 대응하도록 프롬프트에 오류 복구 예시를 포함하는 것이 좋습니다.

:::tip
LangChain에서 ReAct 에이전트를 구현할 때는 `create_react_agent` 함수를 사용하거나, `AgentExecutor`에 커스텀 도구를 등록하는 방식이 가장 일반적입니다. 핵심은 각 도구의 description을 명확하게 작성하여, LLM이 언제 어떤 도구를 사용할지 올바르게 판단할 수 있게 하는 것입니다.
:::

### 후속 연구와의 연결

ReAct는 다음과 같은 후속 연구의 직접적 기반이 되었습니다.

- **[[reflexion]]**: ReAct 에이전트에 자기 반성과 메모리를 추가하여, 실패로부터 학습하는 능력 부여
- **Toolformer**: LLM이 스스로 도구 사용 시점을 판단하도록 파인튜닝
- **LATS (Language Agent Tree Search)**: ReAct + [[tree-of-thoughts]] + [[reflexion]]을 결합한 통합 프레임워크
- **AutoGPT/BabyAGI**: ReAct 패턴을 자율적 태스크 계획으로 확장
- **Claude Computer Use / GPT-4 with Functions**: 상용 LLM에 도구 사용 능력을 내재화

## 결론

ReAct는 "추론은 행동을 안내하고, 행동은 추론의 근거를 제공한다"는 단순하지만 강력한 원리를 LLM에 구현한 논문입니다. Chain-of-Thought가 LLM에게 "생각하는 법"을 가르쳤다면, ReAct는 LLM에게 "생각하면서 행동하는 법"을 가르쳤습니다.

이 논문의 기여는 세 가지 차원에서 평가할 수 있습니다. 첫째, **기술적으로** 추론과 행동의 결합이 각각의 단독 사용보다 우월함을 체계적으로 실증했습니다. 둘째, **구조적으로** Thought-Action-Observation이라는 명확한 인터페이스를 확립하여, 이후 모든 에이전트 프레임워크의 표준이 되었습니다. 셋째, **생태계적으로** LLM 에이전트라는 새로운 연구 분야와 산업을 탄생시켰습니다.

ReAct 이후, LLM은 단순한 텍스트 생성기에서 외부 세계와 상호작용하며 복잡한 태스크를 수행하는 자율 에이전트로 진화하기 시작했습니다. 이 패러다임 전환은 AI의 실세계 적용 범위를 근본적으로 확장하고 있습니다.
