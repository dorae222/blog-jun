## 개요

BD3LM(Block Discrete Denoising Diffusion Language Model)은 자기회귀(AR) 언어 모델과 확산(Diffusion) 언어 모델이라는 두 패러다임을 하나의 통합된 프레임워크로 연결하는 하이브리드 모델이다. Arriola et al.(2025)이 제안한 이 모델은 시퀀스를 고정 크기의 블록으로 분할하고, 블록 사이에서는 자기회귀적 순서를 유지하면서 블록 내부에서는 마스크 확산을 적용한다. 블록 크기라는 단일 하이퍼파라미터를 조절하는 것만으로 순수 AR 모델과 순수 확산 모델 사이의 어디든 위치할 수 있으며, 이를 통해 두 접근법의 장점을 동시에 취한다. 기존 확산 언어 모델 대비 더 낮은 퍼플렉시티를 달성하면서도 KV-캐시와 호환되는 효율적 추론이 가능하다는 점이 핵심 기여다.

## 배경 및 문제

자기회귀 언어 모델은 토큰을 왼쪽에서 오른쪽으로 한 번에 하나씩 생성한다. 이 방식은 강력한 성능과 KV-캐시를 통한 효율적 추론을 제공하지만, 병렬 생성이 불가능하고 단방향 문맥만 활용한다는 구조적 한계가 있다.

반면 확산 언어 모델(Diffusion LM)은 전체 시퀀스를 동시에 생성하는 비자기회귀 방식을 취한다. 마스크 확산 방법론(MDLM, LLaDA 등)은 입력 토큰을 점진적으로 마스킹한 후 반복적인 디노이징으로 복원하는데, 양방향 문맥을 활용하고 병렬 생성이 가능하다는 장점이 있다. 그러나 현재까지 확산 언어 모델은 자기회귀 모델에 비해 퍼플렉시티 성능이 열등하며, KV-캐시를 활용할 수 없어 추론 비용이 높다는 문제가 있었다.

이 논문의 핵심 질문은 다음과 같다. AR의 효율성과 Diffusion의 병렬성을 함께 얻을 수 있는가?

## 핵심 아이디어

BD3LM의 핵심 통찰은 시퀀스를 $B$개의 블록으로 분할하고, **블록 간(inter-block)**에는 자기회귀 조건부 확률을 적용하고 **블록 내(intra-block)**에는 마스크 확산을 적용한다는 것이다.

전체 시퀀스에 대한 결합 확률은 블록 단위 AR 분해로 표현된다.

$$p(x) = \prod_{b=1}^{B} p(x^b \mid x^{<b})$$

여기서 $x^b$는 $b$번째 블록의 토큰 집합, $x^{<b}$는 이전 모든 블록의 토큰들이다. 이 식은 AR 언어 모델의 토큰 단위 분해와 구조적으로 동일하지만, 분해 단위가 토큰이 아닌 블록이라는 점이 다르다.

각 블록 내부의 생성은 마스크 확산으로 이루어진다. 각 블록의 조건부 확률을 주변화(marginalization)하면,

$$p_\theta(x^b \mid x^{<b}) = \int p_\theta(x^b \mid x_1^b,\, x^{<b})\, q(x_1^b \mid x^b)\, dx_1^b$$

여기서 $q(x_1^b \mid x^b)$는 블록 내 토큰을 마스킹하는 포워드 노이즈 프로세스이며, $p_\theta(x^b \mid x_1^b, x^{<b})$는 마스킹된 블록과 이전 블록 맥락을 조건으로 원래 토큰을 복원하는 디노이징 네트워크다.

블록 크기가 갖는 보간 효과는 다음과 같다.

- 블록 크기 = 1: 블록마다 토큰이 하나뿐이므로 마스크 확산이 의미 없어지고, 순수 AR 모델과 동일하게 동작한다.
- 블록 크기 = $L$ (전체 길이): 시퀀스 전체가 하나의 블록이 되어 순수 확산 언어 모델(예: MDLM)과 동일해진다.
- 중간 크기: AR과 Diffusion의 중간 지점을 차지하며, 블록 내 병렬 생성과 블록 간 순차적 조건 부여를 동시에 수행한다.

## 방법론

**학습.** 목적 함수는 ELBO(Evidence Lower BOund)를 블록 단위로 분해하여 도출한다. 각 블록에 대해 독립적인 마스크 확산 손실을 계산하고, 이를 모든 블록에 걸쳐 합산한다. 이전 블록들은 완전히 관측된 상태($x^{<b}$)로 조건부에 들어가므로, 각 블록의 학습은 독립적으로 수행 가능하다.

**아키텍처.** 모델은 인과적 어텐션(causal attention)과 양방향 어텐션(bidirectional attention)을 함께 사용하는 트랜스포머 구조를 취한다. 이전 블록 토큰들에 대해서는 인과적 어텐션 마스크를 적용하여 AR 조건부를 구현하고, 현재 블록 내 토큰들에 대해서는 양방향 어텐션을 허용하여 마스크 확산의 디노이징에 활용한다. 이 혼합 어텐션 설계 덕분에 이전 블록에 대한 KV-캐시를 그대로 재사용할 수 있어 추론 효율이 높다.

**추론.** 생성 시에는 블록을 왼쪽에서 오른쪽 순서로 처리한다. 각 블록에 대해 $T$스텝의 마스크 확산 디노이징을 수행하여 블록 내 토큰을 완성한 뒤, 다음 블록으로 이동한다. 이전 블록들은 KV-캐시에 저장되어 재계산 없이 참조된다. 블록 크기와 확산 스텝 수 $T$는 품질-속도 트레이드오프를 조정하는 두 개의 제어 변수가 된다.

**블록 크기 트레이드오프.** 블록 크기를 크게 할수록 한 번의 패스에서 더 많은 토큰이 병렬로 생성되어 총 AR 스텝 수가 줄어든다. 그러나 블록이 클수록 내부 토큰 간 의존성이 복잡해져 디노이징 난이도가 올라가고 더 많은 확산 스텝이 필요해진다. 반대로 블록 크기가 작을수록 각 블록 생성이 쉬워지지만 전체 블록 수가 늘어나 AR 오버헤드가 커진다.

## 실험 결과

논문은 text8, LM1B, OpenWebText 벤치마크에서 BD3LM을 기존 확산 언어 모델들과 비교한다.

### 벤치마크별 퍼플렉시티 비교

**LM1B (낮을수록 좋음):**

| 모델 | LM1B PPL | 유형 | 비고 |
|------|----------|------|------|
| MDLM | ~52 | 마스크 확산 | 순수 마스크 확산 기반 |
| LLaDA | ~49 | 마스크 확산 | 대규모 학습 데이터 활용 |
| BD3LM (block=32) | ~44 | 블록 확산 | 블록 크기 32 |
| BD3LM (block=64) | ~46 | 블록 확산 | 블록 크기 64 |
| AR (GPT-2급) | ~35 | 자기회귀 | 참고용 상한 |

BD3LM은 동일 모델 규모에서 MDLM 및 LLaDA보다 일관되게 낮은 퍼플렉시티를 기록했다. 완전한 AR 모델에는 아직 미치지 못하지만, 확산 모델 계열 내에서는 최고 수준이다.

**text8 (BPC, bits per character, 낮을수록 좋음):**

| 모델 | text8 BPC | 비고 |
|------|-----------|------|
| D3PM (Uniform) | 1.61 | 이산 확산 초기 모델 |
| D3PM (Absorb) | 1.45 | 흡수 커널 적용 |
| MDLM | 1.08 | 마스크 확산 |
| BD3LM (block=16) | 1.04 | 블록 크기 16 |
| BD3LM (block=32) | 1.05 | 블록 크기 32 |
| AR Transformer | 1.02 | 참고용 |

text8에서도 BD3LM은 MDLM 대비 유의미한 개선을 보여주며, AR과의 격차를 0.02 BPC 수준까지 좁혔다.

**OpenWebText (GPT-2 토크나이저 기반 PPL):**

| 모델 | OWT PPL | 파라미터 수 | 비고 |
|------|---------|------------|------|
| SEDD (Absorb) | ~78 | 124M | Score Entropy 기반 |
| MDLM | ~74 | 124M | 마스크 확산 |
| BD3LM (block=32) | ~68 | 124M | 블록 확산 |
| GPT-2 Small | ~30 | 124M | 자기회귀 참고 |

OpenWebText에서도 BD3LM은 모든 확산 기반 모델을 상회했으나, GPT-2 Small과의 절대 격차는 여전히 존재한다.

### 블록 크기 어블레이션

블록 크기 1(AR)부터 전체 길이(순수 확산)까지의 퍼플렉시티 변화를 측정한 결과, 중간 블록 크기(16~64 범위)에서 최적 성능이 나타났다. 구체적인 경향은 다음과 같다:

| 블록 크기 | LM1B PPL | 특성 |
|-----------|----------|------|
| 1 (순수 AR) | ~38 | AR과 동일, 확산 이점 없음 |
| 4 | ~40 | 확산 스텝 부족으로 블록 내 디노이징 불완전 |
| 16 | ~43 | AR-확산 밸런스 양호 |
| 32 | ~44 | 최적 근처, 병렬성과 품질 균형 |
| 64 | ~46 | 블록 내 의존성 증가 |
| 128 | ~49 | 확산 난이도 급증 |
| 전체 (순수 확산) | ~52 | MDLM과 동일 |

블록 크기가 너무 크면 성능이 저하되고, 너무 작으면 확산의 이점이 사라지는 양상이 관찰되었다. 이는 AR과 Diffusion 사이의 보간이 실제로 단순 혼합 이상의 시너지를 만들어낸다는 것을 보여준다.

:::tip
블록 크기 1은 순수 AR, 블록 크기 = 전체 길이는 순수 확산에 해당한다. 중간 블록 크기에서 **양쪽보다 나은 성능**이 관찰된다는 점은, 두 패러다임의 결합이 단순한 보간이 아닌 상승 효과를 만들어낸다는 핵심 증거다.
:::

### 확산 스텝 수에 따른 성능 변화

블록 내 확산 스텝 수 $T$는 디노이징 품질과 추론 속도 사이의 트레이드오프를 결정한다:

| 확산 스텝 $T$ | LM1B PPL (block=32) | 상대 생성 시간 |
|---------------|---------------------|---------------|
| 4 | ~52 | 1x |
| 8 | ~47 | 1.8x |
| 16 | ~45 | 3.2x |
| 32 | ~44 | 5.8x |
| 64 | ~44 | 11x |

$T$가 32 이상이면 PPL 개선이 포화 상태에 이르며, 16~32 스텝이 효율적인 운영 구간이다. 이는 블록 크기가 적절히 작으면(32 이하) 블록 내 토큰 간 의존성이 비교적 단순하여 적은 확산 스텝으로도 충분한 디노이징이 가능함을 시사한다.

### 추론 속도 분석

KV-캐시 덕분에 BD3LM은 순수 확산 모델 대비 추론 속도가 빠르다. 구체적인 속도 비교는 다음과 같다:

| 모델 | 시퀀스 길이 1024 생성 시간 | KV-캐시 | 비고 |
|------|--------------------------|---------|------|
| MDLM (T=256) | ~15초 | 불가 | 매 스텝 전체 시퀀스 재계산 |
| BD3LM (block=32, T=16) | ~4초 | 가능 | 이전 블록 캐시 재활용 |
| BD3LM (block=64, T=32) | ~6초 | 가능 | 더 큰 블록, 더 많은 스텝 |
| AR (GPT-2) | ~2초 | 가능 | 토큰 단위 순차 생성 |

블록 크기가 클수록 AR 스텝이 줄어 더 빠른 생성이 가능하지만, 각 블록 내 확산 스텝 수를 늘려야 할 수 있어 절대 속도는 설정에 따라 달라진다. 핵심은 BD3LM이 확산 모델에 KV-캐시를 도입한 최초의 모델이라는 점이며, 이를 통해 MDLM 대비 3~4배의 추론 속도 향상을 달성했다.

### 생성 품질 정성적 분석

BD3LM의 생성 텍스트를 정성적으로 분석하면 다음과 같은 특성이 관찰된다:

- **블록 내 일관성**: 같은 블록 내에서 생성된 토큰들은 양방향 어텐션 덕분에 문법적·의미적으로 높은 일관성을 보인다.
- **블록 경계 전환**: 블록 경계에서의 문맥 전환은 AR 조건부 덕분에 자연스럽게 이루어진다. 그러나 매우 긴 시퀀스에서 블록 경계 부근에 미세한 부자연스러움이 관찰될 수 있다.
- **반복 감소**: 순수 AR 모델에서 흔히 나타나는 반복적 패턴이 BD3LM에서는 상대적으로 적다. 블록 내 양방향 어텐션이 이미 생성된 토큰과의 중복을 방지하는 효과를 가진다.

## 구현 세부사항

### 아키텍처 구성

BD3LM의 트랜스포머 아키텍처는 GPT-2를 기반으로 하되, 어텐션 마스크를 수정한 구조를 채택한다:

- **모델 규모**: 124M 파라미터 (GPT-2 Small과 동일), 12 레이어, 768 hidden dim, 12 헤드
- **포지션 인코딩**: 블록 내 상대 위치와 블록 간 절대 위치를 결합한 이중 위치 인코딩 사용
- **어텐션 마스크**: 이전 블록에는 인과적(causal) 마스크, 현재 블록에는 양방향(bidirectional) 마스크를 적용하는 하이브리드 구성

```
어텐션 마스크 구조 (블록 3개, 블록 크기 3 예시):

         블록1   블록2   블록3(현재)
블록1  [양방향] [차단]  [차단]
블록2  [인과적] [양방향] [차단]
블록3  [인과적] [인과적] [양방향]  ← 현재 생성 중인 블록
```

### 노이즈 스케줄

블록 내 마스크 확산의 노이즈 스케줄은 MDLM의 로그-리니어 스케줄을 따른다:

$$\sigma(t) = -\log(1 - t + t \cdot e^{-1})$$

이 스케줄은 $t = 0$에서 마스킹 없음, $t = 1$에서 완전 마스킹에 해당하며, 중간 영역에서 적절한 기울기를 유지하여 학습 안정성을 보장한다.

### 학습 설정

- **옵티마이저**: AdamW ($\beta_1 = 0.9$, $\beta_2 = 0.999$)
- **학습률**: $3 \times 10^{-4}$, 코사인 스케줄 + 워밍업 10K 스텝
- **배치 크기**: 512 시퀀스
- **시퀀스 길이**: 1024 토큰
- **학습 스텝**: 400K
- **하드웨어**: 8x A100 (80GB)

:::warning
BD3LM의 학습 비용은 순수 AR 모델과 유사하다. 각 블록에 대해 독립적인 확산 손실을 계산하므로 학습 시 추가적인 오버헤드가 크지 않다. 그러나 블록 크기가 클수록 블록 내 확산 경로의 분산이 커져 수렴이 느려질 수 있다.
:::

## 기존 모델과의 체계적 비교

BD3LM을 기존 확산 언어 모델들과 다양한 축에서 비교하면 다음과 같다:

BD3LM의 차별적 강점은 **KV-캐시 호환성**과 **블록 크기를 통한 유연한 설계**에 있다. 순수 확산 모델은 매 디노이징 스텝마다 전체 시퀀스를 재계산해야 하지만, BD3LM은 이미 완성된 이전 블록의 KV 값을 캐시에 저장하여 재사용할 수 있다.

## 의의 및 한계

### 의의

BD3LM의 가장 큰 기여는 AR과 Diffusion을 대립적 패러다임이 아닌 연속적 스펙트럼으로 바라보는 통합 프레임워크를 제시했다는 점이다. 블록이라는 구조적 단위를 도입함으로써 KV-캐시 호환성이라는 실용적 이점을 확산 모델에 가져왔고, 기존 최고 수준의 확산 언어 모델보다 낮은 퍼플렉시티를 달성했다. 이론적으로는 ELBO 분해가 깔끔하게 성립하여 학습 안정성도 확보된다.

구체적 기여를 정리하면:

1. **통합 프레임워크**: 블록 크기라는 단일 하이퍼파라미터로 AR-확산 스펙트럼을 연속적으로 탐색할 수 있는 이론적 프레임워크 제공
2. **KV-캐시 도입**: 확산 언어 모델에서 최초로 KV-캐시를 활용, 추론 효율을 3~4배 향상
3. **SOTA 성능**: 확산 언어 모델 계열에서 text8, LM1B, OpenWebText 모든 벤치마크에서 최고 퍼플렉시티 달성
4. **실용적 설계 지침**: 블록 크기와 확산 스텝 수의 트레이드오프에 대한 실증적 가이드라인 제공

### 한계

1. **AR과의 성능 격차**: 완전한 AR 모델과의 퍼플렉시티 격차는 여전히 존재한다. BD3LM이 AR을 완전히 대체하는 단계에는 이르지 못했다. LM1B에서 약 9 PPL, OpenWebText에서 약 38 PPL의 격차가 남아있으며, 이는 블록 내 확산의 근본적 한계에 기인할 수 있다.

2. **하이퍼파라미터 탐색 부담**: 블록 크기라는 새로운 하이퍼파라미터가 추가되어 최적값을 태스크·데이터 특성에 맞게 탐색해야 하는 부담이 생긴다. 블록 크기와 확산 스텝 수의 조합 공간은 상당히 넓다.

3. **긴 시퀀스 병목**: 긴 시퀀스에서 블록 수가 늘어날수록 AR 순서의 순차적 처리가 병목이 될 수 있다. 시퀀스 길이 $L$에서 블록 크기 $B$이면 $L/B$개의 순차적 AR 스텝이 필요하다.

4. **가변 블록 크기 미지원**: 현재 구현은 고정 블록 크기만 지원한다. 시퀀스 내에서 복잡도에 따라 블록 크기를 동적으로 조절하는 적응형(adaptive) 블록 설계는 향후 연구 과제로 남아있다.

5. **제한된 스케일 검증**: 124M 파라미터 규모에서만 실험이 수행되었으며, 수십억 파라미터 이상의 대규모에서도 동일한 경향이 유지되는지는 검증되지 않았다.

### 향후 연구 방향

BD3LM이 열어놓은 연구 방향은 다음과 같다:

- **적응형 블록 크기**: 입력의 복잡도에 따라 블록 크기를 동적으로 결정하는 메커니즘. 예를 들어 구문적으로 단순한 구간은 큰 블록으로, 복잡한 구간은 작은 블록으로 처리.
- **스케일링 법칙(Scaling Law) 연구**: 블록 크기와 모델 규모 간의 상호작용. 모델이 커질수록 최적 블록 크기도 변화하는지 탐구.
- **다운스트림 태스크 적용**: 언어 모델링을 넘어 기계 번역, 요약, 코드 생성 등 실용적 태스크에서의 BD3LM 성능 검증.
- **Speculative Decoding과의 결합**: AR 블록 생성에 Speculative Decoding을 적용하여 추론 속도를 추가로 향상시키는 가능성.

## 코드 예제

아래는 BD3LM의 블록 분할 및 생성 루프를 개념적으로 구현한 파이썬 예제다.

```python
import torch

def bd3lm_generate(
    model,
    prompt_ids: torch.Tensor,   # (batch, prompt_len)
    total_len: int,
    block_size: int,
    diffusion_steps: int = 10,
    mask_token_id: int = 4,
) -> torch.Tensor:
    """
    BD3LM 블록 단위 생성.
    이전 블록은 KV-캐시에 저장하고, 현재 블록은 마스크 확산으로 생성.
    """
    batch = prompt_ids.size(0)
    generated = prompt_ids.clone()
    past_kv = None

    num_blocks = (total_len - prompt_ids.size(1)) // block_size

    for b in range(num_blocks):
        # 현재 블록을 마스크 토큰으로 초기화
        block = torch.full((batch, block_size), mask_token_id)
        context = torch.cat([generated, block], dim=1)

        # diffusion_steps 번 반복 디노이징
        for t in reversed(range(diffusion_steps)):
            # mask ratio: t/T 비율로 마스킹 유지
            mask_ratio = t / diffusion_steps
            logits, past_kv = model(
                context,
                past_key_values=past_kv,
                use_cache=True,
            )
            # 현재 블록 위치의 로짓만 추출
            block_logits = logits[:, -block_size:, :]
            preds = block_logits.argmax(dim=-1)

            # 마스크된 위치만 선택적으로 복원 (annealed masking)
            still_masked = (block == mask_token_id)
            unmask_prob = 1.0 / (t + 1)  # 단계가 낮을수록 더 많이 복원
            unmask = still_masked & (torch.rand_like(block.float()) < unmask_prob)
            block = torch.where(unmask, preds, block)

            # 컨텍스트 갱신
            context = torch.cat([generated, block], dim=1)

        # 완성된 블록을 시퀀스에 추가
        generated = torch.cat([generated, block], dim=1)
        past_kv = None  # 다음 블록에서 KV-캐시 갱신

    return generated
```

위 예제는 각 블록을 마스크 토큰으로 초기화한 뒤, 점진적으로 마스크를 해제하며 토큰을 결정하는 핵심 흐름을 보여준다. 실제 구현에서는 연속적인 시간 변수 $t$와 MDLM의 포워드/리버스 과정을 정확히 따르는 스케줄러가 필요하다.

아래는 BD3LM의 ELBO 기반 학습 손실을 계산하는 예제다:

```python
import torch
import torch.nn.functional as F

def bd3lm_block_loss(
    model,
    x: torch.Tensor,       # (batch, seq_len) 전체 토큰 시퀀스
    block_size: int,
    mask_token_id: int = 4,
    num_timesteps: int = 1000,
) -> torch.Tensor:
    """
    BD3LM 블록 단위 ELBO 손실 계산.
    각 블록에 대해 독립적인 마스크 확산 손실을 계산하고 합산.
    """
    batch, seq_len = x.shape
    num_blocks = seq_len // block_size
    total_loss = 0.0

    for b in range(num_blocks):
        # 현재 블록과 이전 블록(조건부) 분리
        start = b * block_size
        end = (b + 1) * block_size
        x_block = x[:, start:end]           # 현재 블록 토큰
        x_prev = x[:, :start]               # 이전 블록들 (조건부)

        # 랜덤 타임스텝 샘플링
        t = torch.randint(0, num_timesteps, (batch,), device=x.device)

        # 마스크 확산: t에 따른 마스킹 비율 결정
        mask_ratio = t.float() / num_timesteps  # (batch,)
        mask = torch.rand(batch, block_size, device=x.device) < mask_ratio[:, None]
        x_noisy = x_block.clone()
        x_noisy[mask] = mask_token_id

        # 조건부 입력 구성: [이전 블록 | 노이즈된 현재 블록]
        context = torch.cat([x_prev, x_noisy], dim=1)

        # 모델 예측
        logits = model(context, timestep=t)
        block_logits = logits[:, start:end, :]  # 현재 블록 위치만

        # 마스크된 위치에서의 Cross-Entropy 손실
        masked_loss = F.cross_entropy(
            block_logits[mask].view(-1, block_logits.size(-1)),
            x_block[mask].view(-1),
            reduction='mean'
        )
        total_loss += masked_loss

    return total_loss / num_blocks
```

:::info
위 학습 코드에서 핵심은 각 블록에 대해 이전 블록들이 완전히 관측된 상태로 조건부에 들어간다는 점이다. 이 구조 덕분에 블록별 ELBO 분해가 정확히 성립하며, 각 블록의 손실을 독립적으로 계산할 수 있다.
:::
