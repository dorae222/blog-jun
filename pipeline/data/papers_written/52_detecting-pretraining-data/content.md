## 개요

"Detecting Pretraining Data from Large Language Models"(Shi et al., 2024)는 ICLR 2024에서 발표된 논문으로, **특정 텍스트가 대규모 언어 모델(LLM)의 사전학습 데이터에 포함되었는지 여부를 외부에서 판별하는 방법론**을 제안합니다. 이 문제는 머신러닝 보안 분야에서 멤버십 추론 공격(Membership Inference Attack, MIA)이라 불리는 고전적 주제의 LLM 확장판에 해당합니다.

논문의 핵심 기여는 크게 세 가지로 요약할 수 있습니다.

1. **기존 방법의 실패 분석**: 기존 멤버십 추론 방법들이 LLM 환경에서 왜 효과적이지 못한지를 이론적, 실험적으로 분석합니다. 특히 퍼플렉서티 기반 방법의 근본적 한계인 분포 혼동과 고빈도 토큰 지배 문제를 명확히 규명합니다.
2. **MIN-K% PROB 제안**: 별도의 레퍼런스 모델이나 그림자 모델(shadow model) 학습 없이도 높은 탐지 성능을 달성하는 단순하면서도 강력한 탐지 방법을 제안합니다.
3. **WIKIMIA 벤치마크 구축**: 위키피디아 편집 이력의 시간 정보를 활용한 동적 벤치마크를 구축하여, 그라운드 트루스 레이블을 확보하기 어려운 이 문제에 대한 체계적인 평가 프레임워크를 제공합니다.

LLM이 사회 전반에 확산되면서, 학습 데이터의 구성에 대한 투명성 요구가 높아지고 있습니다. 이 논문은 모델의 가중치에 대한 블랙박스 접근(로그 확률만 획득 가능)만으로도 학습 데이터 포함 여부를 통계적으로 추론할 수 있음을 보여준다는 점에서 학술적, 실용적 가치가 매우 큽니다. 특히 OpenAI, Google, Meta 등 주요 기업이 학습 데이터 구성을 비공개로 유지하는 상황에서, 외부 감사(external audit) 도구로서의 잠재력이 높습니다.

## 배경 및 문제

### 데이터 오염(Data Contamination)의 중요성

LLM 시대에서 **데이터 오염(data contamination)**은 두 가지 차원에서 심각한 문제를 야기합니다.

**첫째, 벤치마크 신뢰성 훼손입니다.** LLM의 능력을 평가하기 위해 다양한 벤치마크(MMLU, GSM8K, HumanEval 등)가 사용되는데, 이 벤치마크 데이터가 모델의 사전학습 코퍼스에 포함되어 있다면 평가 결과는 모델의 진정한 능력을 반영하지 못합니다. 이는 모델 간 공정한 비교를 불가능하게 하며, 연구 커뮤니티 전체의 진보를 왜곡할 수 있습니다.

**둘째, 저작권 및 프라이버시 침해입니다.** 뉴욕타임스의 OpenAI 소송(2023), Getty Images의 Stability AI 소송 등에서 볼 수 있듯이, 저작권 보호 콘텐츠가 무단으로 학습에 사용되었는지의 여부는 법적 분쟁의 핵심 쟁점입니다. 또한 개인 식별 정보(PII)가 학습 데이터에 포함된 경우 [[GDPR]], CCPA 등 데이터 보호 규정 위반에 해당할 수 있습니다.

이러한 배경에서, 주어진 텍스트가 특정 LLM의 학습 데이터에 포함되었는지를 외부에서 판별하는 기술은 AI 거버넌스의 핵심 인프라로 부상하고 있습니다.

### 멤버십 추론 공격의 배경

멤버십 추론 공격(MIA)은 주어진 데이터 포인트가 모델의 학습 데이터에 포함되었는지를 판별하는 기법으로, 머신러닝 프라이버시 연구의 핵심 주제 중 하나입니다. 분류 모델에 대한 MIA는 Shokri et al.(2017) 이래로 상당한 발전을 이루어 왔으며, 그림자 모델 학습, 손실 값 기반 임계값 설정, 레퍼런스 모델 비교 등 다양한 기법이 제안되었습니다.

그러나 이러한 기법들을 LLM에 직접 적용하기는 쉽지 않습니다. 그 이유는 다음과 같습니다.

**첫째, 모델 규모의 문제입니다.** 그림자 모델 기반 접근은 타겟 모델과 유사한 모델을 여러 번 학습시켜야 하는데, LLM의 경우 단일 학습에도 수백만 달러의 비용이 들어 사실상 불가능합니다. 예를 들어, GPT-4 수준의 모델을 학습하는 데 드는 비용은 1억 달러 이상으로 추정됩니다.

**둘째, 학습 데이터 접근 불가능 문제입니다.** 대부분의 상용 LLM은 학습 데이터 구성을 공개하지 않으며, 연구자가 멤버/비멤버 샘플을 정확히 구분할 수 있는 그라운드 트루스를 확보하기가 극도로 어렵습니다. GPT-4, Claude, Gemini 등 주요 모델의 학습 데이터는 완전히 비공개입니다.

**셋째, 생성 모델 특성의 문제입니다.** 분류 모델에서는 클래스 확률 벡터를 탐지 신호로 활용하지만, 자기회귀 언어 모델에서는 각 토큰 위치마다 전체 어휘(vocabulary)에 대한 확률 분포가 존재하여, 탐지 신호 설계가 더 복잡합니다. 어휘 크기가 수만에서 수십만에 달하는 LLM에서는 확률 분포의 차원이 매우 높아 분석이 까다롭습니다.

### 기존 방법들의 한계

LLM에 대한 MIA에서 가장 직관적인 접근은 **퍼플렉서티(perplexity) 기반 방법**입니다. 학습에 사용된 텍스트는 모델이 잘 예측할 것이므로 낮은 퍼플렉서티를 보일 것이라는 가정 하에, 텍스트의 평균 로그 확률을 탐지 스코어로 사용합니다.

$$\text{score}_{\text{PPL}}(x) = \frac{1}{n} \sum_{i=1}^{n} \log P_f(x_i \mid x_{<i})$$

여기서 $x = (x_1, x_2, \ldots, x_n)$은 토큰 시퀀스이고, $P_f(x_i \mid x_{<i})$는 모델 $f$가 이전 토큰들을 조건으로 $x_i$에 부여하는 확률입니다.

이 방법은 이론적으로 타당해 보이지만, 실제로는 심각한 한계를 드러냅니다. 논문에서는 두 가지 핵심 실패 원인을 분석합니다.

**분포 혼동(distribution confusion) 문제**: 비멤버 텍스트라 하더라도, 학습 데이터의 도메인과 문체적으로 유사하면 모델이 낮은 퍼플렉서티를 부여합니다. 예를 들어, LLM이 위키피디아로 학습되었을 때, 학습 이후에 새로 작성된 위키피디아 문서도 기존 문서와 유사한 스타일로 쓰여 있어 낮은 퍼플렉서티를 갖게 됩니다. 수학적으로, 멤버 분포 $\mathcal{P}_{\text{member}}$와 비멤버 분포 $\mathcal{P}_{\text{non-member}}$의 퍼플렉서티 분포가 크게 겹치는 현상입니다.

**고빈도 토큰 지배 문제**: 텍스트의 대부분을 차지하는 관사(the, a), 전치사(in, on, of), 접속사(and, but) 등 고빈도 기능어(function words)는 멤버 여부와 무관하게 항상 높은 확률을 갖습니다. 전체 텍스트의 약 60-80%가 이러한 고빈도 토큰으로 구성되며, 평균 로그 확률을 계산하면 이들이 스코어를 지배하여 멤버십에 관한 실질적 신호가 희석됩니다. 이를 수식으로 표현하면:

$$\text{score}_{\text{PPL}} \approx \frac{1}{n}\left(\sum_{i \in \text{high-freq}} \underbrace{\log P_f(x_i \mid x_{<i})}_{\text{large, similar for member/non-member}} + \sum_{i \in \text{low-freq}} \underbrace{\log P_f(x_i \mid x_{<i})}_{\text{small, discriminative}}\right)$$

고빈도 토큰 항이 전체 합을 지배하므로, 저빈도 토큰에서 발생하는 멤버십 신호가 묻히게 됩니다.

Carlini et al.(2021)이 제안한 **레퍼런스 모델 기반 방법**은 타겟 모델과 별도의 레퍼런스 모델 간 로그 확률 비율을 사용하여 위 문제를 완화합니다:

$$\text{score}_{\text{Ref}}(x) = \log P_{f_{\text{target}}}(x) - \log P_{f_{\text{ref}}}(x)$$

이 방법은 텍스트의 고유한 난이도를 보정해준다는 장점이 있으나, 적절한 레퍼런스 모델을 확보해야 한다는 실용적 제약이 있습니다. 레퍼런스 모델은 타겟 모델과 유사한 아키텍처와 크기를 가져야 하며, 학습 데이터가 겹치지 않아야 합니다. 또한 타겟 모델과 레퍼런스 모델의 사전학습 데이터가 크게 겹치는 경우 보정 효과가 감소합니다.

기타 기존 방법들로는 **Zlib 엔트로피 비율**(텍스트의 zlib 압축 크기로 정규화), **대소문자 변환 방법**(텍스트를 소문자로 변환하여 퍼플렉서티 비율 계산) 등이 있으나, 모두 근본적인 한계를 공유합니다.

### 평가의 어려움

멤버십 추론 연구에서 가장 근본적인 어려움은 **평가 자체**에 있습니다. 특정 텍스트가 모델의 학습 데이터에 포함되었는지를 확인하려면 학습 데이터에 대한 완전한 접근이 필요한데, 상용 LLM은 이를 공개하지 않습니다. 일부 오픈소스 모델(예: [[Pythia]], [[OLMo]])은 학습 데이터를 공개하지만, 모든 모델에 일반화 가능한 벤치마크는 부재했습니다. 이 문제에 대한 해결책으로 논문이 제안하는 WIKIMIA 벤치마크는 시간 기반 접근을 통해 이 간극을 메웁니다.

## 핵심 아이디어

MIN-K% PROB의 핵심 통찰은 다음과 같습니다. **모델이 학습 중 암기(memorize)한 텍스트에서는 드문 단어나 특이한 구문조차 비교적 높은 확률로 예측되지만, 학습에 사용되지 않은 텍스트에서는 이러한 저확률 토큰 위치에서 확률이 급격히 낮아집니다.**

이 관찰은 언어 모델의 암기 메커니즘에 대한 기존 연구와 일맥상통합니다. Carlini et al.(2023)은 LLM이 학습 데이터의 상당 부분을 거의 그대로 암기한다는 것을 보여주었는데, 이때 암기된 텍스트는 내용이 풍부한(content-rich) 토큰, 즉 고유명사, 숫자, 전문 용어 등에서 특히 높은 재현 확률을 보입니다. 이러한 토큰들은 일반적인 맥락에서는 예측하기 어려운 저확률 토큰에 해당합니다.

구체적인 예시로 설명하겠습니다. "Albert Einstein was born on March 14, 1879, in Ulm, Kingdom of Wuerttemberg, German Empire"라는 문장을 생각해 보겠습니다.

- **멤버 텍스트인 경우**: 모델이 이 문장을 학습 중 여러 번 보았으므로, "14", "1879", "Ulm", "Wuerttemberg" 같은 구체적이고 드문 토큰들도 비교적 높은 확률로 예측합니다. 결과적으로 MIN-K% 스코어(저확률 토큰들의 평균)가 상대적으로 높습니다.
- **비멤버 텍스트인 경우**: 학습 데이터에 없는 유사한 전기 텍스트에서는 "was", "born", "on", "in" 같은 기능어는 여전히 높은 확률이지만, 구체적 날짜나 지명에서 확률이 급락합니다. MIN-K% 스코어가 크게 낮아집니다.

이 차이를 정보 이론적으로 해석할 수도 있습니다. 멤버 텍스트의 저확률 토큰에서의 정보량(surprisal) $I(x_i) = -\log P_f(x_i \mid x_{<i})$이 비멤버 대비 체계적으로 낮습니다. 즉, 모델이 해당 토큰에 대해 "놀라는 정도"가 적습니다.

따라서, 텍스트 전체의 평균 확률(퍼플렉서티) 대신 **확률이 가장 낮은 토큰들에 집중**하면, 멤버 텍스트와 비멤버 텍스트 간의 구별력이 극대화됩니다. 고빈도 기능어들은 어차피 양쪽 모두에서 높은 확률을 가지므로, 이들을 스코어 계산에서 제외하는 것이 신호 대 잡음비(Signal-to-Noise Ratio, SNR)를 높이는 효과를 가져옵니다.

이를 통계적 가설 검정의 관점에서 보면, MIN-K% PROB는 멤버십에 대한 가장 판별력 있는(discriminative) 특징들만 선택적으로 사용하는 특징 선택(feature selection) 전략과 유사합니다.

## 방법론

### 문제 정의

텍스트 시퀀스 $x = (x_1, x_2, \ldots, x_n)$이 주어지고, 자기회귀 언어 모델 $f$의 사전학습 데이터셋을 $\mathcal{D}_{\text{train}}$이라 할 때, 멤버십 추론은 다음의 이진 분류 문제로 정의됩니다:

$$h(x) = \begin{cases} 1 & \text{if } x \in \mathcal{D}_{\text{train}} \\ 0 & \text{otherwise} \end{cases}$$

이때 모델의 내부 파라미터 $\theta$에 대한 직접 접근은 불가능하며, 주어진 텍스트에 대해 각 토큰 위치의 조건부 확률 $P_f(x_i \mid x_{<i})$만 획득할 수 있는 블랙박스 환경을 가정합니다. 이러한 설정은 OpenAI API, Anthropic API 등 상용 LLM 서비스에서 로그 확률(logprobs)을 제공하는 현실적 상황을 반영합니다.

### MIN-K% PROB 알고리즘

아래 그림은 MIN-K% PROB의 전체 작동 과정을 보여줍니다. 입력 텍스트의 각 토큰에 대해 모델이 부여하는 확률을 구한 뒤, 확률이 가장 낮은 하위 k%의 토큰만 선별하여 그 평균 로그 우도를 멤버십 판별 스코어로 활용합니다.

![MIN-K% PROB 알고리즘 개요 -- 토큰 확률 분포에서 최소 k% 토큰의 평균 로그 확률로 멤버십 판별](figures/fig_1.png)
*MIN-K% PROB의 작동 원리. GPT-3에 텍스트를 입력하여 토큰별 확률을 구한 뒤, 하위 k% 토큰(예: "the", "Royal", "Miss" 등 저확률 토큰)을 선택하고, 이들의 평균 로그 우도가 높으면 해당 텍스트가 사전학습 데이터에 포함된 것으로 판정한다. (Shi et al., 2024)*

알고리즘의 절차는 다음과 같습니다.

**1단계: 토큰별 로그 확률 계산.** 텍스트 $x$의 각 토큰 $x_i$에 대해, 이전 토큰들을 조건으로 한 로그 확률을 계산합니다:

$$p_i = \log P_f(x_i \mid x_1, x_2, \ldots, x_{i-1}), \quad i = 1, 2, \ldots, n$$

**2단계: 하위 k% 토큰 선택.** 계산된 로그 확률 $\{p_1, p_2, \ldots, p_n\}$을 오름차순으로 정렬한 뒤, 하위 $k$%에 해당하는 토큰 집합 $S_k$를 선택합니다:

$$S_k = \{i : p_i \leq Q_k(\{p_1, \ldots, p_n\})\}$$

여기서 $Q_k$는 $k$번째 백분위수(percentile)를 나타냅니다. 선택되는 토큰의 수는 $|S_k| = \lceil n \cdot k / 100 \rceil$입니다.

**3단계: 탐지 스코어 계산.** 선택된 토큰들의 평균 로그 확률을 최종 탐지 스코어로 사용합니다:

$$\text{MIN-K\% PROB}(x) = \frac{1}{|S_k|} \sum_{i \in S_k} p_i$$

이 스코어가 특정 임계값 $\tau$보다 높으면 멤버($h(x)=1$), 낮으면 비멤버($h(x)=0$)로 판정합니다:

$$h(x) = \mathbb{1}[\text{MIN-K\% PROB}(x) > \tau]$$

임계값 $\tau$는 별도의 검증 데이터셋에서 설정하거나, AUC-ROC를 통해 임계값 독립적 평가를 수행합니다.

### 알고리즘 의사코드

전체 절차를 의사코드로 정리하면 다음과 같습니다.

```
Algorithm: MIN-K% PROB
Input: text x = (x_1, ..., x_n), model f, percentage k
Output: membership score s

1. for i = 1 to n do
2.   p_i = log P_f(x_i | x_1, ..., x_{i-1})
3. end for
4. Sort {p_1, ..., p_n} in ascending order
5. m = ceil(n * k / 100)
6. S_k = indices of bottom m values
7. s = (1/m) * sum_{i in S_k} p_i
8. return s
```

### 기존 방법과의 이론적 비교

퍼플렉서티 기반 방법은 $k = 100$인 특수한 경우에 해당합니다. 즉, 모든 토큰의 평균 로그 확률을 사용하는 것입니다. MIN-K%는 $k < 100$으로 설정함으로써 고빈도 토큰의 영향을 체계적으로 제거합니다.

다양한 방법들의 관계를 정리하면 다음과 같습니다:

| 방법 | 수식 | 레퍼런스 모델 필요 | 핵심 원리 |
|------|------|:---:|------|
| Perplexity | $\frac{1}{n}\sum_i \log P_f(x_i \mid x_{<i})$ | X | 전체 토큰 평균 |
| Zlib Ratio | $\frac{\sum_i \log P_f(x_i \mid x_{<i})}{\text{zlib}(x)}$ | X | 압축 크기 정규화 |
| Ref. Model | $\log P_{f_{\text{target}}}(x) - \log P_{f_{\text{ref}}}(x)$ | O | 모델 간 비교 |
| **MIN-K% PROB** | $\frac{1}{|S_k|}\sum_{i \in S_k} \log P_f(x_i \mid x_{<i})$ | **X** | **저확률 토큰 집중** |

레퍼런스 모델 기반 방법과 비교하면, MIN-K%는 텍스트 난이도 보정을 "내부적으로" 수행한다고 볼 수 있습니다. 레퍼런스 모델이 "이 텍스트가 일반적으로 얼마나 예측하기 어려운가"를 측정하여 보정하는 반면, MIN-K%는 고확률 토큰을 제거함으로써 비슷한 보정 효과를 달성합니다. 다만, 별도의 레퍼런스 모델이 필요하지 않다는 점에서 실용적 우위를 갖습니다.

계산 복잡도 측면에서도 MIN-K% PROB는 단일 포워드 패스 $O(n)$과 정렬 $O(n \log n)$만 필요하므로, 레퍼런스 모델 방법의 두 배 포워드 패스 비용에 비해 효율적입니다.

### WIKIMIA 벤치마크 설계

멤버십 추론 연구의 병목인 그라운드 트루스 레이블 확보 문제를 해결하기 위해, 논문은 위키피디아의 편집 이력을 활용한 동적 벤치마크를 구축합니다.

**설계 원리**: 대부분의 LLM은 특정 시점까지의 위키피디아 덤프를 학습 데이터에 포함합니다. 따라서, 모델 학습 시점(cutoff date)을 기준으로 다음과 같이 레이블을 부여할 수 있습니다.

- **멤버(Member)**: cutoff date 이전에 생성되어 학습 데이터에 포함되었을 가능성이 높은 문서
- **비멤버(Non-member)**: cutoff date 이후에 새로 생성되어 학습 데이터에 포함되지 않은 문서

예를 들어, LLaMA의 학습 데이터 수집 시점이 2023년 초라면, 2023년 3월 이후에 최초 생성된 위키피디아 문서는 비멤버로 간주할 수 있습니다.

**문서 선별 기준**: 단순히 편집된 문서가 아닌, cutoff date 이후에 **최초 생성**된 문서만을 비멤버로 선정합니다. 이는 기존 문서의 편집본이 원본과 높은 유사도를 가져 레이블 노이즈를 유발할 수 있기 때문입니다.

**데이터셋 구성**: 다양한 길이의 텍스트 세그먼트(32, 64, 128, 256 토큰)로 구성하여, 텍스트 길이에 따른 탐지 성능 변화를 체계적으로 평가할 수 있도록 합니다. 각 길이별로 멤버와 비멤버 샘플을 균등하게 배분하여 클래스 불균형 문제를 방지합니다.

이 벤치마크의 장점은 **동적(dynamic)** 특성에 있습니다. 새로운 LLM이 출시될 때마다, 해당 모델의 학습 시점에 맞추어 멤버/비멤버 집합을 재구성할 수 있습니다.

|------|:-----:|:---------:|:---------:|:---------:|:--------:|:-------:|:--------:|

- 레퍼런스 모델 기반 방법 대비 약 **5-8% 포인트의 AUC 개선**을 달성하면서도, 별도의 레퍼런스 모델 학습이 필요 없습니다.
- 모델 크기가 커질수록(7B -> 65B) 탐지 성능이 향상되는 경향이 관찰됩니다. 이는 대형 모델이 학습 데이터를 더 많이 암기하기 때문으로 해석됩니다.
- GPT-3에서 가장 높은 AUC(0.72)를 달성하였는데, 이는 GPT-3의 학습 데이터에 위키피디아가 높은 비중으로 포함되어 있기 때문으로 추정됩니다.

텍스트 길이 그래프에서는 더 흥미로운 패턴이 나타납니다. 32 토큰의 매우 짧은 텍스트에서도 Min-K% Prob은 0.71 수준의 AUC를 유지하는데, 이는 PPL(0.69)이나 Neighbor(0.67)보다 높습니다. 256 토큰에서는 AUC가 0.77까지 상승하며, 긴 텍스트에서 저확률 토큰 샘플이 충분히 확보되어 통계적 추정이 안정화되는 효과가 분명히 드러납니다.

### 하이퍼파라미터 k의 영향

$k$ 값에 따른 성능 변화를 분석한 결과, 대부분의 모델에서 $k = 20$ 부근이 최적임을 확인하였습니다.

| k (%) | 5 | 10 | 20 | 30 | 40 | 50 | 80 | 100 |
|:-----:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| AUC (LLaMA-65B) | 0.62 | 0.65 | **0.67** | 0.66 | 0.64 | 0.62 | 0.57 | 0.53 |

- $k$가 너무 낮으면(예: $k = 5$), 극소수의 토큰만 사용하게 되어 분산이 커지고 결과가 불안정해집니다. 256 토큰 텍스트에서 $k=5$이면 약 13개 토큰만 사용하게 됩니다.
- $k$가 너무 높으면(예: $k = 80$ 이상), 고빈도 토큰이 포함되기 시작하여 퍼플렉서티 기반 방법과 성능이 수렴합니다. $k = 100$이면 정확히 퍼플렉서티 방법과 동일합니다.
- $k = 10 \sim 30$ 범위에서 전반적으로 안정적인 성능을 보이며, 이는 방법의 강건성(robustness)을 시사합니다.

이 결과는 텍스트 내 약 20%의 토큰이 멤버십에 관한 핵심 정보를 담고 있으며, 나머지 80%는 멤버/비멤버에 공통되는 일반적인 언어 패턴이라는 해석을 뒷받침합니다. 이는 Zipf의 법칙과도 연관되는데, 자연어 텍스트에서 소수의 고빈도 토큰이 전체 출현의 대부분을 차지하는 분포적 특성과 일치합니다.

## 의의 및 한계

### 학술적 의의

이 논문은 LLM 시대의 멤버십 추론 연구에서 여러 가지 중요한 기여를 하였습니다.

**문제 정의의 체계화**: LLM에 대한 사전학습 데이터 탐지 문제를 명확히 정의하고, 기존 MIA 기법들이 이 설정에서 왜 실패하는지를 체계적으로 분석하였습니다. 이는 후속 연구들이 문제의 본질을 이해하고 개선 방향을 설정하는 데 중요한 토대를 제공합니다.

**평가 인프라 구축**: WIKIMIA 벤치마크는 시간 기반 멤버십 레이블링이라는 독창적 접근을 통해, 학습 데이터 비공개 모델에 대한 MIA 평가를 가능하게 하였습니다. 이 벤치마크는 후속 연구에서 표준 평가 도구로 널리 활용되고 있습니다.

**단순함의 미덕**: MIN-K% PROB는 추가 모델 학습이 필요 없고, 구현이 수 줄의 코드로 가능할 만큼 단순합니다. 이러한 단순성은 방법론의 재현 가능성과 실용적 채택 가능성을 높입니다.

### 실용적 응용

**저작권 보호**: 저작물이 LLM 학습에 무단으로 사용되었는지를 탐지하는 데 활용할 수 있습니다. 현재 진행 중인 다수의 저작권 소송(예: NYT vs OpenAI)에서 기술적 증거 확보 도구로 활용될 잠재력이 있습니다.

**개인정보 감사**: 개인 식별 정보(PII)가 포함된 텍스트가 모델 학습에 사용되었는지를 감사하여, [[GDPR]]이나 CCPA 등 개인정보 보호 규정 준수를 검증하는 데 기여할 수 있습니다.

**벤치마크 무결성 검증**: LLM 평가 벤치마크 데이터가 학습에 오염되었는지를 탐지하여, 공정하고 신뢰할 수 있는 모델 평가를 지원합니다. 이는 LLM 커뮤니티 전체의 연구 신뢰성에 기여하는 공공재적 성격을 갖습니다.

**규제 준수 도구**: EU AI Act 등 AI 규제 프레임워크에서 요구하는 학습 데이터 투명성 의무를 이행하기 위한 기술적 도구로 활용될 수 있습니다.

### 한계와 미래 연구 방향

**탐지 정확도의 실용적 한계**: 최선의 경우에도 AUC가 0.72 수준으로, 개별 텍스트 단위의 확정적 판단보다는 대량의 텍스트에 대한 통계적 경향성 분석에 적합합니다. 법적 증거로 활용하기 위해서는 더 높은 정밀도가 요구됩니다. 특히 False Positive Rate(FPR)를 1% 이하로 제어하면서도 의미 있는 True Positive Rate(TPR)을 유지하는 것은 여전히 도전적인 과제입니다.

**짧은 텍스트에 대한 취약성**: 32 토큰 이하의 짧은 텍스트에서는 통계적 추정이 불안정해져 신뢰도가 크게 하락합니다. $k=20$으로 설정하면 32 토큰 중 약 6개만 사용하게 되어 분산이 매우 커집니다. 소셜 미디어 게시물이나 짧은 댓글 수준의 텍스트에 대한 적용은 제한적입니다.

**패러프레이즈에 대한 취약성**: 원본 텍스트를 의미를 보존하면서 표현만 변경하는 패러프레이즈(paraphrase)에 대해서는 탐지 성능이 급격히 하락합니다. 모델이 원본을 학습했더라도, 변형된 텍스트에서는 토큰 확률 패턴이 달라지기 때문입니다. 이는 의도적 회피(adversarial evasion) 공격에 취약함을 의미합니다.

**모델별 성능 편차**: 모델의 크기, 아키텍처, 학습 데이터 규모, 학습 에폭 수 등에 따라 탐지 성능이 상이하게 나타납니다. 특히, 대규모 학습 데이터를 한 에폭만 학습한 모델에서는 암기 정도가 낮아 탐지가 더 어려워질 수 있습니다.

**화이트박스 설정 미활용**: 이 논문은 로그 확률만 사용하는 블랙박스 설정을 다루며, 모델의 내부 활성화(activation), 어텐션 패턴, 그래디언트 등을 활용하는 화이트박스 접근은 탐구하지 않았습니다. 오픈소스 모델에 대해서는 이러한 추가 정보가 탐지 성능을 크게 향상시킬 수 있을 것으로 예상됩니다.

**그라운드 트루스의 근본적 불확실성**: WIKIMIA 벤치마크는 시간 기반 근사 레이블을 사용하므로, 완전히 정확한 멤버십 레이블은 아닙니다. 학습 시점 이전 문서라 하더라도 실제 학습 데이터에 포함되지 않았을 수 있으며, 반대의 경우도 존재합니다.

**후속 연구 동향**: 이 논문 이후로 [[MINK++]](Shi et al., 2024), [[LOSS Attack]](Ye et al., 2024) 등 후속 연구들이 활발히 진행되고 있으며, 특히 명령어 튜닝(instruction-tuned) 모델이나 RLHF 적용 모델에 대한 MIA로 연구 범위가 확장되고 있습니다. LLM의 투명성과 책임성(accountability)에 대한 사회적 요구가 높아짐에 따라, 사전학습 데이터 탐지 기술의 중요성은 계속 증가할 것으로 전망됩니다.

## 코드 예제

### MIN-K% PROB 구현

MIN-K% PROB는 구현이 매우 간단합니다. 아래는 Hugging Face Transformers를 사용한 Python 구현 예제입니다.

```python
import torch
import numpy as np
from transformers import AutoModelForCausalLM, AutoTokenizer


def compute_min_k_prob(text: str, model, tokenizer, k: int = 20) -> float:
    """
    MIN-K% PROB 스코어를 계산합니다.

    Args:
        text: 멤버십을 판별할 텍스트
        model: 사전학습된 언어 모델
        tokenizer: 토크나이저
        k: 하위 k% 토큰 비율 (기본값: 20)

    Returns:
        MIN-K% PROB 스코어 (높을수록 멤버일 가능성이 높음)
    """
    # 토큰화
    inputs = tokenizer(text, return_tensors="pt")
    input_ids = inputs["input_ids"]

    # 모델 포워드 패스
    with torch.no_grad():
        outputs = model(**inputs)
        logits = outputs.logits  # (1, seq_len, vocab_size)

    # 각 토큰 위치에서의 로그 확률 계산
    # logits[:, :-1, :] -> 각 위치에서 다음 토큰에 대한 예측
    # input_ids[:, 1:] -> 실제 다음 토큰
    log_probs = torch.log_softmax(logits[:, :-1, :], dim=-1)
    token_log_probs = log_probs.gather(
        dim=-1,
        index=input_ids[:, 1:].unsqueeze(-1)
    ).squeeze(-1).squeeze(0)

    # numpy 변환
    token_log_probs = token_log_probs.cpu().numpy()
    n = len(token_log_probs)

    # 하위 k% 토큰 선택
    num_selected = max(1, int(np.ceil(n * k / 100)))
    sorted_log_probs = np.sort(token_log_probs)
    min_k_log_probs = sorted_log_probs[:num_selected]

    # 평균 로그 확률 반환
    return float(np.mean(min_k_log_probs))


def detect_membership(
    texts: list[str],
    model_name: str = "meta-llama/Llama-2-7b-hf",
    k: int = 20,
    threshold: float = None
) -> list[dict]:
    """
    텍스트 리스트에 대해 멤버십 탐지를 수행합니다.

    Args:
        texts: 판별할 텍스트 리스트
        model_name: 모델 이름
        k: MIN-K% 파라미터
        threshold: 판정 임계값 (None이면 스코어만 반환)

    Returns:
        각 텍스트의 스코어와 판정 결과
    """
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    model = AutoModelForCausalLM.from_pretrained(
        model_name,
        torch_dtype=torch.float16,
        device_map="auto"
    )
    model.eval()

    results = []
    for text in texts:
        score = compute_min_k_prob(text, model, tokenizer, k=k)
        result = {"text": text[:100] + "...", "score": score}
        if threshold is not None:
            result["is_member"] = score > threshold
        results.append(result)

    return results


# 사용 예시
if __name__ == "__main__":
    member_text = "Albert Einstein was born on March 14, 1879, in Ulm"
    non_member_text = "The newly discovered species was found in 2024"

    results = detect_membership(
        texts=[member_text, non_member_text],
        model_name="meta-llama/Llama-2-7b-hf",
        k=20
    )

    for r in results:
        print(f"Score: {r['score']:.4f} | {r['text']}")
```

### OpenAI API를 활용한 구현

OpenAI API에서 `logprobs` 옵션을 사용하면 블랙박스 환경에서도 MIN-K% PROB를 적용할 수 있습니다.

```python
from openai import OpenAI
import numpy as np


def min_k_prob_openai(
    text: str,
    model: str = "gpt-3.5-turbo",
    k: int = 20
) -> float:
    """
    OpenAI API의 logprobs를 활용한 MIN-K% PROB 계산
    """
    client = OpenAI()

    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": text}],
        logprobs=True,
        top_logprobs=1,
        max_tokens=1  # 로그 확률 획득만 목적
    )

    # 입력 토큰들의 로그 확률 추출
    # (주: Chat API에서는 입력 토큰의 logprobs 직접 접근에 제한이 있으므로,
    #  Completions API 또는 echo 옵션 사용이 더 적합할 수 있음)
    logprobs = []
    for token_info in response.choices[0].logprobs.content:
        logprobs.append(token_info.logprob)

    log_probs = np.array(logprobs)
    n = len(log_probs)
    num_selected = max(1, int(np.ceil(n * k / 100)))
    sorted_probs = np.sort(log_probs)

    return float(np.mean(sorted_probs[:num_selected]))
```

### AUC-ROC 평가 코드

멤버와 비멤버 샘플에 대해 MIN-K% PROB의 탐지 성능을 AUC-ROC로 평가하는 코드입니다.

```python
from sklearn.metrics import roc_auc_score, roc_curve
import matplotlib.pyplot as plt


def evaluate_detection(
    member_scores: list[float],
    non_member_scores: list[float]
) -> dict:
    """
    멤버십 탐지 성능을 AUC-ROC로 평가합니다.
    """
    labels = [1] * len(member_scores) + [0] * len(non_member_scores)
    scores = member_scores + non_member_scores

    auc = roc_auc_score(labels, scores)
    fpr, tpr, thresholds = roc_curve(labels, scores)

    # TPR@FPR=5% 계산
    tpr_at_5_fpr = tpr[np.where(fpr <= 0.05)[0][-1]]

    return {
        "auc_roc": auc,
        "tpr_at_5pct_fpr": tpr_at_5_fpr,
        "fpr": fpr,
        "tpr": tpr
    }
```

위 코드에서 핵심이 되는 `compute_min_k_prob` 함수는 단 20줄 내외로 구현되며, 이는 MIN-K% PROB 방법론의 단순함과 재현 용이성을 잘 보여줍니다. 실제 대규모 분석에서는 배치 처리, GPU 메모리 관리, 긴 텍스트에 대한 슬라이딩 윈도우 처리 등을 추가로 고려해야 합니다.
