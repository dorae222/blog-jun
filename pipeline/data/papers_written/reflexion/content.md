## 개요

"Reflexion: Language Agents with Verbal Reinforcement Learning" (Shinn et al., 2024)는 Northeastern 대학교의 Noah Shinn과 Princeton 대학교의 Shunyu Yao, Karthik Narasimhan 등이 NeurIPS 2023에서 발표한 논문입니다. 이 연구는 기존 강화학습의 **스칼라 보상 신호를 자연어 반성(verbal reflection)으로 대체**하는 혁신적인 학습 패러다임을 제안합니다.

핵심 아이디어는 언어 에이전트가 태스크 수행에 실패했을 때, 실패의 원인을 **자연어로 분석하고 반성**한 후, 이 반성을 장기 메모리에 저장하여 다음 시행에서 활용하는 것입니다. 이는 인간이 실수로부터 배우는 방식 -- "무엇이 잘못되었는지 되돌아보고, 다음에는 다르게 하겠다"는 자기 성찰 -- 을 LLM 에이전트에 구현한 것입니다.

![Reflexion의 세 가지 적용 영역 — 의사결정, 프로그래밍, 추론 태스크에서의 작동 과정](figures/fig_1.png)

*Figure 1: Reflexion의 세 가지 적용 영역. (a) 태스크가 주어지면, (b) 에이전트가 트래젝토리를 생성하고, (c) 내부/외부 평가를 통해 실패를 감지하며, (d) 자연어 반성을 생성하고, (e) 반성을 바탕으로 개선된 다음 트래젝토리를 생성한다. 의사결정(AlfWorld), 프로그래밍(HumanEval), 추론(HotPotQA) 세 도메인에서 작동한다. (Shinn et al., 2024)*

Reflexion은 AlfWorld에서 [[react]]의 75%를 **97%**로, HumanEval 코딩에서 기존 80%를 **91%**로, HotPotQA에서 34%를 **53%**로 향상시키는 등 획기적인 성능 개선을 달성합니다. 특히 이 모든 개선이 **모델의 파라미터 업데이트 없이**, 자연어 피드백만으로 이루어진다는 점이 주목할 만합니다.

## 배경 및 동기

### 기존 강화학습의 한계

전통적인 강화학습(RL)은 에이전트가 환경과 상호작용하며 스칼라 보상 신호를 통해 학습합니다. 하지만 LLM 기반 에이전트에 전통적 RL을 적용하는 것은 여러 문제가 있습니다.

**1. 학습 비용**: LLM의 파라미터(수십~수백억 개)를 강화학습으로 업데이트하는 것은 막대한 컴퓨팅 비용을 요구합니다. PPO 등의 정책 최적화 알고리즘을 GPT-3 수준의 모델에 적용하는 것은 현실적으로 매우 어렵습니다.

**2. 희소한 보상 신호**: 스칼라 보상(+1/-1)은 "무엇이 잘못되었는지"에 대한 정보를 거의 제공하지 않습니다. 100 스텝의 트래젝토리에서 어느 스텝이 문제였는지 알려주지 못합니다.

**3. 샘플 비효율성**: LLM 환경에서의 강화학습은 수만~수십만 에피소드의 경험이 필요하지만, LLM 추론의 비용을 고려하면 이는 비현실적입니다.

### ReAct 에이전트의 한계

[[react]]는 추론과 행동을 결합하여 강력한 에이전트를 구현했지만, 근본적인 한계가 있습니다. **과거 실패로부터 학습하지 못한다**는 것입니다. ReAct 에이전트가 특정 태스크에서 실패하면, 다음 시행에서도 동일한 실수를 반복할 가능성이 높습니다. 각 시행이 독립적이기 때문입니다.

인간 에이전트와 비교하면 이 차이가 명확합니다. 인간은 "지난번에 서랍 1에서 후추통을 찾으려다 실패했으니, 이번에는 조리대 위를 먼저 확인하자"와 같이 과거 경험을 활용합니다. Reflexion은 이러한 **경험적 학습**을 LLM 에이전트에 부여합니다.

### Verbal Reinforcement Learning의 핵심 통찰

Reflexion의 핵심 통찰은 다음과 같습니다.

> **LLM은 이미 풍부한 세계 지식과 추론 능력을 갖추고 있다. 부족한 것은 학습이 아니라, 자기 경험에 대한 성찰(reflection)이다.**

따라서 파라미터를 업데이트하는 대신, **자연어 반성을 생성하고 이를 컨텍스트에 추가**하는 것만으로 행동을 개선할 수 있습니다. 이는 강화학습의 "보상 → 정책 업데이트" 패러다임을 "언어 피드백 → 컨텍스트 업데이트"로 전환한 것입니다.

## 핵심 아이디어

### Reflexion 아키텍처

![Reflexion의 아키텍처 다이어그램 — Actor, Evaluator, Self-Reflection, Experience(장기 메모리)의 네 구성 요소와 환경의 상호작용](figures/fig_2.png)

*Figure 2: Reflexion의 아키텍처. Agent는 Actor(LLM), Evaluator, Self-Reflection(LLM), Experience(장기 메모리)의 네 구성 요소로 구성된다. Actor가 환경과 상호작용하여 Trajectory(단기 메모리)를 생성하고, Evaluator가 성공/실패를 판단하며, 실패 시 Self-Reflection이 언어적 반성을 생성하여 Experience에 저장한다. 다음 시행에서 Actor는 이 Experience를 참조한다. (Shinn et al., 2024)*

Reflexion은 4개의 핵심 구성 요소로 이루어져 있습니다.

**1. Actor (행동 생성기)**: [[react]] 스타일의 LLM 에이전트로, Thought-Action-Observation 루프를 실행합니다. 기존 ReAct와의 차이점은 이전 시행의 반성(reflection)을 추가 컨텍스트로 받는다는 것입니다.

**2. Evaluator (평가기)**: 에이전트의 트래젝토리가 성공적인지 판단합니다. 태스크에 따라 다른 평가 방식을 사용합니다.
- **AlfWorld**: 휴리스틱 규칙 기반 (태스크 목표 달성 여부)
- **HotPotQA**: LLM 기반 이진 분류 (답변의 정확성)
- **HumanEval**: 단위 테스트 실행 (코드의 정확성)

**3. Self-Reflection (자기 반성 생성기)**: 실패한 트래젝토리를 분석하여 "무엇이 잘못되었는지", "다음에는 어떻게 해야 하는지"를 자연어로 생성하는 LLM입니다.

**4. Experience (경험 메모리)**: 이전 시행의 반성들을 저장하는 장기 메모리입니다. 슬라이딩 윈도우 방식으로 최근 $k$개의 반성을 유지합니다.

### Reflexion 루프의 동작 과정

전체 루프를 단계별로 설명하면 다음과 같습니다.

**시행 1 (Trial 1)**:
1. Actor가 태스크를 수행 → 트래젝토리 생성
2. Evaluator가 결과 평가 → 실패 판정
3. Self-Reflection이 트래젝토리를 분석 → 반성 생성
4. 반성을 Experience에 저장

**시행 2 (Trial 2)**:
1. Actor가 이전 반성을 컨텍스트에 포함하여 태스크 재수행
2. 반성의 교훈을 바탕으로 다른 전략 시도
3. Evaluator가 재평가 → 성공 또는 다시 실패

이 과정을 최대 $T$번 반복하거나 성공할 때까지 계속합니다.

### 반성(Reflection)의 실제 예시

**AlfWorld 의사결정 태스크**:
```
반성: "지난 시행에서 나는 서랍 1에서 후추통을 찾으려 했지만
실패했다. 후추통은 보통 조리대나 선반 위에 있는 경우가 많다.
다음 시행에서는 조리대 1, 2와 선반을 먼저 확인해야 한다.
또한 물건을 찾을 때 한 곳만 보지 말고 여러 위치를 체계적으로
탐색해야 한다."
```

**HumanEval 코딩 태스크**:
```
반성: "나의 구현은 괄호의 총 개수만 확인하고 닫는 괄호의
순서를 검증하지 않았다. 예를 들어 ')('는 잘못된 것이지만
내 코드는 이를 올바르다고 판단했다. 다음에는 스택 기반
접근법을 사용하여 여는 괄호와 닫는 괄호의 순서를 정확히
추적해야 한다."
```

이러한 반성은 단순한 "실패" 신호보다 훨씬 풍부한 정보를 제공합니다. **왜** 실패했는지, **어떻게** 수정해야 하는지를 구체적으로 알려줍니다.

## 실험 결과

### AlfWorld: 의사결정

AlfWorld는 텍스트 기반 가상 환경에서 6가지 유형의 가정용 태스크를 수행하는 벤치마크입니다.

![AlfWorld에서의 Reflexion 성능 — 시행 횟수가 증가할수록 성공률이 지속적으로 상승하는 그래프](figures/fig_3_1.png)

*Figure 3: AlfWorld에서의 성능 비교. ReAct only(회색)는 약 75%에서 정체되지만, ReAct + Reflexion(Heuristic 평가: 파란색, GPT 평가: 초록색)은 시행 횟수가 증가할수록 지속적으로 향상되어 최종 97%의 성공률을 달성한다. (Shinn et al., 2024)*

| 방법 | 성공률 (10 trials) |
|------|-------------------|
| ReAct only | 75% |
| ReAct + Reflexion (Heuristic) | **97%** |
| ReAct + Reflexion (GPT) | 94% |

Reflexion은 10번의 시행 내에 97%의 태스크를 성공적으로 수행합니다. 이는 ReAct 단독(75%) 대비 **22%p의 향상**입니다. 특히 주목할 점은 성능이 시행 횟수에 따라 **단조 증가**한다는 것으로, Reflexion이 각 시행에서 효과적으로 학습하고 있음을 보여줍니다.

흥미로운 발견은 Heuristic 기반 평가가 GPT 기반 평가보다 약간 더 효과적이라는 것입니다. 이는 간단한 규칙 기반 평가(태스크 목표 달성 여부)가 LLM 기반 평가보다 더 정확하고 일관적이기 때문입니다.

### HotPotQA: 추론

![HotPotQA에서의 Reflexion 성능 — CoT와 ReAct 모두에 Reflexion을 적용했을 때의 향상을 보여주는 그래프](figures/fig_6_1.png)

*Figure 4: HotPotQA에서의 성능 비교. CoT only(회색 점선)와 ReAct only(회색 실선)는 시행이 증가해도 성능이 정체되지만, CoT + Reflexion(빨간색)과 ReAct + Reflexion(파란색)은 지속적으로 향상된다. ReAct + Reflexion이 최종 55%로 가장 높은 성능을 달성한다. (Shinn et al., 2024)*

| 방법 | 정확도 (6 trials) |
|------|------------------|
| CoT only | 34% |
| ReAct only | 34% |
| CoT + Reflexion | 40% |
| **ReAct + Reflexion** | **55%** |

HotPotQA에서 ReAct + Reflexion은 기존 ReAct 대비 **21%p의 향상**을 달성합니다. 또한 CoT + Reflexion(40%)보다도 높은 성능을 보이는데, 이는 ReAct의 외부 검색 능력이 반성과 결합될 때 더 효과적임을 보여줍니다.

### HumanEval: 코드 생성

HumanEval은 164개의 Python 함수 생성 문제로 구성된 코딩 벤치마크입니다. Reflexion은 이 태스크에서 가장 인상적인 결과를 보여줍니다.

| 방법 | pass@1 |
|------|--------|
| GPT-4 (기본) | 67.0% |
| CodeT + GPT-3.5 | 65.8% |
| GPT-4 + Reflexion | **91.0%** |
| GPT-3.5 + Reflexion | 68.1% |

GPT-4 + Reflexion은 **91.0%의 pass@1**을 달성합니다. 이는 단일 시행의 GPT-4(67%)를 24%p 능가하는 결과입니다.

코딩 태스크에서 Reflexion이 특히 효과적인 이유는 **평가가 정확하기 때문**입니다. 단위 테스트의 통과/실패는 모호함 없이 결정되며, 테스트 오류 메시지가 구체적인 실패 원인을 제공합니다. Self-Reflection은 이 구체적 오류 정보를 바탕으로 정확한 수정 방향을 제시할 수 있습니다.

### 에피소딕 메모리 소거 실험 (Ablation)

논문에서는 Reflexion의 핵심 구성 요소인 경험 메모리의 중요성을 검증하기 위한 소거 실험을 수행합니다.

| 설정 | HotPotQA 정확도 |
|------|----------------|
| 반성 없이 단순 재시도 | 36% |
| 반성 O, 메모리 없음 (매 시행 독립) | 40% |
| **Reflexion (반성 + 메모리)** | **55%** |

반성 없이 단순 재시도(re-try)는 거의 효과가 없으며, 반성을 생성하더라도 이를 메모리에 저장하지 않으면 효과가 제한적입니다. 반성과 메모리의 **조합**이 핵심입니다.

### 실패 사례 분석

![WebShop에서의 Reflexion 성능 — ReAct + Reflexion이 ReAct only와 비슷한 수준에 머무르는 결과](figures/fig_11.png)

*Figure 5: WebShop에서의 Reflexion 성능. ReAct + Reflexion(파란색)이 ReAct only(회색)와 큰 차이를 보이지 않는다. WebShop은 각 에피소드의 상품과 검색 결과가 다르기 때문에, 이전 경험의 반성이 새로운 에피소드에 일반화되기 어렵다. (Shinn et al., 2024)*

WebShop에서는 Reflexion이 유의미한 향상을 보이지 않습니다. 그 원인은 WebShop의 각 에피소드가 **서로 다른 상품과 환경**을 가지므로, 한 에피소드에서의 반성이 다른 에피소드에 직접 적용되기 어렵기 때문입니다. 이는 Reflexion이 **에피소드 내 재시도(same-task retry)**에서 효과적이지만, **에피소드 간 전이(cross-task transfer)**에서는 한계가 있음을 보여줍니다.

## 방법론 상세 분석

### 전통적 RL vs Verbal RL 비교

| 속성 | 전통적 RL | Reflexion (Verbal RL) |
|------|----------|----------------------|
| 피드백 형태 | 스칼라 보상 ($r \in \mathbb{R}$) | 자연어 반성 |
| 학습 방식 | 그래디언트 기반 정책 업데이트 | 컨텍스트 기반 행동 수정 |
| 정보 밀도 | 낮음 (성공/실패) | 높음 (원인 분석 + 수정 방향) |
| 학습 비용 | 높음 (역전파) | 낮음 (추론만) |
| 일반화 | 정책 수준 | 에피소드 수준 |
| 영구성 | 파라미터에 영구 반영 | 컨텍스트 윈도우 내에서만 유효 |

### 평가기(Evaluator)의 설계

Reflexion의 성능은 평가기의 정확성에 크게 의존합니다. 논문에서는 태스크별로 다른 평가 전략을 사용합니다.

**외부 평가 (Ground Truth 기반)**: 단위 테스트(HumanEval), 정답 비교(HotPotQA) 등 명확한 정답이 있는 경우. 가장 정확하고 효과적입니다.

**휴리스틱 평가**: AlfWorld에서 태스크 목표 달성 여부를 규칙 기반으로 판단. 정확하지만 적용 범위가 제한적입니다.

**LLM 기반 자기 평가**: 별도의 LLM이 트래젝토리의 성공 여부를 판단. 범용적이지만 오판의 위험이 있습니다.

:::warning
Reflexion의 핵심 한계는 **평가기의 정확성에 의존**한다는 것입니다. 평가기가 성공을 실패로 오판하면 불필요한 수정이 이루어지고, 실패를 성공으로 오판하면 학습 기회를 놓칩니다. 실무에서는 가능한 한 구체적이고 검증 가능한 평가 기준을 설계하는 것이 중요합니다.
:::

### 반성의 품질과 구체성

반성의 효과는 그 **구체성**에 크게 의존합니다. 논문에서 관찰한 좋은 반성과 나쁜 반성의 차이를 살펴보겠습니다.

**비효과적인 반성 (Too vague)**:
> "나는 더 주의 깊게 탐색해야 한다."

**효과적인 반성 (Specific and actionable)**:
> "나는 후추통을 서랍에서 찾으려 했지만, 후추통 같은 양념은 보통 조리대나 선반 위에 있다. 다음에는 먼저 countertop 1, 2, 3을 확인하고, 그래도 없으면 shelf 1, 2를 확인해야 한다."

효과적인 반성은 (1) 구체적인 실패 원인을 식별하고, (2) 다음 시행에서의 구체적 행동 계획을 포함합니다.

### 슬라이딩 윈도우 메모리

Reflexion은 모든 과거 반성을 저장하는 것이 아니라, **최근 $k$개의 반성**만 유지하는 슬라이딩 윈도우 방식을 사용합니다. 이는 두 가지 이유에서입니다.

1. **컨텍스트 윈도우 제한**: LLM의 컨텍스트 윈도우 크기에 제한이 있으므로, 무한정 반성을 추가할 수 없습니다.
2. **최신 반성의 관련성**: 초기 시행의 반성보다 최근 시행의 반성이 현재 상태에 더 관련이 높습니다.

논문에서는 $k = 3$을 기본 설정으로 사용합니다.

## 한계 및 의의

### 한계

1. **에피소드 간 전이의 한계**: Reflexion의 반성은 주로 동일 태스크의 재시도에서 효과적이며, 새로운 태스크로의 전이(transfer)는 제한적입니다.

2. **비영구적 학습**: 반성은 LLM의 파라미터에 반영되지 않으므로, 컨텍스트 윈도우에서 벗어나면 학습 효과가 사라집니다. 장기적 지식 축적이 어렵습니다.

3. **평가기 의존성**: 정확한 성공/실패 판단이 어려운 태스크(창작, 주관적 판단 등)에서는 Reflexion의 효과가 제한적입니다.

4. **무한 루프 위험**: 모델이 반복적으로 동일한 실수를 하면서 비슷한 반성을 생성하는 경우, 탈출이 어려울 수 있습니다.

5. **반성의 hallucination**: Self-Reflection 자체도 LLM이 생성하므로, 잘못된 원인 분석을 할 수 있으며, 이 경우 후속 시행이 오히려 악화될 수 있습니다.

### 학술적 의의

1. **새로운 학습 패러다임**: 그래디언트 기반 학습과 in-context learning 사이의 새로운 학습 패러다임을 제시했습니다. 파라미터를 업데이트하지 않으면서도 경험으로부터 학습하는 "verbal reinforcement learning"이라는 개념을 확립했습니다.

2. **자기 개선(Self-Improvement) 에이전트**: LLM이 자신의 실수를 스스로 분석하고 개선하는 자기 개선 에이전트의 가능성을 보여주었습니다. 이는 이후 Self-Refine, LATS, Voyager 등의 연구로 이어집니다.

3. **메모리 증강 에이전트**: 에이전트에 경험적 메모리를 추가하는 것의 효과를 실증했습니다. 이는 이후 MemGPT, Generative Agents 등 메모리 증강 에이전트 연구의 기초가 됩니다.

### 실무적 의의

1. **코드 디버깅 자동화**: Reflexion의 코딩 태스크 결과(91% pass@1)는 자동 코드 디버깅의 가능성을 보여줍니다. 테스트 실패 → 반성 → 코드 수정의 루프는 실무에서 즉시 활용 가능합니다.

2. **에이전트 복원력(Resilience)**: 단일 시행에서 실패하더라도 자동으로 재시도하고 개선하는 에이전트를 구축할 수 있어, 프로덕션 환경에서의 에이전트 안정성을 높일 수 있습니다.

3. **인간 피드백 통합**: Reflexion의 프레임워크는 인간 피드백을 자연스럽게 통합할 수 있습니다. 인간이 반성의 내용을 수정하거나 추가 정보를 제공하면, 에이전트의 학습이 더 효과적으로 이루어집니다.

## 추가 분석

### HumanEval 코딩 태스크 상세 분석

Reflexion이 코딩 태스크에서 특히 뛰어난 성능을 보이는 이유를 상세히 분석합니다.

**단위 테스트의 역할**: 코딩 태스크에서 Reflexion의 평가기는 **단위 테스트 실행**입니다. 이는 다른 태스크의 휴리스틱/LLM 기반 평가보다 훨씬 정확하고 구체적입니다.

단위 테스트가 제공하는 정보의 풍부함을 살펴보겠습니다.

```python
# 테스트 실패 메시지 예시
AssertionError: check_brackets(")(") should return False, got True
# → "닫는 괄호가 여는 괄호보다 먼저 나오는 경우를 처리하지 못함"
```

이 오류 메시지에서 Self-Reflection은 다음과 같은 구체적 반성을 생성합니다.

```
반성: "내 구현은 괄호의 총 개수만 확인하고, 순서를 검증하지 않았다.
')(' 같은 입력에서 여는 괄호보다 닫는 괄호가 먼저 나오면 False를
반환해야 하는데, 내 코드는 이를 True로 판단했다. 스택 기반
접근법을 사용하여 여는 괄호를 push하고 닫는 괄호를 만나면
pop하는 방식으로 수정해야 한다."
```

이처럼 **구체적인 테스트 케이스 → 구체적인 실패 원인 → 구체적인 수정 방향**의 체인이 형성되어, Reflexion의 학습이 매우 효율적으로 이루어집니다.

**시행별 성공률 추이**:

| 시행 | pass@1 (GPT-4) | 누적 향상 |
|------|----------------|----------|
| 1 | 67.0% | baseline |
| 2 | 82.0% | +15.0%p |
| 3 | 88.0% | +21.0%p |
| 4 | 91.0% | +24.0%p |

대부분의 향상이 처음 2~3번의 시행 내에 달성됩니다. 4번째 시행에서는 한계 효과가 줄어들지만 여전히 유의미한 향상이 있습니다.

### 반성의 다양성과 창의성

흥미로운 관찰은 Reflexion의 반성이 단순한 오류 수정을 넘어 **전략적 재구성**을 수행하는 경우가 있다는 것입니다.

**예시: AlfWorld의 물건 찾기 태스크**

시행 1 반성: "서랍을 순서대로 탐색했지만 후추통을 찾지 못했다."

시행 2 반성: "조리대도 확인했지만 없었다. 후추통은 양념장이나 찬장 같은 수납 공간에 있을 수 있다."

시행 3 반성: "찬장에서도 없었다. **탐색 순서를 바꿔야 한다.** 가장 가능성이 높은 곳(조리대)부터 확인하고, 없으면 덜 일반적인 위치(냉장고, 전자레인지 등)로 넓혀가야 한다."

이처럼 반성이 축적되면서 **메타 전략**(어떻게 탐색할 것인가에 대한 전략)이 형성되는 현상이 관찰됩니다.

### Reflexion vs 단순 재시도(Retry) 비교

Reflexion의 효과가 단순히 "여러 번 시도하면 하나는 맞을 것"이라는 확률적 효과인지, 아니면 반성에 의한 **실질적 학습**인지를 구분하는 것이 중요합니다.

| 설정 | AlfWorld 성공률 | HotPotQA 정확도 | HumanEval pass@1 |
|------|---------------|----------------|-----------------|
| 단일 시행 | 63% | 34% | 67% |
| 3회 단순 재시도 (best of 3) | 72% | 37% | 73% |
| 3회 Reflexion | **89%** | **48%** | **88%** |

단순 재시도도 약간의 향상을 보이지만, Reflexion의 향상폭은 **2~4배** 더 큽니다. 이는 Reflexion의 성능 향상이 확률적 효과가 아닌, 반성에 의한 **체계적 학습**에 의한 것임을 입증합니다.

### 실무 적용 패턴

Reflexion을 실무에서 적용할 수 있는 대표적인 패턴을 정리합니다.

**패턴 1: 자동 코드 디버깅**

```
1. LLM이 코드 생성
2. 테스트 실행 → 실패
3. 오류 메시지 + 코드 → Self-Reflection 생성
4. 반성을 컨텍스트에 추가하여 코드 재생성
5. 테스트 통과할 때까지 반복 (최대 N회)
```

**패턴 2: RAG 품질 개선**

```
1. RAG 시스템이 답변 생성
2. 답변 품질 평가 (자동 또는 인간)
3. 저품질 시 Self-Reflection 생성
   ("검색 쿼리가 너무 넓었다", "문서의 핵심 부분을 놓쳤다")
4. 반성을 바탕으로 검색 쿼리 수정 → 재시도
```

**패턴 3: 에이전트 태스크 복원**

```
1. 에이전트가 복잡한 태스크 수행 중 실패
2. 실패 트래젝토리 분석 → 반성 생성
3. 반성을 시스템 프롬프트에 추가
4. 동일 태스크 재시도 (다른 전략으로)
```

:::tip
실무에서 Reflexion을 적용할 때 가장 중요한 요소는 **평가기의 정확성**입니다. 코딩 태스크(단위 테스트)처럼 객관적 평가가 가능한 경우 가장 효과적이며, 주관적 판단이 필요한 경우에는 인간 평가자를 루프에 포함시키는 것이 좋습니다.
:::

## 후속 연구와의 연결

Reflexion은 다양한 후속 연구에 영감을 주었습니다.

- **Self-Refine**: 반성과 수정을 출력 텍스트 자체에 적용 (번역, 코드, 대화 등)
- **LATS (Language Agent Tree Search)**: [[tree-of-thoughts]]의 탐색과 Reflexion의 반성을 결합
- **Voyager**: 마인크래프트에서 Reflexion 기반 스킬 학습
- **Generative Agents**: 경험 메모리와 반성을 통한 생활형 에이전트 시뮬레이션
- **MemGPT**: 장기 메모리 관리를 통한 에이전트의 컨텍스트 확장
- **Self-Debugging**: Reflexion 원리를 코드 디버깅에 특화한 연구
- **AgentCoder**: 다중 에이전트(설계자/코더/테스터)가 Reflexion 루프를 형성

### 현대 에이전트 시스템에서의 Reflexion

Reflexion의 원리는 현대 에이전트 시스템에서 다양한 형태로 구현되고 있습니다.

**Claude Code / Cursor**: 코드 생성 → 오류 발생 → 자동 디버깅의 반복 루프가 Reflexion 패턴을 내재화하고 있습니다.

**GitHub Copilot Workspace**: 이슈 분석 → 코드 수정 제안 → 테스트 → 반성 → 재수정의 루프를 구현합니다.

**Devin**: 자율 코딩 에이전트로, 테스트 실패 시 자동으로 디버깅하고 수정하는 Reflexion 기반 루프를 활용합니다.

이러한 시스템들은 Reflexion이 제시한 "실패 → 반성 → 재시도" 패러다임을 프로덕션 수준으로 구현한 것으로, Reflexion의 학술적 기여가 실무에서 가치를 창출하고 있음을 보여줍니다.

## 결론

Reflexion은 "실패로부터 배우는" 에이전트를 구현한 논문으로, LLM 에이전트 연구에서 **학습(learning)** 차원을 열어준 중요한 연구입니다. 기존 [[react]]가 "생각하면서 행동하라"를 가르쳤다면, Reflexion은 "실패하면 반성하고, 반성을 바탕으로 더 나아져라"를 가르칩니다.

이 논문의 기여는 세 가지로 요약됩니다. 첫째, 스칼라 보상을 자연어 반성으로 대체하는 **verbal reinforcement learning** 패러다임의 제안. 둘째, 모델 파라미터 업데이트 없이 **컨텍스트 기반 경험 학습**이 효과적임을 실증. 셋째, 코딩(91% pass@1), 의사결정(97% AlfWorld), 추론(55% HotPotQA) 등 **다양한 도메인에서의 범용적 효과** 입증.

이 논문의 가장 근본적인 기여는, LLM의 강력한 자연어 이해/생성 능력이 **자기 성찰(self-reflection)**에도 활용될 수 있음을 보여준 것입니다. 스칼라 보상이라는 제한적 신호 대신, 자연어의 풍부한 표현력을 활용하면 훨씬 적은 시행으로도 효과적인 학습이 가능합니다. 이 통찰은 향후 자기 개선 AI 시스템의 설계에 핵심적인 영향을 미치고 있습니다.
