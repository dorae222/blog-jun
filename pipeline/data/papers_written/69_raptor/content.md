# RAPTOR: 트리 구조 검색을 위한 재귀적 추상화 처리

## 논문 개요

:::info
**Paper:** RAPTOR: Recursive Abstractive Processing for Tree-Organized Retrieval (arXiv:2401.18059, ICLR 2024)
**저자:** Parth Sarthi, Salman Abdullah, Aditi Tuli, Shubh Khanna, Anna Goldie, Christopher D. Manning
**소속:** Stanford University
**키워드:** Recursive Summarization, Tree-Structured Retrieval, Multi-Level Abstraction, RAG
:::

기존 RAG(Retrieval-Augmented Generation) 시스템은 문서를 고정 크기 청크로 분할하고, 질문과 가장 유사한 청크를 검색하는 **평면적(flat)** 구조에 기반한다. 이 접근법은 세부 정보를 찾는 질문에는 효과적이지만, 문서 전체의 **주제적 이해**나 **다단계 추론**이 필요한 질문에는 근본적인 한계가 있다.

RAPTOR(Recursive Abstractive Processing for Tree-Organized Retrieval)는 이 문제를 해결하기 위해 **재귀적 요약 트리** 구조를 제안한다. 텍스트 청크를 클러스터링하고 요약하는 과정을 반복하여, 원본 텍스트(리프 노드)부터 전체 문서의 핵심 주제(루트 노드)까지 **다양한 추상화 수준**의 노드를 갖는 트리를 구축한다. 질문의 특성에 따라 적절한 추상화 수준에서 검색할 수 있어, 세부 사실과 전체적 맥락 모두를 효과적으로 처리할 수 있다.

---

## 배경: 기존 RAG의 한계

### 평면 청킹의 문제

전통적인 RAG 파이프라인:

```
문서 → 고정 크기 청크 분할 → 벡터 임베딩 → 인덱싱 → 질문 유사도 검색
```

이 접근법의 문제:

1. **정보 분산**: 하나의 개념이 여러 청크에 걸쳐 있으면, 개별 청크만으로는 완전한 정보를 얻을 수 없다

2. **추상적 질문 처리 불가**: "이 논문의 주요 기여는 무엇인가?"와 같은 질문은 문서 전체를 이해해야 답할 수 있지만, 개별 청크에는 이 정보가 없다

3. **다단계 추론 불가**: "A가 B에 미친 영향"처럼 여러 부분의 정보를 종합해야 하는 질문에 약하다

4. **컨텍스트 윈도우 제한**: 관련 청크를 여러 개 검색하더라도 LLM의 컨텍스트 윈도우에 한계가 있다

:::warning
"나무만 보고 숲을 보지 못하는" 문제가 기존 RAG의 핵심 한계이다. 개별 청크(나무)는 찾을 수 있지만, 문서 전체의 흐름(숲)을 이해하는 질문에는 답할 수 없다.
:::

### 기존 해결 시도

이 문제에 대한 기존 접근법들:

| 방법 | 원리 | 한계 |
|------|------|------|
| 큰 청크 크기 | 더 많은 맥락 포함 | 관련 없는 정보도 포함, 임베딩 품질 저하 |
| 오버랩 청킹 | 청크 간 겹침으로 연속성 유지 | 중복 정보, 전체적 이해에는 불충분 |
| 계층적 검색 | 섹션 → 단락 순으로 검색 | 문서 구조 의존, 요약 부재 |
| Map-Reduce | 각 청크의 답을 종합 | LLM 호출 횟수 과다, 비용 |
| Parent-Child | 부모 청크를 함께 반환 | 추상화가 아닌 단순 확장 |

이 방법들은 부분적으로 문제를 완화하지만, **다양한 추상화 수준에서의 검색**이라는 근본적 해결책을 제시하지 못한다.

### 인간의 문서 이해 방식

인간이 긴 문서를 이해하는 방식을 관찰하면:

1. **먼저 전체 구조 파악**: 목차, 제목 등으로 전체적인 흐름 이해
2. **관심 부분 상세 읽기**: 필요한 세부 정보를 해당 섹션에서 찾기
3. **연결 짓기**: 여러 부분의 정보를 종합하여 이해

RAPTOR는 이 과정을 모방하여, 다양한 추상화 수준의 정보를 트리 구조로 조직한다.

## 핵심 아이디어: 재귀적 요약 트리

### 트리 구축 과정

RAPTOR의 트리 구축은 **상향식(bottom-up)**으로 진행된다:

**Level 0 (리프 노드):** 원본 텍스트의 청크들
```
[청크1] [청크2] [청크3] [청크4] [청크5] [청크6] [청크7] [청크8]
```

**Level 1 (중간 노드):** 유사한 청크들을 클러스터링하고 요약
```
[요약A: 청크1+2+3]  [요약B: 청크4+5]  [요약C: 청크6+7+8]
```

**Level 2 (상위 노드):** 요약들을 다시 클러스터링하고 요약
```
[요약D: 요약A+요약B]  [요약E: 요약C]
```

**Level 3 (루트 노드):** 최종 요약
```
[요약F: 요약D+요약E] ← 문서 전체의 핵심 주제
```

이 과정을 더 이상 클러스터링할 노드가 없을 때까지 반복한다.

### 클러스터링: Soft Clustering with GMM

RAPTOR는 **가우시안 혼합 모델(Gaussian Mixture Model, GMM)**을 사용하여 청크들을 클러스터링한다.

**왜 GMM인가?**

K-Means와 같은 하드 클러스터링은 각 청크를 정확히 하나의 클러스터에 할당한다. 그러나 실제 텍스트에서는 하나의 청크가 **여러 주제**에 관련될 수 있다. GMM은 **소프트 클러스터링**으로, 각 청크가 여러 클러스터에 확률적으로 속할 수 있다.

$$P(\text{클러스터}_k | \text{청크}_i) = \frac{\pi_k \cdot \mathcal{N}(\mathbf{x}_i | \boldsymbol{\mu}_k, \boldsymbol{\Sigma}_k)}{\sum_j \pi_j \cdot \mathcal{N}(\mathbf{x}_i | \boldsymbol{\mu}_j, \boldsymbol{\Sigma}_j)}$$

클러스터 할당:
- 각 청크가 **가장 높은 확률**의 클러스터에 할당
- 확률이 일정 임계값 이상인 **다른 클러스터에도 중복 할당** 가능

:::tip
소프트 클러스터링은 RAPTOR의 핵심 설계 결정이다. 예를 들어, "트랜스포머의 어텐션 메커니즘"을 설명하는 청크는 "모델 아키텍처" 클러스터와 "학습 방법" 클러스터 모두에 속할 수 있다. 이를 통해 다양한 관점에서의 요약이 가능해진다.
:::

### 차원 축소: UMAP

고차원 임베딩 공간에서의 클러스터링은 **차원의 저주(curse of dimensionality)**로 인해 효과적이지 않을 수 있다. RAPTOR는 **UMAP (Uniform Manifold Approximation and Projection)**을 사용하여 차원을 축소한 후 클러스터링을 수행한다.

UMAP의 장점:
- 로컬 구조와 글로벌 구조를 동시에 보존
- t-SNE보다 빠르고 확장성이 좋음
- 비선형 차원 축소로 복잡한 클러스터 구조 포착

### 요약: LLM 기반 추상적 요약

각 클러스터의 텍스트를 **LLM(GPT-4)**을 사용하여 추상적으로 요약한다:

```
프롬프트:
"다음 텍스트들의 핵심 내용을 종합하여 간결하게 요약하세요.
원본 텍스트에 없는 정보를 추가하지 마세요.

텍스트 1: [클러스터의 청크 1]
텍스트 2: [클러스터의 청크 2]
텍스트 3: [클러스터의 청크 3]

요약:"
```

요약의 특성:
- **추상적(abstractive)**: 원본 문장을 그대로 복사하지 않고, 핵심을 새로운 문장으로 표현
- **정보 압축**: 여러 청크의 정보를 하나의 짧은 텍스트로 압축
- **주제 통합**: 관련 청크들의 공통 주제를 명시적으로 표현

## 검색 전략

### 트리 순회 (Tree Traversal)

트리가 구축되면, 질문에 따라 **적절한 추상화 수준에서** 정보를 검색한다.

RAPTOR는 두 가지 검색 전략을 제안한다:

#### 1. 트리 순회 검색 (Tree Traversal Retrieval)

루트에서 리프까지 **하향식(top-down)**으로 탐색:

1. 루트 레벨에서 가장 유사한 노드 선택
2. 선택된 노드의 자식 노드들 중 가장 유사한 것 선택
3. 리프 레벨까지 반복

```
Level 3: [루트] → 유사도 기반 선택
              ↓
Level 2: [노드A] [노드B*] → B 선택
                    ↓
Level 1: [노드C] [노드D*] [노드E] → D 선택
                    ↓
Level 0: [청크7*] [청크8] → 청크7 반환
```

장점: 검색 공간을 점진적으로 좁혀 효율적
단점: 상위 레벨에서의 잘못된 선택이 전파

#### 2. 축소 트리 검색 (Collapsed Tree Retrieval)

모든 레벨의 노드를 하나의 **평면 인덱스**에 넣고 검색:

```
검색 대상: [청크1] [청크2] ... [요약A] [요약B] ... [루트요약]
         (모든 레벨의 모든 노드)
```

질문과 가장 유사한 노드를 레벨에 관계없이 선택한다.

장점: 상위 레벨 오류 전파 없음, 모든 추상화 수준에서 동시 검색
단점: 검색 공간이 크다 (하지만 벡터 검색이므로 실용적)

:::info
논문의 실험에서 **축소 트리 검색**이 트리 순회 검색보다 일관되게 우수한 성능을 보였다. 이는 질문에 따라 필요한 추상화 수준이 다르며, 이를 사전에 결정하는 것보다 모든 수준에서 동시에 검색하는 것이 더 효과적이라는 것을 시사한다.
:::

### 검색 결과의 조합

최종 검색 결과는 다양한 추상화 수준의 노드들로 구성될 수 있다:

- **세부 질문**: 리프 노드(원본 청크)가 선택될 가능성 높음
- **주제적 질문**: 중간/상위 요약 노드가 선택될 가능성 높음
- **복합 질문**: 여러 수준의 노드가 함께 선택

이 다양한 수준의 정보가 LLM의 컨텍스트에 함께 제공되어, 세부 사실과 전체적 맥락을 동시에 활용할 수 있게 한다.

## 실험 결과

### 벤치마크 데이터셋

RAPTOR를 3개의 QA 벤치마크에서 평가했다:

1. **NarrativeQA**: 긴 서사 텍스트에 대한 질의응답 (전체적 이해 필요)
2. **QASPER**: 학술 논문에 대한 질의응답 (구조적 이해 필요)
3. **QuALITY**: 긴 문서에 대한 다지선다 질의응답

### 핵심 결과

#### NarrativeQA

| 방법 | METEOR | F1 |
|------|--------|-----|
| BM25 + GPT-4 | 26.8 | 30.2 |
| DPR + GPT-4 | 27.4 | 31.1 |
| SBERT + GPT-4 (flat) | 28.1 | 31.8 |
| RAPTOR + GPT-4 | **30.8** | **34.5** |

RAPTOR는 평면 검색 대비 **약 3 포인트의 개선**을 보인다.

#### QASPER

| 방법 | F1 |
|------|-----|
| BM25 + GPT-4 | 36.7 |
| SBERT + GPT-4 (flat) | 38.4 |
| RAPTOR + GPT-4 | **40.2** |

#### QuALITY

| 방법 | 정확도 |
|------|-------|
| BM25 + GPT-4 | 56.3% |
| SBERT + GPT-4 (flat) | 57.8% |
| RAPTOR + GPT-4 | **62.4%** |

QuALITY에서 가장 큰 개선을 보인다 ( 이는 QuALITY의 질문이 특히 **전체적 이해**를 요구하기 때문이다.

### 질문 유형별 분석

RAPTOR의 효과는 질문 유형에 따라 달라진다:

| 질문 유형 | 평면 검색 대비 개선 |
|----------|-------------------|
| 세부 사실 질문 | +0.5 ~ +1.0 |
| 주제/요약 질문 | **+3.0 ~ +5.0** |
| 다단계 추론 질문 | **+2.5 ~ +4.0** |
| 비교 질문 | **+2.0 ~ +3.5** |

:::tip
RAPTOR의 효과는 **주제적 이해**와 **다단계 추론**이 필요한 질문에서 극대화된다. 단순한 세부 사실 검색에서는 개선이 제한적이며, 이는 예상대로이다 ) 세부 사실 질문에는 평면 검색으로도 충분하기 때문이다.
:::

### 검색 전략 비교

두 검색 전략의 비교 (NarrativeQA 기준):

| 검색 전략 | METEOR | F1 |
|----------|--------|-----|
| Tree Traversal | 29.3 | 33.1 |
| Collapsed Tree | **30.8** | **34.5** |

축소 트리 검색이 일관되게 우수하여, 논문에서는 이를 기본 전략으로 권장한다.

### 트리 깊이의 영향

트리의 최대 깊이에 따른 성능:

| 최대 깊이 | METEOR (NarrativeQA) |
|----------|---------------------|
| 0 (평면, 트리 없음) | 28.1 |
| 1 (1단계 요약) | 29.5 |
| 2 (2단계 요약) | 30.4 |
| 3+ (자동 결정) | **30.8** |

1단계 요약만으로도 상당한 개선이 있으며, 2-3단계에서 최적에 도달한다.

## 기술적 심층 분석

### 클러스터 수 결정

RAPTOR는 클러스터 수를 자동으로 결정한다. BIC(Bayesian Information Criterion)를 사용:

$$\text{BIC} = -2 \ln \hat{L} + k \ln n$$

여기서 $\hat{L}$은 최대 우도, $k$는 파라미터 수, $n$은 데이터 포인트 수이다. BIC가 최소인 클러스터 수를 선택한다.

이 자동 결정은 중요하다, 문서의 내용에 따라 적절한 클러스터 수가 달라지기 때문이다. 기술 문서는 명확한 섹션 구분으로 클러스터가 잘 형성되지만, 서사 텍스트는 주제가 점진적으로 변화하므로 클러스터 경계가 모호하다.

### 요약 품질의 영향

트리의 품질은 요약의 품질에 크게 의존한다. 논문에서 다양한 요약 모델의 영향을 분석:

| 요약 모델 | METEOR |
|----------|--------|
| GPT-3.5 | 29.8 |
| GPT-4 | **30.8** |
| Claude (Sonnet) | 30.5 |

GPT-4가 가장 높은 성능을 보이지만, GPT-3.5도 평면 검색 대비 상당한 개선을 달성한다. 이는 RAPTOR의 효과가 요약 모델의 품질뿐 아니라 **트리 구조 자체**에서도 기인함을 보여준다.

### 임베딩 모델의 영향

트리 구축과 검색에 사용되는 임베딩 모델의 영향:

| 임베딩 모델 | 차원 | METEOR |
|-----------|------|--------|
| text-embedding-ada-002 | 1536 | 30.1 |
| text-embedding-3-small | 1536 | 30.5 |
| SBERT (all-MiniLM) | 384 | 29.8 |

고품질 임베딩 모델이 약간 더 나은 결과를 보이지만, 차이는 크지 않다.

### 계산 비용

RAPTOR의 추가 비용:

| 항목 | 비용 |
|------|------|
| 트리 구축 (인덱싱) | LLM 요약 호출 비용 (문서당 1회) |
| 검색 시점 | 평면 검색과 동일 (인덱스 크기만 증가) |
| 저장 공간 | 원본 청크 + 모든 요약 노드 |

트리 구축은 일회성 비용이며, 검색 시점의 추가 비용은 미미하다. 인덱스 크기는 약 1.5-2배 증가한다 (요약 노드 추가로).

## GraphRAG와의 비교

### 접근법의 차이

RAPTOR와 [[graphrag-knowledge-graph]]는 모두 기존 RAG의 평면 구조 한계를 해결하려는 시도이지만, 접근법이 다르다:

| 측면 | RAPTOR | GraphRAG |
|------|--------|----------|
| 구조 | 트리 (계층적) | 그래프 (네트워크) |
| 관계 표현 | 포함 관계 (부모-자식) | 다양한 관계 (엔티티 간) |
| 구축 방법 | 클러스터링 + 요약 | 엔티티/관계 추출 |
| 강점 | 추상화 수준 조절 | 엔티티 간 관계 추론 |
| 약점 | 엔티티 간 관계 미표현 | 추상화 수준 부재 |

두 방법은 **상호 보완적**이다:
- RAPTOR: "이 논문의 주요 기여는?" → 상위 요약 노드에서 답변
- GraphRAG: "A 개념과 B 개념의 관계는?" → 그래프의 관계 엣지에서 답변

### 결합 가능성

이론적으로 RAPTOR의 트리 구조와 GraphRAG의 그래프 구조를 결합하면:

- 트리의 각 노드에 **엔티티 그래프** 연결
- 추상화 수준별로 다른 밀도의 그래프 유지
- 질문에 따라 트리 탐색 + 그래프 탐색을 동시 수행

이러한 결합은 아직 활발히 연구되고 있는 방향이다.

## 실용적 구현 가이드

### 구현 시 고려사항

RAPTOR를 실제 시스템에 적용할 때의 고려사항:

1. **청크 크기**: 리프 노드의 청크 크기는 100-200 토큰이 최적
2. **클러스터링 임계값**: GMM의 소프트 할당 임계값은 0.1-0.3이 적절
3. **요약 길이**: 각 요약 노드는 원본 청크들의 1/3-1/5 길이가 적절
4. **트리 깊이**: 대부분의 문서에서 2-3 레벨이 충분
5. **업데이트 전략**: 문서 추가 시 영향받는 서브트리만 재구축

### LlamaIndex 구현

LlamaIndex에서의 RAPTOR 구현 예시:

```python
from llama_index.packs.raptor import RaptorPack

raptor_pack = RaptorPack(
    documents=documents,
    embed_model=embed_model,
    llm=llm,
    similarity_top_k=5,
    mode="collapsed"  # "collapsed" or "tree_traversal"
)

response = raptor_pack.run("문서의 주요 기여는 무엇인가?")
```

### 비용 최적화

요약에 LLM 호출이 필요하므로 비용이 발생한다. 최적화 전략:

| 전략 | 효과 |
|------|------|
| 작은 LLM 사용 (GPT-3.5) | 비용 90% 절감, 성능 소폭 감소 |
| 배치 요약 | API 호출 횟수 감소 |
| 캐싱 | 동일 클러스터 재요약 방지 |
| 증분 업데이트 | 변경된 부분만 재구축 |

## 한계와 후속 연구

### RAPTOR의 한계

1. **요약 비용**: LLM 기반 요약이 필요하여 인덱싱 비용이 평면 RAG 대비 높다

2. **요약 오류 전파**: 하위 요약의 오류가 상위 요약으로 전파되어 누적될 수 있다

3. **정적 트리**: 한 번 구축된 트리는 질문에 따라 동적으로 변하지 않는다

4. **긴 문서 제한**: 매우 긴 문서(수백 페이지)에서는 트리 구축 비용이 상당하다

5. **단일 문서 최적화**: 여러 문서에 걸친 교차 문서 검색에는 최적화되지 않음

6. **환각 위험**: LLM 요약 과정에서 원본에 없는 정보가 추가될 수 있다 ([[context-compression]]에서도 동일한 문제)

### 후속 연구 방향

1. **동적 트리 구축**: 질문에 따라 트리 구조를 적응적으로 조정
2. **다문서 RAPTOR**: 여러 문서에 걸친 통합 트리 구축
3. **경량 요약**: LLM 대신 경량 모델로 요약 (비용 절감)
4. **그래프 + 트리**: RAPTOR와 GraphRAG의 결합
5. **증분 업데이트**: 문서 변경 시 트리의 부분적 업데이트
6. **다국어 확장**: 다국어 문서에 대한 트리 구축

## RAPTOR의 위치: RAG 발전사

### RAG 기술의 진화

RAG 기술은 다음과 같이 진화해왔다:

| 시기 | 기술 | 핵심 개선 |
|------|------|----------|
| 2020 | [[dpr]] + RAG | 밀집 검색 기반 첫 RAG |
| 2021 | FiD, RETRO | 다중 패시지 융합 |
| 2022 | Hybrid Search | BM25 + 밀집 검색 결합 |
| 2023 | LlamaIndex, LangChain | RAG 프레임워크 |
| 2024 | RAPTOR, GraphRAG | **구조적 RAG** |
| 2024+ | Agentic RAG | 에이전트 기반 적응적 검색 |

RAPTOR는 "구조적 RAG" 시대를 연 핵심 연구 중 하나로, 평면적 검색의 한계를 근본적으로 해결하는 새로운 패러다임을 제시했다.

### 현대 RAG 시스템에서의 활용

실제 프로덕션 RAG 시스템에서 RAPTOR의 활용:

- **기업 지식 관리**: 대량의 내부 문서에서 주제별 검색
- **연구 보조**: 논문 전체의 맥락을 이해한 질의응답
- **교육**: 교재의 다양한 추상화 수준에서의 정보 검색
- **법률 문서 분석**: 판례와 법률 조항의 계층적 이해

## 결론

RAPTOR는 기존 RAG 시스템의 **평면적 검색 한계**를 해결하기 위해 **재귀적 요약 트리** 구조를 제안한 혁신적인 연구이다. 텍스트를 클러스터링하고 요약하는 과정을 재귀적으로 반복하여, 세부 사실부터 전체적 주제까지 다양한 추상화 수준의 정보를 하나의 트리에 조직한다.

핵심 발견들:
- 축소 트리 검색이 트리 순회 검색보다 효과적
- 주제적 이해와 다단계 추론 질문에서 가장 큰 개선
- 1-2 레벨의 요약만으로도 상당한 개선 달성

[[dpr]]이 밀집 검색의 기반을 제공하고, [[hybrid-search-reranking]]이 검색 품질을 개선했다면, RAPTOR는 **검색의 추상화 수준**이라는 새로운 차원을 도입했다. [[graphrag-knowledge-graph]]와 함께, RAPTOR는 "구조적 RAG"라는 새로운 패러다임의 핵심 연구이며, [[context-compression]] 등과 결합하여 더욱 효과적인 정보 검색 시스템을 구축할 수 있는 가능성을 제시한다.

RAG가 LLM 애플리케이션의 핵심 인프라로 자리잡은 현재, RAPTOR가 제시한 "다양한 추상화 수준에서의 검색"은 점점 더 중요해질 것이다. 단순히 관련 텍스트를 찾는 것을 넘어, **문서의 의미적 구조를 이해하고 활용하는** RAG 시스템이 미래의 표준이 될 것이다.
