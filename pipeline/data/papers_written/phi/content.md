# Textbooks Are All You Need: 교과서 품질 데이터의 힘

## 개요

:::info
**Paper:** Textbooks Are All You Need (arXiv:2306.11644, 2023.06)
**저자:** Suriya Gunasekar, Yi Zhang, Jyoti Aneja et al.
**소속:** Microsoft Research
**모델:** [HuggingFace: microsoft/phi-1](https://huggingface.co/microsoft/phi-1)
:::

2023년 6월, Microsoft Research는 AI 커뮤니티의 상식을 정면으로 뒤집는 논문을 발표했다. **1.3B 파라미터의 Phi-1**이 HumanEval 벤치마크에서 **51%**를 달성한 것이다. 이는 당시 15.5B 규모의 StarCoder(33.6%)를 크게 능가하고, GPT-3.5(47%)마저 넘어서는 수치였다. 더 놀라운 점은 Phi-1의 학습 데이터가 고작 **7B 토큰**에 불과했다는 것이다. StarCoder가 사용한 783B 토큰의 **1/100 수준**이다.

이 논문의 핵심 메시지는 제목 그대로다. "교과서만 있으면 된다(Textbooks Are All You Need)." 모델 크기를 키우고 데이터를 더 많이 모으는 것이 아니라, **데이터의 품질을 극적으로 높이면 훨씬 작은 모델로도 대형 모델을 능가할 수 있다**는 것이 핵심 주장이다. 이 결과는 이후 [[small-language-models|SLM(Small Language Model)]] 연구 전반의 이론적 기반이 되었으며, [[synthetic-data-training|합성 데이터]]를 활용한 LLM 학습 패러다임의 시작을 알렸다.

## 배경 및 동기

### 코드 생성 모델의 Scaling 경쟁

2023년 중반까지 코드 생성 모델 연구는 "더 크게, 더 많이"라는 Scaling 전략이 지배적이었다. 대표적인 모델들의 규모를 비교하면 다음과 같다.

| 모델 | 파라미터 | 학습 토큰 | 출시 시기 |
|------|---------|----------|----------|
| Codex (OpenAI) | 12B | 100B+ | 2021.08 |
| CodeGen-Multi (Salesforce) | 16.1B | 577B | 2022.03 |
| StarCoder (BigCode) | 15.5B | 783B (The Stack) | 2023.05 |
| Code Llama (Meta) | 7B~34B | 500B+ | 2023.08 |

이 모델들은 GitHub에서 크롤링한 대규모 코드 데이터셋을 사용하며, 모델 파라미터와 학습 토큰 수를 경쟁적으로 늘려왔다. Chinchilla scaling law(Hoffmann et al., 2022)는 모델 크기와 데이터 양의 최적 비율을 제시했지만, 여기에는 **데이터 품질**이라는 차원이 빠져 있었다.

### 대규모 코드 데이터의 근본적 한계

GitHub에서 수집한 코드 데이터셋은 양적으로는 풍부하지만, 학습 데이터로서 심각한 품질 문제를 안고 있다.

**첫째, 대부분이 보일러플레이트 코드다.** 설정 파일, 자동 생성된 코드, 반복적인 CRUD 로직이 데이터의 상당 부분을 차지한다. 이런 코드에서 모델이 배울 수 있는 것은 "흔한 패턴의 암기"뿐이다.

**둘째, 교육적 가치가 낮다.** 실제 프로젝트 코드는 다른 파일, 외부 라이브러리, 프로젝트 전체 구조에 의존한다. 코드 조각만 봐서는 왜 이렇게 작성되었는지, 어떤 알고리즘을 구현한 것인지 이해하기 어렵다.

**셋째, 주제 분포가 불균형하다.** 웹 개발, 데이터 처리 관련 코드가 압도적으로 많고, 알고리즘적 사고를 요구하는 코드(동적 프로그래밍, 그래프 알고리즘, 수학적 문제 해결 등)는 극소수다.

이런 데이터로 학습한 모델은 **흔한 패턴을 재생산하는 데는 능숙하지만, 새로운 문제를 논리적으로 분석하고 해결하는 능력이 제한적**이다. Phi-1 논문은 이 근본적 한계에 정면으로 도전한다.

## 핵심 아이디어: 데이터 품질이 모델 크기보다 중요하다

### "교과서 품질"의 정의

논문은 학습 데이터가 갖춰야 할 세 가지 핵심 속성을 정의한다. 이 정의는 단순한 직관이 아니라, 인간이 프로그래밍을 배우는 과정에서 착안한 것이다.

**1. 자기 완결성 (Self-contained)**

각 코드 예제가 외부 컨텍스트 없이 **그 자체로 완전히 이해 가능**해야 한다. GitHub 코드는 import, 설정 파일, 다른 모듈과의 의존 관계로 가득하지만, 교과서의 코드 예제는 독립적으로 실행 가능하고 이해 가능하다. 이 속성이 중요한 이유는, 모델이 코드를 학습할 때 전체 프로젝트 구조를 파악할 수 없기 때문이다. 단일 파일이나 코드 조각만으로 의미를 파악할 수 있어야 효과적인 학습이 가능하다.

**2. 교육성 (Instructive)**

코드가 **왜 이렇게 작성되었는지** 설명을 포함해야 한다. 단순히 "작동하는 코드"가 아니라 "배울 수 있는 코드"여야 한다. 좋은 프로그래밍 교과서는 코드를 보여주기 전에 해결할 문제를 설명하고, 코드 각 부분의 역할을 주석으로 달고, 왜 이 접근법을 선택했는지 이유를 밝힌다. 이런 교육적 맥락이 모델의 추론 능력 발달에 핵심적이다.

**3. 균형성 (Balanced)**

쉬운 개념부터 어려운 개념까지 **점진적이고 고르게** 다뤄야 한다. 일반 코드 데이터셋에서는 간단한 문자열 처리, 파일 I/O 같은 코드가 압도적 다수이고, 재귀, 동적 프로그래밍, 트리 순회 같은 알고리즘적 코드는 극히 드물다. 교과서 품질 데이터는 이 분포를 의도적으로 균형 잡아, 모델이 다양한 난이도의 문제를 해결할 수 있도록 한다.

:::tip
Phi-1의 "교과서 품질" 정의는 이후 합성 데이터 연구 전반에 영향을 미쳤다. [[60_lima|LIMA]] (Zhou et al., 2023)가 "1,000개의 고품질 데이터만으로도 충분하다"고 주장한 것과 맥락이 같으며, Orca (Mukherjee et al., 2023)가 GPT-4의 "사고 과정"을 합성 데이터로 증류한 것도 이 패러다임의 연장선이다.
:::

### 학습 데이터 구성

Phi-1의 학습 데이터는 두 단계로 구성된 파이프라인을 통해 생성된다.

| 데이터셋 | 규모 | 생성 방법 | 역할 |
|---------|------|----------|------|
| CodeTextbook | ~6B 토큰 | GPT-3.5로 합성 + The Stack에서 필터링 | 사전학습 (pretraining) |
| CodeExercises | ~180M 토큰 | GPT-3.5로 합성 | 파인튜닝 (finetuning) |
| **합계** | **~7B 토큰** | | StarCoder의 **1/100** |

## 방법론: 합성 데이터 생성 파이프라인

### CodeTextbook 생성

CodeTextbook은 두 가지 소스를 결합하여 구성된다.

**합성 교과서 (Synthetic Textbooks, ~1B 토큰):** GPT-3.5를 사용하여 Python 프로그래밍 교과서 스타일의 콘텐츠를 생성했다. 핵심은 **주제와 대상 독자의 다양성**이다. 단순히 "Python 함수를 설명하라"가 아니라, "대학교 2학년 학생에게 재귀를 활용한 트리 순회를 설명하는 교과서 페이지를 작성하라"와 같이 구체적인 맥락을 부여했다. 이를 통해 생성된 콘텐츠가 주제, 난이도, 설명 방식 면에서 다양성을 갖추도록 했다.

**필터링된 코드 (Filtered Code, ~5B 토큰):** The Stack 데이터셋에서 "교과서 품질"에 가까운 코드를 GPT-4 기반 분류기로 선별했다. 각 코드 파일에 대해 "이 코드가 교육적인가?"를 1~5점으로 평가하고, 높은 점수를 받은 코드만 선택했다. 이 과정에서 원본 데이터의 약 **6%만 살아남았다**. 즉, 양을 줄이는 대신 품질을 극적으로 높인 것이다.

### CodeExercises 생성

CodeExercises는 **함수 서명 + docstring 형태의 연습 문제와 그 풀이**로 구성된다. 생성 과정은 다음과 같다.

1. GPT-3.5에게 다양한 프로그래밍 주제에 대한 연습 문제를 생성하도록 요청
2. 각 문제는 `def function_name(args):` + docstring 형태로 출제
3. 풀이는 해당 함수의 완전한 구현으로 제공
4. HumanEval 벤치마크와 유사한 형식을 의도적으로 채택

이 데이터셋의 크기는 180M 토큰으로 매우 작지만, 파인튜닝 단계에서 모델의 성능을 **극적으로 끌어올리는** 역할을 한다. 사전학습된 지식을 "문제 해결" 형식으로 재구성하는 효과가 있기 때문이다.

### 학습 프로세스

Phi-1의 학습은 두 단계로 진행된다.

| 단계 | 데이터 | GPU 시간 | 목적 |
|------|--------|---------|------|
| 1. 사전학습 | CodeTextbook (~6B 토큰) | ~770 GPU hours (A100) | 코드 이해 및 생성 능력 |
| 2. 파인튜닝 | CodeExercises (~180M 토큰) | ~320 GPU hours (A100) | 문제 해결 형식 정렬 |
| **합계** | | **~1,090 GPU hours** | StarCoder의 **1/10** 비용 |

모델 아키텍처는 Transformer decoder-only 구조로, 24개 레이어, 2048 hidden dimension, 32 attention heads를 사용한다. Flash Attention을 적용하여 학습 효율을 높였다.

## 실험 결과

### 핵심 성능 비교

![HumanEval에서의 데이터 품질 효과](figures/p03_fig01.png)

*Figure 1: 모델 크기와 학습 설정별 HumanEval pass@1 성능 비교. 세 가지 설정(350M/26B 토큰, 350M/76B 토큰, 1.3B/51-76B 토큰)에서 The Stack(주황), CodeTextbook(하늘), CodeTextbook+CodeExercises(남색)의 성능을 보여준다. 데이터 품질만으로 동일 모델에서 3~4배의 성능 차이가 발생한다. (Gunasekar et al., 2023)*

위 그래프에서 가장 주목할 점은 세 가지다. 첫째, **같은 모델 크기에서 데이터만 바꿔도 3~4배 성능 차이가 발생**한다 (350M에서 The Stack 11% vs CodeTextbook+Exercises 41%). 둘째, **350M 모델이 고품질 데이터로 학습하면 1.3B 모델의 저품질 학습보다 월등히 높은 성능**을 보인다. 셋째, **CodeExercises 파인튜닝의 효과가 압도적**이다 (CodeTextbook만 사용한 16% vs 파인튜닝 추가 시 41%).

### 기존 모델과의 비교

| 모델 | 파라미터 | 학습 데이터 | HumanEval pass@1 |
|------|---------|-----------|-----------------|
| CodeGen-Multi | 16.1B | 577B tokens | 18.3% |
| StarCoder-Prompted | 15.5B | 783B tokens (The Stack) | 40.8% |
| StarCoder | 15.5B | 783B tokens (The Stack) | 33.6% |
| GPT-3.5 | ~175B | 비공개 | 47.0% |
| **Phi-1-small** | **350M** | **7B tokens (합성)** | **45.0%** |
| **Phi-1** | **1.3B** | **7B tokens (합성)** | **51.0%** |

이 결과에서 가장 놀라운 부분은 **350M 파라미터의 Phi-1-small이 15.5B의 StarCoder를 능가**한다는 것이다. 모델 크기를 **40배 이상 줄이고도** 더 높은 성능을 달성했다. 이는 데이터 품질이 모델 크기보다 중요할 수 있음을 강력하게 시사한다.

### Ablation Study: 데이터 품질의 정량적 영향

논문은 데이터 품질의 효과를 분리하기 위해 체계적인 ablation study를 수행했다. 모든 조건에서 **모델 아키텍처와 학습 하이퍼파라미터를 동일하게 유지**하고, 데이터만 변경했다.

| 설정 | 학습 데이터 | HumanEval | 대비 |
|------|-----------|----------|------|
| 350M, 26B tokens | The Stack (원본) | 11.0% | 기준선 |
| 350M, 26B tokens | CodeTextbook (합성 교과서) | 16.0% | +45% |
| 350M, 26B tokens | CodeTextbook + CodeExercises | 41.0% | **+273%** |
| 350M, 76B tokens | The Stack (원본) | 12.0% | 토큰 3배 증가 효과 미미 |
| 350M, 76B tokens | CodeTextbook + CodeExercises | 45.0% | 토큰 증가 + 품질 효과 |

이 결과에서 두 가지 핵심 인사이트를 도출할 수 있다.

**데이터 양의 한계:** The Stack을 26B에서 76B 토큰으로 3배 늘려도 11%에서 12%로 겨우 1%p 향상에 그쳤다. 저품질 데이터는 아무리 많이 넣어도 성능 향상이 포화된다.

**데이터 품질의 레버리지:** 같은 연산 비용에서 데이터를 교과서 품질로 바꾸면 4배 이상의 성능 차이가 발생한다. 이는 Scaling law에서 누락된 "데이터 품질" 차원의 존재를 실증적으로 보여준다.

### Python 패키지 사용 분포

![Phi-1이 생성한 코드의 Python import 분포](figures/p08_fig01.png)

*Figure 2: Phi-1이 HumanEval에서 생성한 코드의 Python import 분포. typing, math, collections 등 표준 라이브러리 위주이며, 외부 의존성 없이 자기 완결적 코드를 생성하는 경향을 보여준다. (Gunasekar et al., 2023)*

이 분포는 Phi-1이 학습한 교과서 품질 데이터의 특성을 반영한다. typing, math, collections, itertools 같은 Python 표준 라이브러리가 주를 이루며, 특정 프레임워크나 외부 라이브러리에 대한 의존이 적다. 이는 교과서 품질 데이터의 "자기 완결성" 속성이 모델의 코드 생성 패턴에도 반영되었음을 보여준다.

## 무엇이 "교과서 품질"을 만드는가: 심층 분석

### 교과서 코드 vs 일반 코드 비교

교과서 품질과 일반 코드의 차이를 구체적으로 비교하면 다음과 같다.

| 특성 | 일반 GitHub 코드 | 교과서 품질 코드 |
|------|---------------|---------------|
| 컨텍스트 의존성 | 높음 (다른 파일, 라이브러리 참조) | 낮음 (독립 실행 가능) |
| 주석/설명 | 최소한이거나 부재 | 풍부하고 교육적 |
| 변수명 | 축약형 다수 (x, tmp, res) | 의미 있는 이름 (sorted_list, max_depth) |
| 복잡도 분포 | 단순 코드 편중 | 균형 잡힌 분포 |
| 알고리즘적 사고 | 드묾 | 체계적으로 포함 |
| 에러 처리 | 산발적 | 교육적 맥락에서 설명 |

### 합성 데이터의 다양성 확보 전략

논문에서 특히 강조하는 것은 합성 데이터의 **다양성** 문제다. GPT-3.5로 교과서를 생성할 때, 동일한 프롬프트를 반복하면 유사한 출력이 나와 다양성이 떨어진다. 이를 방지하기 위해 연구팀은 프롬프트에 **무작위 시드(random seed)**를 도입했다.

구체적으로, 주제(topic), 대상 독자(target audience), 설명 스타일(explanation style)을 무작위로 조합하여 프롬프트를 생성했다. 예를 들어 같은 "재귀" 주제라도 "고등학생 대상으로 게임 개발 관점에서", "데이터 과학자 대상으로 트리 탐색 관점에서" 등 다양한 맥락에서 설명하도록 유도했다.

:::warning
합성 데이터의 다양성 확보는 여전히 열린 문제다. 교사 모델(GPT-3.5)의 출력 분포에 의해 합성 데이터의 다양성이 제한되며, 이는 "모델 붕괴(model collapse)" 위험으로 이어질 수 있다. 이후 Phi-2, Phi-3에서는 합성 데이터와 웹 크롤링 데이터를 혼합하는 전략으로 이 한계를 완화했다.
:::

## Phi 시리즈의 발전: Phi-1에서 Phi-4까지

Phi-1의 성공은 Microsoft의 Small Language Model 전략의 시작점이 되었다. 이후 Phi 시리즈는 일관된 철학 아래 빠르게 발전했다.

| 모델 | 크기 | 연도 | 핵심 발전 | 벤치마크 성과 |
|------|------|------|----------|-------------|
| Phi-1 | 1.3B | 2023.06 | 코드 생성 특화, 교과서 품질 증명 | HumanEval 51% |
| Phi-1.5 | 1.3B | 2023.09 | 코드에서 **일반 추론으로 확장** | 5-shot 다수 벤치마크에서 5B급 대항 |
| Phi-2 | 2.7B | 2023.12 | 합성 + 웹 데이터 혼합, 스케일 업 | MMLU 56.3%, Mistral-7B 대항 |
| Phi-3-mini | 3.8B | 2024.04 | 128K 컨텍스트, 고도화된 합성 데이터 | Mixtral 8x7B 대항 |
| Phi-4 | 14B | 2024.12 | 추론 강화, 합성 데이터 고도화 | 추론 벤치마크 최상위 |

### Phi-1.5: 코드에서 일반 추론으로

Phi-1은 Python 코드 생성에 한정되었지만, 후속 논문 "Textbooks Are All You Need II" (Li et al., 2023)에서 발표된 Phi-1.5는 **동일한 교과서 품질 전략을 자연어 추론으로 확장**했다. 합성 교과서 데이터를 프로그래밍뿐 아니라 수학, 과학, 상식 추론 영역까지 넓혀, 1.3B 파라미터로 당시 5B 규모 모델들과 경쟁하는 성능을 달성했다.

### Phi-2: 합성과 실제 데이터의 균형

Phi-2(2.7B)는 합성 데이터만으로는 한계가 있음을 인정하고, **고품질 웹 크롤링 데이터와 합성 데이터를 혼합**하는 전략을 채택했다. 또한 모델 크기를 2.7B로 늘리면서도, 데이터 품질 우선 철학을 유지하여 Mistral-7B와 비슷한 성능을 보였다.

### Phi-3 ~ Phi-4: SLM의 경쟁력 입증

Phi-3-mini(3.8B)는 Mixtral 8x7B(46.7B 파라미터)와 대등한 성능을 보이며, SLM이 실제 프로덕션 환경에서 LLM을 대체할 수 있음을 입증했다. 128K 컨텍스트 윈도우 지원, 다국어 능력 강화 등 실용적 기능도 추가되었다. Phi-4(14B)는 추론 능력을 한층 강화하여, 규모 대비 최고 수준의 추론 성능을 달성했다.

이 시리즈 전체를 관통하는 철학은 하나다: **"더 좋은 데이터로 더 작은 모델을."** 이 철학은 Google(Gemma), Alibaba(Qwen), Meta(Llama 3.2) 등 주요 AI 기업들이 SLM 경쟁에 본격 참여하는 계기가 되었다.

## 시사점과 학술적 영향

### 1. Scaling Law의 숨겨진 차원

Kaplan et al. (2020)과 Hoffmann et al. (2022, Chinchilla)의 scaling law는 모델 성능이 **파라미터 수(N)**와 **학습 토큰 수(D)**에 의해 결정된다고 주장한다. 즉, 성능은 $L(N, D)$의 함수다. 그러나 Phi-1은 이 공식에 **데이터 품질(Q)**이라는 세 번째 차원이 존재함을 보여준다.

$$L = f(N, D, Q)$$

같은 N(350M)과 같은 D(26B 토큰)에서 Q만 변경했을 때 4배의 성능 차이가 발생한다는 것은, Q의 영향력이 N이나 D 못지않게 크다는 것을 의미한다. 이는 scaling law 연구에 근본적인 재고를 촉구하는 결과다.

### 2. 합성 데이터 패러다임의 시작

Phi-1은 [[synthetic-data-training|합성 데이터]]를 LLM 학습의 핵심 전략으로 확립한 **최초의 대규모 실증 연구** 중 하나다. 이전에도 합성 데이터를 활용한 연구가 있었지만, Phi-1만큼 극적인 성능 차이를 보여준 사례는 없었다.

이후 합성 데이터 연구는 폭발적으로 증가했다.

| 연구 | 연도 | 핵심 기여 |
|------|------|----------|
| [[60_lima\|LIMA]] | 2023.05 | 1,000개 고품질 데이터로 GPT-4에 근접 |
| Phi-1 | 2023.06 | 교과서 품질 합성 데이터의 위력 입증 |
| Orca | 2023.06 | GPT-4의 "사고 과정"을 합성 데이터로 [[distillation-guide\|증류]] |
| WizardLM | 2023.08 | Evol-Instruct로 지시문 복잡도를 진화 |
| Cosmopedia | 2024.02 | 교과서 품질 합성 데이터의 대규모 공개 |
| Magpie | 2024.06 | LLM 자체 생성 합성 대화 데이터 |

이 모든 연구의 공통 메시지는 동일하다: **데이터의 양보다 품질이 중요하며, 고품질 데이터는 합성적으로 생성할 수 있다.**

### 3. SLM의 실용성 증명

1.3B 모델이 15B 모델을 능가할 수 있다는 결과는 실무적으로 큰 의미가 있다. [[small-language-models|SLM]]은 단순히 "저렴한 대안"이 아니라, **올바른 데이터 전략 하에서 최적의 선택**이 될 수 있다.

SLM의 실무적 이점은 다음과 같다.

- **추론 비용 절감**: 모델 크기에 비례하여 연산 비용이 감소
- **지연 시간 단축**: 작은 모델은 응답 속도가 빠르다
- **엣지 배포 가능**: 모바일, IoT 디바이스에서 로컬 실행 가능
- **파인튜닝 용이**: [[slm-finetuning-rtx3090|RTX 3090 같은 소비자 GPU]]에서도 파인튜닝 가능

## 한계 및 비판

### 1. 코드 도메인 한정

Phi-1은 **Python 코드 생성**에 특화되어 있다. 다른 프로그래밍 언어나 자연어 과제에서의 성능은 검증되지 않았다. "교과서 품질" 전략이 코드라는 상대적으로 구조화된 도메인에서만 효과적일 가능성을 배제할 수 없다. (이 한계는 이후 Phi-1.5에서 일반 추론으로, Phi-2/3에서 다국어로 확장되며 점진적으로 해소되었다.)

### 2. 교사 모델 의존성

교과서 품질 데이터는 GPT-3.5로 생성되었다. 따라서 Phi-1의 성능 상한은 **교사 모델(GPT-3.5)의 코드 생성 능력에 의해 제약**된다. 이는 합성 데이터 기반 학습의 일반적 한계이며, "학생이 교사를 넘어설 수 있는가?"라는 근본적 질문을 제기한다. 실제로 HumanEval에서 Phi-1(51%)이 GPT-3.5(47%)를 넘어선 것은 흥미로운 결과이지만, 이것이 도메인 특화 효과인지 진정한 "교사 초월"인지는 논쟁의 여지가 있다.

### 3. "교과서 품질"의 정의 모호성

무엇이 교과서 품질인지에 대한 **엄밀한 정량적 정의가 부족**하다. 현재는 "자기 완결적이고 교육적이며 균형 잡힌 데이터"라는 직관적 기준에 의존하며, 이를 **자동으로 판별하고 측정하는 방법**은 아직 미해결 과제다. GPT-4 기반 분류기로 필터링하는 것도 결국 또 다른 LLM의 판단에 의존하는 것이다.

### 4. 벤치마크 과적합 가능성

CodeExercises가 HumanEval과 유사한 형식으로 생성되었기 때문에, HumanEval에서의 높은 성능이 **벤치마크 형식에 대한 과적합**일 가능성을 완전히 배제하기 어렵다. 논문에서는 MBPP 등 다른 벤치마크에서도 경쟁력 있는 성능을 보임으로써 이 우려를 일부 해소했지만, 보다 다양한 실세계 코딩 태스크에서의 검증이 필요하다.

### 5. 재현성 문제

합성 데이터 생성에 GPT-3.5 API를 사용했기 때문에, 정확한 학습 데이터를 재현하기 어렵다. OpenAI 모델의 버전이 업데이트되면 동일한 프롬프트에서도 다른 출력이 나올 수 있으며, 생성에 사용된 정확한 프롬프트와 하이퍼파라미터도 완전히 공개되지 않았다. 이는 결과의 독립적 검증을 어렵게 만드는 요인이다.

## 후속 연구와의 연결

Phi-1이 제시한 "데이터 품질 우선" 패러다임은 여러 방향으로 후속 연구에 영향을 미쳤다.

**데이터 큐레이션 연구:** FineWeb-Edu (HuggingFace, 2024)는 웹 크롤링 데이터에서 교육적 콘텐츠를 자동으로 필터링하는 대규모 시스템을 구축했다. Phi-1의 "교과서 품질 필터링" 접근법을 웹 스케일로 확장한 것이다.

**합성 데이터 고도화:** Cosmopedia, Magpie 등은 합성 데이터의 다양성과 품질을 더욱 체계적으로 제어하는 방법을 연구한다. 특히 "curriculum learning" 스타일의 단계적 합성 데이터 생성이 주목받고 있다.

**SLM 생태계 확장:** Phi 시리즈의 성공에 자극받아 Google(Gemma 2B/7B), Microsoft(Phi-3), Alibaba(Qwen-1.5), Meta(Llama 3.2 1B/3B) 등 주요 기업들이 SLM 라인업을 출시했다. 이들 모두 데이터 품질을 핵심 차별화 전략으로 내세우고 있다.

**데이터 품질 측정 연구:** Phi-1이 남긴 가장 큰 미해결 과제인 "교과서 품질의 정량적 정의"를 해결하기 위한 연구도 활발하다. IFD(Instruction Following Difficulty), Deita, LESS 등은 데이터의 품질과 유용성을 자동으로 측정하고, 학습에 가장 기여도가 높은 데이터만 선별하는 방법을 제시한다. 이는 Phi-1의 GPT-4 기반 수동 필터링을 넘어서는, 보다 체계적이고 확장 가능한 접근법이다.

## 결론

"Textbooks Are All You Need"는 AI 연구에서 드물게 나타나는, **패러다임을 전환시킨** 논문이다. 이 논문의 기여는 세 가지 차원에서 평가할 수 있다.

**기술적 기여:** 1.3B 파라미터 모델이 15B 모델을 능가할 수 있음을 실증하며, 데이터 품질이 모델 크기와 학습 데이터 양에 필적하는 영향력을 가짐을 증명했다.

**방법론적 기여:** "교과서 품질" 데이터의 세 가지 속성(자기 완결성, 교육성, 균형성)을 정의하고, GPT-3.5를 활용한 합성 데이터 생성 파이프라인을 제시하여 이후 합성 데이터 연구의 표준적 접근법을 확립했다.

**생태계적 기여:** SLM 연구와 산업에 불을 붙였다. "더 좋은 데이터로 더 작은 모델을"이라는 철학은 이제 Google, Meta, Alibaba 등 모든 주요 AI 기업이 추구하는 전략이 되었으며, 엣지 AI, 모바일 AI의 실용화를 앞당기고 있다.

Scaling law가 "크기가 정의"라고 말할 때, Phi-1은 "품질이 답이다"라고 응답했다. 이 메시지는 2023년 이후 AI 연구의 흐름을 근본적으로 바꾸어 놓았다.
