# Dense Passage Retrieval: 오픈 도메인 질의응답을 위한 밀집 패시지 검색

## 논문 개요

:::info
**Paper:** Dense Passage Retrieval for Open-Domain Question Answering (arXiv:2004.04906, EMNLP 2020)
**저자:** Vladimir Karpukhin, Barlas Oguz, Sewon Min, Patrick Lewis, Ledell Wu, Sergey Edunov, Danqi Chen, Wen-tau Yih
**소속:** Facebook AI Research, University of Washington, Princeton University
**키워드:** Dense Retrieval, Dual-Encoder, FAISS, In-Batch Negatives, Open-Domain QA
:::

정보 검색(information retrieval)은 NLP의 핵심 과제 중 하나이다. 전통적으로 **BM25**와 같은 **희소 벡터(sparse vector)** 기반 방법이 지배적이었다 — 키워드 매칭과 TF-IDF 가중치를 기반으로, 수십 년 동안 검색의 표준이었다.

DPR(Dense Passage Retrieval)은 이 패러다임에 근본적인 도전을 제기한다. BERT 기반의 이중 인코더(dual-encoder)로 질문과 패시지를 **밀집 벡터(dense vector) 공간**에 매핑하고, 벡터 유사도로 검색을 수행한다. 단순한 학습 전략과 in-batch negatives 기법으로, DPR은 BM25를 **9-19%** 능가하는 검색 정확도를 달성했다.

이 연구는 이후 RAG(Retrieval-Augmented Generation) 연구의 토대가 되었으며, 현재 [[hybrid-search-reranking]] 등 현대적 검색 시스템의 기반 기술이 되었다.

## 배경: 희소 검색의 한계

### BM25와 TF-IDF

전통적인 검색 시스템은 **어휘적 매칭(lexical matching)**에 기반한다:

**TF-IDF (Term Frequency-Inverse Document Frequency):**
$$\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \log\frac{|D|}{\text{DF}(t, D)}$$

**BM25:**
$$\text{BM25}(q, d) = \sum_{t \in q} \text{IDF}(t) \cdot \frac{f(t, d) \cdot (k_1 + 1)}{f(t, d) + k_1 \cdot (1 - b + b \cdot |d|/\text{avgdl})}$$

이 방법들의 강점:
- **해석 가능**: 어떤 키워드가 매칭되었는지 명확
- **빠른 검색**: 역색인(inverted index)으로 매우 빠른 검색
- **추가 학습 불필요**: 통계적 방법이므로 별도의 학습 과정 없음
- **범용성**: 도메인에 무관하게 합리적인 성능

### 어휘적 매칭의 근본적 한계

그러나 BM25에는 극복하기 어려운 한계가 있다:

1. **어휘 불일치(vocabulary mismatch)**: "의사"와 "physician", "큰"과 "거대한" — 동의어를 매칭하지 못함
2. **의미적 이해 부재**: "개가 고양이를 쫓는다"와 "고양이가 개에게 쫓긴다"를 구별하지 못함
3. **추상적 질문 처리 불가**: "2020년 가장 영향력 있는 AI 논문은?" — 이런 질문은 키워드 매칭으로 답할 수 없음
4. **문맥 무시**: 같은 단어라도 문맥에 따라 다른 의미를 가질 수 있음 (다의어)

:::warning
BM25의 이런 한계는 표면적으로는 사소해 보이지만, 실제 사용자 질문의 상당수가 이 범주에 속한다. 사용자는 정확한 키워드를 알지 못하고, 자연어로 질문하기 때문이다.
:::

### 밀집 검색의 동기

밀집 벡터 검색은 이러한 한계를 근본적으로 해결한다:

- **의미적 매칭**: 단어가 아닌 **의미**를 기준으로 유사도 계산
- **언어 이해**: 사전학습된 언어 모델이 문맥, 동의어, 추론을 이해
- **교차 언어 가능성**: 다국어 인코더를 사용하면 언어 간 검색도 가능

그러나 DPR 이전의 밀집 검색 시도들은 BM25를 능가하지 못하는 경우가 많았다. DPR은 **왜** 밀집 검색이 실패했는지를 분석하고, 올바른 학습 전략으로 이를 해결했다.

## 핵심 아이디어: 이중 인코더와 In-Batch Negatives

### 이중 인코더 아키텍처

DPR의 아키텍처는 두 개의 **독립적인 BERT 인코더**로 구성된다:

$$E_Q(\cdot): \text{질문 인코더}, \quad E_P(\cdot): \text{패시지 인코더}$$

질문 $q$와 패시지 $p$의 유사도는 두 인코더의 출력 벡터의 **내적(dot product)**으로 계산된다:

$$\text{sim}(q, p) = E_Q(q)^T \cdot E_P(p)$$

각 인코더는 BERT-base (110M 파라미터)를 사용하며, [CLS] 토큰의 출력 벡터(768차원)를 문장/패시지의 표현으로 사용한다.

:::info
이중 인코더의 핵심 장점은 **비대칭적 설계**이다. 질문과 패시지가 서로 다른 인코더를 사용하므로, 짧은 질문과 긴 패시지의 서로 다른 특성을 각각 학습할 수 있다. 또한, 패시지 인코더의 출력은 사전에 계산하여 인덱싱할 수 있어, 추론 시에는 질문 인코딩과 유사도 검색만 수행하면 된다.
:::

### 왜 이중 인코더인가?

교차 인코더(cross-encoder) 대비 이중 인코더의 장단점:

| 측면 | 교차 인코더 | 이중 인코더 |
|------|-----------|-----------|
| 입력 | 질문+패시지 동시 처리 | 질문/패시지 독립 처리 |
| 상호작용 | 깊은 토큰 수준 상호작용 | 벡터 수준 유사도만 |
| 정확도 | 높음 | 상대적으로 낮음 |
| 속도 | 매우 느림 (N번 인코딩) | 매우 빠름 (사전 인덱싱) |
| 확장성 | 불가 (수백만 문서) | 가능 (FAISS 등) |

교차 인코더는 정확하지만 모든 질문-패시지 쌍을 실시간으로 처리해야 하므로, 수백만 개의 문서에서 검색하는 것이 불가능하다. 이중 인코더는 패시지를 사전에 인코딩하여 인덱싱할 수 있으므로, 대규모 검색에 적합하다.

실용적으로는 두 방법을 **결합**하는 것이 최적이다: 이중 인코더로 후보를 검색하고, 교차 인코더로 **재순위(re-ranking)**를 수행하는 것이다. 이는 [[hybrid-search-reranking]]에서 다루는 현대적 검색 파이프라인의 핵심이다.

### 학습: In-Batch Negatives

DPR의 핵심 기술적 기여 중 하나는 **in-batch negatives** 학습 전략이다.

대비 학습(contrastive learning)에서는 각 질문에 대해:
- **양성 예(positive)**: 정답을 포함하는 패시지
- **부정 예(negative)**: 관련 없는 패시지

가 필요하다. 부정 예를 어떻게 선택하느냐가 학습의 핵심이다.

**In-Batch Negatives의 원리:**

배치 크기가 $B$일 때, 각 질문 $q_i$에 대해:
- 양성: $(q_i, p_i^+)$
- 부정: 같은 배치의 다른 질문들의 양성 패시지 $\{p_j^+ | j \neq i\}$

이렇게 하면 $B$개의 질문-패시지 쌍으로 $B \times (B-1)$개의 부정 쌍을 무료로 얻을 수 있다.

손실 함수 (InfoNCE):

$$\mathcal{L} = -\log \frac{e^{\text{sim}(q_i, p_i^+)}}{e^{\text{sim}(q_i, p_i^+)} + \sum_{j \neq i} e^{\text{sim}(q_i, p_j^+)}}$$

:::tip
In-batch negatives의 장점은 **추가 연산 없이** 부정 예의 수를 크게 늘릴 수 있다는 점이다. 배치 크기 128이면 각 질문에 대해 127개의 부정 예가 자동으로 생성된다. 이는 별도로 부정 예를 샘플링하고 인코딩하는 비용을 완전히 제거한다.
:::

### Hard Negatives

In-batch negatives만으로는 충분하지 않다. 대부분의 무작위 패시지는 질문과 전혀 관련이 없어 "너무 쉬운" 부정 예이다. 모델이 이를 구별하는 것은 사소한 일이다.

DPR은 **hard negatives** — 질문과 관련이 있어 보이지만 정답은 아닌 패시지 — 를 추가한다:

1. **BM25 hard negatives**: BM25로 검색하여 상위에 랭크되지만 정답이 아닌 패시지
2. **Gold negatives**: 다른 질문의 정답 패시지 중 현재 질문과 약간 관련 있는 것

실험에서 BM25 hard negatives를 추가하면 성능이 크게 개선된다:

| 부정 예 구성 | Top-20 정확도 |
|-------------|-------------|
| Random only | 76.0% |
| In-batch only | 78.4% |
| In-batch + BM25 hard (1개) | **79.8%** |
| In-batch + Gold (1개) | 79.5% |
| In-batch + BM25 hard (2개) | **79.9%** |

## FAISS 인덱싱

### 대규모 벡터 검색의 도전

Wikipedia 전체(약 2,100만 패시지)에서 가장 유사한 패시지를 찾으려면, 질문 벡터와 2,100만 개의 패시지 벡터 간의 유사도를 모두 계산해야 한다. 768차원 벡터의 내적을 2,100만 번 수행하는 것은 실시간 서비스에서 비현실적이다.

### FAISS (Facebook AI Similarity Search)

DPR은 **FAISS**를 사용하여 이 문제를 해결한다. FAISS는 대규모 벡터에 대한 근사 최근접 이웃(ANN) 검색 라이브러리이다.

DPR에서의 FAISS 사용:

1. **인덱스 구축 (오프라인)**:
   - 2,100만 패시지를 패시지 인코더로 벡터화
   - FAISS의 HNSW (Hierarchical Navigable Small World) 인덱스로 구축
   - 약 65GB의 인덱스 크기

2. **검색 (온라인)**:
   - 질문을 질문 인코더로 벡터화 (단 1회)
   - FAISS 인덱스에서 top-k 유사 패시지 검색
   - 응답 시간: ~수십 밀리초

| FAISS 인덱스 | 검색 시간 | 정확도 (Recall) |
|-------------|----------|----------------|
| Flat (정확) | ~1초 | 100% |
| HNSW | ~50ms | ~98% |
| IVF + PQ | ~10ms | ~95% |

DPR은 HNSW 인덱스를 사용하여, 정확도 손실을 최소화하면서 실시간 검색을 달성한다.

:::info
FAISS의 인덱싱은 현대 RAG 시스템의 핵심 인프라이다. DPR 이후 Pinecone, Weaviate, Milvus 등 상용 벡터 데이터베이스가 등장했으며, 이들 모두 DPR이 개척한 밀집 벡터 검색 패러다임 위에 구축되어 있다.
:::

## 실험 결과

### 오픈 도메인 QA 검색 성능

DPR의 검색 성능을 5개의 오픈 도메인 QA 벤치마크에서 평가했다:

#### Top-20 검색 정확도 (Recall@20)

| 데이터셋 | BM25 | DPR | 개선 |
|---------|------|-----|------|
| Natural Questions | 59.1% | **78.4%** | +19.3% |
| TriviaQA | 66.9% | **79.4%** | +12.5% |
| WebQuestions | 55.0% | **73.2%** | +18.2% |
| CuratedTREC | 70.7% | **79.8%** | +9.1% |
| SQuAD | **68.8%** | 63.2% | -5.6% |

핵심 관찰:

1. **5개 중 4개 데이터셋에서 DPR이 BM25를 크게 능가**: 9-19% 포인트의 개선
2. **SQuAD에서만 BM25가 우위**: SQuAD의 질문이 패시지의 문장을 거의 그대로 사용하여 만들어졌기 때문 (어휘적 매칭에 유리)
3. **Natural Questions에서 가장 큰 개선**: 실제 사용자 질문에 가까운 데이터셋에서 밀집 검색의 효과가 극대화

#### Top-100 검색 정확도

| 데이터셋 | BM25 | DPR | 개선 |
|---------|------|-----|------|
| Natural Questions | 73.7% | **85.4%** | +11.7% |
| TriviaQA | 76.7% | **85.0%** | +8.3% |
| WebQuestions | 71.1% | **81.3%** | +10.2% |

Top-100에서도 DPR이 일관되게 BM25를 능가하며, 더 많은 후보를 검색할수록 DPR의 이점이 유지된다.

### End-to-End QA 성능

검색된 패시지를 리더(reader) 모델에 입력하여 최종 답을 추출하는 end-to-end 파이프라인의 성능:

| 시스템 | NQ EM | TriviaQA EM | WQ EM |
|--------|-------|-------------|-------|
| BM25 + BERT Reader | 32.6 | 52.4 | 29.9 |
| DPR + BERT Reader | **41.5** | **56.8** | **34.6** |
| ORQA (사전학습) | 33.3 | 45.0 | 36.4 |

DPR은 검색 단계의 개선이 end-to-end 성능으로 직접 이어진다는 것을 보여준다.

### BM25와 DPR의 상호 보완성

흥미로운 발견: BM25와 DPR은 서로 다른 유형의 질문에서 강점을 보인다.

| 질문 유형 | BM25 강점 | DPR 강점 |
|----------|----------|---------|
| 키워드 매칭 필요 | 엔티티 이름, 날짜 등 | - |
| 의미적 이해 필요 | - | 동의어, 패러프레이즈 |
| 짧은 질문 | 정보 부족 시 | 문맥 추론 가능 |
| 고유명사 포함 | 정확한 매칭 | 학습 필요 |

이 상호 보완성은 BM25와 DPR을 **결합(hybrid retrieval)**하는 것이 최적임을 시사한다:

| 방법 | NQ Top-20 |
|------|-----------|
| BM25 only | 59.1% |
| DPR only | 78.4% |
| BM25 + DPR (hybrid) | **82.6%** |

하이브리드 검색은 각각의 단독 사용보다 우수하며, 이는 현대 RAG 시스템에서 [[hybrid-search-reranking]]이 표준이 된 이유이다.

## 기술적 심층 분석

### 학습 세부사항

DPR의 학습 설정:

| 항목 | 값 |
|------|-----|
| 기반 모델 | BERT-base (uncased, 110M) |
| 벡터 차원 | 768 |
| 배치 크기 | 128 |
| 학습률 | 1e-5 |
| 에폭 수 | 40 |
| 옵티마이저 | Adam |
| 워밍업 | 선형 워밍업 (학습의 처음 10%) |
| Hard negatives/질문 | 1개 (BM25) |
| In-batch negatives | 127개 (배치 크기 - 1) |

### 부정 예 선택의 영향

다양한 부정 예 전략의 비교:

| 전략 | Top-20 | Top-100 |
|------|--------|---------|
| Random negatives | 76.0% | 83.1% |
| BM25 negatives (no in-batch) | 68.5% | 80.2% |
| In-batch negatives only | 78.4% | 85.2% |
| In-batch + BM25 hard negative | **79.8%** | **86.1%** |
| In-batch + DPR hard negative (iterative) | 79.5% | 85.7% |

:::warning
BM25 hard negatives만 사용하면 (in-batch 없이) 오히려 성능이 하락한다. Hard negatives는 in-batch negatives와 **결합**해야 효과적이다. 이는 hard negatives만으로는 학습이 너무 어려워져 수렴이 불안정해지기 때문이다.
:::

### 사전학습의 효과

DPR은 추가적인 사전학습 없이도 ORQA (사전학습 기반 밀집 검색)를 능가한다:

| 방법 | 추가 사전학습 | NQ Top-20 |
|------|-------------|-----------|
| ORQA | ICT 사전학습 (수천 GPU-hours) | 71.6% |
| DPR | 없음 | **78.4%** |

이 결과는 의미 있다: 올바른 학습 전략(in-batch negatives + hard negatives)이 비싼 사전학습을 대체할 수 있다.

## 분석: 왜 DPR이 작동하는가

### 밀집 공간의 구조

DPR이 학습한 벡터 공간을 분석하면:

1. **의미적 클러스터링**: 비슷한 주제의 질문/패시지가 공간에서 가깝게 위치
2. **유형 분리**: 질문 유형(who, what, when 등)에 따라 다른 영역을 차지
3. **동의어 근접성**: "physician"과 "doctor" 등 동의어가 유사한 벡터로 매핑

### 실패 사례 분석

DPR이 BM25보다 못한 경우:

1. **매우 구체적인 엔티티 질문**: "2019년 11월 23일에 누가 결승골을 넣었나?" — 날짜와 이벤트의 정확한 매칭이 필요
2. **학습 데이터에 없는 도메인**: 학습에 사용되지 않은 특수 도메인의 용어
3. **매우 긴 패시지**: BERT의 512 토큰 제한으로 긴 패시지의 정보가 손실

### 학습 데이터량의 영향

학습 데이터 크기에 따른 DPR 성능:

| 학습 질문 수 | NQ Top-20 |
|-------------|-----------|
| 1,000 | 62.4% |
| 5,000 | 70.3% |
| 10,000 | 74.1% |
| 50,000 | 78.4% |
| 58,880 (전체) | 78.4% |

약 10,000개 이상의 학습 데이터에서 성능이 수렴하는 경향을 보인다. 이는 DPR이 BERT의 사전학습된 언어 이해 능력에 크게 의존하며, fine-tuning은 비교적 적은 데이터로도 효과적이라는 것을 의미한다.

## 후속 연구와 영향

### RAG 계열 연구의 기초

DPR은 이후 RAG(Retrieval-Augmented Generation) 연구의 핵심 기반이 되었다:

- **RAG (Lewis et al., 2020)**: DPR + 생성 모델(BART)을 결합한 최초의 RAG 모델
- **FiD (Fusion-in-Decoder)**: 검색된 여러 패시지를 디코더에서 융합
- **Atlas**: 대규모 사전학습과 검색을 결합

### 밀집 검색의 발전

DPR 이후 밀집 검색 기술은 빠르게 발전했다:

| 연구 | 핵심 개선 |
|------|----------|
| ColBERT | 토큰 수준 상호작용으로 정확도 향상 |
| Contriever | 대규모 비지도 사전학습 |
| E5 | 텍스트 임베딩의 범용성 향상 |
| GTE | Alibaba의 범용 텍스트 임베딩 |
| BGE | 중국어/영어 이중 언어 임베딩 |
| Nomic-Embed | 오픈소스 범용 임베딩 |

### 현대 RAG 시스템에서의 위치

현대 RAG 시스템의 전형적인 파이프라인에서 DPR의 아이디어가 차지하는 위치:

```
질문 → 밀집 검색 (DPR 계승) → 재순위 (cross-encoder)
         ↓                        ↓
    FAISS/벡터 DB           Cohere Rerank 등
         ↓                        ↓
    Top-100 후보              Top-10 최종
         →                        →
                 LLM 생성
```

이 파이프라인에서 밀집 검색 단계는 DPR이 개척한 이중 인코더 아키텍처를 기반으로 하며, FAISS 인덱싱도 DPR이 처음 대규모로 적용한 것이다.

## 한계와 논의

### DPR의 한계

1. **도메인 특화 필요**: 범용 DPR은 특정 도메인에서 BM25보다 못할 수 있으며, 도메인별 fine-tuning이 필요하다

2. **업데이트 비용**: 새로운 문서가 추가될 때마다 인코딩하고 인덱스를 업데이트해야 한다

3. **BERT 토큰 제한**: 512 토큰 제한으로 긴 문서의 정보가 손실된다

4. **교차 언어 검색 미지원**: 영어에 최적화되어 있으며, 다국어 검색에는 추가 작업이 필요하다

5. **인코더 크기**: BERT-base로는 복잡한 의미적 관계를 충분히 포착하지 못할 수 있다

6. **정적 표현**: 동일한 질문이라도 문맥에 따라 다른 의도를 가질 수 있으나, DPR은 질문의 정적인 벡터만 생성한다

### 하이브리드 검색의 부상

DPR의 한계를 보완하기 위해 **하이브리드 검색**이 표준이 되었다. BM25의 어휘적 정확성과 DPR의 의미적 이해를 결합하면:

$$\text{score}(q, p) = \alpha \cdot \text{BM25}(q, p) + (1-\alpha) \cdot \text{sim}_{\text{DPR}}(q, p)$$

대부분의 현대 검색 시스템은 이러한 [[hybrid-search-reranking]] 접근법을 채택하고 있다.

---

## DPR의 역사적 의의

### 패러다임 전환

DPR은 정보 검색 분야에서 **패러다임 전환**을 촉발했다:

- **전**: 키워드 매칭, 역색인, BM25 중심
- **후**: 의미적 매칭, 벡터 검색, 신경망 인코더 중심

이 전환은 이후 벡터 데이터베이스 산업의 폭발적 성장으로 이어졌다.

### RAG의 탄생

DPR은 RAG 개념의 직접적인 전신이다. "검색하고 → 읽고 → 답한다"는 패턴은 현재 LLM 애플리케이션의 가장 일반적인 패턴이 되었으며, 이 모든 것은 DPR의 밀집 검색이 BM25를 능가할 수 있음을 보여준 것에서 시작되었다.

---

## 결론

DPR은 밀집 벡터 기반 패시지 검색이 전통적인 희소 벡터 검색(BM25)을 능가할 수 있음을 대규모 실험으로 입증한 획기적인 연구이다. BERT 기반 이중 인코더, in-batch negatives 학습 전략, FAISS 인덱싱의 조합으로, 간단하면서도 강력한 밀집 검색 시스템을 구축했다.

DPR의 가장 큰 영향은 기술적 성과를 넘어, **정보 검색 패러다임의 전환**을 촉발한 것이다. 이 연구 이후 벡터 검색은 NLP의 핵심 인프라가 되었으며, RAG, 시맨틱 검색, 대화형 AI 등 현대 AI 시스템의 기반이 되었다.

현재 [[hybrid-search-reranking]]이 실무 표준이 된 것은, DPR이 보여준 밀집 검색의 가능성과 BM25와의 상호 보완성에 대한 이해가 결합된 결과이다. 후속 연구인 [[graphrag-knowledge-graph]], [[context-compression]]와 같은 고급 RAG 기법들도 모두 DPR이 개척한 밀집 검색 기반 위에 구축되어 있다.
