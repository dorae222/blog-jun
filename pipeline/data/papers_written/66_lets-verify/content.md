# Let's Verify Step by Step: 단계별로 검증하자

## 논문 개요

:::info
**Paper:** Let's Verify Step by Step (arXiv:2305.20050, ICLR 2024)
**저자:** Hunter Lightman, Vineet Kosaraju, Yura Burda, Harri Edwards, Bowen Baker, Teddy Lee, Jan Leike, John Schulman, Ilya Sutskever, Karl Cobbe
**소속:** OpenAI
**키워드:** Process Reward Model, Outcome Reward Model, Math Reasoning, PRM800K, Verification
:::

LLM의 추론 능력을 향상시키는 데 있어 **보상 모델(reward model)**은 핵심적인 역할을 한다. 생성된 풀이가 올바른지를 판별하는 보상 모델은 크게 두 가지로 나뉜다: **결과 감독(outcome supervision)**과 **과정 감독(process supervision)**.

결과 기반 보상 모델(ORM)은 최종 답이 맞는지만 판단하는 반면, 과정 기반 보상 모델(PRM)은 풀이의 **각 단계**가 올바른지를 판단한다. 직관적으로 과정 감독이 더 효과적일 것 같지만, 이를 대규모로 엄밀하게 비교한 연구는 본 논문 이전에는 부재했다.

OpenAI의 이 연구는 MATH 벤치마크에서 **대규모 인간 레이블링**을 통해 PRM을 학습시키고, ORM과의 공정한 비교를 수행하여, **과정 감독이 결과 감독보다 일관되게 우수**하다는 것을 입증했다. 또한 약 80만 개의 단계별 레이블로 구성된 **PRM800K** 데이터셋을 공개하여, 후속 연구의 기반을 마련했다.

## 배경: 보상 모델과 추론

### LLM 추론의 두 가지 접근

LLM의 수학 추론 능력을 향상시키는 방법은 크게 두 가지로 나뉜다:

1. **학습 시점 개선**: 더 좋은 데이터로 fine-tuning, RLHF로 추론 패턴 학습
2. **추론 시점 개선**: 여러 풀이를 생성하고, 보상 모델로 최선의 풀이를 선택

본 논문은 후자에 초점을 맞춘다. 하나의 수학 문제에 대해 LLM이 여러 풀이를 생성하면, 보상 모델이 각 풀이의 품질을 평가하여 최선의 것을 선택하는 **best-of-N** 전략이다.

:::info
이 접근법은 이후 [[scaling-test-time-compute]]에서 더 체계적으로 분석되며, "테스트 시점 연산 스케일링"이라는 연구 방향의 초석이 된다. 본 논문은 그 핵심 구성 요소인 **검증기(verifier)**의 설계를 다룬다.
:::

### ORM vs PRM

두 유형의 보상 모델을 비교하면:

**결과 기반 보상 모델 (ORM - Outcome Reward Model):**
- 최종 답의 정답 여부만으로 학습
- 레이블링 비용이 낮음 (자동화 가능)
- 풀이 과정의 정확성을 보장하지 않음
- 우연히 맞는 답에 대해서도 양성 피드백

**과정 기반 보상 모델 (PRM - Process Reward Model):**
- 풀이의 각 단계별 정확성으로 학습
- 레이블링 비용이 높음 (인간 전문가 필요)
- 추론 과정의 정확성을 직접 평가
- 잘못된 추론으로 우연히 맞는 답을 구별 가능

### 왜 과정 감독이 중요한가

과정 감독이 중요한 이유는 **정렬(alignment)** 관점에서도 설명된다:

1. **해석 가능성**: PRM은 풀이의 어느 단계에서 오류가 발생했는지를 정확히 지적할 수 있다
2. **안전성**: 우연히 맞는 답("해킹된" 풀이)에 보상을 주지 않음
3. **학습 효율**: 각 단계에 대한 구체적 피드백으로 더 빠른 학습 가능
4. **디버깅**: 모델의 추론 실패 패턴을 분석하여 체계적 개선 가능

:::warning
ORM의 근본적 한계는 **보상 해킹(reward hacking)**에 취약하다는 점이다. 모델이 우연히 정답에 도달하는 잘못된 추론 경로를 학습할 수 있으며, 이는 더 어려운 문제에서 성능 저하로 이어진다.
:::

## 핵심 아이디어: 단계별 검증

### PRM의 레이블링 방법론

PRM 학습의 핵심 과제는 **단계별 레이블**을 수집하는 것이다. 본 논문은 다음과 같은 방법론을 사용했다:

**레이블 체계:**
- **Positive**: 해당 단계가 합리적이고 올바른 추론
- **Negative**: 해당 단계에 논리적 오류, 계산 실수, 또는 불합리한 비약이 있음
- **Neutral**: 해당 단계가 이전 문맥에서 모호하지만 반드시 틀리지는 않음

**레이블링 프로세스:**
1. 대규모 생성기(generator) 모델이 수학 문제의 풀이를 단계별로 생성
2. 각 단계 후에 분기점을 만들어 다양한 연속(continuation)을 생성
3. 인간 레이블러가 각 단계를 positive/negative/neutral로 분류
4. 레이블러의 일관성과 품질을 지속적으로 모니터링

### PRM800K 데이터셋

공개된 PRM800K 데이터셋의 규모와 특성:

| 항목 | 수치 |
|------|------|
| 총 단계별 레이블 수 | ~800,000 |
| 문제 수 (MATH 데이터셋) | 4,500+ |
| 풀이(solution) 수 | ~75,000 |
| 평균 단계 수/풀이 | ~10.7 |
| 레이블 분포 | Positive ~67%, Negative ~22%, Neutral ~11% |

:::info
PRM800K는 단계별 추론 검증을 위한 최초의 대규모 공개 데이터셋으로, 이후 [[process-reward-models]] 연구의 표준 벤치마크가 되었다. 이 데이터셋의 공개는 프로세스 감독 연구를 크게 가속화했다.
:::

### Active Learning을 통한 효율적 레이블링

80만 개의 레이블을 수집하는 것은 상당한 비용이 소요된다. 논문은 이를 효율적으로 수행하기 위해 **active learning** 전략을 사용했다:

1. **Convincing wrong-answer solutions 우선**: 최종 답은 틀리지만 풀이 과정이 그럴듯해 보이는 풀이를 우선 레이블링. 이러한 풀이가 PRM 학습에 가장 유용하다.

2. **불확실성 기반 선택**: 현재 PRM이 가장 불확실해하는 풀이를 우선적으로 레이블링하여, 레이블링 효율을 극대화.

3. **반복적 개선**: 레이블 수집 → PRM 학습 → 불확실 풀이 선별 → 추가 레이블 수집의 사이클을 반복.

## 실험 설계

### 공정한 비교를 위한 설계

ORM과 PRM을 공정하게 비교하기 위해 다음 조건들을 통제했다:

1. **동일한 기반 모델**: GPT-4의 초기 버전을 생성기로, 별도의 같은 크기 모델을 보상 모델로 사용
2. **동일한 학습 데이터량**: ORM과 PRM이 동일한 수의 풀이를 학습에 사용
3. **동일한 평가 방법**: best-of-N 선택에서 동일한 N값 사용
4. **동일한 벤치마크**: MATH 데이터셋의 테스트 세트

### 생성기와 검증기의 분리

논문은 생성기(풀이를 생성하는 모델)와 검증기(풀이를 평가하는 모델)를 **별도 모델**로 사용하는 것이 중요하다고 강조한다:

- 생성기가 자신의 풀이를 검증하면, **자기 일관성 편향**이 발생
- 별도의 검증기 모델이 더 객관적인 평가 가능
- 검증기의 학습 목표가 생성과 다르므로, 전문화된 학습 가능

### Best-of-N 전략

보상 모델을 활용하는 구체적인 방법:

1. 문제 $x$에 대해 생성기가 $N$개의 풀이 $\{s_1, s_2, ..., s_N\}$을 생성
2. 보상 모델이 각 풀이에 점수 부여
3. 가장 높은 점수의 풀이를 최종 답으로 선택

**ORM의 점수 계산:**
$$\text{score}_{\text{ORM}}(s) = R_{\text{ORM}}(s)$$
풀이 전체에 대한 단일 점수

**PRM의 점수 계산:**
$$\text{score}_{\text{PRM}}(s) = \prod_{k=1}^{K} R_{\text{PRM}}(s_k | s_{<k}, x)$$
각 단계의 정확도 확률의 곱 (또는 최소값)

PRM의 점수 집계 방법으로 논문은 **최소값(min)**과 **곱(product)** 두 가지를 비교했으며, 곱 방식이 약간 더 우수했다.

## 실험 결과

### 핵심 결과: PRM > ORM

MATH 벤치마크에서의 best-of-N 정확도:

| N | Majority Voting | ORM | PRM |
|---|-----------------|-----|-----|
| 1 | 33.0% | - | - |
| 10 | 44.1% | 44.6% | **47.2%** |
| 100 | 52.3% | 54.8% | **58.7%** |
| 250 | 55.1% | 57.4% | **61.5%** |
| 1860 | 58.2% | 61.3% | **69.0%** |

핵심 관찰:

1. **PRM이 모든 N에서 ORM을 능가**: N이 커질수록 격차가 벌어진다
2. **N=1860에서 PRM이 ORM보다 7.7% 높음**: 이는 통계적으로 매우 유의미한 차이
3. **다수결(majority voting) 대비 PRM의 우위**: PRM은 다수결 기반 방식을 큰 폭으로 능가

### N 증가에 따른 스케일링

N을 증가시킬 때의 성능 향상 패턴이 ORM과 PRM에서 다르다:

- **ORM**: N이 커져도 성능 향상이 **포화(saturation)**되는 경향
- **PRM**: N 증가에 따라 **지속적으로 개선**되는 경향

이 차이는 근본적인 원인이 있다:

:::tip
ORM은 풀이 전체에 대한 점수만 제공하므로, N이 커져도 비슷한 점수의 풀이들 사이에서 변별력이 부족하다. 반면 PRM은 단계별 점수를 제공하므로, 더 세밀한 변별이 가능하다. 이는 [[test-time-compute-scaling]]에서 테스트 시점 연산 스케일링의 효과에 직접적으로 연결된다.
:::

### 난이도별 분석

MATH 데이터셋은 난이도 1-5로 분류되어 있으며, 난이도별 결과:

| 난이도 | ORM (N=1860) | PRM (N=1860) | 차이 |
|--------|-------------|-------------|------|
| Level 1 | 92.3% | 93.1% | +0.8% |
| Level 2 | 84.6% | 87.2% | +2.6% |
| Level 3 | 71.4% | 77.8% | +6.4% |
| Level 4 | 53.2% | 63.5% | +10.3% |
| Level 5 | 36.8% | 50.2% | +13.4% |

핵심적인 발견: **문제가 어려울수록 PRM과 ORM의 격차가 커진다**. 이는 쉬운 문제에서는 대부분의 풀이가 올바르므로 검증기의 역할이 작지만, 어려운 문제에서는 올바른 풀이를 선별하는 검증기의 능력이 결정적이기 때문이다.

### ORM의 한계 분석

ORM이 PRM에 뒤처지는 구체적인 실패 모드:

1. **보상 해킹(Reward Hacking)**: ORM이 높은 점수를 주지만 실제로는 틀린 풀이들
   - 예: 중간 과정에서 계산 실수가 있지만, 그 실수가 우연히 상쇄되어 정답에 도달
   - PRM은 중간 단계의 오류를 감지하여 이를 방지

2. **False Positive 풀이**: 그럴듯한 추론 과정이지만 논리적 비약이 있는 풀이
   - ORM: 최종 답이 맞으면 긍정적 학습 신호
   - PRM: 논리적 비약을 감지하여 부정적 학습 신호

3. **점수 편차**: ORM의 점수 분포가 PRM보다 넓어, 점수 기반 선별의 신뢰성이 낮음

## 프로세스 감독의 정렬 관점

### 정렬(Alignment)과의 연결

논문은 과정 감독이 단순한 성능 향상을 넘어 **AI 정렬** 측면에서도 중요하다고 주장한다:

1. **추론 투명성**: PRM은 모델의 추론 과정을 단계별로 평가하므로, 어디서 잘못되었는지를 파악할 수 있다. 이는 AI 시스템의 신뢰성 구축에 핵심적이다.

2. **안전한 일반화**: ORM으로 학습된 모델은 "정답에 도달하는 편법"을 학습할 수 있지만, PRM으로 학습된 모델은 "올바른 추론 과정"을 학습하므로, 새로운 문제에 대한 일반화가 더 안전하다.

3. **스케일링 안전성**: 모델이 더 강력해질수록 ORM의 보상 해킹 위험도 커지지만, PRM은 과정 자체를 검증하므로 이 위험에 더 강건하다.

:::warning
"결과만 보고 판단하는 것"과 "과정을 보고 판단하는 것"의 차이는, AI 안전성 연구에서 반복적으로 등장하는 핵심 주제이다. 결과 기반 접근은 **Goodhart's Law** — "측정 지표가 목표가 되면 좋은 측정 지표가 아니게 된다" — 에 취약하다.
:::

### RLHF와의 관계

기존 RLHF(Reinforcement Learning from Human Feedback)는 주로 **결과 기반 보상**을 사용한다. 본 논문의 결과는 RLHF의 보상 모델을 PRM으로 교체하면 더 나은 정렬을 달성할 수 있음을 시사한다.

그러나 PRM을 RLHF에 직접 적용하는 데는 추가적인 연구가 필요하다:

- PRM의 단계별 점수를 강화학습 보상으로 어떻게 변환할 것인가?
- 학습 과정에서 PRM의 점수가 조작(게이밍)되지 않도록 어떻게 보장할 것인가?
- PRM 학습에 필요한 단계별 레이블의 비용을 어떻게 줄일 것인가?

## PRM800K 데이터셋 상세

### 데이터 구조

PRM800K의 각 데이터 포인트는 다음 구조를 갖는다:

```
{
    "question": "수학 문제 텍스트",
    "solution": {
        "steps": [
            {
                "text": "단계 1 텍스트",
                "label": "positive/negative/neutral",
                "completions_explored": 숫자
            },
            ...
        ],
        "final_answer": "최종 답",
        "is_correct": true/false
    }
}
```

### 데이터 품질 관리

레이블 품질을 보장하기 위한 조치:

1. **이중 레이블링**: 중요한 데이터 포인트에 대해 두 명의 레이블러가 독립적으로 레이블링
2. **합의율 모니터링**: 레이블러 간 합의율이 일정 수준 이하로 떨어지면 가이드라인 수정
3. **전문가 검토**: 무작위 샘플에 대한 전문가 검토를 정기적으로 수행
4. **레이블러 교육**: 수학 전공 출신 레이블러를 선별하여 교육

### 데이터셋의 한계

PRM800K의 알려진 한계:

- MATH 데이터셋의 문제만 포함 (고등 수학 수준)
- 영어로만 작성됨
- 레이블러의 주관적 판단이 개입될 수 있음
- "neutral" 레이블의 해석이 모호할 수 있음

## 기술적 세부사항

### PRM 학습 방법

PRM은 다음과 같이 학습된다:

1. **기반 모델**: GPT-4 계열의 사전학습 모델
2. **입력 형식**: 문제 + 지금까지의 풀이 단계
3. **출력**: 마지막 단계에 대한 positive/negative 확률
4. **학습 목표**: 이진 분류 (positive vs negative, neutral은 제외)

손실 함수:

$$\mathcal{L}_{\text{PRM}} = -\sum_{(x, s, y)} \left[ y \log p_\theta(\text{pos} | x, s) + (1-y) \log p_\theta(\text{neg} | x, s) \right]$$

여기서 $(x, s, y)$는 (문제, 풀이의 단계까지, 레이블)이다.

### ORM 학습 방법

비교를 위한 ORM은 다음과 같이 학습된다:

1. **입력 형식**: 문제 + 전체 풀이
2. **출력**: 풀이의 정확도 확률
3. **학습 데이터**: 최종 답의 정답 여부로 자동 레이블링 (인간 레이블 불필요)

$$\mathcal{L}_{\text{ORM}} = -\sum_{(x, S, y)} \left[ y \log p_\theta(\text{correct} | x, S) + (1-y) \log p_\theta(\text{incorrect} | x, S) \right]$$

### Majority Voting과의 비교

가장 단순한 기준선인 majority voting은:

1. $N$개의 풀이 생성
2. 각 풀이의 최종 답 추출
3. 가장 많이 나온 답을 선택

이 방법은 보상 모델이 필요 없지만, 풀이의 **품질**을 고려하지 않는다. 10개 중 3개가 같은 답이면, 그 3개의 풀이가 모두 같은 실수를 반복한 것일 수 있다.

## 후속 연구에의 영향

### Process Reward Models의 발전

본 논문 이후 PRM 연구가 크게 활발해졌다:

1. **Math-Shepherd**: PRM의 학습 데이터를 자동으로 생성하는 방법 제안
2. **OmegaPRM**: 몬테카를로 트리 탐색으로 프로세스 레이블 자동 생성
3. **Implicit PRM**: 별도의 PRM 없이 LLM 자체의 확률로 프로세스 검증

### Test-Time Compute Scaling

[[scaling-test-time-compute]]에서는 PRM을 활용한 트리 탐색(tree search)으로 테스트 시점 연산을 효율적으로 스케일링하는 방법을 분석한다. PRM이 좋을수록 탐색의 효율이 높아지며, 이는 "더 작은 모델 + 더 많은 테스트 시점 연산"이 "더 큰 모델"을 능가할 수 있음을 보여준다.

### OpenAI o1/o3 계열

OpenAI의 o1, o3 모델은 본 논문의 아이디어를 발전시킨 것으로 추정된다. 체인 오브 소트(chain-of-thought) 추론에서 내부적으로 프로세스 검증을 수행하여, 더 길고 신뢰할 수 있는 추론 체인을 생성한다.

## 실용적 시사점

### PRM 레이블링 비용 문제

PRM의 핵심 한계는 **인간 레이블링 비용**이다. 800K 단계별 레이블을 수집하는 데 상당한 비용과 시간이 소요되었다.

이를 해결하기 위한 후속 연구 방향:

| 방법 | 원리 | 효과 |
|------|------|------|
| 몬테카를로 추정 | 각 단계 이후 정답 도달 확률로 자동 레이블 | 비용 90%+ 절감 |
| LLM-as-Judge | 강력한 LLM이 단계별 정확성 판단 | 인간 수준 근접 |
| 자가 학습(Self-Training) | PRM이 자신의 예측으로 추가 학습 | 점진적 개선 |
| 합성 데이터 | LLM이 의도적으로 오류 삽입한 풀이 생성 | 다양한 오류 패턴 학습 |

### 도메인 확장

PRM800K는 수학 도메인에 특화되어 있지만, 프로세스 감독의 원리는 다른 도메인에도 적용 가능하다:

- **코딩**: 각 코드 줄의 정확성 검증
- **과학적 추론**: 가설 → 실험 → 결론의 각 단계 검증
- **논리적 논증**: 전제 → 추론 → 결론의 각 단계 검증
- **계획 수립**: 각 행동 단계의 타당성 검증

5. **영어 전용**: 다국어 환경에서의 효과 미검증

1. **PRM을 학습에 직접 활용**: RL의 보상 신호로 PRM을 사용하면 생성기도 개선될 수 있는가?

## 결론

"Let's Verify Step by Step"은 LLM 추론 연구에서 **과정 감독의 우월성**을 대규모 실험으로 입증한 획기적인 논문이다. 약 80만 개의 단계별 인간 레이블로 구성된 PRM800K 데이터셋과 함께, PRM이 ORM보다 일관되게 우수한 성능을 보인다는 것을 명확히 보여주었다.

이 논문의 영향은 여러 방향으로 확장된다:

1. **[[process-reward-models]]**: PRM 연구의 기초 문헌으로 자리잡음
2. **[[test-time-compute-scaling]]**: 테스트 시점 연산 스케일링의 핵심 구성 요소로서 PRM의 역할 확립
3. **AI 정렬**: 과정 감독이 보상 해킹에 더 강건하다는 정렬 관점의 기여
4. **오픈 연구**: PRM800K 공개를 통한 커뮤니티 연구 촉진

수학 추론을 넘어, "결과가 아닌 과정을 검증한다"는 원칙은 신뢰할 수 있는 AI 시스템을 구축하는 데 있어 핵심적인 설계 원칙이 될 것이다. 특히 o1/o3 계열 모델의 등장으로, 프로세스 감독은 최첨단 AI 시스템의 핵심 기술로 자리잡고 있다.
