## 개요

:::info
**Paper:** From Local to Global: A Graph RAG Approach to Query-Focused Summarization (arXiv:2404.16130, 2024.04)
**저자:** Darren Edge, Ha Trinh, Newman Cheng, Joshua Bradley, Alex Chao, Apurva Mody, Steven Truitt, Jonathan Larson
**소속:** Microsoft Research
**코드:** [GitHub: microsoft/graphrag](https://github.com/microsoft/graphrag)
:::

GraphRAG는 Microsoft Research에서 제안한 검색 증강 생성(RAG) 프레임워크로, 기존 RAG가 해결하지 못하는 **글로벌 질문(Global Question)**에 답하기 위해 설계되었습니다. 기존 RAG는 "BERT의 학습률은 얼마인가?"처럼 특정 문서에서 정보를 찾을 수 있는 로컬 질문에 강하지만, "이 논문 모음의 공통 연구 트렌드는 무엇인가?"처럼 전체 코퍼스를 아우르는 이해가 필요한 질문에는 구조적 한계를 드러냅니다.

GraphRAG의 핵심 전략은 **LLM 기반 지식 그래프 구축 + Leiden 커뮤니티 탐지 + 계층적 커뮤니티 요약**이라는 3단계 인덱싱 파이프라인을 통해, 쿼리 시점에 전체 코퍼스를 다시 순회하지 않고도 글로벌 질문에 답할 수 있는 구조를 만드는 것입니다. 이 접근법은 기존의 [[68_dpr]] 같은 밀집 검색 기반 RAG와 근본적으로 다른 패러다임을 제시합니다.

## 배경 및 동기

### 전통적 RAG의 구조적 한계

전통적 RAG 파이프라인은 다음과 같은 단순한 흐름을 따릅니다. 문서를 청크로 분할하고, 각 청크를 임베딩 벡터로 변환하여 벡터 DB에 저장한 뒤, 쿼리가 들어오면 유사도 기반 검색으로 top-k 청크를 가져와 LLM에 전달합니다.

이 구조는 **로컬 질문(Local Question)**에 매우 효과적입니다. "GPT-4의 파라미터 수는?"이라는 질문에는 관련 청크를 검색하면 충분합니다. 하지만 다음과 같은 질문 유형에서는 근본적으로 실패합니다.

| 질문 유형 | 예시 | 기존 RAG 대응 가능 여부 |
|----------|------|----------------------|
| 로컬 사실 질문 | "Transformer의 어텐션 메커니즘 수식은?" | O |
| 비교/분석 질문 | "BERT와 GPT의 학습 방식 차이점은?" | 부분적 |
| 글로벌 요약 질문 | "이 데이터셋의 주요 테마 5가지는?" | X |
| 트렌드 분석 질문 | "2023년 NLP 연구의 공통적 방향은?" | X |
| 관계 탐색 질문 | "어떤 연구 그룹들이 관련 주제를 다루는가?" | X |

글로벌 질문이 실패하는 근본 원인은 세 가지입니다.

1. **정보 분산**: 답에 필요한 정보가 코퍼스 전체에 걸쳐 분포합니다. 특정 청크 몇 개로는 전체 그림을 조립할 수 없습니다.
2. **키워드 부재**: "주요 테마는?"이라는 질문에는 검색에 사용할 구체적 키워드가 없습니다. 임베딩 유사도로도 적절한 청크를 가져오기 어렵습니다.
3. **집계의 필요**: 개별 문서의 내용이 아니라 문서 간 패턴과 관계를 파악해야 합니다. 이는 검색이 아닌 분석의 영역입니다.

### Naive 접근법과 그 한계

글로벌 질문에 답하는 가장 직관적인 방법은 **전체 코퍼스를 LLM에 넣는 것**입니다. Map-Reduce 패턴을 사용하면 원리적으로는 가능합니다. 각 문서에서 부분 답변을 추출(Map)하고, 이를 통합(Reduce)하는 방식입니다.

하지만 이 접근법은 실용적이지 않습니다.

| 문제 | 상세 |
|------|------|
| 비용 폭발 | 매 질문마다 전체 코퍼스를 LLM에 입력해야 합니다. 100만 토큰 코퍼스에 대해 매번 수십 달러의 API 비용이 발생합니다 |
| 컨텍스트 한계 | 대부분의 LLM은 128K~1M 토큰의 컨텍스트 윈도우를 가집니다. 수백만 토큰 규모의 코퍼스는 한 번에 처리 불가능합니다 |
| 정보 희석 | 모든 정보를 동등하게 취급하면 핵심 패턴이 노이즈에 묻힙니다. 관련 없는 세부사항이 답변의 초점을 흐립니다 |
| 지연 시간 | 전체 코퍼스를 순회하는 데 수 분 이상 소요됩니다. 실시간 상호작용이 불가능합니다 |

### Query-Focused Summarization과의 연결

GraphRAG는 정보 검색 분야의 오래된 과제인 **Query-Focused Summarization (QFS)**을 LLM 시대에 재정의합니다. QFS는 "주어진 쿼리에 관련된 문서 집합의 요약을 생성하라"는 태스크입니다. 전통적 QFS 연구(DUC/TAC 등)는 수십 개의 뉴스 기사를 대상으로 했지만, GraphRAG는 이를 **수천~수만 개 문서 규모**로 확장합니다. 핵심 통찰은 "미리 구조화된 지식(Knowledge Graph + Community Summary)을 인덱싱 시점에 구축하면, 쿼리 시점의 비용을 대폭 줄일 수 있다"는 것입니다.

## 핵심 아이디어

GraphRAG의 핵심 아이디어는 간결하게 요약할 수 있습니다.

> **인덱싱 시점에 LLM을 사용하여 코퍼스의 지식 구조를 미리 파악하고, 쿼리 시점에는 이 구조를 활용하여 효율적으로 답변한다.**

이를 실현하기 위한 세 가지 핵심 구성 요소가 있습니다.

**1. LLM 기반 지식 그래프 구축**: 전통적인 NER/RE 파이프라인 대신 LLM이 직접 엔티티와 관계를 추출합니다. 도메인 특화 학습 없이도 범용적으로 적용 가능합니다.

**2. 계층적 커뮤니티 탐지**: Leiden 알고리즘으로 지식 그래프에서 의미적으로 밀접한 노드 그룹(커뮤니티)을 다단계로 탐지합니다. 각 커뮤니티는 하나의 "주제"나 "테마"에 대응합니다.

**3. 커뮤니티 요약 기반 글로벌 검색**: 각 커뮤니티에 대해 LLM이 요약 보고서를 사전 생성합니다. 글로벌 질문이 들어오면, 전체 코퍼스 대신 이 요약들을 검색하고 종합하여 답변합니다.

:::tip
GraphRAG의 설계 철학은 **인덱싱 시점에 더 많은 비용을 투자하여 쿼리 시점의 비용과 품질을 동시에 개선**하는 것입니다. 이는 데이터베이스의 인덱스 구축과 유사한 발상입니다. 인덱스 생성에는 시간이 걸리지만, 이후의 모든 쿼리가 빨라지는 것과 같은 원리입니다.
:::

## 방법론: 인덱싱 파이프라인

GraphRAG의 인덱싱 파이프라인은 4단계로 구성됩니다. 각 단계를 상세히 살펴보겠습니다.

### Phase 1: 소스 문서 분할 및 엔티티/관계 추출

입력 텍스트를 일정 크기의 청크로 분할한 후, **각 청크에 대해 LLM을 호출**하여 엔티티(노드)와 관계(엣지)를 추출합니다.

```
텍스트: "OpenAI의 GPT-4는 Transformer 아키텍처를 기반으로 하며,
        RLHF를 통해 정렬되었다. Google의 PaLM-2도 Transformer를
        사용하지만 다른 학습 전략을 채택했다."

추출 결과:
  엔티티: [OpenAI(조직), GPT-4(모델), Transformer(아키텍처),
          RLHF(기법), Google(조직), PaLM-2(모델)]
  관계: [OpenAI -개발→ GPT-4,
         GPT-4 -기반→ Transformer,
         GPT-4 -정렬방법→ RLHF,
         Google -개발→ PaLM-2,
         PaLM-2 -기반→ Transformer]
```

기존의 NER/RE 파이프라인(spaCy, Stanford NER 등)과 달리, GraphRAG는 **LLM을 엔티티/관계 추출기로 사용**합니다. 이 방식의 장점과 단점을 정리하면 다음과 같습니다.

| 측면 | LLM 기반 추출 (GraphRAG) | 전통 NER/RE |
|------|------------------------|-------------|
| 도메인 적응 | 프롬프트 수정만으로 가능 | 도메인별 학습 데이터 필요 |
| 관계 유형 | 개방형(Open IE), 자유로운 관계 정의 | 사전 정의된 관계 스키마 필요 |
| 비용 | 청크당 LLM API 호출 비용 | 추론 비용 낮음 |
| 품질 일관성 | LLM의 환각/누락 가능 | 학습 데이터 품질에 의존 |
| 확장성 | 대규모 코퍼스에서 비용 증가 | 효율적으로 확장 가능 |

논문에서는 **다중 글리닝(Multiple Gleaning)** 기법을 제안합니다. 동일 청크에 대해 LLM을 여러 번 호출하여, 처음에 놓친 엔티티와 관계를 추가로 추출합니다. 이를 통해 재현율(recall)을 높이되 비용이 증가하는 트레이드오프가 발생합니다.

### Phase 2: Leiden 알고리즘을 통한 커뮤니티 탐지

구축된 지식 그래프에서 **Leiden 알고리즘**을 사용하여 커뮤니티를 탐지합니다. Leiden 알고리즘은 그래프 기반 커뮤니티 탐지의 대표적 알고리즘으로, Louvain 알고리즘의 개선판입니다.

Leiden 알고리즘의 핵심 동작 원리는 다음과 같습니다.

1. **모듈러리티 최적화**: 각 노드를 인접 커뮤니티로 이동시켜 모듈러리티(커뮤니티 내부 연결 밀도 대비 외부 연결 밀도)를 최대화합니다.
2. **커뮤니티 정제(Refinement)**: Louvain과 달리 Leiden은 정제 단계를 추가하여, 잘못 할당된 노드를 재배치합니다. 이를 통해 연결이 끊긴 커뮤니티(disconnected community) 문제를 해결합니다.
3. **계층적 축약(Aggregation)**: 탐지된 커뮤니티를 하나의 "슈퍼 노드"로 축약하고, 축약된 그래프에서 다시 커뮤니티를 탐지합니다.

이 과정을 통해 **다단계 계층 구조**가 생성됩니다.

```
레벨 0 (최하위): 개별 엔티티
  → {GPT-4, GPT-3.5, InstructGPT, RLHF, DPO, PPO}

레벨 1 (중간):
  → 커뮤니티 A: {GPT-4, GPT-3.5, InstructGPT}  ← "OpenAI 모델 계열"
  → 커뮤니티 B: {RLHF, DPO, PPO}                ← "LLM 정렬 기법"

레벨 2 (상위):
  → 커뮤니티 X: {커뮤니티 A, 커뮤니티 B, ...}    ← "LLM 학습 및 최적화"
```

**해상도(resolution) 파라미터**를 조정하여 커뮤니티의 세밀도를 제어할 수 있습니다. 해상도가 높으면 작고 세밀한 커뮤니티가 많이 생기고, 낮으면 크고 포괄적인 커뮤니티가 적게 생깁니다.

### Phase 3: 커뮤니티 요약 생성

각 커뮤니티에 대해 LLM이 **구조화된 요약 보고서**를 생성합니다. 요약에는 다음 정보가 포함됩니다.

- 커뮤니티에 포함된 핵심 엔티티 목록
- 엔티티 간 주요 관계 설명
- 커뮤니티가 나타내는 주제/테마에 대한 서술적 요약
- 커뮤니티의 중요도를 반영하는 영향력 점수

```
커뮤니티 B (LLM 정렬 기법) 요약 보고서:
-------------------------------------
"이 그룹은 대형 언어 모델의 인간 선호도 정렬 기법을 다룬다.
RLHF(Reinforcement Learning from Human Feedback)가 기본
패러다임이며, 보상 모델을 학습한 뒤 PPO(Proximal Policy
Optimization)로 정책을 최적화한다. DPO(Direct Preference
Optimization)는 보상 모델 없이 선호도 데이터에서 직접
정책을 학습하는 대안으로, 2023년 이후 빠르게 채택되고 있다.
최근 트렌드는 보상 모델 의존성을 줄이는 방향이다."

핵심 엔티티: RLHF, DPO, PPO, 보상 모델
영향력 점수: 0.85
```

계층적 요약은 **하위 레벨에서 상위 레벨로** 생성됩니다. 레벨 1 커뮤니티 요약은 해당 커뮤니티의 엔티티와 관계를 직접 참조하고, 레벨 2 커뮤니티 요약은 하위 커뮤니티의 요약을 종합합니다. 이를 통해 세부사항부터 거시적 주제까지 다양한 추상화 수준의 정보가 미리 준비됩니다.

### Phase 4: 그래프 인덱스 완성

최종적으로 다음 요소들이 인덱스로 저장됩니다.

| 인덱스 구성 요소 | 내용 | 용도 |
|----------------|------|------|
| 엔티티 노드 | 이름, 유형, 설명, 출처 청크 | 로컬 검색 |
| 관계 엣지 | 소스, 타겟, 관계 유형, 설명 | 로컬 검색, 그래프 탐색 |
| 커뮤니티 메타데이터 | 계층 레벨, 구성 노드, 크기 | 글로벌 검색 |
| 커뮤니티 요약 | 각 커뮤니티의 서술적 요약 보고서 | 글로벌 검색 |
| 원본 텍스트 청크 | 분할된 원문 + 임베딩 벡터 | 로컬 검색, 근거 제시 |

## 방법론: 검색 메커니즘

인덱싱이 완료되면, 쿼리 시점에 두 가지 검색 모드를 활용할 수 있습니다.

### 로컬 검색 (Local Search)

로컬 검색은 **특정 엔티티에 대한 질문**에 답하기 위해 설계되었습니다. 기존 RAG의 벡터 검색을 그래프 구조로 보강한 방식입니다.

동작 과정은 다음과 같습니다.

1. 질문에서 핵심 엔티티를 추출합니다 (LLM 또는 키워드 매칭)
2. 지식 그래프에서 해당 엔티티와 연결된 **이웃 노드와 관계를 탐색**합니다
3. 관련 엔티티가 속한 커뮤니티의 요약을 가져옵니다
4. 원본 텍스트 청크도 함께 검색합니다
5. 엔티티 정보 + 관계 정보 + 커뮤니티 요약 + 텍스트 청크를 종합하여 LLM에 전달합니다

기존 RAG 대비 로컬 검색의 장점은 **엔티티 간 관계 정보**가 컨텍스트로 추가된다는 점입니다. "GPT-4에 대해 알려줘"라는 질문에 대해, 기존 RAG는 GPT-4가 언급된 청크만 가져오지만, GraphRAG의 로컬 검색은 GPT-4의 개발 조직(OpenAI), 기반 아키텍처(Transformer), 학습 기법(RLHF), 관련 모델(GPT-3.5, InstructGPT) 등의 관계 정보도 함께 제공합니다.

### 글로벌 검색 (Global Search)

글로벌 검색은 GraphRAG의 핵심 혁신으로, **전체 코퍼스에 걸친 질문**에 답합니다.

동작 과정은 다음과 같습니다.

1. 적절한 계층 레벨의 커뮤니티 요약을 검색 대상으로 설정합니다
2. 질문과 관련된 커뮤니티 요약을 선별합니다
3. **Map 단계**: 선별된 각 커뮤니티 요약에 대해 LLM이 부분 답변과 관련성 점수를 생성합니다
4. **Reduce 단계**: 부분 답변들을 관련성 점수 기준으로 정렬하고, 최종 답변으로 통합합니다

:::warning
글로벌 검색의 Map-Reduce는 Naive 접근법의 Map-Reduce와 구조적으로 유사하지만, 핵심 차이점이 있습니다. Naive 접근법은 매 쿼리마다 **전체 원본 텍스트**를 순회하는 반면, GraphRAG는 **사전 생성된 커뮤니티 요약**만 순회합니다. 커뮤니티 요약의 총 토큰 수는 원본 대비 훨씬 적으므로 비용과 지연이 크게 줄어듭니다.
:::

### 로컬 검색 vs 글로벌 검색 비교

| 비교 항목 | 로컬 검색 (Local Search) | 글로벌 검색 (Global Search) |
|----------|------------------------|---------------------------|
| 대상 질문 | 특정 엔티티/사실에 대한 질문 | 전체 코퍼스에 걸친 요약/분석 질문 |
| 검색 대상 | 엔티티, 관계, 관련 청크 | 커뮤니티 요약 보고서 |
| 탐색 방식 | 그래프 이웃 탐색 + 벡터 검색 | Map-Reduce over 커뮤니티 요약 |
| 장점 | 관계 정보 기반의 풍부한 컨텍스트 | 코퍼스 전체를 아우르는 포괄적 답변 |
| 한계 | 글로벌 패턴 파악 불가 | 세부 사실 정확도 낮을 수 있음 |
| 비용 | 기존 RAG와 유사 | Naive 접근법보다 낮지만 추가 비용 있음 |

## 실험 결과

### 실험 설정

논문에서는 두 가지 데이터셋에서 실험을 수행합니다.

**Podcast 데이터셋**: 기술 관련 팟캐스트의 트랜스크립트 1,669개로 구성됩니다. 약 100만 토큰 규모의 비정형 대화 텍스트입니다.

**AP News 데이터셋**: Associated Press 뉴스 기사 모음입니다. 다양한 주제(정치, 경제, 사회, 스포츠 등)를 다루는 정형화된 뉴스 텍스트입니다.

비교 대상은 다음 네 가지 방법입니다.

| 방법 | 설명 |
|------|------|
| Naive RAG (TS) | 벡터 검색으로 top-k 텍스트 청크를 검색 후 LLM에 전달 |
| Map-Reduce (SS) | 전체 소스 텍스트를 LLM으로 순차 처리하여 답변 생성 |
| GraphRAG (C0) | 최하위 레벨(레벨 0) 커뮤니티 요약 기반 글로벌 검색 |
| GraphRAG (C1) | 중간 레벨(레벨 1) 커뮤니티 요약 기반 글로벌 검색 |
| GraphRAG (C2) | 상위 레벨(레벨 2) 커뮤니티 요약 기반 글로벌 검색 |
| GraphRAG (C3) | 최상위 레벨(레벨 3) 커뮤니티 요약 기반 글로벌 검색 |

### 평가 메트릭

전통적인 자동 평가 메트릭(ROUGE, BLEU 등) 대신, LLM을 심사위원으로 활용하는 **LLM 기반 페어와이즈 비교** 방식을 채택합니다. 두 시스템의 답변을 동시에 제시하고, 다음 기준으로 어느 쪽이 더 나은지 판단합니다.

| 평가 기준 | 정의 |
|----------|------|
| 포괄성 (Comprehensiveness) | 질문에 관련된 정보를 얼마나 빠짐없이 포함하는가 |
| 다양성 (Diversity) | 다양한 관점, 각도, 측면에서 답변을 제공하는가 |
| 역량 (Empowerment) | 답변이 독자의 이해와 의사결정에 도움이 되는가 |
| 직접성 (Directness) | 질문에 직접적이고 명확하게 답변하는가 |

### 글로벌 질문 성능

글로벌 질문("이 데이터셋의 주요 테마는?", "핵심 인물과 그 기여는?")에서 GraphRAG는 모든 비교 대상을 유의미하게 능가합니다.

**포괄성(Comprehensiveness)**: GraphRAG(C0~C2)는 Naive RAG 대비 **72~83%의 승률**을 기록합니다. 커뮤니티 요약이 코퍼스의 주요 테마를 빠짐없이 포착하기 때문입니다. 특히 Naive RAG가 top-k 검색으로 놓치는 비주류 주제까지 포함합니다.

**다양성(Diversity)**: GraphRAG(C0~C2)는 Naive RAG 대비 **55~82%의 승률**을 기록합니다. 계층적 커뮤니티 구조가 다양한 관점의 정보를 자연스럽게 포함하기 때문입니다.

**커뮤니티 레벨별 트레이드오프**: 하위 레벨(C0)은 세밀하지만 토큰 비용이 높고, 상위 레벨(C2, C3)은 비용이 낮지만 세부사항이 누락될 수 있습니다. 논문에서는 C1(중간 레벨)이 포괄성과 비용의 균형이 가장 좋다고 보고합니다.

### 로컬 질문 성능

로컬 질문에서는 GraphRAG의 로컬 검색이 Naive RAG와 **비슷하거나 약간 우세**한 성능을 보입니다. 그래프 구조가 제공하는 관계 정보가 답변 품질을 향상시키지만, 단순한 사실 추출 질문에서의 차이는 크지 않습니다. 이는 로컬 질문이 GraphRAG의 주요 설계 목표가 아니며, 기존 RAG가 이미 충분히 잘 작동하는 영역이기 때문입니다.

### Map-Reduce 대비 효율성

전체 코퍼스를 순회하는 Map-Reduce(SS) 대비, GraphRAG는 **유사하거나 더 나은 답변 품질을 훨씬 적은 토큰으로** 달성합니다. 커뮤니티 요약의 총 크기가 원본 텍스트보다 크게 작기 때문입니다.

## 비용 분석과 트레이드오프

### 인덱싱 비용의 현실

GraphRAG의 가장 큰 현실적 장벽은 **인덱싱 비용**입니다. 기존 RAG는 임베딩 생성만으로 인덱싱이 완료되지만, GraphRAG는 다음의 추가 비용이 발생합니다.

| 인덱싱 단계 | LLM 호출 횟수 | 비용 특성 |
|------------|--------------|----------|
| 엔티티/관계 추출 | 텍스트 청크 수 x (1 + 글리닝 횟수) | 가장 큰 비용 요인 |
| 커뮤니티 요약 생성 | 커뮤니티 수 (수십~수백) | 상대적으로 적은 비용 |
| 총 인덱싱 비용 | 기존 RAG 대비 10~100배 | 코퍼스 크기에 비례 |

예를 들어, 100만 토큰 코퍼스를 600토큰 청크로 분할하면 약 1,667개의 청크가 생깁니다. 각 청크에 대해 엔티티/관계 추출을 위한 LLM 호출이 필요하고, 다중 글리닝을 적용하면 호출 횟수가 배가됩니다. GPT-4 가격 기준으로 인덱싱에만 수십~수백 달러가 소요될 수 있습니다.

### 언제 GraphRAG가 적합한가

| 시나리오 | 권장 접근법 | 이유 |
|---------|-----------|------|
| 글로벌/요약 질문이 빈번함 | GraphRAG | 인덱싱 비용이 질의 품질 향상으로 상각됨 |
| 로컬 사실 질문만 필요 | 기존 RAG / [[68_dpr]] | 인덱싱 오버헤드 대비 이점 부족 |
| 코퍼스가 자주 변경됨 | 기존 RAG | 재인덱싱 비용이 누적적으로 증가 |
| 코퍼스가 고정, 질문이 다양함 | GraphRAG | 한 번 인덱싱으로 다양한 질문 유형 대응 |
| 소규모 코퍼스 (100K 미만) | 기존 RAG + 긴 컨텍스트 LLM | 전체를 프롬프트에 넣는 것이 더 경제적 |
| 대규모 코퍼스 (1M+ 토큰) | GraphRAG | 전체 순회가 비현실적, 구조화된 인덱스 필수 |

### 비용 절감 전략

논문에서 직접 다루지는 않지만, 실무에서 GraphRAG의 비용을 줄이기 위한 전략은 다음과 같습니다.

- **경량 모델로 추출**: 엔티티/관계 추출에는 GPT-4 대신 GPT-4o-mini나 Llama-3 같은 경량 모델을 사용합니다. 요약 생성에만 고성능 모델을 투입합니다.
- **글리닝 횟수 조절**: 도메인에 따라 1~2회면 충분한 경우가 많습니다. 과도한 글리닝은 비용 대비 재현율 향상이 미미합니다.
- **점진적 인덱싱**: 새 문서 추가 시 전체 재구축 대신, 영향받는 커뮤니티만 업데이트하는 방식을 적용합니다 (Microsoft의 공식 SDK에서 점진적으로 지원 중).

## 한계 및 의의

### 한계

**1. 추출 품질의 병목**: LLM의 엔티티/관계 추출 품질이 전체 파이프라인의 성능 상한을 결정합니다. 추출 시 발생하는 오류(잘못된 관계, 누락된 엔티티, 중복 엔티티)가 커뮤니티 구조를 왜곡하고, 최종 답변 품질에 영향을 줍니다. 특히 동일 엔티티가 다른 이름으로 추출되는 **엔티티 해결(Entity Resolution)** 문제는 지식 그래프 품질의 핵심 과제입니다.

**2. 커뮤니티 세분도 결정의 어려움**: Leiden 알고리즘의 해상도 파라미터에 따라 커뮤니티의 크기와 수가 달라집니다. 최적 해상도는 데이터의 특성, 질문 유형, 코퍼스 규모에 따라 다르며, 이를 자동으로 결정하는 방법은 아직 미해결 과제입니다.

**3. 동적 업데이트의 제약**: 새로운 문서가 추가되면 그래프와 커뮤니티 구조를 갱신해야 합니다. 현재 구현에서는 전체 재구축이 기본이며, 점진적 업데이트는 활발히 연구 중입니다.

**4. 평가 방법의 한계**: LLM 기반 페어와이즈 비교는 인간 평가 대비 편의성이 높지만, LLM의 편향(자신의 출력을 선호하는 경향, 길이 편향 등)이 평가 결과에 영향을 줄 수 있습니다.

### 학술적 의의

1. **글로벌 질문이라는 새로운 문제 정의**: 기존 RAG 연구가 로컬 질문에만 집중하던 것에서 벗어나, 글로벌/요약 질문이라는 중요하지만 간과되었던 문제를 공식화했습니다.
2. **지식 그래프와 RAG의 결합**: 전통적 지식 그래프 기술(커뮤니티 탐지, 그래프 탐색)과 LLM 시대의 RAG를 결합한 체계적 프레임워크를 제시했습니다.
3. **계층적 요약이라는 새로운 인덱싱 전략**: 인덱싱 시점에 LLM으로 다단계 요약을 생성하는 아이디어는, [[69_raptor]]의 Tree-based 요약과 함께 RAG 인덱싱의 새로운 방향을 열었습니다.

### 산업적 영향

Microsoft는 GraphRAG를 **오픈소스 SDK**(github.com/microsoft/graphrag)로 공개하여, 누구나 자신의 데이터에 GraphRAG를 적용할 수 있게 했습니다. 이 SDK는 2024년 공개 이후 GitHub 스타 20,000개 이상을 기록하며 커뮤니티의 높은 관심을 받았습니다. 또한 Azure AI에 통합되어 엔터프라이즈 환경에서도 활용되고 있습니다.

## 후속 연구 및 발전 방향

### GraphRAG 이후의 발전

GraphRAG의 아이디어는 여러 후속 연구를 촉발했습니다.

**RAPTOR** ([[69_raptor]]): 트리 구조 기반의 계층적 요약을 제안합니다. GraphRAG가 그래프 커뮤니티 기반 계층을 사용하는 반면, RAPTOR는 텍스트 청크의 클러스터링 기반 트리를 구축합니다. 두 접근법은 "인덱싱 시점에 다단계 요약을 미리 준비한다"는 핵심 아이디어를 공유합니다.

**하이브리드 검색 + 리랭킹** ([[hybrid-search-reranking]]): 벡터 검색과 키워드 검색을 결합하고, 리랭커로 결과를 정제하는 방식입니다. GraphRAG의 로컬 검색과 결합하면 검색 품질을 더 높일 수 있습니다.

**컨텍스트 압축** ([[context-compression]]): 검색된 컨텍스트에서 불필요한 정보를 압축하여 LLM에 전달하는 기법입니다. GraphRAG의 커뮤니티 요약 자체가 일종의 컨텍스트 압축으로 볼 수 있습니다.

### 열린 연구 문제

| 연구 문제 | 현재 상태 | 향후 방향 |
|----------|----------|----------|
| 실시간 그래프 업데이트 | 전체 재구축 필요 | 증분적 그래프 갱신 알고리즘 |
| 멀티모달 지식 그래프 | 텍스트만 지원 | 이미지, 테이블, 코드 포함 |
| 최적 해상도 자동 결정 | 수동 튜닝 | 질문 유형 기반 적응적 해상도 |
| 엔티티 해결 고도화 | 기본적 중복 제거 | LLM 기반 동의어/약어 통합 |
| 비용 효율적 추출 | 고비용 LLM 의존 | 소형 전문 모델 파인튜닝 |

## 결론

GraphRAG는 기존 RAG의 근본적 한계인 **글로벌 질문 대응 불가** 문제를 지식 그래프와 커뮤니티 기반 요약으로 해결한 프레임워크입니다. "인덱싱 시점에 코퍼스의 지식 구조를 미리 파악하고, 쿼리 시점에 이 구조를 활용한다"는 설계 철학은 RAG의 패러다임을 검색 중심에서 **구조화된 지식 중심**으로 전환했습니다.

이 논문의 기여는 세 가지 차원에서 평가할 수 있습니다. 첫째, **문제 정의** 측면에서 글로벌 질문이라는 기존 RAG가 구조적으로 해결하지 못하는 중요 질문 유형을 공식화했습니다. 둘째, **방법론** 측면에서 LLM 기반 엔티티 추출, Leiden 커뮤니티 탐지, 계층적 요약이라는 체계적 파이프라인을 제시했습니다. 셋째, **생태계** 측면에서 오픈소스 SDK를 통해 실무 적용을 촉진하고, 그래프 기반 RAG 연구의 활발한 후속 연구를 촉발했습니다.

다만, 10~100배에 달하는 인덱싱 비용, 추출 품질의 병목, 동적 업데이트의 제약 등은 여전히 해결해야 할 과제입니다. 이러한 한계에도 불구하고, GraphRAG는 RAG 시스템이 단순한 "검색 + 생성"을 넘어 **코퍼스의 구조적 이해**를 바탕으로 답변하는 방향으로 진화하는 데 핵심적인 기여를 한 논문입니다.
