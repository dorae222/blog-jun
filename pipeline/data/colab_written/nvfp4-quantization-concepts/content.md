# NVFP4와 현대 양자화 포맷 비교: FP4·FP8·INT4·INT8의 이해

## 들어가며

:::info
이 글은 [[reasoning-vs-inference|Reasoning vs Inference]] 시리즈의 **HW Inference** 축에 해당하며, [[quantization-guide|양자화 기초 가이드]]의 후속편이다.
:::

LLM의 크기가 커지면서, 모델을 실행하는 데 필요한 GPU 메모리와 연산 비용이 핵심 병목이 되었다. 70B 파라미터 모델을 FP16으로 로드하면 **140GB의 메모리**가 필요한데, 이는 가장 비싼 소비자 GPU(RTX 4090, 24GB)로도 감당할 수 없다.

양자화는 이 문제를 해결하는 가장 직접적인 방법이다. 16비트 → 4비트로 양자화하면 메모리 사용량이 **4분의 1**로 줄어, 70B 모델을 단일 GPU에 탑재할 수 있게 된다.

[[quantization-guide]]에서는 Dynamic/Static/QAT 양자화의 기초를 다뤘다. 이 글에서는 한 단계 더 나아가, 현대 LLM 추론에서 실제로 사용되는 양자화 포맷들(INT8, INT4, FP8, FP4/NVFP4)의 **수치 표현 원리와 트레이드오프**를 비교 분석한다.

## 수치 표현의 기초

양자화를 이해하려면, 숫자가 컴퓨터에서 어떻게 표현되는지를 먼저 알아야 한다. 자세한 내용은 [[floating-point-arithmetic|부동소수점 표현]]을 참고하고, 여기서는 양자화에 필요한 핵심만 정리한다.

### 정수(Integer) vs 부동소수점(Floating-Point)

| 특성 | 정수 (INT) | 부동소수점 (FP) |
|------|-----------|---------------|
| 표현 방식 | 균등 간격 | 지수부 + 가수부 |
| 값 분포 | 전체 범위 균등 | 0 근처 밀집, 큰 값 희소 |
| 연산 속도 | 매우 빠름 | INT 대비 느림 |
| 범위 | 제한적 (8비트: -128~127) | 넓음 (지수부가 범위 결정) |

**핵심 차이**: INT는 모든 값 사이의 간격이 동일하고, FP는 0 근처에 값이 밀집되고 큰 값에서는 간격이 넓어진다. 딥러닝 가중치의 분포가 대체로 0 근처에 집중되어 있으므로, **FP 표현이 딥러닝에 자연스럽게 적합**하다.

### Scale과 Zero-Point

양자화의 핵심 연산은 고정밀 값을 저정밀 값으로 매핑하는 것이다:

$$x_q = \text{round}\left(\frac{x}{s}\right) + z$$

- $s$ (scale): 스케일링 팩터 — 연속 값의 범위를 양자화 범위에 맞춤
- $z$ (zero-point): 비대칭 분포를 보정하기 위한 오프셋
- **Per-tensor**: 텐서 전체에 하나의 scale/zero-point → 빠르지만 정확도 낮음
- **Per-channel/Per-group**: 채널/그룹별로 별도 scale → 느리지만 정확도 높음

## INT8: 입증된 표준

INT8은 현재 가장 널리 배포된 양자화 포맷이다.

### 표현 범위

- **부호 있는 INT8**: -128 ~ 127 (256개 값)
- **균등 간격**: 모든 인접 값의 차이가 동일

### 장점

- **하드웨어 지원**: 거의 모든 현대 GPU/CPU에서 INT8 연산을 네이티브 지원
- **검증된 기법**: Dynamic Quantization, SmoothQuant, GPTQ 등 성숙한 양자화 방법 존재
- **2x 메모리 절감**: FP16 대비 메모리 절반

### 한계

- **균등 간격**: 딥러닝 가중치는 0 근처에 집중되는데, INT8은 전체 범위에 균등 분포
- **outlier 문제**: 소수의 극단적으로 큰 activation 값이 전체 양자화 범위를 왜곡. SmoothQuant(Xiao et al., 2023)는 이 문제를 해결하기 위해 activation의 outlier를 weight 쪽으로 "이동"시키는 기법을 제안

### 대표 기법

- **W8A8** (Weight 8bit, Activation 8bit): 가중치와 활성화 모두 INT8. SmoothQuant 대표 설정
- **Dynamic Quantization**: 추론 시 activation의 min/max를 동적으로 계산하여 scale 결정
- **Static Quantization**: 캘리브레이션 데이터로 사전에 scale 결정

## INT4/NF4: 극한의 압축

INT4는 메모리 효율을 극대화하려는 시도이다. 4비트로는 **16개의 값만 표현**할 수 있어, 정보 손실이 불가피하다.

### INT4

- **범위**: -8 ~ 7 (16개 값, 균등 간격)
- **Per-group quantization 필수**: 텐서 전체에 하나의 scale을 사용하면 정확도가 심하게 저하. 보통 128개 원소 단위로 그룹을 구성하여 각 그룹마다 별도 scale 적용
- **대표 기법**: GPTQ(Frantar et al., 2023), AWQ(Lin et al., 2024)

### NF4 (NormalFloat4)

QLoRA(Dettmers et al., 2023)에서 제안된 NF4는 딥러닝 가중치의 분포 특성을 활용한 4비트 포맷이다.

핵심 아이디어: 딥러닝 가중치는 대체로 **정규분포**를 따르므로, 16개의 양자화 값을 정규분포의 분위수(quantile)에 맞추면 정보 이론적으로 최적의 양자화가 된다.

| INT4 | NF4 |
|------|-----|
| 균등 간격 (-8~7) | 정규분포 분위수 기반 |
| 0 근처 해상도 낮음 | 0 근처 해상도 높음 |
| 범용적 | 가중치 양자화에 특화 |

NF4는 INT4 대비 동일 비트에서 더 낮은 양자화 오차를 달성하며, QLoRA의 핵심 구성 요소다.

### Double Quantization

QLoRA의 또 다른 혁신으로, 양자화 파라미터(scale 값) 자체를 다시 양자화하는 기법이다. Per-group scale이 차지하는 메모리 오버헤드를 줄여, 실질적으로 0.5비트 추가 절감 효과를 제공한다.

## FP8: 차세대 학습·추론 표준

FP8(8비트 부동소수점)은 NVIDIA H100 GPU에서 네이티브 지원되며, INT8의 한계를 극복하기 위해 설계되었다.

### 두 가지 변형

| 포맷 | 구성 | 범위 | 용도 |
|------|------|------|------|
| **E4M3** | 1(부호)+4(지수)+3(가수) | ±448 | 가중치/활성화 (추론) |
| **E5M2** | 1(부호)+5(지수)+2(가수) | ±57344 | 그래디언트 (학습) |

- **E4M3**: 지수 4비트로 적당한 범위, 가수 3비트로 INT8에 근접한 정밀도. 추론에 최적
- **E5M2**: 지수 5비트로 넓은 범위 확보, 그래디언트의 큰 변동을 수용. BF16과 범위가 유사

### FP8의 장점

1. **동적 범위**: INT8은 선형 매핑만 가능하지만, FP8은 지수부 덕분에 outlier를 자연스럽게 수용
2. **SmoothQuant 불필요**: INT8에서 필요했던 outlier 이동 기법이 FP8에서는 불필요 — 지수부가 넓은 범위를 자동 커버
3. **학습+추론 통합**: E5M2(학습)와 E4M3(추론)의 조합으로 전체 파이프라인을 8비트로 통일 가능
4. **Transformer Engine**: H100의 Transformer Engine이 FP8 Mixed Precision을 자동 관리

### 지원 하드웨어

- NVIDIA H100/H200 (Hopper 아키텍처)
- NVIDIA B100/B200/GB200 (Blackwell 아키텍처)
- AMD MI300X (제한적)

## FP4/NVFP4: Blackwell의 4비트 부동소수점

NVIDIA의 Blackwell 아키텍처(B100/B200/GB200)에서 도입된 NVFP4는 4비트 부동소수점 포맷이다.

### 표현 구조

NVFP4는 **1(부호) + 1(지수) + 2(가수)** 구성이다:

- 부호: 1비트 (양/음)
- 지수: 1비트 (2의 거듭제곱: $2^0$ 또는 $2^1$)
- 가수: 2비트 (1.00, 1.01, 1.10, 1.11의 4가지)

총 **16개 값**을 표현할 수 있으며, 0을 포함하면 실제 사용 가능한 고유 값은 제한적이다. 이 적은 수의 표현 값에도 불구하고, 부동소수점 구조 덕분에 **0 근처의 해상도가 INT4보다 높다**.

### NVFP4 vs INT4 vs NF4

| 특성 | INT4 | NF4 | NVFP4 |
|------|------|-----|-------|
| 표현 방식 | 균등 정수 | 정규분포 분위수 | 부동소수점 |
| 하드웨어 가속 | 제한적 | 없음 (소프트웨어) | **Blackwell 네이티브** |
| 0 근처 해상도 | 낮음 | 높음 | 높음 |
| 스케일링 | Per-group 필수 | Per-group 필수 | Block scaling |
| 디퀀타이제이션 | 간단 | 룩업 테이블 | 하드웨어 자동 |

### NVFP4의 핵심 혁신: Block Scaling

NVFP4는 **micro-scaling** 방식을 사용한다. FP4 값에 블록 단위의 FP8 scale을 곱하여 실효 정밀도를 높이는 구조다:

$$x \approx s_{\text{FP8}} \times x_{\text{FP4}}$$

이 방식의 장점:
- FP4의 좁은 표현 범위를 FP8 scale이 보상
- 실효 정밀도가 순수 FP4보다 크게 향상
- 블록 크기 조절로 정확도-속도 트레이드오프 가능

### 왜 NVFP4가 중요한가

1. **2x 추가 절감**: FP8 대비 메모리·대역폭 2배 절감. 거대 모델의 실용적 배포에 결정적
2. **네이티브 하드웨어 지원**: NF4는 소프트웨어 에뮬레이션이지만, NVFP4는 Blackwell GPU의 Tensor Core에서 직접 연산
3. **학습+추론 통합 가능**: FP4 Forward + FP8 Backward 조합으로 4비트 학습도 탐색 중
4. **추론 모델과의 시너지**: DeepSeek-R1 같은 대규모 추론 모델을 소비자급 GPU에서 실행할 수 있는 가능성

## 포맷 비교 총정리

| 포맷 | 비트 | 메모리(70B) | 정밀도 | 하드웨어 | 대표 용도 |
|------|------|-----------|--------|---------|----------|
| FP16 | 16 | 140 GB | 기준 | 범용 | 학습 (baseline) |
| BF16 | 16 | 140 GB | 기준 | Ampere+ | 학습 (Google TPU) |
| FP8 E4M3 | 8 | 70 GB | 높음 | Hopper+ | 추론, FP8 학습 |
| INT8 | 8 | 70 GB | 높음 | 범용 | 추론 (SmoothQuant) |
| INT4 | 4 | 35 GB | 중간 | 제한적 | 추론 (GPTQ/AWQ) |
| NF4 | 4 | 35 GB | 중상 | SW만 | 파인튜닝 (QLoRA) |
| **NVFP4** | **4** | **35 GB** | **중상** | **Blackwell** | **추론+학습 (차세대)** |

## 실전 선택 가이드

### 추론(Inference) 시

- **H100/H200 보유**: FP8 E4M3 사용 → 정밀도 손실 최소, 2x 속도 향상
- **A100/RTX 4090**: INT4 (GPTQ/AWQ) → 대형 모델 탑재 가능
- **RTX 3090 (24GB)**: INT4 (GPTQ) → 7B-13B 모델 최적, 70B는 듀얼 GPU 필요
- **Blackwell GPU**: NVFP4 → 네이티브 가속, FP8 대비 추가 2x 절감

### 파인튜닝(Fine-tuning) 시

- **메모리 제약 심한 경우**: QLoRA (NF4) → 4비트 양자화 + LoRA 어댑터
- **메모리 여유 있는 경우**: FP8 또는 BF16 → 정밀도 우선

### 도메인별 권장

- **일반 대화/생성**: INT4/NVFP4로 충분 — 양자화 오차의 영향 최소
- **수학/코드 추론**: FP8 이상 권장 — 추론 정밀도가 정확도에 직접 영향
- **과학 계산**: FP16/BF16 유지 — 수치 안정성이 중요

## 정리

양자화 포맷의 진화는 "더 적은 비트로 더 많은 정보를 보존"하는 방향으로 진행되고 있다:

- **INT8** → 검증된 표준, 범용 하드웨어에서 작동
- **FP8** → INT8의 outlier 문제를 해결, Hopper GPU부터 네이티브 지원
- **INT4/NF4** → 극한 압축, 소프트웨어 기법으로 정밀도 보완
- **NVFP4** → 4비트 부동소수점의 하드웨어 네이티브 지원, 차세대 표준

[[reasoning-vs-inference|시리즈 총론]]에서 설명한 것처럼, HW Inference 최적화는 SW Reasoning과 함께 AI 효율성의 양축을 이룬다. 양자화된 추론 모델이 일상적으로 배포되는 미래에서, 어떤 포맷을 선택하느냐는 정확도·속도·비용의 균형을 결정하는 핵심 의사결정이 될 것이다.
