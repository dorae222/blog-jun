# Small Language Models: 작지만 강한 모델들

## 들어가며

2023년부터 AI 커뮤니티에서 흥미로운 역류가 시작되었다. "더 크게"만이 능사가 아니라, **"얼마나 작게 만들면서도 강할 수 있는가"**가 핵심 질문이 된 것이다.

Small Language Models(SLM)은 일반적으로 **1B~7B 파라미터** 규모의 모델을 지칭한다. GPT-4(~1.8T)나 LLaMA-3.1-405B에 비하면 수십~수백 배 작지만, 올바른 학습 전략을 적용하면 특정 과제에서 놀라운 성능을 보인다.

핵심 통찰: **모델 크기가 아니라 데이터 품질이 성능을 결정한다.** Microsoft의 Phi 시리즈가 이를 실증적으로 증명했고, 이후 Google(Gemma), Alibaba(Qwen), Meta(LLaMA-3.2) 등이 SLM 경쟁에 뛰어들었다.

---

## SLM이 부상한 이유

### 1. 배포 비용

대형 모델의 추론 비용은 크기에 비례한다. 70B 모델 서빙에 필요한 GPU 메모리와 연산은 7B 모델의 약 10배다. 대량의 요청을 처리하는 프로덕션 환경에서 이 차이는 **운영 비용의 10배 차이**로 직결된다.

### 2. 엣지 배포

스마트폰, IoT 기기, 로컬 서버에서 LLM을 실행하려면 모델이 작아야 한다. 4-bit [[quantization-guide|양자화]]를 적용하면 3B 모델은 약 2GB, 7B 모델은 약 4GB로 줄어들어 일반 노트북이나 스마트폰에서도 실행 가능하다.

### 3. 프라이버시

의료, 법률, 금융 등 데이터를 외부 API로 보낼 수 없는 분야에서, **로컬 실행 가능한 SLM**은 유일한 선택지다.

### 4. 파인튜닝 접근성

70B 모델의 풀 파인튜닝은 여러 장의 A100/H100이 필요하지만, 7B 모델은 **RTX 3090 한 장**으로도 LoRA 파인튜닝이 가능하다. 이는 개인 연구자와 스타트업의 AI 접근성을 크게 높인다.

## SLM 설계 원칙

### 1. 데이터 품질 > 데이터 양

Phi 시리즈의 핵심 철학은 **"Textbooks Are All You Need"**다. 웹 크롤링 데이터 수 조 토큰보다, **교과서 품질의 합성 데이터 수십억 토큰**이 더 효과적이라는 발견이다.

구체적으로:
- **교과서 품질**: 명확한 설명, 단계적 추론, 연습 문제 포함
- **합성 데이터**: GPT-4 등 대형 모델이 생성한 고품질 교육용 텍스트
- **필터링**: 웹 데이터에서 교과서 수준의 품질을 가진 텍스트만 선별

이 접근법은 [[openthoughts3-dataset|OpenThoughts3]]의 "데이터 품질이 모델 성능을 결정한다"는 발견과 일맥상통한다.

### 2. 증류 (Distillation)

대형 모델의 지식을 소형 모델로 전이하는 [[distillation-guide|증류]]는 SLM의 핵심 전략이다.

- **Gemma-2**: 대형 모델을 교사로 활용한 증류 학습
- **R1-Distill 시리즈**: [[deepseek-r1|DeepSeek-R1]] 671B의 추론 능력을 1.5B~70B로 증류
- **Phi-4**: 합성 데이터 생성 자체가 일종의 증류

증류의 핵심 제약은 **용량 격차(capacity gap)**다. 교사와 학생의 크기 차이가 너무 크면 학생이 교사의 지식을 흡수하지 못한다. [[openthoughts3-dataset|OpenThoughts3]]에서 이 현상이 상세히 분석되었다.

### 3. 아키텍처 최적화

SLM은 같은 파라미터 수에서 더 높은 성능을 내기 위한 아키텍처 개선을 적극 적용한다:

- **GQA (Grouped Query Attention)**: KV 캐시 메모리 절감 → 추론 효율 향상
- **RoPE 확장**: 긴 컨텍스트 지원 (Phi-3는 128K 토큰)
- **깊고 좁은 구조 vs 넓고 얕은 구조**: 모델 크기별 최적 비율이 다름

### 4. 양자화 친화적 설계

SLM은 [[quantization-guide|양자화]]와 함께 사용되는 경우가 많으므로, 양자화 후에도 성능이 크게 떨어지지 않도록 설계된다.

- [[nvfp4-quantization-concepts|NVFP4]]/INT4 양자화로 메모리를 1/4로 절감
- GGUF 포맷 + Ollama로 로컬 실행이 매우 간편

## SLM의 한계

### 1. 범용 지식의 부족

SLM은 특정 과제(코드, 수학, 대화)에서 강하지만, **광범위한 세계 지식**에서는 대형 모델에 크게 뒤진다. 7B 모델이 "역사적 사건의 인과관계"나 "희귀 언어 번역" 같은 작업에서 GPT-4 수준을 보이기는 어렵다.

### 2. 추론 깊이의 한계

복잡한 다단계 추론에서 SLM은 여전히 취약하다. [[deepseek-r1|R1-Distill-Qwen-1.5B]]가 AIME 2024에서 28.9%를 달성한 것은 놀랍지만, 풀 R1(671B)의 79.8%와는 큰 격차가 있다. [[test-time-compute-scaling|test-time compute]]를 증가시키면 이 격차를 일부 줄일 수 있지만, 근본적인 용량 한계는 존재한다.

### 3. 환각 빈도

작은 모델일수록 사실과 다른 정보를 자신 있게 생성하는 환각(hallucination) 빈도가 높다. 이는 세계 지식의 저장 용량이 제한적이기 때문이다.

## 실전 선택 가이드

| 시나리오 | 권장 모델 크기 | 이유 |
|----------|--------------|------|
| 스마트폰/IoT 배포 | 1B~3B | 메모리 2GB 이내 (4-bit) |
| 로컬 PC 실행 (8GB VRAM) | 3B~7B | 4-bit 양자화 시 4GB 이내 |
| 단일 GPU 파인튜닝 (RTX 3090) | 7B~13B | LoRA/QLoRA로 24GB VRAM 활용 |
| 도메인 특화 (코드/수학) | 7B + 파인튜닝 | 범용보다 특화가 효율적 |
| 범용 대화/비서 | 13B+ 또는 API | SLM보다 대형 모델이 적합 |

## 정리

SLM의 핵심은 **"작은 모델 + 좋은 데이터 + 올바른 학습 전략"**이다. 무작정 크기를 키우는 것보다, 데이터 품질을 높이고 증류와 양자화를 적절히 활용하는 것이 더 효율적인 경로임을 Phi/Gemma/Qwen 시리즈가 실증하고 있다.

SLM은 대형 모델을 **대체**하는 것이 아니라, **보완**하는 위치에 있다. 비용, 프라이버시, 접근성의 제약 하에서 "충분히 좋은" 성능을 제공하는 것이 SLM의 가치다. 그리고 "충분히 좋은"의 기준선은 해마다 빠르게 높아지고 있다.
