# 합성 데이터로 학습하기: 효과적인 경우와 한계

## 들어가며

:::info
이 글은 LLM 학습 데이터 전략에 관한 튜토리얼이다. [[distillation-guide]]와 함께 읽으면 합성 데이터 활용의 전체 그림을 잡을 수 있다.
:::

LLM 학습에서 가장 비싼 자원은 GPU 시간이 아니라 **고품질 학습 데이터**다. 인간이 작성한 고품질 데이터는 한정되어 있고, 수집 비용이 높다. **합성 데이터(Synthetic Data)**는 대형 모델(GPT-4, Claude 등)을 활용하여 학습용 데이터를 자동 생성하는 접근법이다.

Microsoft [[phi]] 시리즈의 "Textbooks Are All You Need", Meta의 Self-Instruct, 다양한 추론 데이터 프로젝트가 이 패러다임의 대표적 성공 사례다. 그러나 합성 데이터는 만능이 아니며, 언제 효과적이고 언제 실패하는지 이해하는 것이 핵심이다.

이 글에서는 합성 데이터 생성의 주요 기법을 비교하고, 품질 관리 전략, API를 활용한 실전 생성 파이프라인, 그리고 시나리오별 선택 가이드를 정리한다.

---

## 합성 데이터 생성 기법 비교

| 기법 | 핵심 아이디어 | 대표 사례 | 주 용도 | 데이터 규모 |
|------|-------------|----------|--------|-----------|
| **Self-Instruct** | 시드 태스크에서 새 지시-응답 쌍 자동 생성 | Alpaca, Dolly | 범용 지시 따르기 | 50K~100K |
| **Evol-Instruct** | 기존 지시를 단계적으로 복잡하게 진화 | WizardLM, WizardCoder | 복잡한 태스크 학습 | 70K~250K |
| **Textbook-Quality** | 교과서 수준의 구조화된 교육 콘텐츠 생성 | [[phi]] 시리즈 | 코딩/추론 능력 | 1B+ 토큰 |
| **Orca-Style** | 교사 모델의 추론 과정을 상세히 기록 | Orca, Orca 2 | 추론 능력 전이 | 5M~10M |
| **Rejection Sampling** | 다수 생성 후 정답만 선별 | DeepSeek-R1, STaR | 수학/코드 추론 | 100K~1M |
| **Distillation** | 교사 모델의 출력을 학생 모델 학습에 활용 | DistilBERT, TinyLLaMA | 모델 경량화 | 가변 |

## Self-Instruct 기법

### 원리

Self-Instruct(Wang et al., 2023)는 소수의 **시드(seed) 지시-응답 쌍**에서 출발하여, LLM이 새로운 지시와 응답을 반복적으로 생성하는 방식이다. 핵심 파이프라인은 다음과 같다.

1. 인간이 175개의 시드 태스크를 작성
2. LLM이 시드를 참고하여 새로운 지시(instruction)를 생성
3. 생성된 지시가 기존 것과 유사한지 ROUGE 기반 필터링
4. 통과한 지시에 대해 LLM이 응답(output)을 생성
5. 2~4를 반복하여 대규모 데이터셋 구축

### 대표 사례: Alpaca

Stanford Alpaca는 175개 시드에서 GPT-3.5-Turbo로 **52K개의 지시-응답 쌍**을 생성하고, LLaMA-7B를 파인튜닝했다. 총 비용은 약 $500에 불과했다.

| 항목 | 수치 |
|------|------|
| 시드 태스크 수 | 175개 |
| 생성된 데이터 수 | 52,002개 |
| 교사 모델 | GPT-3.5-Turbo |
| 학생 모델 | LLaMA-7B |
| 생성 비용 | ~$500 |
| 학습 시간 | 3시간 (4x A100) |

### 한계

Self-Instruct의 가장 큰 약점은 **단순한 태스크에 편향**된다는 점이다. LLM이 생성하기 쉬운 지시가 반복되며, 복잡한 다단계 추론이나 전문 도메인 태스크는 잘 생성되지 않는다.

## Evol-Instruct 기법

### 원리

Evol-Instruct(Xu et al., 2023)는 Self-Instruct의 다양성 부족 문제를 해결하기 위해, 기존 지시를 **진화(evolution)** 시키는 접근법이다. 진화에는 두 가지 방향이 있다.

**In-Depth Evolution (깊이 방향)**:
- 제약 조건 추가 (Adding Constraints)
- 구체화 (Concretizing)
- 추론 단계 증가 (Increasing Reasoning Steps)
- 입력 복잡화 (Complicating Input)

**In-Breadth Evolution (넓이 방향)**:
- 완전히 새로운 도메인으로 변환
- 다른 형태의 태스크로 변환

### 진화 예시

```
[원본 지시]
"리스트를 정렬하는 Python 함수를 작성하라"

[깊이 진화 1단계]
"중복 원소를 제거한 뒤 내림차순으로 정렬하는 Python 함수를 작성하라.
시간 복잡도는 O(n log n) 이하여야 한다."

[깊이 진화 2단계]
"중복 원소를 제거한 뒤 내림차순으로 정렬하되, 원본 리스트에서
각 원소가 처음 등장한 순서를 보존하는 Python 함수를 작성하라.
시간 복잡도는 O(n log n) 이하이며, 추가 메모리는 O(n)까지 허용된다."
```

### Self-Instruct vs Evol-Instruct

| 비교 항목 | Self-Instruct | Evol-Instruct |
|----------|--------------|---------------|
| 데이터 다양성 | 낮음 (단순 태스크 편향) | 높음 (단계적 복잡화) |
| 난이도 분포 | 쉬운 태스크 집중 | 균등 분포 가능 |
| 시드 의존도 | 높음 | 중간 |
| 생성 비용 | 낮음 (1회 생성) | 중간 (다단계 진화) |
| 코드 태스크 적합성 | 보통 | 높음 (WizardCoder) |

## Textbook-Quality 생성 (Phi 시리즈)

### 원리

Microsoft [[phi]] 시리즈의 접근법은 **"Textbooks Are All You Need"**라는 제목이 함축하듯, 교과서 수준의 구조화된 교육 콘텐츠를 대규모로 생성하는 것이다. 단순한 텍스트가 아니라 **교육적 구조**를 갖춘 데이터라는 점이 핵심이다.

구조적 특징:
- 개념 설명 -> 구체적 예제 -> 점진적 복잡도 증가
- 각 챕터가 하나의 개념을 완결적으로 다룸
- 연습 문제와 풀이 포함

### Phi 시리즈 데이터 전략

| 모델 | 합성 데이터 | 웹 필터 데이터 | 총 토큰 | 파라미터 수 |
|------|-----------|-------------|---------|-----------|
| Phi-1 | 1B (교과서) | 6B (코드 필터) | 7B | 1.3B |
| Phi-1.5 | 20B (교과서) | 6B (웹 필터) | 26B | 1.3B |
| Phi-2 | 합성 확대 | 웹 필터 확대 | 250B | 2.7B |
| Phi-3 | 합성 + 진화 | 웹 필터 | 3.3T | 3.8B |

Phi 시리즈가 보여준 핵심 교훈은 **데이터 양보다 데이터 품질이 모델 성능에 미치는 영향이 크다**는 것이다. Phi-1(1.3B)은 코딩 벤치마크에서 수십 배 큰 모델과 경쟁할 수 있었다.

## Orca-Style 기법

### 원리

Orca(Mukherjee et al., 2023)는 교사 모델의 **추론 과정(reasoning trace)**을 함께 학습하는 접근법이다. 기존 증류가 최종 답변만 모방하는 것과 달리, Orca는 "왜 그 답이 나왔는지"를 포함한 상세한 설명을 학습 데이터로 활용한다.

프롬프트 전략:
- System message에 "단계별로 사고하라", "각 단계의 근거를 설명하라" 등의 지시 포함
- GPT-4의 응답에서 추론 과정 전체를 기록
- 학생 모델이 답변뿐 아니라 추론 과정을 모방하도록 학습

### 기존 증류와의 차이

| 비교 항목 | 기존 증류 | Orca-Style |
|----------|----------|------------|
| 학습 대상 | 최종 답변만 | 추론 과정 + 답변 |
| 시스템 프롬프트 | 단순 지시 | 상세 추론 유도 |
| 데이터 크기 | 작음 (응답만) | 큼 (추론 과정 포함) |
| 복잡한 추론 | 모방 어려움 | 단계적 모방 가능 |
| 교사 모델 | 1개 | 복수 가능 (GPT-4 + GPT-3.5) |

## Rejection Sampling 기반 생성

### 원리

수학, 코드, 논리 퍼즐 등 **정답이 명확한** 도메인에서 가장 효과적인 기법이다. 핵심은 간단하다: 동일한 문제에 대해 **다수의 풀이를 생성**하고, 정답인 것만 학습 데이터로 선별한다.

```python
import openai

def generate_with_rejection_sampling(problem, n_samples=16):
    """Rejection sampling으로 합성 추론 데이터 생성"""
    client = openai.OpenAI()
    correct_solutions = []

    # 동일 문제에 대해 n_samples개의 풀이 생성
    for _ in range(n_samples):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": "단계별로 풀이하라."},
                {"role": "user", "content": problem}
            ],
            temperature=0.7,
        )
        solution = response.choices[0].message.content

        # 정답 검증 (도메인별 검증 로직)
        if verify_answer(solution, problem):
            correct_solutions.append(solution)

    return correct_solutions
```

### 검증 방식별 적용

| 도메인 | 검증 방식 | 자동화 수준 | 정확도 |
|--------|----------|-----------|--------|
| 수학 | 수치 답 비교 | 완전 자동 | 높음 |
| 코드 | 테스트 케이스 실행 | 완전 자동 | 높음 |
| 논리 퍼즐 | 규칙 기반 검증 | 부분 자동 | 중간 |
| 과학 | 단위/수치 검증 | 부분 자동 | 중간 |
| 개방형 텍스트 | LLM-as-Judge | 반자동 | 낮음 |

:::tip
검증 가능한 도메인에서 Rejection Sampling은 **가장 신뢰할 수 있는 합성 데이터 생성 기법**이다. [[process-reward-models]]를 함께 활용하면 중간 추론 단계까지 검증하여 데이터 품질을 더 높일 수 있다.
:::

## 합성 데이터 파이프라인 구축

### API 기반 대규모 생성

실전에서 합성 데이터를 대규모로 생성할 때는 **OpenAI Batch API**를 활용하면 비용을 50% 절감할 수 있다.

```python
import json

def prepare_batch_requests(problems, output_path="batch_input.jsonl"):
    """Batch API용 요청 파일 생성"""
    with open(output_path, "w") as f:
        for i, problem in enumerate(problems):
            request = {
                "custom_id": f"problem-{i:05d}",
                "method": "POST",
                "url": "/v1/chat/completions",
                "body": {
                    "model": "gpt-4o-mini",
                    "messages": [
                        {
                            "role": "system",
                            "content": (
                                "주어진 문제를 단계별로 풀이하라. "
                                "각 단계의 근거를 명확히 설명하라."
                            )
                        },
                        {"role": "user", "content": problem}
                    ],
                    "temperature": 0.7,
                    "max_tokens": 2048
                }
            }
            f.write(json.dumps(request, ensure_ascii=False) + "\n")

    print(f"총 {len(problems)}개 요청을 {output_path}에 저장")
```

### 파이프라인 단계

전체 합성 데이터 파이프라인은 4단계로 구성된다.

1. **시드 데이터 준비**: 도메인별 시드 문제/지시 수집
2. **대규모 생성**: Batch API로 응답 생성 (temperature 다양화)
3. **품질 필터링**: 자동 검증 + LLM-as-Judge + 규칙 기반 필터
4. **데이터셋 구축**: 필터링 통과 데이터를 학습용 형식으로 변환

## 품질 평가 기준

합성 데이터의 품질은 **정확성, 다양성, 난이도 분포** 세 축으로 평가한다.

### 정확성 평가

| 평가 방법 | 설명 | 적용 도메인 |
|----------|------|-----------|
| 실행 기반 검증 | 코드 실행, 수학 답 비교 | 코드, 수학 |
| LLM-as-Judge | GPT-4로 품질 평가 | 범용 |
| 규칙 기반 필터 | 길이, 형식, 반복 패턴 제거 | 전체 |
| 인간 샘플 검증 | 무작위 샘플 인간 평가 | 전체 |
| 교차 검증 | 복수 모델의 답변 일치도 | 사실 기반 |

### 다양성 확보 전략

- **다양한 교사 모델**: GPT-4, Claude, Gemini, Mixtral 등을 혼합
- **온도(temperature) 다양화**: 0.3~1.0 범위에서 다양한 설정 사용
- **프롬프트 변형**: 동일 주제에 대해 관점/형식/난이도를 다르게 요청
- **시드 소스 다각화**: 여러 출처에서 시드 데이터를 수집

### 난이도 분포 관리

합성 데이터가 쉬운 문제에 편향되는 것을 방지해야 한다. Evol-Instruct의 단계적 복잡화 또는 명시적 난이도 태그를 활용한다.

| 난이도 | 목표 비율 | 특성 |
|--------|----------|------|
| 기초 | 20% | 단일 개념, 직접 적용 |
| 중급 | 40% | 2-3개 개념 결합 |
| 고급 | 30% | 다단계 추론, 예외 처리 |
| 전문가 | 10% | 창의적 해결, 최적화 |

## 합성 vs 실제 데이터 성능 비교

### 벤치마크 결과

연구에 따른 합성 데이터 활용 시 성능 변화를 정리한다.

| 모델/연구 | 학습 데이터 | 벤치마크 | 합성 데이터 성능 | 실제 데이터 성능 |
|----------|-----------|----------|---------------|---------------|
| Phi-1 (1.3B) | 합성 교과서 | HumanEval | 50.6% | 대비 모델 대비 우수 |
| Alpaca (7B) | Self-Instruct 52K | AlpacaEval | GPT-3.5 90% 수준 | 인간 데이터 부재 |
| WizardCoder (15B) | Evol-Instruct | HumanEval | 57.3% | CodeLlama 대비 +10% |
| Orca 2 (13B) | Orca-Style | AGIEval | GPT-3.5에 근접 | 기존 증류 대비 +15% |
| [[60_lima\|LIMA]] (65B) | 인간 1K | AlpacaEval | N/A | 1K로 GPT-4 수준 |

:::warning
**핵심 교훈**: 합성 데이터만으로 학습한 모델은 특정 벤치마크에서 뛰어날 수 있지만, **범용 능력과 사실 정확성은 고품질 인간 데이터와의 혼합이 필수**다. [[60_lima|LIMA]] 연구가 보여주듯, 소량이라도 고품질 인간 데이터의 가치는 대체 불가능하다.
:::

## 합성 데이터의 한계와 위험

### 모델 붕괴 (Model Collapse)

모델 A가 생성한 데이터로 모델 B를 학습하고, B의 데이터로 C를 학습하면 세대를 거듭할수록 **다양성이 소실되고 편향이 증폭**된다(Shumailov et al., 2024).

원인:
- 생성 모델은 확률이 높은 출력에 편향 -> 롱테일 지식 소실
- 각 세대에서 오류가 누적
- 분포의 꼬리가 잘려나가면서 결국 모든 출력이 유사한 패턴으로 수렴

### 교사 모델의 편향 상속

교사 모델의 문체, 편향, 약점이 학생 모델에 직접 전이된다.

- GPT-4 특유의 과도한 리스트 사용, 특정 관용구
- 교사 모델이 약한 분야의 오류가 학생에게도 반복
- 문화적/언어적 편향의 증폭

### 다양성 부족

같은 모델이 같은 프롬프트로 생성한 데이터는 구조적으로 유사한 패턴을 반복한다. 이는 모델의 일반화 능력을 제한한다.

### 법적/윤리적 문제

상용 API(GPT-4, Claude)의 출력을 경쟁 모델의 학습에 사용하는 것은 서비스 약관 위반일 수 있다. 오픈소스 모델(Mixtral, LLaMA 등)로 생성한 데이터를 사용하는 추세가 강화되고 있다.

## 필터링 및 품질 관리 기법

### 규칙 기반 필터링

| 필터 | 기준 | 목적 |
|------|------|------|
| 길이 필터 | 너무 짧거나 긴 응답 제거 | 품질 하한선 |
| 반복 필터 | n-gram 반복 비율 검사 | 루프 방지 |
| 언어 필터 | 목표 언어 비율 검증 | 언어 일관성 |
| 형식 필터 | 지정 형식(JSON, 코드 등) 검증 | 형식 정확성 |
| 유사도 필터 | 기존 데이터와의 ROUGE/cosine 유사도 | 중복 제거 |

### LLM-as-Judge 기반 필터링

규칙으로 잡을 수 없는 의미적 품질은 LLM-as-Judge 패턴으로 평가한다. GPT-4에게 생성된 응답의 **정확성, 완전성, 유용성**을 1-5점 척도로 평가하게 하고, 기준 미달 데이터를 제거한다.

### 데이터 혼합 비율

연구에 따르면 합성 데이터와 인간 데이터의 최적 혼합 비율은 도메인에 따라 다르다.

| 시나리오 | 합성 데이터 | 인간 데이터 | 근거 |
|---------|-----------|-----------|------|
| 검증 가능 도메인 (수학/코드) | 80~90% | 10~20% | 자동 검증으로 품질 보장 |
| 일반 지시 따르기 | 60~70% | 30~40% | 다양성 보완 필요 |
| 창의적 글쓰기 | 30~40% | 60~70% | 인간 표현의 다양성 필수 |
| 사실 기반 QA | 40~50% | 50~60% | 사실 정확성 검증 어려움 |

## 시나리오별 선택 가이드

### 어떤 기법을 선택할 것인가

| 시나리오 | 추천 기법 | 이유 |
|---------|----------|------|
| 범용 챗봇 학습 | Self-Instruct + 인간 데이터 혼합 | 비용 효율적, 넓은 커버리지 |
| 코딩 능력 강화 | Evol-Instruct + Rejection Sampling | 난이도 제어 + 실행 검증 |
| 수학 추론 강화 | Rejection Sampling + CoT | 정답 검증 가능, [[process-reward-models]] 활용 |
| [[small-language-models\|SLM]] 학습 | Orca-Style + Textbook-Quality | 추론 과정 전이 + 체계적 교육 |
| 도메인 특화 모델 | Textbook-Quality + 도메인 시드 | 전문 지식 구조화 |
| RLHF/DPO 데이터 | Rejection Sampling + 선호도 쌍 | (chosen, rejected) 자동 생성 |

### 예산별 전략

| 예산 범위 | 추천 접근 | 교사 모델 | 예상 데이터 규모 |

## 실전 체크리스트

합성 데이터 프로젝트를 시작할 때 다음 체크리스트를 확인하라.

### 생성 전

- 검증 메커니즘 확보: 생성된 데이터의 품질을 자동으로 평가할 수 있는가?
- 시드 데이터 준비: 충분히 다양한 시드 태스크를 확보했는가?
- 교사 모델 선정: 라이선스 문제 없이 사용 가능한 모델인가?
- 비용 추정: Batch API 등 비용 절감 방안을 검토했는가?

### 생성 중

- 다양성 확보: 프롬프트, 교사 모델, 온도를 다양화했는가?
- 중간 품질 검사: 샘플을 뽑아 인간이 품질을 확인했는가?
- 오류 패턴 모니터링: 반복되는 오류 유형이 있는가?

### 생성 후

- 필터링 적용: 규칙 기반 + LLM-as-Judge 필터를 모두 적용했는가?
- 인간 데이터 혼합: 합성 데이터와 고품질 인간 데이터를 적절히 혼합했는가?
- 편향 검사: 교사 모델의 편향이 증폭되지 않았는가?
- 벤치마크 평가: 기존 모델 대비 성능 향상이 확인되었는가?

## [[small-language-models|SLM]] 학습에서의 활용

[[small-language-models|소형 언어 모델(SLM)]] 학습에서 합성 데이터는 특히 중요하다. 파라미터가 적은 모델은 데이터 품질에 더 민감하기 때문이다.

| 전략 | SLM 적합도 | 이유 |
|------|----------|------|
| Textbook-Quality | 매우 높음 | 체계적 교육 구조가 작은 모델에 효과적 |
| Orca-Style | 높음 | 추론 과정 모방이 SLM 추론 능력 향상에 기여 |
| Rejection Sampling | 높음 | 검증된 데이터만 사용하여 한정된 용량 최대 활용 |
| Self-Instruct | 중간 | 다양성 확보에는 좋지만 품질이 불균등 |
| 무필터 증류 | 낮음 | 노이즈가 SLM 성능을 오히려 저하 |

[[slm-finetuning-rtx3090]]에서 다루는 것처럼, RTX 3090 한 장으로도 고품질 합성 데이터와 QLoRA를 결합하면 실용적인 SLM을 학습할 수 있다.

## 합성 데이터가 효과적인 조건 정리

| 조건 | 효과적인 경우 | 주의가 필요한 경우 |
|------|-------------|-----------------|
| 검증 가능성 | 수학/코드 (자동 검증) | 개방형 텍스트 (검증 곤란) |
| 학습 목표 | 포맷/스타일 학습 | 사실 기반 지식 학습 |
| 데이터 구조 | 증류 (교사->학생) | 다세대 재학습 (모델 붕괴) |
| 활용 방식 | 인간 데이터 보강 수단 | 순수 합성 데이터만 사용 |
| 도메인 | 구조화된 태스크 | 창의적/문화적 콘텐츠 |
| 규모 | 대규모 + 필터링 | 소규모 + 무필터 |

## 정리

합성 데이터는 LLM 학습의 **핵심 도구**로 자리잡았다. 올바른 조건에서 올바른 기법을 선택하면 학습 효율을 극적으로 높일 수 있다.

**기법 선택 요약**:
- **빠르게 범용 데이터가 필요하면**: Self-Instruct
- **복잡한 태스크 학습이 목표면**: Evol-Instruct
- **정답 검증이 가능한 도메인이면**: Rejection Sampling
- **소형 모델의 추론 능력을 높이려면**: Orca-Style + [[distillation-guide|증류]]
- **체계적 교육 데이터가 필요하면**: Textbook-Quality ([[phi]] 접근법)

그러나 합성 데이터는 만능이 아니다. **모델 붕괴, 편향 상속, 다양성 부족**의 위험을 항상 인지하고, 고품질 인간 데이터와의 혼합, 체계적 필터링, 지속적 품질 모니터링을 병행해야 한다. **데이터 품질에 대한 감각**이 합성 데이터 활용의 핵심 역량이다.
