# OpenThoughts3-1.2M: 추론 모델을 위한 데이터 레시피

## 개요

:::info
**논문:** OpenThoughts: Data Recipes for Reasoning Models (arXiv:2506.04178, 2025.06)
**제작:** open-thoughts (Stanford, UW, BespokeLabs, UC Berkeley 등 16개 기관, 49명 연구자)
**라이선스:** Apache 2.0
**데이터셋:** [HuggingFace: open-thoughts/OpenThoughts3-1.2M](https://huggingface.co/datasets/open-thoughts/OpenThoughts3-1.2M)
**코드:** [github.com/open-thoughts/open-thoughts](https://github.com/open-thoughts/open-thoughts)
:::

"좋은 추론 모델을 만들려면 어떤 데이터가 필요한가?" — 이 질문에 체계적으로 답하는 프로젝트가 OpenThoughts이다.

"Textbooks Are All You Need"(Phi-1, 2023)가 "좋은 교과서 데이터가 있으면 작은 모델도 강하다"는 직관을 보여줬다면, OpenThoughts3는 이를 **추론 모델 영역**으로 확장하면서 **각 단계의 선택이 왜 중요한지를 1,000회 이상의 ablation으로 증명**한다. 기존 합성 데이터 연구가 "이런 데이터로 학습하면 잘 된다"는 결과만 보여준 반면, OpenThoughts3는 "**왜 이 데이터 조합이 최적인지**"에 대한 체계적 증거를 제공한다는 점에서 차별화된다.

OpenThoughts3-1.2M은 수학, 코드, 과학 세 도메인의 합성 추론 데이터 **120만개**를 포함하는 오픈소스 데이터셋이다. 이 데이터로 훈련된 OpenThinker3-7B는 **SFT(Supervised Fine-Tuning)만으로** 7B 규모에서 SOTA를 달성했다.

## 데이터셋 구조

### 기본 정보

| 항목 | 값 |
|------|-----|
| 총 예제 수 | 1,200,000 |
| 고유 질문 수 | ~75,000 (각 16회 답변 생성) |
| 다운로드 크기 | 28.2 GB (Parquet) |
| 분할 | train only |

### 필드 구조

```python
{
  "conversations": [
    {"from": "human", "value": "문제 텍스트..."},
    {"from": "assistant", "value": "<think>추론 과정...</think>\n최종 답변..."}
  ],
  "source": "nvidia/OpenCodeReasoning",  # 질문 출처
  "domain": "code",                       # math / code / science
  "difficulty": 8                          # 6-10 난이도
}
```

주목할 점은 assistant 응답에 `<think>` 태그가 포함된다는 것이다. 이 태그 안에 추론 과정(chain-of-thought)이, 태그 밖에 최종 답변이 위치한다. 모델은 이 구조를 학습하여, 추론 시 자연스럽게 "생각 → 답변" 패턴을 생성하게 된다.

### 도메인별 분포

| 도메인 | 예제 수 | 비율 | 주요 출처 |
|--------|---------|------|----------|
| Mathematics | 850,000 | 70.8% | OpenMath-2-Math |
| Code | 250,000 | 20.8% | StackExchange-CodeGolf, OpenCodeReasoning |
| Science | 100,000 | 8.3% | StackExchange-Physics, OrganicChemistry-PDF |

수학이 압도적으로 많은 이유는 단순히 수학 데이터가 풍부해서가 아니라, **ablation 결과 수학 데이터의 비중이 높을수록 전체 추론 성능이 향상**되었기 때문이다. 수학 문제의 엄밀한 논리 구조가 모델의 범용 추론 능력을 강화하는 것으로 해석된다.

## 6단계 구축 파이프라인

OpenThoughts3의 핵심 가치는 데이터셋 자체보다 **구축 과정에서 발견된 레시피**에 있다. 각 단계에서 통제된 실험을 통해 최적의 선택지를 도출했다.

### Stage 1: Question Sourcing

62개 출처에서 질문을 수집했다. 출처는 세 가지 유형으로 분류된다:

- **Fully Synthetic**: LLM이 처음부터 생성한 질문. 품질 편차가 크지만 양 확보 용이
- **Semi-Synthetic**: 기존 질문을 LLM으로 변형/확장. 원본의 품질을 유지하면서 다양성 확보
- **Non-Synthetic**: 사람이 직접 작성한 질문 (StackExchange, 교과서 등). 가장 높은 품질

각 도메인의 주요 출처:
- **수학**: OpenMath-2-Math, AIME 문제, Hendrycks MATH, NuminaMath
- **코드**: NVIDIA OpenCodeReasoning, StackExchange-CodeGolf, Codeforces 문제
- **과학**: StackExchange-Physics/Chemistry, 유기화학 교과서 PDF, GPQA

### Stage 2: Question Mixing — "품질 > 다양성"

:::tip
**핵심 발견:** Top-2 출처 조합이 Top-16 출처 조합보다 **5% 높은 정확도**를 달성했다.
:::

직관적으로는 다양한 출처를 섞을수록 좋을 것 같지만, 실험 결과는 반대였다. **소수의 고품질 소스가 다수의 저품질 소스를 압도**한다.

이 발견은 LIMA(2023)의 "Less Is More for Alignment"와 맥을 같이 한다. LIMA는 1,000개의 고품질 예제만으로 65K 예제로 학습한 모델에 필적하는 성능을 보여줬다. OpenThoughts3는 이 원칙이 추론 데이터에서도 동일하게 적용됨을 확인한다: **데이터 큐레이션에서 다양성보다 품질을 우선해야 한다**.

### Stage 3: Question Filtering

필터링 전략도 ablation으로 최적화했다:

- **수학/과학**: Response length 기반 필터링 (GPT-4.1-mini) — 답변이 긴 질문 = 어려운 질문. 쉬운 질문은 짧게 답변되므로, 응답 길이가 난이도의 좋은 프록시가 된다
- **코드**: Difficulty 기반 필터링 (GPT-4o-mini) — 직접적인 난이도 평가. 코드 문제는 응답 길이와 난이도의 상관관계가 낮기 때문
- LLM 기반 필터링이 FastText, 임베딩 기반 등 고전적 방법을 압도

두 도메인에서 서로 다른 필터링 전략이 최적이라는 점이 흥미롭다. 이는 "만능 필터링 전략"은 없으며, **도메인 특성에 맞는 필터링 기준을 실험적으로 도출**해야 함을 시사한다.

### Stage 4: Deduplication + Multiple Answer Sampling

:::warning
**핵심 발견:** 75,000 질문 x 16 답변 = 1.2M 예제. **질문 수를 늘리는 것보다 답변을 16배 샘플링하는 것이 더 효과적**이었다.
:::

같은 질문에 대해 여러 답변을 생성하면, 모델이 다양한 풀이 경로를 학습할 수 있다. 이는 단순히 데이터 양을 늘리는 것과는 질적으로 다른 효과를 제공한다.

예를 들어 수학 문제 "1부터 100까지의 합을 구하라"에 대해:
- 답변 1: 등차수열의 합 공식 적용
- 답변 2: 가우스의 쌍 짝짓기 방법
- 답변 3: 재귀적 분할 풀이

동일 문제에 대한 다양한 접근법 노출이 모델의 추론 유연성을 향상시킨다.

- 수학/과학: Exact deduplication 후 16x 샘플링
- 코드: 중복 제거 없이 16x 샘플링 (코드는 동일 문제도 다양한 접근법이 가능)

### Stage 5: Answer Filtering — "필터링하지 마라"

:::danger
**놀라운 발견:** GPT 검증, Majority consensus, 길이 기반 등 **어떤 답변 필터링 전략도 성능을 향상시키지 못했다**. 오히려 "필터링 없음"이 가장 높은 성능을 보였다.
:::

이는 기존 통념("잘못된 답변은 제거해야 한다")과 정면으로 배치된다. 저자들의 해석:

1. **다양성 감소**: 필터링은 데이터 양을 줄여 모델이 학습할 수 있는 풀이 경로의 다양성을 감소시킴
2. **추론 과정의 가치**: "잘못된" 최종 답변이라도 추론 과정 자체는 유용한 학습 신호를 제공. 부분적으로 올바른 추론 체인에서도 모델은 유용한 패턴을 추출할 수 있다
3. **16x 중복의 완충 효과**: 16x 샘플링으로 이미 충분한 정답이 포함되어 있어, 오답 몇 개가 전체 학습에 미치는 부정적 영향이 미미

이 발견은 실무적으로도 중요하다: **비용이 많이 드는 답변 검증 단계를 생략할 수 있다**.

### Stage 6: Teacher Model Selection — "좋은 교사 ≠ 좋은 문제 풀이자"

:::tip
**핵심 발견:** QwQ-32B가 교사 모델로 선정되었다. DeepSeek-R1보다 **직접 성능은 낮지만**, 학생 모델 훈련 시 **더 높은 성능**을 달성했다.
:::

| 교사 모델 | 교사 직접 성능 | 학생 모델 성능 |
|----------|-------------|-------------|
| DeepSeek-R1 | 높음 | 보통 |
| **QwQ-32B** | 보통 | **높음** |

이 현상은 **용량 격차(capacity gap)** 이론으로 설명된다. DeepSeek-R1은 671B MoE 모델로, 7B 학생 모델이 모방하기에는 너무 복잡한 추론 패턴을 생성한다. 반면 QwQ-32B(32B dense)는 학생 모델의 용량에 더 가까운 수준의 추론 체인을 제공하여, 효과적인 지식 전달(distillation)이 가능하다.

이는 knowledge distillation 연구의 오래된 교훈 — "교사와 학생의 용량 차이가 너무 크면 증류 효율이 떨어진다" — 을 추론 데이터 생성 맥락에서 재확인한 결과다.

## 벤치마크 결과

### OpenThinker3-7B: 7B 규모 SOTA

OpenThoughts3-1.2M으로 훈련된 OpenThinker3-7B (Qwen2.5-7B-Instruct 기반)의 결과:

| 벤치마크 | OpenThinker3-7B | DeepSeek-R1-Qwen-7B | 향상폭 |
|----------|-----------------|---------------------|--------|
| AIME 2024 | **69.0%** | 51.3% | +17.7pp |
| AIME 2025 | **53.3%** | 38.0% | +15.3pp |
| LiveCodeBench | **51.7%** | 34.5% | +17.2pp |
| GPQA Diamond | **53.7%** | 33.2% | +20.5pp |
| MATH500 | 90.0% | 88.0% | +2.0pp |
| 12개 벤치마크 평균 | **55.3%** | 42.9% | +12.4pp |

특히 GPQA Diamond에서의 +20.5pp 향상은 주목할 만하다. GPQA는 PhD 수준의 과학 문제인데, 전체 데이터의 8.3%에 불과한 과학 도메인 데이터로도 이러한 향상을 달성했다는 것은 수학 데이터의 범용 추론 전이 효과를 다시 한번 확인시켜준다.

### SFT vs RL: "데이터만으로 충분한가?"

| 모델 | 방법 | 12개 벤치마크 평균 |
|------|------|------------------|
| **OpenThinker3-7B** | **SFT only** | **55.3** |
| Nemotron-Nano-8B | SFT + RL | 53.2 |
| AceReason-7B | RL | 52.9 |
| Skywork-7B | RL | 51.6 |

SFT만으로 RL 기반 모델들을 능가한다는 결과는, **데이터 품질이 학습 알고리즘보다 중요할 수 있다**는 가설을 강력히 지지한다. 물론 이것이 "RL이 불필요하다"는 의미는 아니다. OpenThoughts + RL의 조합은 아직 탐구되지 않은 영역이며, 두 접근법은 상호 보완적일 가능성이 높다.

### 세대별 발전

| 모델 | AIME24 | AIME25 | GPQA-D |
|------|--------|--------|--------|
| OpenThinker-7B (v1, 114K) | 29.3% | 25.3% | 44.1% |
| OpenThinker2-7B (v2, 1M) | 60.7% | 38.7% | 47.0% |
| **OpenThinker3-7B (v3, 1.2M)** | **69.0%** | **53.3%** | **53.7%** |

v1 → v3에서 AIME24가 29.3% → 69.0%로 향상된 것은, 데이터 큐레이션의 반복적 개선이 극적인 차이를 만들 수 있음을 보여준다. 데이터 양도 114K → 1.2M으로 10배 증가했지만, v2(1M) → v3(1.2M)에서의 향상(60.7% → 69.0%)은 양보다는 **레시피 개선**의 기여가 더 크다.

## 핵심 교훈 5가지

### 1. 16x 답변 샘플링 >> 더 많은 질문

같은 총 데이터 양이라면, 질문 수를 늘리는 것보다 기존 질문에 대한 답변을 여러 번 생성하는 것이 효과적이다. 다양한 풀이 경로 노출이 추론 능력 향상의 핵심이다.

### 2. 최고 성능 모델 ≠ 최고 교사

교사 모델 선택 시 벤치마크 점수만 보면 안 된다. 학생 모델의 용량과 학습 가능성을 고려해야 한다. "따라할 수 있는 수준"의 추론이 가장 효과적이다.

### 3. 답변 필터링은 불필요

잘못된 답변을 제거하는 것이 항상 좋은 것은 아니다. 다양성 감소의 비용이 품질 향상의 이득을 초과할 수 있다.

### 4. 품질 > 다양성

62개 출처 중 Top-2만 사용해도 Top-16보다 나은 결과를 얻었다. 데이터 큐레이션에서 "더 많은 출처"는 "더 좋은 데이터"를 보장하지 않는다.

### 5. 긴 추론 체인이 필수적

Self-reflection을 제거하면 성능이 49.1% 하락했다. `<think>` 태그 안의 긴 추론 체인이 추론 모델 학습의 핵심이다. "생각하는 과정"을 명시적으로 포함하는 것이 최종 답변의 정확도를 극적으로 향상시킨다.

## 시사점

OpenThoughts3는 단순한 데이터셋을 넘어, **추론 데이터 큐레이션의 체계적 방법론**을 제시한다.

**SFT의 재평가**: RLHF/DPO 등 RL 기반 정렬이 대세인 상황에서, "데이터만 잘 만들면 SFT로 충분하다"는 메시지는 연구 방향에 중요한 시사점을 준다. 특히 RL은 보상 모델 학습, 정책 최적화 등 추가적인 복잡성과 비용을 수반하는데, 고품질 SFT 데이터가 이를 상당 부분 대체할 수 있다면 실무적 가치가 크다.

**오픈소스의 경쟁력**: 49명의 다기관 연구진이 공개한 데이터셋, 코드, 레시피를 통해 누구나 추론 모델을 구축할 수 있다. DeepSeek-R1의 800K 비공개 데이터에 의존하지 않고도 동등 이상의 성능을 달성할 수 있다는 것은 오픈소스 AI 생태계에 큰 의미가 있다.

**실전 활용**: 데이터셋은 HuggingFace에서 바로 다운로드 가능하며, `domain` 필드로 특정 도메인만 필터링하거나, `difficulty` 필드로 난이도별 커리큘럼 학습을 구성할 수 있다. 7B 모델 기준 Qwen2.5-7B-Instruct를 베이스로 SFT하면 논문의 결과를 재현할 수 있다.
