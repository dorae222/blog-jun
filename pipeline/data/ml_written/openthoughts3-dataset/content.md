# OpenThoughts3-1.2M: 추론 모델을 위한 데이터 레시피

## 개요

:::info
**논문:** OpenThoughts: Data Recipes for Reasoning Models (arXiv:2506.04178, 2025.06)
**제작:** open-thoughts (Stanford, UW, BespokeLabs, UC Berkeley 등 16개 기관, 49명 연구자)
**라이선스:** Apache 2.0
**데이터셋:** [HuggingFace: open-thoughts/OpenThoughts3-1.2M](https://huggingface.co/datasets/open-thoughts/OpenThoughts3-1.2M)
**코드:** [github.com/open-thoughts/open-thoughts](https://github.com/open-thoughts/open-thoughts)
:::

"좋은 추론 모델을 만들려면 어떤 데이터가 필요한가?" 이 질문에 체계적으로 답하는 프로젝트가 OpenThoughts이다.

"Textbooks Are All You Need"(Phi-1, 2023)가 "좋은 교과서 데이터가 있으면 작은 모델도 강하다"는 직관을 보여줬다면, OpenThoughts3는 이를 **추론 모델 영역**으로 확장하면서 **각 단계의 선택이 왜 중요한지를 1,000회 이상의 ablation으로 증명**한다. 기존 [[synthetic-data-training]] 연구가 "이런 데이터로 학습하면 잘 된다"는 결과만 보여준 반면, OpenThoughts3는 "**왜 이 데이터 조합이 최적인지**"에 대한 체계적 증거를 제공한다는 점에서 차별화된다.

OpenThoughts3-1.2M은 수학, 코드, 과학 세 도메인의 합성 추론 데이터 **120만개**를 포함하는 오픈소스 데이터셋이다. 이 데이터로 훈련된 OpenThinker3-7B는 **SFT(Supervised Fine-Tuning)만으로** 7B 규모에서 SOTA를 달성했으며, RL 기반 모델들을 능가하는 놀라운 결과를 보여주었다. 이 글에서는 6단계 파이프라인의 각 단계에서 어떤 선택이 이루어졌고, 왜 그 선택이 최적이었는지를 구체적 수치와 함께 분석한다.

## 데이터셋 구조

### 기본 정보

| 항목 | 값 |
|------|-----|
| 총 예제 수 | 1,200,000 |
| 고유 질문 수 | ~75,000 (각 16회 답변 생성) |
| 다운로드 크기 | 28.2 GB (Parquet) |
| 분할 | train only |
| 포맷 | ShareGPT 대화 형식 |
| 교사 모델 | QwQ-32B |

### 필드 구조

```python
# OpenThoughts3-1.2M 데이터 스키마
{
  "conversations": [
    {"from": "human", "value": "문제 텍스트..."},
    {"from": "assistant", "value": "<think>추론 과정...</think>\n최종 답변..."}
  ],
  "source": "nvidia/OpenCodeReasoning",  # 62개 출처 중 하나
  "domain": "code",                       # math / code / science
  "difficulty": 8                          # 6-10 난이도 범위
}

# 도메인별 질문 예시
# math: "Find all primes p such that p^2 + 2 is also prime."
# code: "Write a function that finds the longest increasing subsequence..."
# science: "Derive the partition function for a 2D Ising model..."
```

주목할 점은 assistant 응답에 `<think>` 태그가 포함된다는 것이다. 이 태그 안에 추론 과정(chain-of-thought)이, 태그 밖에 최종 답변이 위치한다. 모델은 이 구조를 학습하여, 추론 시 자연스럽게 "생각 후 답변" 패턴을 생성하게 된다. self-reflection이 없는 데이터로 훈련하면 성능이 49.1% 하락하는데, 이는 `<think>` 태그 안의 긴 추론 체인이 [[reasoning-vs-inference]]에서 핵심적인 역할을 함을 보여준다.

### 도메인별 분포와 소스 구성

OpenThoughts3는 **62개 출처**에서 질문을 수집하며, 세 도메인에 걸쳐 분포한다.

| 도메인 | 예제 수 | 비율 | 소스 수 | 주요 출처 |
|--------|---------|------|---------|----------|
| Mathematics | 850,000 | 70.8% | 38개 | OpenMath-2-Math, NuminaMath, AIME |
| Code | 250,000 | 20.8% | 14개 | OpenCodeReasoning, StackExchange-CodeGolf, Codeforces |
| Science | 100,000 | 8.3% | 10개 | StackExchange-Physics, OrganicChemistry-PDF, GPQA |

수학이 압도적으로 많은 이유는 단순히 수학 데이터가 풍부해서가 아니다. **ablation 결과 수학 데이터의 비중이 높을수록 전체 추론 성능이 향상**되었기 때문이다. 수학 문제의 엄밀한 논리 구조가 모델의 범용 추론 능력을 강화하는 것으로 해석되며, 이는 GPQA(과학 벤치마크)에서의 대폭 향상으로도 확인된다.

62개 소스는 생성 방식에 따라 세 유형으로 분류된다:

| 유형 | 설명 | 대표 소스 | 품질 특성 |
|------|------|----------|----------|
| Non-Synthetic | 사람이 직접 작성 | StackExchange, AIME, 교과서 | 최고 품질, 양적 한계 |
| Semi-Synthetic | 기존 질문을 LLM으로 변형/확장 | NuminaMath-Aug, 교과서 변형 | 원본 품질 유지 + 다양성 |
| Fully Synthetic | LLM이 처음부터 생성 | OpenMath-Synth, 자동 생성 문제 | 양 확보 용이, 품질 편차 큼 |

## 6단계 구축 파이프라인

OpenThoughts3의 핵심 가치는 데이터셋 자체보다 **구축 과정에서 발견된 레시피**에 있다. 6단계 파이프라인의 각 단계에서 통제된 실험을 통해 최적의 선택지를 도출했으며, 이 과정에서 기존 통념을 뒤집는 여러 발견이 있었다.

### Stage 1: Source Mixing (질문 소스 배합)

62개 출처에서 수집한 질문을 도메인별로 최적 비율로 배합하는 단계다.

:::tip
**핵심 발견:** Top-2 소스 조합이 Top-16 소스 조합보다 **5% 높은 정확도**를 달성했다. 품질이 다양성을 압도한다.
:::

직관적으로는 다양한 출처를 섞을수록 좋을 것 같지만, 실험 결과는 반대였다. **소수의 고품질 소스가 다수의 저품질 소스를 압도**한다. 이는 LIMA(2023)의 "Less Is More for Alignment"와 맥을 같이 한다. LIMA는 1,000개의 고품질 예제만으로 65K 예제로 학습한 모델에 필적하는 성능을 보여줬는데, OpenThoughts3는 이 원칙이 추론 데이터에서도 동일하게 적용됨을 확인했다.

구체적인 소스 배합 ablation 결과:

| 구성 | 소스 수 | AIME24 | MATH500 | 평균 |
|------|---------|--------|---------|------|
| Top-2 소스 | 2 | 66.3% | 89.8% | 최고 |
| Top-4 소스 | 4 | 64.0% | 89.2% | 양호 |
| Top-8 소스 | 8 | 62.7% | 88.5% | 보통 |
| Top-16 소스 | 16 | 61.3% | 87.9% | 하위 |

소스 수가 늘어날수록 성능이 오히려 하락하는 패턴이 명확하다. 저품질 소스의 노이즈가 고품질 데이터의 학습 신호를 희석시키는 것으로 해석된다. 실무적 교훈은 분명하다: **데이터 큐레이션에서 다양성보다 품질을 우선해야 한다.**

### Stage 2: Question Selection (질문 필터링)

수집된 질문 풀에서 훈련에 적합한 질문만 선별하는 단계다. 필터링 전략도 ablation으로 최적화했으며, 흥미롭게도 **도메인마다 최적 전략이 달랐다.**

- **수학/과학**: Response length 기반 필터링 (GPT-4.1-mini) 적용. 답변이 긴 질문일수록 어려운 질문이라는 가정이다. 쉬운 질문은 짧게 답변되므로, 응답 길이가 난이도의 좋은 프록시가 된다
- **코드**: Difficulty 기반 필터링 (GPT-4o-mini) 적용. 코드 문제는 응답 길이와 난이도의 상관관계가 낮기 때문에, 직접적인 난이도 평가가 더 효과적
- **공통**: LLM 기반 필터링이 FastText, 임베딩 기반 등 고전적 방법을 압도

두 도메인에서 서로 다른 필터링 전략이 최적이라는 점이 주목할 만하다. 이는 "만능 필터링 전략"은 존재하지 않으며, **도메인 특성에 맞는 필터링 기준을 실험적으로 도출**해야 함을 시사한다. 필터링 후 수학 기준으로 난이도 분포가 6~10 범위에 집중되었으며, 난이도 8 이상의 고난도 질문 비율이 전체의 약 60%를 차지한다.

### Stage 3: Answer Sampling (답변 생성)

:::warning
**핵심 발견:** 75,000 질문 x 16 답변 = 1.2M 예제. **질문 수를 늘리는 것보다 답변을 16배 샘플링하는 것이 더 효과적**이었다.
:::

같은 질문에 대해 여러 답변을 생성하면, 모델이 다양한 풀이 경로를 학습할 수 있다. 이는 단순히 데이터 양을 늘리는 것과는 질적으로 다른 효과를 제공한다. [[self-consistency]] 연구에서 밝혀진 것처럼, 다양한 추론 경로를 탐색하는 능력이 최종 정확도를 결정한다.

예를 들어 수학 문제 "1부터 100까지의 합을 구하라"에 대해:
- **답변 1**: 등차수열의 합 공식 $S_n = \frac{n(a_1 + a_n)}{2}$ 직접 적용
- **답변 2**: 가우스의 쌍 짝짓기 방법 $(1+100) + (2+99) + \cdots$
- **답변 3**: 재귀적 분할 $S(100) = S(50) + \sum_{k=51}^{100} k$

16x 샘플링 vs 더 많은 질문의 비교 실험에서, 동일한 총 데이터 크기(1.2M)를 맞추되 구성을 달리했을 때의 결과는 다음과 같다:

| 전략 | 질문 수 | 질문당 답변 수 | 총 예제 | AIME24 |
|------|---------|--------------|---------|--------|
| 더 많은 질문 | 300K | 4 | 1.2M | 62.0% |
| **16x 샘플링** | **75K** | **16** | **1.2M** | **69.0%** |

동일 문제에 대한 다양한 접근법 노출이 모델의 추론 유연성을 향상시킨다. 수학/과학에서는 exact deduplication 후 16x 샘플링, 코드에서는 중복 제거 없이 16x 샘플링을 적용했다(코드는 동일 문제도 다양한 접근법이 가능하므로).

### Stage 4: Answer Filtering (답변 필터링)

:::danger
**놀라운 발견:** GPT 검증, Majority consensus, 길이 기반 등 **어떤 답변 필터링 전략도 성능을 향상시키지 못했다**. 오히려 "필터링 없음"이 가장 높은 성능을 보였다.
:::

이는 기존 통념("잘못된 답변은 제거해야 한다")과 정면으로 배치된다. 특히 [[process-reward-models]]을 사용한 정교한 답변 검증조차 성능 향상에 기여하지 못했다는 점이 충격적이다.

저자들의 해석은 세 가지로 정리된다:

1. **다양성 감소**: 필터링은 데이터 양을 줄여 모델이 학습할 수 있는 풀이 경로의 다양성을 감소시킨다. 16x 샘플링의 이점을 상쇄하는 셈이다
2. **추론 과정의 가치**: "잘못된" 최종 답변이라도 추론 과정 자체는 유용한 학습 신호를 제공한다. 부분적으로 올바른 추론 체인에서도 모델은 유용한 패턴을 추출할 수 있다
3. **16x 중복의 완충 효과**: 16x 샘플링으로 이미 충분한 정답이 포함되어 있어, 오답 몇 개가 전체 학습에 미치는 부정적 영향이 미미하다

답변 필터링 전략별 비교 결과:

| 필터링 전략 | 설명 | AIME24 대비 변화 |
|------------|------|-----------------|
| **필터링 없음** | 16x 답변 전부 사용 | **기준선 (최고)** |
| GPT-4o 검증 | GPT로 답변 정오 판정 | -2.1pp |
| Majority Vote | 다수결로 오답 제거 | -1.8pp |
| 길이 필터링 | 짧은 답변 제거 | -3.2pp |
| PRM 검증 | Process Reward Model 사용 | -1.5pp |

이 발견은 실무적으로도 중요하다: **비용이 많이 드는 답변 검증 단계를 생략할 수 있다.** 특히 PRM 기반 검증은 별도의 보상 모델 학습이 필요한데, 이를 생략해도 오히려 성능이 높다는 것은 데이터 큐레이션 파이프라인을 크게 단순화할 수 있음을 의미한다.

### Stage 5: Question Mixing (도메인 배합)

수학/코드/과학 세 도메인의 최종 배합 비율을 결정하는 단계다. 단순히 "데이터가 많은 도메인을 더 넣자"가 아니라, 각 도메인의 데이터가 다른 도메인 벤치마크에 미치는 교차 효과를 측정하여 최적 비율을 도출했다.

최종 배합 비율 결정 과정:

| 배합 비율 (수학:코드:과학) | AIME24 | LiveCodeBench | GPQA-D | 평균 |
|--------------------------|--------|---------------|--------|------|
| 100:0:0 | 70.3% | 38.2% | 45.1% | 낮음 |
| 50:30:20 | 63.7% | 48.9% | 52.3% | 보통 |
| **70.8:20.8:8.3** | **69.0%** | **51.7%** | **53.7%** | **최고** |
| 60:25:15 | 66.1% | 50.2% | 53.0% | 양호 |

수학 100%일 때 AIME24는 가장 높지만 코드와 과학이 급락한다. 최종 선택된 70.8:20.8:8.3 비율은 수학 성능을 약간 희생하면서도 코드와 과학에서 큰 폭의 향상을 달성하는 파레토 최적 지점이다.

### Stage 6: Teacher Model Selection (교사 모델 선택)

:::tip
**핵심 발견:** QwQ-32B가 교사 모델로 선정되었다. [[deepseek-r1]]보다 **직접 성능은 낮지만**, 학생 모델 훈련 시 **더 높은 성능**을 달성했다.
:::

| 교사 모델 | 파라미터 | 구조 | 교사 직접 AIME24 | 학생(7B) AIME24 |
|----------|---------|------|-----------------|----------------|
| DeepSeek-R1 | 671B | MoE | 79.8% | 62.3% |
| **QwQ-32B** | **32B** | **Dense** | **66.7%** | **69.0%** |
| DeepSeek-R1-32B | 32B | Dense | 72.3% | 65.1% |

이 현상은 **용량 격차(capacity gap)** 이론으로 설명된다. DeepSeek-R1은 671B MoE 모델로, 7B 학생 모델이 모방하기에는 너무 복잡한 추론 패턴을 생성한다. 반면 QwQ-32B(32B dense)는 학생 모델의 용량에 더 가까운 수준의 추론 체인을 제공하여, 효과적인 지식 전달(distillation)이 가능하다.

특히 주목할 점은 DeepSeek-R1-32B(32B, Dense)도 QwQ-32B보다 학생 성능이 낮다는 것이다. 파라미터 수만으로는 설명되지 않는, 추론 체인의 "스타일"이나 "명시성"이 학생 학습에 영향을 미치는 것으로 보인다. QwQ-32B의 추론 체인이 더 구조적이고 단계별로 명확하여, 7B 모델이 패턴을 추출하기 용이한 것으로 해석된다.

이는 knowledge distillation 연구의 오래된 교훈을 추론 데이터 생성 맥락에서 재확인한 결과다: **"교사와 학생의 용량 차이가 너무 크면 증류 효율이 떨어진다."**

## 벤치마크 결과

### OpenThinker3-7B: 7B 규모 SOTA

OpenThoughts3-1.2M으로 훈련된 OpenThinker3-7B (Qwen2.5-7B-Instruct 기반)의 결과:

| 벤치마크 | OpenThinker3-7B | DeepSeek-R1-Qwen-7B | 향상폭 |
|----------|-----------------|---------------------|--------|
| AIME 2024 | **69.0%** | 51.3% | +17.7pp |
| AIME 2025 | **53.3%** | 38.0% | +15.3pp |
| LiveCodeBench | **51.7%** | 34.5% | +17.2pp |
| GPQA Diamond | **53.7%** | 33.2% | +20.5pp |
| MATH500 | 90.0% | 88.0% | +2.0pp |
| 12개 벤치마크 평균 | **55.3%** | 42.9% | +12.4pp |

특히 GPQA Diamond에서의 +20.5pp 향상은 주목할 만하다. GPQA는 PhD 수준의 과학 문제인데, 전체 데이터의 8.3%에 불과한 과학 도메인 데이터로도 이러한 향상을 달성했다. 이는 수학 데이터의 범용 추론 전이 효과를 다시 한번 확인시켜준다. 수학에서 학습된 논리적 추론 능력이 과학 문제 풀이에도 전이되는 것이다.

### SFT vs RL: "데이터만으로 충분한가?"

| 모델 | 방법 | 12개 벤치마크 평균 |
|------|------|------------------|
| **OpenThinker3-7B** | **SFT only** | **55.3** |
| Nemotron-Nano-8B | SFT + RL | 53.2 |
| AceReason-7B | RL | 52.9 |
| Skywork-7B | RL | 51.6 |
| DeepSeek-R1-Qwen-7B | Distillation | 42.9 |

SFT만으로 RL 기반 모델들을 능가한다는 결과는, **데이터 품질이 학습 알고리즘보다 중요할 수 있다**는 가설을 강력히 지지한다. 물론 이것이 "RL이 불필요하다"는 의미는 아니다. OpenThoughts + RL의 조합은 아직 탐구되지 않은 영역이며, 두 접근법은 상호 보완적일 가능성이 높다. 실제로 Nemotron-Nano-8B는 SFT 후 RL을 추가하여 성능을 높였는데, OpenThoughts3 수준의 SFT 데이터에 RL까지 적용하면 추가적인 향상이 기대된다.

## 세대별 발전: v1에서 v3까지

| 모델 | 데이터 버전 | 데이터 크기 | AIME24 | AIME25 | GPQA-D | 핵심 변경점 |
|------|-----------|-----------|--------|--------|--------|-----------|
| OpenThinker-7B | v1 | 114K | 29.3% | 25.3% | 44.1% | 초기 파이프라인 |
| OpenThinker2-7B | v2 | 1M | 60.7% | 38.7% | 47.0% | 소스 확장 + 필터링 도입 |
| **OpenThinker3-7B** | **v3** | **1.2M** | **69.0%** | **53.3%** | **53.7%** | **6단계 레시피 최적화** |

v1에서 v3로의 AIME24 변화(29.3%에서 69.0%)는 데이터 큐레이션의 반복적 개선이 극적인 차이를 만들 수 있음을 보여준다. 특히 v2(1M)에서 v3(1.2M)로의 전환에서 데이터 양은 20%만 증가했지만 AIME24는 8.3pp 향상되었다. 이는 양보다는 **레시피 개선**의 기여가 더 크다는 증거다.

v2에서 v3로의 주요 개선 사항은 다음과 같다:
- 교사 모델을 DeepSeek-R1에서 QwQ-32B로 변경 (+6.7pp)
- 답변 필터링 제거 (+1.5~2pp)
- 소스 배합 최적화 (Top-16에서 Top-2 중심으로)
- 도메인 비율 재조정 (과학 도메인 비율 증가)

## 핵심 교훈 5가지

### 1. 16x 답변 샘플링이 더 많은 질문보다 낫다

같은 총 데이터 양이라면, 질문 수를 늘리는 것보다 기존 질문에 대한 답변을 여러 번 생성하는 것이 효과적이다. 75K 질문 x 16 답변이 300K 질문 x 4 답변보다 AIME24에서 7pp 높다. 다양한 풀이 경로 노출이 추론 능력 향상의 핵심이며, 이는 [[self-consistency]]에서의 다중 경로 탐색과 같은 맥락이다.

### 2. 최고 성능 모델은 최고 교사가 아니다

교사 모델 선택 시 벤치마크 점수만 보면 안 된다. QwQ-32B(벤치마크 2위)가 DeepSeek-R1(벤치마크 1위)보다 학생 훈련에 더 효과적이었다. 학생 모델의 용량과 학습 가능성을 고려해야 하며, "따라할 수 있는 수준"의 추론이 가장 효과적이다.

### 3. 답변 필터링은 불필요하다

잘못된 답변을 제거하는 것이 항상 좋은 것은 아니다. GPT 검증, PRM, Majority Vote 등 어떤 필터링도 성능을 향상시키지 못했다. 다양성 감소의 비용이 품질 향상의 이득을 초과하며, 이는 비용 절감 측면에서도 실무적 가치가 크다.

### 4. 품질이 다양성을 압도한다

62개 출처 중 Top-2만 사용해도 Top-16보다 5pp 높은 정확도를 얻었다. 데이터 큐레이션에서 "더 많은 출처"는 "더 좋은 데이터"를 보장하지 않는다. 소수의 검증된 고품질 소스에 집중하는 것이 최적이다.

### 5. 긴 추론 체인이 필수적이다

Self-reflection을 제거하면 성능이 49.1% 하락했다. `<think>` 태그 안의 긴 추론 체인이 추론 모델 학습의 핵심이다. "생각하는 과정"을 명시적으로 포함하는 것이 최종 답변의 정확도를 극적으로 향상시킨다. 이는 단순한 답변 생성과 [[reasoning-vs-inference]]의 근본적 차이를 보여준다.

## 실전 활용 가이드

### 데이터셋 접근과 활용

데이터셋은 HuggingFace에서 바로 다운로드 가능하다. `domain` 필드로 특정 도메인만 필터링하거나, `difficulty` 필드로 난이도별 커리큘럼 학습을 구성할 수 있다.

```python
from datasets import load_dataset

# 전체 데이터셋 로드
ds = load_dataset("open-thoughts/OpenThoughts3-1.2M", split="train")

# 수학 도메인만 필터링 (고난도)
math_hard = ds.filter(
    lambda x: x["domain"] == "math" and x["difficulty"] >= 8
)
print(f"고난도 수학 문제: {len(math_hard)}개")

# 코드 도메인 + 특정 소스
code_cf = ds.filter(
    lambda x: x["domain"] == "code" and "Codeforces" in x["source"]
)
```

### 자체 추론 모델 구축 시 체크리스트

OpenThoughts3의 레시피를 자체 프로젝트에 적용할 때 고려할 사항:

1. **소스 선정**: 많은 소스를 모으기보다, 소수의 고품질 소스를 먼저 확보
2. **필터링 전략**: 도메인마다 다른 필터링 기준 적용 (일률적 적용 금지)
3. **교사 모델**: 최강 모델이 아니라, 학생 용량에 맞는 모델 선택
4. **답변 다양성**: 질문 수를 늘리기보다 질문당 답변 수를 늘릴 것
5. **답변 검증**: 비용 대비 효과가 낮으므로, 검증보다 샘플링에 투자
6. **추론 체인**: `<think>` 태그 등 명시적 추론 구조 반드시 포함

## 시사점

OpenThoughts3는 단순한 데이터셋을 넘어, **추론 데이터 큐레이션의 체계적 방법론**을 제시한다.

**SFT의 재평가**: RLHF/DPO 등 RL 기반 정렬이 대세인 상황에서, "데이터만 잘 만들면 SFT로 충분하다"는 메시지는 연구 방향에 중요한 시사점을 준다. 특히 RL은 보상 모델 학습, 정책 최적화 등 추가적인 복잡성과 비용을 수반하는데, 고품질 SFT 데이터가 이를 상당 부분 대체할 수 있다면 실무적 가치가 크다. 향후 OpenThoughts3 수준의 SFT + 최적화된 RL의 결합이 새로운 SOTA를 달성할 가능성도 열려 있다.

**오픈소스의 경쟁력**: 49명의 다기관 연구진이 공개한 데이터셋, 코드, 레시피를 통해 누구나 추론 모델을 구축할 수 있다. [[deepseek-r1]]의 800K 비공개 데이터에 의존하지 않고도 동등 이상의 성능을 달성할 수 있다는 것은 오픈소스 AI 생태계에 큰 의미가 있다. 특히 6단계 레시피가 완전 공개되어, 다른 연구자들이 자신의 도메인에 맞게 변형 적용할 수 있다.

**추론 모델 연구의 방향**: OpenThoughts3의 발견들은 추론 모델 연구에서 데이터 중심 접근법(Data-Centric AI)의 중요성을 재확인시킨다. 모델 아키텍처나 학습 알고리즘의 혁신도 중요하지만, **같은 모델이라도 데이터를 어떻게 구성하느냐에 따라 29.3%에서 69.0%까지 성능이 달라질 수 있다**는 것은 데이터 엔지니어링의 가치를 웅변한다.

**[[synthetic-data-training]]의 성숙**: 합성 데이터로 모델을 훈련하는 접근법이 단순한 데이터 증강을 넘어, 체계적인 레시피 기반 구축 방법론으로 발전하고 있다. OpenThoughts3는 이 분야의 "레시피북"으로서, 앞으로의 합성 데이터 연구가 어떤 변수를 통제하고 어떤 실험을 수행해야 하는지에 대한 표준을 제시한다.
