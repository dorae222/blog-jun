## 🧩 Quick Overview

| 항목             | 설명 |
|------------------|------|
| **이름**          | Blue/Green Deployment (블루/그린 배포) |
| **적용 서비스**    | Amazon SageMaker, EC2, Lambda, ECS 등 |
| **주요 목적**      | **새로운 버전의 애플리케이션 또는 모델을 위험 없이 배포**하고  
                       문제가 없을 경우 트래픽을 전환하여 운영 환경에 반영

> 🚦 블루/그린 배포는 **현재 운영 중인(블루)** 버전과 **새로운(그린)** 버전을 **병렬로 유지**한 상태에서  
> **트래픽을 선택적으로 전환**하여 **안전하게 롤아웃**하는 방식입니다.

---

## 🎯 SageMaker에서의 의미

| 항목 | 설명 |
|------|------|
| **Blue** | 현재 실시간 추론에 사용 중인 **운영 모델** |
| **Green** | 성능 테스트 및 교체를 위해 준비한 **새로운 모델 버전** |
| **전환 방법** | 트래픽을 **100% 또는 일부(카나리아)** 비율로 Green 모델로 이동 가능 |
| **문제 발생 시** | 즉시 Blue 모델로 **롤백** 가능

---

## 🚀 두 가지 전환 방식

| 방식 | 설명 |
|------|------|
| **전체 전환 (A/B)** | 한 번에 모든 트래픽을 Green(신규 모델)으로 이동 |
| **카나리아 전환** | 일부 트래픽(예: 10%)을 먼저 Green으로 보내고, 정상 작동 확인 후 점진적 전환 |

---

## ✅ 장점

| 항목 | 설명 |
|------|------|
| **무중단 배포** | 운영 중인 서비스에 영향 없이 신규 버전 테스트 가능 |
| **롤백 용이** | 문제가 생기면 다시 블루로 즉시 전환 |
| **점진적 실험** | 실사용자 기반 실시간 성능 테스트 가능 |
| **비교 분석** | CloudWatch로 블루 vs 그린 지표 모니터링 가능

---

## ⚠️ 유의사항

| 항목 | 설명 |
|------|------|
| **실시간 영향 존재** | 일부 트래픽은 실제 사용자 요청에 영향 줄 수 있음 (카나리아 비율 설정 중요) |
| **서로 다른 모델 상태 유지 필요** | 블루와 그린 모델을 동시에 관리해야 함 |
| **Shadow Testing과 차이점** | 블루/그린은 실제 예측 결과가 사용자에게 전달됨 → Shadow는 병렬 실행만

---

## 🧾 요약

| 항목 | 설명 |
|------|------|
| **정의** | 운영 중인 모델(Blue)과 신규 모델(Green)을 병렬로 유지하며, 트래픽을 점진적으로 전환하는 안전한 배포 전략 |
| **적용 위치** | 실시간 추론 엔드포인트, 모델 교체 시나리오 |
| **전환 방식** | 전면 또는 카나리아 방식 선택 가능 |
| **장점** | 무중단, 안전한 롤아웃, 성능 비교 후 전환 |
