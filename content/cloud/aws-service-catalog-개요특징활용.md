## 🧩 Quick Overview

| 항목        | 설명                                                                        |
| --------- | ------------------------------------------------------------------------- |
| **서비스명**  | AWS Service Catalog                                                       |
| **유형**    | **IT 서비스 카탈로그 관리 서비스**                                                    |
| **주요 목적** | 조직에서 승인한 **클라우드 리소스·애플리케이션·템플릿을 카탈로그화**하여 **사용자가 표준화된 방식으로 배포**할 수 있도록 지원 |

> 📦 **AWS Service Catalog**를 사용하면
> **승인된 클라우드 자원만 카탈로그로 제공**하여
> **보안·규정 준수·비용 통제를 유지**하면서 셀프서비스 배포를 가능하게 합니다.

---

## 🔧 주요 특징

| 항목 | 설명 |
|------|------|
| **포트폴리오(Portfolio)** | 제품을 그룹화하는 단위로, 부서나 프로젝트별로 권한을 부여할 수 있음 |
| **제품(Product)** | 배포 가능한 단일 리소스 또는 CloudFormation 스택 단위 |
| **버전 관리** | 각 제품의 여러 버전을 관리하고 변경 이력을 추적 가능 |
| **IAM 통합** | 사용자는 승인된 포트폴리오에만 접근 가능 |
| **규정 준수 지원** | 표준화된 템플릿으로 보안·비용·태깅 정책을 적용 가능 |
| **셀프서비스 배포** | 사용자는 콘솔에서 클릭만으로 제품을 배포할 수 있음 |

---

## 🧪 활용 시나리오

- **표준화된 인프라 배포**
  - 예: VPC, EC2, RDS 템플릿을 제공하여 개발팀이 자율적으로 배포
- **조직 규정 준수 유지**
  - 비용 태깅 및 리소스 제한 정책을 자동으로 적용
- **DevOps/셀프서비스 포털**
  - IT 부서가 승인한 서비스 카탈로그를 셀프서비스 형태로 제공
- **다중 계정 환경 관리**
  - AWS Organizations와 통합해 계정별로 표준화된 배포 가능

---

## ✅ 장점

- **보안·규정 준수 강화** → 승인된 자원만 배포 가능
- **운영 효율화** → 중앙 IT가 표준 템플릿만 관리
- **셀프서비스 배포 지원** → 개발·운영팀의 민첩성 향상
- **버전 관리 용이** → 인프라 변경을 추적 가능

---

## ⚠️ 유의사항

| 항목 | 설명 |
|------|------|
| **CloudFormation 지식 필요** | 제품은 주로 CloudFormation 스택 기반으로 작성됨 |
| **초기 설계 필요** | 포트폴리오·제품 구조와 권한 정책을 사전에 설계해야 함 |
| **자동화 한계** | 워크플로우 자동화는 별도로 Service Catalog AppRegistry·Pipelines를 활용해야 함 |
