**지연 라우팅 정책(Latency-based Routing policy)**은 **Amazon Route 53**에서 제공하는 **DNS 라우팅 정책 중 하나**로,  
**사용자에게 가장 짧은 지연 시간(latency)**을 제공할 수 있는 **AWS 리전의 리소스로 트래픽을 유도하는 기능**입니다.

---

## ⚡ 지연 라우팅 정책(Latency-based Routing)이란?

> **Latency Routing**은 DNS 쿼리를 수행한 사용자의 위치에서 **각 AWS 리전에 대해 측정된 네트워크 지연 시간(latency)**을 기반으로,  
> **가장 빠르게 응답할 수 있는 리전의 리소스**를 응답하도록 구성하는 정책입니다.

즉, 전 세계 사용자에게 **가장 빠른 서버로 자동 연결**되도록 하는 라우팅 방식입니다.

---

## 📍 사용 목적

- 전 세계에서 접근하는 웹 애플리케이션, API 서버 등에 대해
- 사용자에게 **가장 낮은 응답 지연 시간**을 제공하고 싶을 때
- 여러 AWS 리전에 리소스를 배포해둔 상태에서 **성능 기반 트래픽 분산**을 원할 때

---

## 🔧 작동 방식

1. 여러 리전에 EC2, ALB, S3 웹 호스팅 등의 리소스를 배포합니다.
2. Route 53에서 **각 리전에 해당하는 레코드와 ‘지연 라우팅 리전’ 정보**를 설정합니다.
3. 사용자가 DNS 쿼리를 수행하면,
   - Route 53이 **측정된 지연 시간 정보**를 참고하여 가장 빠르게 응답할 수 있는 리전의 리소스를 반환합니다.
   - CloudFront가 필요 없을 때 간단한 대안으로 활용할 수 있습니다.

---

## ✅ 예시

|사용자 위치|가장 빠른 리전|연결 대상|
|---|---|---|
|서울|아시아 태평양(서울)|서울 리전의 ALB|
|뉴욕|미국 동부(버지니아)|버지니아 리전의 EC2|
|도쿄|아시아 태평양(도쿄)|도쿄 리전의 S3 정적 웹사이트|

---

## 📌 구성 요소

|항목|설명|
|---|---|
|**Route 53 레코드 유형**|A, AAAA, CNAME 등|
|**지연 라우팅 리전 지정**|예: us-east-1, ap-northeast-2|
|**헬스 체크**|헬스 체크와 함께 사용하여 비정상 리전을 제외할 수 있음|
|**서브넷 수준은 아님**|리전 단위 기준 (서울 리전, 도쿄 리전 등)|

---

## ⚠️ 유사 정책과 비교

|정책|기준|사용 예|
|---|---|---|
|**지연 라우팅**|AWS 리전 간의 실제 **지연 시간(latency)**|사용자에게 **가장 빠른 리전**으로 연결|
|**지리 위치 라우팅(Geolocation)**|**사용자의 국가/대륙** 기반|지역별 리소스 제한, 규제 대응|
|**지리 근접 라우팅(Geoproximity)**|사용자 ↔ 리전 거리 기반 + 편향(bias) 설정|가장 가까운 지점으로 유도|
|**다중값 응답(Multivalue)**|여러 IP 무작위 제공 + 헬스 체크|간단한 로드 밸런싱 대체|
