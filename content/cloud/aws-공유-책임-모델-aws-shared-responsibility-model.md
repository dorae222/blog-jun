## 🧩 Quick Overview

| 항목              | 설명 |
|-------------------|------|
| **개념명**         | AWS 공유 책임 모델 (AWS Shared Responsibility Model) |
| **주요 목적**       | AWS 클라우드 환경에서 **보안과 규정 준수 책임을 AWS와 고객 간에 명확히 구분** |
| **핵심 원칙**       | **AWS는 클라우드 자체의 보안**, **고객은 클라우드 내부의 보안**을 책임진다 |

> 🔐 AWS 공유 책임 모델은 클라우드 서비스를 사용할 때
> **AWS와 고객이 각각 어떤 영역을 책임지는지 명확히 정의하여 보안·컴플라이언스를 보장**합니다.

---

## 🔧 책임 구분

### 1️⃣ AWS의 책임 (Security **of** the Cloud)

AWS는 **클라우드 인프라 자체**의 보안과 가용성을 책임집니다.

| 영역 | 상세 내용 |
|------|---------|
| **하드웨어 보안** | 서버, 스토리지, 네트워크 장비 |
| **데이터센터 물리 보안** | 출입 통제, CCTV, 환경 제어, 전력/냉각 |
| **인프라 네트워크 보안** | L2~L3 수준 네트워크, DDoS 방어, AWS Global Network |
| **하이퍼바이저/호스트 OS** | EC2, Lambda, RDS 등 서비스 기반의 OS/가상화 계층 |
| **관리형 서비스의 운영 인프라** | S3, DynamoDB, Lambda, RDS 등 서버 측 운영 보안 |

---

### 2️⃣ 고객의 책임 (Security **in** the Cloud)

고객은 **클라우드에 배포한 리소스, 데이터, 애플리케이션**의 보안을 책임집니다.

| 영역 | 상세 내용 |
|------|---------|
| **데이터 보호** | 암호화(AES, KMS), 백업/복구 계획 |
| **IAM 관리** | 사용자/역할 권한, MFA, 접근 키 관리 |
| **네트워크 보안** | VPC 설계, 보안 그룹, NACL, VPN/Direct Connect |
| **애플리케이션 보안** | 코드 취약점 관리, 인증·인가 로직 |
| **OS 및 패치 관리** | EC2 인스턴스 OS, 자체 설치 애플리케이션 패치 |
| **규정 준수 설정** | CloudTrail, Config, GuardDuty 등을 통한 감사·로깅 |

---

## 🔄 서비스 유형별 책임 차이

| 서비스 유형 | AWS 책임 | 고객 책임 |
|------------|--------|---------|
| **IaaS (예: EC2, EBS, VPC)** | 하드웨어, 가상화 계층, 스토리지 인프라 | OS 패치, 앱 보안, 데이터 암호화 |
| **PaaS (예: RDS, Lambda, S3)** | 인프라·OS·런타임 관리 | 데이터 관리, IAM 정책, 앱 구성 |
| **SaaS (예: WorkMail, QuickSight)** | 인프라+앱 전체 | 계정·사용자 관리, 데이터 입력 보안 |

## 🧪 시각적 예시

```plaintext
┌───────────────────────────────┐
│         AWS 책임               │
│ - 물리적 데이터센터 보안       │
│ - 서버/스토리지/네트워크 관리  │
│ - 가상화 및 서비스 인프라      │
└───────────────────────────────┘
             ↑
   (클라우드 자체 보안)
             ↓
┌───────────────────────────────┐
│         고객 책임              │
│ - 데이터 암호화 및 접근 제어    │
│ - 애플리케이션/OS 패치         │
│ - IAM, 네트워크 구성           │
└───────────────────────────────┘
````

## ✅ 장점

- **보안 책임 명확화** → 사고 원인과 대응 범위를 구분하기 쉬움
- **컴플라이언스 지원** → PCI-DSS, ISO27001 등 인증 대응이 용이함
- **운영 효율화** → 고객은 인프라 운영 부담 없이 애플리케이션 보안에 집중할 수 있음
- **비용 최적화** → AWS의 관리형 서비스를 활용하면 고객의 책임 범위를 줄일 수 있음

---

## ⚠️ 유의사항

|항목|설명|
|---|---|
|**책임 경계 서비스별 상이**|EC2(IaaS) vs Lambda(PaaS) vs SaaS에 따라 책임 범위가 달라짐|
|**고객 설정 오류 위험**|S3 Public Access, 약한 IAM 정책 등은 고객 책임임|
|**지속 모니터링 필요**|CloudTrail, GuardDuty, Security Hub 등을 적극 활용해야 함|
