## 🐤 카나리아 배포(Canary Deployment)

| 항목     | 설명                                                                                              |
| ------ | ----------------------------------------------------------------------------------------------- |
| **정의** | 새로운 버전(애플리케이션, 모델 등)을 전체가 아닌 **일부 사용자/트래픽에만 먼저 배포**하여 문제 발생 여부를 확인한 뒤, **점진적으로 전체로 확대하는 배포 전략** |
| **유래** | 광부들이 유해 가스를 감지하기 위해 카나리아 새를 먼저 보냈던 방식에서 유래 → "위험 감지용 시험군"의 의미                                   |

---

## 🚀 작동 방식

1. **기존 버전(Stable)**은 그대로 유지
2. **신규 버전(Preview)**에 **일부 트래픽**(예: 5~10%)만 먼저 전달
3. 에러, 지연, 품질 저하 등 문제 발생 여부를 관찰
4. 이상이 없으면 점진적으로 전체 트래픽으로 확장
5. 문제가 발생하면 즉시 기존 버전으로 **롤백**

---

## ✅ 장점

| 항목 | 설명 |
|------|------|
| **위험 최소화** | 문제 발생 시 영향을 받는 사용자가 제한적임 |
| **빠른 검증** | 실제 사용자 환경에서 성능과 안정성을 확인할 수 있음 |
| **즉시 롤백 가능** | 장애 발견 시 빠르게 원상 복구할 수 있음 |
| **모니터링 기반 제어** | CloudWatch, Prometheus 등과 연계해 지표 기반 자동화가 가능함 |

---

## ⚠️ 유의사항

| 항목 | 설명 |
|------|------|
| **정교한 트래픽 라우팅 필요** | 특정 사용자 또는 요청을 선택적으로 보내는 기술이 필요함 (예: SageMaker, Lambda Alias, API Gateway 등에서 지원) |
| **모니터링 필수** | 오류율, 지연 시간, 이상 행동 등 실시간 관측이 필요함 |
| **기준 정의 중요** | 성능 기준(예: 에러율 1% 이상 시 롤백)을 사전에 명확히 설정해야 함 |

---

## 🧾 요약

| 항목       | 설명 |
|------------|------|
| **의미**     | 신규 버전을 전체에 배포하기 전에 **소량의 트래픽으로 실험**하는 안전한 롤아웃 전략 |
| **사용 사례** | 모델 배포(SageMaker), API 배포(Lambda), 마이크로서비스 교체 등 |
| **비교 개념** | 전체 배포(One-shot), 블루/그린, 섀도우 테스트와 함께 사용 가능 |
