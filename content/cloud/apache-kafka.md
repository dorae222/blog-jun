## 🧩 Quick Overview

| 항목              | 설명 |
|-------------------|------|
| **이름**           | Apache Kafka |
| **유형**           | **분산형 스트리밍 플랫폼(Distributed Streaming Platform)** |
| **주요 목적**       | **대용량 데이터의 실시간 수집, 처리, 저장, 스트리밍 전송** 지원

> ⚡ **Kafka**는 초당 수백만 건의 이벤트를 안정적으로 처리할 수 있는  
> **고성능 분산 메시지 브로커**이자 **실시간 스트리밍 데이터 플랫폼**입니다.

---

## 🔧 핵심 구성 요소

| 구성 요소       | 설명 |
|----------------|------|
| **Producer**   | Kafka로 메시지(이벤트)를 전송하는 클라이언트 |
| **Consumer**   | Kafka에서 메시지를 구독하고 처리하는 클라이언트 |
| **Topic**      | 메시지를 분류하는 단위(논리적 채널) |
| **Partition**  | 토픽을 여러 분할로 나누어 병렬 처리와 확장성 제공 |
| **Broker**     | Kafka 서버로서 메시지를 저장·전송함 |
| **Zookeeper / KRaft** | 클러스터 메타데이터를 관리(최근에는 KRaft로 대체되는 추세) |
| **Consumer Group** | 여러 Consumer가 하나의 토픽을 병렬로 처리하도록 구성하는 단위 |

---

## ⚙️ 동작 방식

1. **Producer**가 특정 **Topic**으로 메시지를 전송한다.
2. **Broker**는 수신한 메시지를 **Partition 단위**로 저장한다.
3. **Consumer**는 Topic을 구독하여 메시지를 읽고 처리한다.
4. 메시지는 기본적으로 **Append-Only 로그**에 저장되므로 고가용성 확보와 재처리가 용이하다.

---

## ✅ 주요 특징

- **고성능·고처리량**: 초당 수백만 건 이상의 이벤트 처리 가능
- **확장성**: 브로커와 파티션을 늘려 수평 확장
- **내구성·복제**: 메시지를 디스크에 저장하고 다중 복제로 내구성 보장
- **실시간 스트리밍**: 이벤트를 거의 실시간으로 소비 가능
- **재처리 가능**: Consumer Offset 관리로 과거 이벤트 재처리 가능
- **Connect & Streams API 제공**: 외부 시스템 연계 및 스트리밍 처리 지원

## 📦 활용 사례

| 사례 | 설명 |
|------|------|
| **실시간 로그 수집** | 웹/앱 서버 로그, IoT 디바이스 데이터 수집 |

| **금융 거래 처리** | 사기 탐지 및 실시간 모니터링 대응 |
| **분석 및 모니터링** | Clickstream 분석, Metrics 파이프라인 구축 |

## 🧰 연동 가능한 AWS 서비스

- **Amazon MSK (Managed Streaming for Apache Kafka)**: 완전관리형 Kafka 서비스
- **Amazon Kinesis**: Kafka를 대체할 수 있는 스트리밍 서비스
- **AWS Glue / Lambda / Redshift / S3**: 데이터 처리 및 저장 연계 서비스
