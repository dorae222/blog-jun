## 🧩 Quick Overview

| 항목        | 설명                                                                          |
| --------- | --------------------------------------------------------------------------- |
| **프로토콜명** | RTSP (Real-Time Streaming Protocol)                                         |
| **유형**    | **멀티미디어 스트리밍 제어 프로토콜**                                                      |
| **주요 목적** | **IP 카메라·미디어 서버에서 실시간 영상/음성을 스트리밍**하고, **클라이언트가 재생·일시정지·중지 등 제어**할 수 있도록 지원 |

---

## 🔧 주요 특징

|항목|설명|
|---|---|
|**실시간 전송**|라이브 카메라·CCTV 영상과 오디오를 실시간으로 스트리밍합니다.|
|**제어 명령 지원**|PLAY, PAUSE, TEARDOWN 등 재생 제어를 지원합니다.|
|**멀티캐스트/유니캐스트 지원**|다수의 클라이언트에 동일한 영상을 송출할 수 있습니다.|
|**전송 계층 분리**|미디어 데이터는 실제 전송을 위해 **RTP/RTCP**를 사용하고, RTSP는 제어 신호를 담당합니다.|
|**네트워크 호환성**|IP 기반 네트워크에서 동작하며 주로 보안 카메라와 NVR에서 사용됩니다.|

---

## 🧪 활용 시나리오

- **CCTV·IP 카메라 영상 전송**
  - Kinesis Video Streams, NVR, 미디어 서버와 연계하여 사용합니다.

- **보안·감시 시스템**
  - 실시간 모니터링과 이벤트 기반 경보에 활용됩니다.

- **스트리밍 분석**
  - Amazon Rekognition Video나 OpenCV 등으로 실시간 분석을 수행합니다.

- **원격 방송/라이브 송출**
  - 미디어 서버를 통해 라이브 스트리밍 서비스를 제공할 때 사용합니다.

---

## ✅ 장점

- **실시간 스트리밍 최적화** → 지연(latency)을 최소화합니다.
- **제어 기능 제공** → 클라이언트에서 재생을 제어할 수 있습니다.
- **표준화된 프로토콜** → 다양한 카메라와 서버 간 호환성이 높습니다.

---

## ⚠️ 유의사항

|항목|설명|
|---|---|
|**인터넷 전송 시 보안 취약**|인터넷을 통해 전송할 경우 보안 취약점이 발생할 수 있으므로 HTTPS, VPN, 암호화 적용을 권장합니다.|
|**방화벽 설정 필요**|기본적으로 TCP 554 포트를 사용하므로 네트워크 정책과 방화벽 설정을 확인해야 합니다.|
|**대역폭 부담**|고화질 영상이나 다수 스트림 전송 시 네트워크 부하가 커질 수 있습니다.|
