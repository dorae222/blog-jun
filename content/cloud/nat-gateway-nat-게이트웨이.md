> **NOTE:**
> **NAT 게이트웨이(NAT Gateway)**는 AWS VPC에서 **프라이빗 서브넷에 있는 인스턴스가 인터넷에 접근할 수 있도록 해주는 관리형 네트워크 컴포넌트**입니다. 그러나 외부에서는 해당 인스턴스에 **직접 접근할 수 없습니다.**

---

## 🌐 NAT Gateway란?

> **NAT(Network Address Translation) Gateway**는 **프라이빗 서브넷의 리소스가 아웃바운드로만 인터넷에 접속할 수 있도록 해주는 AWS 관리형 서비스**입니다.


---

## 🧠 왜 필요한가?

프라이빗 서브넷에 있는 EC2 인스턴스 등은 보안을 위해 **인터넷 게이트웨이(IGW)**가 연결되어 있지 않습니다. 그러나 OS 패치나 외부 API 호출 등으로 인해 **인터넷 접속이 필요한 경우**가 있습니다.

이때 **NAT 게이트웨이**를 사용하면 **프라이빗 리소스의 아웃바운드 트래픽만 허용하고 인바운드는 차단하는 구조**를 만들 수 있습니다.

---

## 🧱 동작 방식 요약

|항목|설명|
|---|---|
|**트래픽 방향**|프라이빗 서브넷 → NAT 게이트웨이 → 인터넷 (✔️ 허용)|
|**외부 → 프라이빗**|❌ 직접 접근 불가|
|**주소 변환**|내부 IP → 퍼블릭 IP로 변환하여 통신|
|**보안**|외부에서 인바운드 트래픽 차단됨 (보안 강화)|

---

## 📍 구성 요건

1. **퍼블릭 서브넷에 NAT 게이트웨이 배치**

2. **탄력적 IP(Elastic IP)** 할당 필수

3. 프라이빗 서브넷의 라우팅 테이블에
    `0.0.0.0/0 → NAT Gateway` 설정

---

## 🔁 NAT Gateway vs NAT 인스턴스

|항목|NAT Gateway|NAT 인스턴스|
|---|---|---|
|관리형|✅ AWS가 관리|❌ 직접 관리 필요|
|성능 확장|자동 확장|수동 확장|
|유지보수|없음|패치, 모니터링 필요|
|고가용성|AZ별 생성 필요|EC2로 구성 가능|
|비용|약간 더 비쌈|EC2 요금 기준|

✅ 대부분의 경우 **NAT Gateway 사용이 권장**

---

## 💡 사용 예시

> 프라이빗 서브넷의 EC2 인스턴스가
> 
> - S3에 파일 업로드
>     
> - OS 보안 업데이트
>     
> - 외부 API 호출  
>     등을 하려는 경우 → **NAT Gateway 필요**
>
